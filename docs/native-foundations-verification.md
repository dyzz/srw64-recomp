# 语言设置、保存集合与状态对照

2026-09-12。范围为项目自有模块，不接入外部 MOD。语言内容生产另排期；原版随机时序保持不变，只验证并记录差异。

## 语言设置与覆盖

统一 profile 运行中按 **F7** 按**日文 → 中文 → 英文**循环热切换，**没有弹窗**，同时记住下次启动的选择；窗口标题显示当前语言。设置写到 `build/recomp/profile-play/presentation.json`，与游戏 SRAM 和玩法身份分开。启动器优先级为显式 `--language`、保存的设置、profile 默认值。无效设置明确报错，可用显式语言覆盖恢复启动。

2026-09-13 起，热键按 profile 注册顺序 `ja` → `zh-Hans` → `en` 循环，窗口语言名称来自目录配置；旧的单语言探针仍可运行。F7 通过同一原生事件路径处理游戏画面和姓名编辑器；自动重复、带修饰键的组合不触发切换，输入法正在组字时把 F7 留给输入法。切换期间及之后等待物理键盘与原始游戏输入全部释放，避免仍按住的确认键/START/R 被当成新按键。切换请求交给游戏线程，先准备新排版，成功后发布不可变目录及阅读状态；失败保留旧目录和阅读状态。配置写盘失败在窗口标题和日志报告，不弹窗、不冒充已记住设置。

当前对白保留同一 TextKey、结构片段和事件身份，从该片段开头重新排版、显示，自动推进/快进/跳过暂停；不会替玩家确认下一句。已完成的回看片段切换为新语言，姓名等动态参数使用该事件当时保存的展开结果。未完成片段没有可靠的跨语言字符位置映射，因此新语言从片段开头阅读，不把未读尾部自动放入历史。游戏原始姓名字段不翻译或改写。姓名页文案刷新时保留输入字段和当前焦点。

每个渲染帧携带生成时的语言目录引用；仍在 GPU 队列中的旧帧继续使用其旧字体/标签，新帧整套使用新目录，避免旧正文与新标签混排。显示切换不写玩法内存，原菜单、烘焙文字等未适配消费者仍用原文，不能称为全 UI 已本地化。

`prepare_profile()` 编译所有已注册目录，按源版本和控制结构校验翻译，输出 `coverage.json`。`tools/content/compile_profile.py` 的结果包含报告路径和摘要。报告分别统计翻译、草稿、已审校、缺译及各文本表；记录原菜单、战斗标签、开场烘焙文字等尚未接入的消费者。缺译继续使用日文原文。日文是源语言，不用“0 条翻译”表示日文缺失。

本次源数据共 **51,174 条**；中英文各 **153 条草稿、0 条已审校、51,021 条缺译回退**，英文范围与既有中文相同，另有全部 40 条原生 UI 文案。分母为已提取文本记录，并不代表所有记录已有原生绘制路径；153 条不能称为全游戏翻译覆盖。

## 保存：文件事务已验证，完整恢复仍有门槛

`src/srw64_native/checkpoints.py` 是保存集合的**存储原型**，尚未连接玩家自动保存。SRAM 与扩展状态写入不可变新代次，逐成员计算 SHA-256，校验 manifest 后原子发布单一索引。恢复按索引选择完整代次，损坏时整组回退，不拼接不同代次的成员。中断留下的未发布目录不会被自动提升为可恢复存档。轮转限制索引中的代次数，目前不自动删除旧目录。

测试覆盖成员损坏、manifest 损坏、部分写入、索引提交失败、未知状态/规则、错误索引与符号链接。这里的 `node_verified` 是适配层必须提供的前置条件，存储库本身不判定游戏安全节点。现有扩展原型只含 RNG 表和索引，**尚不含重新播种计数、已读状态，也没有生产恢复消费者**。

锁定 JP Rev 0 的原始序列化入口：

| 入口 | 已确认作用 |
| --- | --- |
| `800924D8` | 整备数据写入 RAM `801C2600`，长 `1F00`。该 RAM 在地图阶段会覆盖另一 overlay，不能随时调用。 |
| `80093278` | 战术数据写入 RAM `800FBEF0`，长 `3AE0`。参数 0 为原版内存备份，参数 1 写入 SRAM。 |
| `800927A4` / `800936A0` | 原版整备 / 战术恢复。 |
| `8009EDB8` | 脚本阶段 `C1` 完成、状态 `80` 时转为 `C0`，调用战术内存备份。 |

`original_saves.py` 核对原格式：SRAM 三个槽位分别位于 `10`、`1F10`、`3E10`。战术原校验只累加 `1F00` 字节，即使整个战术段长 `3AE0`；尾部损坏可能通过原校验，因此不能代替全文件摘要。

实际运行在女性超级系第一话开场事件结束后捕获原版内存备份：`first-tactical-capture/state-96-tactical-save.json`、`tactical-95.payload`。这次采集使用较早探针，文件编号相差 1；新探针已改为在观察记录中显式引用同编号附件。

将该备份装入独立实验 SRAM，并用 `config/recomp/load-continue.json` 完全退出后冷启动，已返回第一话地图。来源、摘要、原校验记录在 `first-turn-candidate.json`；恢复观察在 `first-turn-cold/state-1-tactical-restored.json`，地图截图为 `first-turn-cold/present-1620.png`。

`first-turn-restore-comparison.json` 比较原序列化返回与原恢复返回的共同观察区：战役旗标、剧情变量、玩家进度/姓名、机体、驾驶员和部件数组一致；RNG 区有 **2,079 字节差异**，地图单位记录有 **28 字节差异**。后者均位于 14 个 `20` 字节记录的 `+2` 字段；恢复返回时为 `FFFF`，地图完成重建后已重新分配。overlay `000AB160` 的 `801DE0B8`、`801E06C4` 指令将渲染对象 `800FFA70 + index*C4 + 48` 的句柄写到该字段，因此有重建表现资源的静态依据。原始差异仍保留，不据此删除 RNG 差异或宣称完整等价。旧采集尚未包括两处重新播种计数。

**结论：已验证这个原版备份能冷启动回地图，尚未验证完整状态恢复。** 因此不把存储原型或这次实验接成默认自动保存，不声称分歧书签、所有回合/整备节点已完成。下一实现门槛是补全扩展状态与恢复顺序、验证重建引用及恢复后的下一次实际行动，再逐节点开启自动保存。

## 跳过对照：保留原版随机时序

`SRW64_STATE_PROBE=1` 在游戏线程同步观察对白片段、选择项、原始序列化和恢复边界，记录关键内存区、RNG 调用及返回值。观察始终标记 `coverage_complete=false`；`compare_game_states.py` 不会把局部字节一致输出为完整等价。

原版 RNG 表位于 `800D49E0`，索引位于 `800D49D0`；战斗和演出重新播种还读取 `8015DC50`、`80172D0C`。主循环 `80080838` 每帧推进后两项。新观察已纳入这两个计数，不能把它们归为无关的显示计时后忽略。

第一次普通推进/跳过实验在跳过发生前已相差一次初始播种，不能把整张 RNG 表的差异归因于跳过。为此增加仅限静音、有限时长、空 SRAM 的 QA 初态对齐：`SRW64_STATE_FIXTURE` 在指定首个对白边界，仅一次写入 RNG 表、索引及两个重新播种计数。仅允许固定地址和长度，先全部校验再写，保留应用记录；不在后续比较节点重写状态。实验生成的存档被正常历史恢复入口排除。

这项设施用于制造相同测试初态，不是保存加载器或随机规则修正。正式运行不设置这些环境变量，原版每帧更新与重新播种顺序不变。结果需要区分初态、后续对白节点和战斗覆盖，不能把对白实验扩大为战斗全开/全关验收。

同一二进制、同一初态夹具的结果保存在 `paired-verification.json`：首个对白观察区全部一致；随后 **5 个**匹配节点均出现 `battle_seed_clock` 差异，其余已观察区一致。例如同一 `17410` 后续片段在普通推进的 VI 3721、跳过的 VI 3601 到达，重新播种计数不同。按本轮用户决定，保留这项原版差异，**不将严格随机状态等价标为通过，也不增加规则修正选项**。此实验尚未覆盖战斗动画结算。
