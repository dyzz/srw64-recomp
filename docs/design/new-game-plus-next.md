# 周目继承：下一步的目标与困境

2026-10-20。0.4.9 已发布第一版周目继承（[new-game-plus.md](new-game-plus.md)）。本文整理下一版要往哪走、卡在哪里、现阶段能落地到什么程度。原版事实都来自静态分析，未实机的地方单独标出。尚未实现。

## 1. 设计目标

1. **已完成的隐藏要素，以后的周目默认完成**：人物和机体照样加入，完成数跨周目记录（历代达成 N/33）。
2. **不影响路线**：周目继承不能改变这一周目走哪条线、进哪个支线。
3. **尽量像真的完成过**：能播的入队戏、剧情里的选项、之后的台词差异都保留，不只是把人塞进名册。
4. **不分路线、不分主角都能收到**：二周目换主角或换路线，也拿得到以前的要素。
5. **不做大改**：只用原版自己的指令和机制（登记 `3D5A`、改造 `3D6C`、禁止出击 `3D59`），不改原版逻辑。

## 2. 0.4.9 已经做到的

- 历代记录 `saves/legacy/legacy.json`；本关情报页的「历代已完成」「历代达成 N/33」，以及ガトー的「已完成（继承）」。
- 原路线上，在原入队关之后的场间补登记，照抄原版登记指令，不写变量，所以完全不影响路线。Windows 实机验证过。
- 局限：
  - 没有入队戏，也没有之后的台词差异，剧情仍按「没招到」演。
  - 原入队关这一周目打不到的要素收不到。真实系／超级系限定的、只有一条路线才有的，换了就拿不到。
  - **已知问题**：补登记的ガトー不会离队，但 OZ 线后期（S98–S101）照样部署敌方的他，可能误触发事件（见 §3.4）。

## 3. 现实困境

### 3.1 原版没有「已入队」标记，进度全靠剧情变量

- 跨关变量 0–54 用了 52 个（33、34、41 未用），都是 2 位，值 0–3。3 同时表示「没开始」和「失败了」。单关变量 100–139 用了 15 个，每关重置。55–99、140–199 全部空闲。
- 大部分要素变量各路线共用，意思一致（数字表示进度，入队值相同，只是各路线步骤不同），这类不难处理。
- 麻烦的是**同一个值在不同路线意思不同**：

| 变量 | 问题 |
| --- | --- |
| var23 ナイーダ | 「入队」在独立军线是 0（S77 选第 1 项时不写变量），在 OZ 线是 1（S91 选 1 → 1）；2 在两条线都表示她自爆 |
| var21 カーツ | 独立军线、OZ 线上 2 表示入队（S124 关末）；完全和平线上 S66 击破后关末也写 2，只是结局标记，用来选 7 关台词 |
| var14 リッシュ | 独立军线、完全和平线上 1 表示 S35／S65 选了另一个回答；OZ 线上 1 是推进中的一步 |
| var18 エルリッヒ | OZ 线 0 → 1 → 2 逐步推进；独立军线说服后直接写 2 |
| var3 アレンビー | 「救下」在独立军线写 2（S129），在 OZ 线写 1（S137） |
| var13 アイシャ | 1 只在完全和平线作为中间一步出现 |

- **一个变量兼管几件事**：var37（ガトー＋去 S51／S108）、var20／21（カーツ＋布拉德换乘超级大地加）、var4（ガラリア＋シルキー条件＋フォウ的一步）、var27（プル＋プルツー门槛＋改色）、var31（ムゲ／地球圈选择＋改色）、var9（蕾拉支线＋エルリッヒ门槛）、var38（S107 去向＋エルリッヒ的 S56 条件）。
- 所以不能给每项写一个统一的「完成值」。

### 3.2 入队戏和后续台词只能靠写变量恢复，而有的变量决定路线

- 入队戏、选项、之后的台词差异都是原版脚本按变量分支的。要恢复它们，只能在原版读取之前把变量写成满足值，让原版自己演。
- 全部事件里，决定下一关（`3D4B`）的跨关变量只有 var9、var10、var11、var18（经单关变量 var128）、var21、var31（经 var130）、var37、var52（经 var128）。其中隐藏要素的入队变量是 **var37 ガトー、var21 カーツ、var18 エルリッヒ**，这三项不能写。
- 其余要素的变量不改路线，但会连带改变**关内内容**，和一周目真做到时一样：アレンビー救下后 S137 不出狂战士；フォウ相关的 S128、S57 卡缪晚到；アイシャ（OZ）S57 玛娜米不能出击、母舰换成斯维姆鲁格S。
- 写的时机要精确：关内事件会改写这些变量（例如ガトー的 var37 在 S49 按谁先进区域写 0／1／3）。太早会被覆盖，太晚错过分支。

### 3.3 有些要素必须玩家在关内亲手做到

说服（ロザミア、プル、プルツー）、关内转阵营（ガラリア、アイシャ独立军／完全和平线）、击坠数门槛（銀鈴，读 `3E0D`，写变量满足不了）、关内条件（ミネルバX）。写变量最多打开门槛；玩家没做到，就只能补登记兜底，没有戏。

### 3.4 跨路线、跨主角有身份冲突

- 存档不会坏：部署出击 `8020ABB4` 只在**同一阵营**的名册里复用同号驾驶员，敌方另建记录。
- 但原版很多地方**按人物号**找人、不分阵营：

| 位置 | 作用 | 我方和敌方同时有他时 |
| --- | --- | --- |
| 状态表 `D_8015DE90`（`3E1B`、类型 2 击坠触发 `8009E604`，经 `800A293C` 按人物号查） | 在场、被击坠、离场 | 我方的他撤退被当成敌方的他被击坠 |
| 类型 4／5 交战触发 | 「A 和 B 交战前后」 | 我方的他也会触发 |
| 类型 3 HP、类型 8 区域触发 | 按人物号判定 | 可能拿我方那台判断 |
| `3D46` 撤退、`3D58` 转阵营 | 按人物号找地图上的单位 | 可能处理错那一台 |
| `3D5A` 2000／4000 删人（`800AA62C`） | 按人物号依次查三张名册 | 先删到我方那条 |

- 把这些全改成分敌我要动很多原版函数，不现实。改用**冲突关禁止出击**：这个人以敌方／第三方身份被部署的关，如果他在我方名册里，就把他加进 `3D59` 的排除名单。地图上同一时间只会有一个他，上面所有按人物号的查找都只找到敌方那台。
- `3D59`（处理函数 `800A0C80`）：把人物号追加到 `8015F700` 的排除名单（最多 29 项，以 −1 结尾）；出击选择（`3D3D` → `801C78A0`）跳过名单里的人。名单在 `3D4D` 和 `3D3D` 时清空，所以要在**每次出击选择之前**追加。原版用法：S99 豹马、S19 兽战机三人、S18 卡缪、S8 布莱特的母舰。
- 中途从母舰发进（`801D050C`）读的是本关地图上的单位栏 `D_8015E10C`，不是整个我方名册。所以出击时被排除的人上不了地图，也没法从母舰发进（静态结论，待实机）。
- 需要冲突关的 8 项（只算入队话数之后、他以敌方或第三方被部署的关）：

| 要素 | 冲突关 |
| --- | --- |
| ガトー | S53、S60、S98–S101（OZ）；S75（完全和平）；S87、S133、S141（独立军）；S103–S105（共通） |
| エルリッヒ | S41、S56、S69 |
| リッシュ | S38、S66、S69 |
| ロゼ | S77、S136 |
| カーツ | S41 |
| アイシャ | S56 |
| プルツー | S88 |
| ロザミア | S60、S75（只有按人物号的事件引用，也排除） |

- 只在事件里按人物号引用、没有部署他的关，多数是写给原版里作为我方的他的，不排除，只列清单备查。
- 跨路线没有原入队关，入队戏和后续台词无从播放。

### 3.5 剧情违和避免不了

- 补登记的人，台词按「没招到」演；冲突关里他在你队里却不能出击（ガトー最多，后期十来关）。
- 主角专属的劲敌和搭档（カーツ、エルリッヒ、リッシュ、アイシャ）给别的主角，剧情上说不通。アイシャ给别的主角时只补她和厄尔布鲁士，不做玛娜米母舰的换乘。

## 4. 现阶段能落地的方案（不改路线、不做大改）

| 情况 | 做法 | 戏和台词 |
| --- | --- | --- |
| 原路线、入队变量不碰路线（约 14 项，§4.1） | 在原版读取前写变量，让原版自己演；没做到的再补登记兜底 | 有 |
| 原路线、碰路线（ガトー、カーツ、エルリッヒ） | 补登记（现状） | 没有 |
| 原路线、本来就是选项或自动给（エリカ、量産型ν、トールギスIII、ゼクス＋エピオン、アポリー＆ロベルト、Mk-III、FA百式、量産型グレート等） | 不处理，原版照常 | 有 |
| 原路线、要玩家在关内亲手做到（§3.3） | 写变量打开门槛（不碰路线的才写）；没做到就补登记兜底 | 做到了才有 |
| 跨路线、跨主角 | 话数（`8010F5EF`）到了原入队关的话数时，在场间补登记；不看路线和主角条件；冲突关用 `3D59` 禁止出击 | 没有 |

33 项都能做到不分路线、不分主角收到。入队之后任何路线都不再以敌方出现的 25 项直接放开；§3.4 的 8 项靠冲突关禁止出击。这同时修掉 §2 的ガトー问题。

### 4.1 写变量的项（初步，要逐项核对）

| 要素 | 变量＝值 | 原版读取位置 | 写入时机 |

| ヒルデ | var16＝0 | S38 关末 | `3D4A` 时 |

| キリカ | var24＝1 | S78／S92 关末 | `3D4A` 时 |

- 写入时机：「`3D4A` 时」= 包装过关指令的处理函数 `8020DB08`，结束事件紧跟在它之后跑；「载入关卡时」= `8009DE7C` 重置单关变量之后、开场事件之前。
- シルキー还要マーベル击坠 ≥30（`3E0D`），写变量满足不了，随トッド补登记。
- 每项要确认：入队后这个变量只被用来换台词或改关内内容，不参与任何路线分支；被写入的那一关里没有关内事件会把它改掉。

### 4.2 实现要点

- 数据：在 `inherit-grants.json` 每项加三栏：写变量（变量、值、关卡、时机）、原入队关的话数、冲突关（脚本扫出击记录自动生成，测试锁住）。
- 宿主：包装 `3D4A`（`8020DB08`）和关卡载入（`8009DE7C`）写变量；场间读话数做跨路线补登记；包装出击选择（`3D3D`）往 `8015F700` 追加冲突的人。
- 现有的补登记保留，作为所有情况的兜底；它的「已拥有」判断能防止重复登记。
- 实机：每类挑一两项在 Windows 台式机上看戏能否正常播放、选项能否正常出现，以及冲突关里出击界面有没有把人排除；再从母舰发进确认一次。
