# 机体 MOD 网页工具

2026-11-20。用户要求：最终要有一个网页工具，能添加人物和机体，机体的武器动画也能在网页里处理。它取代 [机体 MOD 规划](unit-mod-kit.md) 里 P10 的命令行模板（`new_unit.py`），也是 P6 武器动画编辑器的落地形式。

## 1. 已定的

- **一页**：官网新开「机体 MOD 制作」页（`/<lang>/mods/units/`），分人物、机体、武器、动画几栏，整个包一起编辑；能打开已有 `.srw64mod` 改了再导出，包里工具不认识的文件原样保留。名字、图标、语音、数值几个工具照旧保留，相关部分复用它们的代码。
- **动画预览连本机游戏**：网站不放 ROM 里的图，浏览器里也不重写原版 380 个行为例程。游戏设置里打开「网页工具连接」，网页经本机回环把包热加载进游戏，在战斗鉴赏里重播；没连游戏时网页只做结构编辑和校验。
- **顺序**：先人物、机体、武器（W1、W2），再游戏连接（W3），最后动画（W4）。

## 3. 分期

### W1 人物、机体、武器

- **起步**：照抄一台原版机体或一名原版人物（`copy`），表单里显示原版值，改过的才写进包。
- **人物**：名字（四语，`name`／`full`）、能力值、地形、技能、精神、SP、换乘类别（`swap_class`）、恋爱补正（`love`）、合体技里当谁（`combo_as`）、声部（借谁的台词）、头像（像素图 96×96 与 HD 图）。
- **机体**：名字、数值（HP、EN、装甲、运动性、移动、地形、尺寸、特殊能力、改造上限）、武器表（原版武器和本包新武器混排）、形态（`forms`）、合体（`combine`）、乘员（`crew`）、继承（`inherits_from`）、站姿图（`pose`）、地图图标（复用图标工具）、战斗精灵（`sprites`）。
- **武器**：照抄原版武器，改数值与种类字段、合体技（`combination`：参与机体、各自的武器、倍率、驾驶员）。
- **图片**：选本机的 PNG，只在浏览器里处理，不发到网站（网站没有存东西的后端）。像素图在浏览器里按 `sprite_pixels.py` 的规则缩放、减色（移植成 TS），给出和游戏里一样的预览；HD 图检查尺寸与透明边。
- **校验**：网页实现 `validate.py` 里机体 MOD 相关的规则（错误指到栏位）；仓库里加对照测试，用同一批样例包同时跑 Python 校验器和网页校验逻辑（Node），结论必须一致。
- **导出**：`.srw64mod`，可选同时生成 Thunderstore 包（`thunderstore.py` 的规则）。

### W2 台词、语音、入队

- **战斗台词**：新人物自己的台词（`battle_quotes.json`：九种情境、特定武器、特定对手），每句可配语音；语音部分复用语音工具。
- **入队**：生成最简单的剧情 MOD 事件（第几话开场后或过关后加入、开哪台机体、加入等级），连同本关情报条目和周目继承（`stage_info` 的 `id`／`inherit`）。复杂剧情仍手写剧情文件。
- **敌方**：剧情 MOD 增援组（`deployments`），把新人物、新机体放到某一话的敌方。

#### W2 做法（2026-11-20）

- **台词**：人物页「战斗台词」九种情境各一个折叠列表，每句四语（日文必填、42 字），「配语音」选本机音频：Ogg 原样，别的由浏览器解码后用语音工具的 Vorbis worker 编码（质量 4），文件名 `<人物>-<n>.ogg`，写进 `audio/voice/battle/`。「条件台词」一组一个条件：武器（可勾「有时」）或对手（原版人物 0–359＋情境），最多 119 句。包模型 `Pilot.quotes`，`toFiles` 写 `dialogue/battle_quotes.json`（空句、空情境不写；别的包的条目原样留），`fromFiles` 读回，`voicesOf` 列出用到的语音。浏览器草稿不存语音，读草稿时去掉 `voice`。
- **入队与增援**：第五栏「入队与增援」。入队：关卡（`scenes.csv` 的场景号与原版标题，构建时读入页面）、开场后／过关后、人物、机体、等级加减，可选写进本关情报（四语标题和说明、日文必填，`done` 是这台机体在机体池里）并勾「周目继承」（过关后入队写 `after`，开场入队写 `before`）。增援：关卡、第几回合、谁的回合开始，1–30 台（坐标、人物、机体、阵营、等级＋、改造）。
- **编译**：包里放的是编译后的剧情文件，所以 `lib/story-image.ts` 把这两种照 `story.py` 编成 `story/unit-maker.json`（`srw64.story-image.v1`：入队 `3D5A 人物,等级,机体,500`、增援 `3D45` 加 `groups`，新名字留 `0xFFFD` 和 `numbers`），本关情报和 `inherit.commands` 也一样；打开包时 `read` 从这份文件读回。别的剧情文件原样保留。`StoryTests` 用同一份数据让 `story.py` 从 `source()` 编译，结果必须和网页的完全一样，读回也一样。
- **验证**：浏览器里照抄阿兰建凯（攻击台词带一段 1 秒的语音、ギガンティックマグナム 49 的武器台词），第 78 话过关后凯开 228 入队（带本关情报与周目继承），同一关第 2 回合我方回合开始时增援一台ムゲ兵开新机体。导出的包 `validate.py` 通过；「打开」读回再导出，7 个文件逐字节相同（修了一个漏洞：打开时 `battle_quotes.json` 没交给包模型，台词丢了）。游戏里还没跑。

### W3 游戏连接

- **游戏侧**：设置里的开关，默认关；打开后只在 127.0.0.1 上开一个 WebSocket，只接受官网与本机开发地址的 `Origin`，第一次连接要在游戏里确认配对。只开放少数命令：装入／替换一个临时包（单独的开发目录，不进玩家的 MOD 列表）、开战斗鉴赏（指定攻守、武器）、进迷你关（开发者）、取截图。底层复用调试接口的实现，但不暴露调试接口本身。
- **网页侧**：「连接游戏」按钮；改动后一键「在游戏里看」。
- **先做验证**：HTTPS 页面连 `ws://127.0.0.1` 在 Chrome、Edge、Firefox、Safari 上是否放行（本机算安全来源，但 Chrome 的私有网络访问限制还在收紧）；不行就退回让游戏开一个本机网页（`http://127.0.0.1:端口/`）承载同一套页面。

#### W3 做法（2026-11-20）

- **用 HTTP，不用 WebSocket**：浏览器对 `http://127.0.0.1` 和 `ws://127.0.0.1` 的放行规则一样（回环地址算安全来源，不算混合内容），HTTP 不用在游戏里实现握手和分帧。固定端口 46464（Switch 调试接口也用这个号，但 Switch 不开网页连接）。
- **验证结果**：官网自己的 CSP（`astro.config.mjs` 的 `connect-src`）原来只放本站和广告像素，内置浏览器（Chrome 156）在官网页面里连 `127.0.0.1` 被 CSP 挡下，请求根本没发出；已把 `http://127.0.0.1:46464` 加进 `connect-src`。CSP 之后还有 Chrome 的本地网络访问授权（公网页面访问本机时弹一次），游戏的预检回 `Access-Control-Allow-Private-Network: true`；这一步要等官网部署后才能实测（0.5.4 之前不部署官网）。Firefox、Safari 还没试。
- **游戏侧**（`src/host/web_link.cpp`）：关于页「网页工具连接」开关（`settings::web_link`，存 `web_link`，默认关），每帧由窗口线程 `web_link::service()` 跟着开关开／关监听，只绑 127.0.0.1。只认 `Origin` 是 `https://srw64.dreamquest.club` 或本机开发地址（`http://localhost:端口`、`http://127.0.0.1:端口`）的请求，别的一律 403（没有 Origin 的本机程序也不行）。
  - `GET /hello`：游戏、版本、协议号 1、这个令牌是否已配对。
  - `POST /pair`、`GET /pair?id=`：页面请求配对，游戏弹出确认框（默认选「拒绝」，写明是哪个网站），允许后页面轮询拿到令牌；令牌只在这次运行有效，关开关就全部作废。
  - 以下要 `Authorization: Bearer 令牌`：`POST /package`（zip 字节，写成临时文件后 `mods::install_trial`，回包 id 和本包新机体、新人物、新武器的编号 `@名字 → 号`）、`POST /viewer`（choice 同调试接口 `viewer.start`；交给窗口线程照鉴赏页「开始」的做法开：只在标题画面、鉴赏没在播时，否则回原因；不会自动回标题，以免丢进度）、`GET /screenshot`（下一帧截图，PNG）。
- **试用包**（`mod_library`）：放在 `<mods>/.web-link/<id>/`，`installed()` 把它和玩家的包一起列出、默认开、顶替同 id 的已装包（`Package::trial`），不写 `mods.json`；一次一个，新的顶替旧的；游戏启动时清空（`host.cpp` 调 `clear_trial`）。
- **网页侧**（`web/src/lib/game-link.ts`、制作页「在游戏里看」一栏）：端口、「连接游戏」（配对令牌存 sessionStorage）、攻方选本包新机体＋驾驶员＋这台的武器、守方三个原版号（默认ムゲ兵 170／298／677）、伤害；「装进游戏并在鉴赏里看」把当前内容打成包（不下载）发给游戏，用回来的编号开鉴赏；「截图」显示游戏当前画面。
- **试用包的数据何时读进来**：包的数据平时在游戏读资源时（`8007F704`、`80089BBC`）重算，标题画面什么都不读，刚装的包一直没算进去，鉴赏的台词检查就说新人物没有台词。`game_hooks.cpp` 在标题画面（`title_major` 2、3）每帧调一次 `mod_data::refresh`（没变化时立刻返回）；装包的回复等到 `mod_data::current()` 成立（最多 3 秒）。装进去但没生效的包（要更新的游戏、缺依赖）回它的原因。
- **Windows 实测**（开发版 0.5.3.1，`D:\srw64-units`，Mac 的内置浏览器开本机开发服务器的制作页，ssh 把 Mac 的 46464 转到 Windows 的 127.0.0.1:46464；测试时在页面里把包的版本要求改成 0.5.3）：
  - 开关打开后日志 `SRW64_WEB_LINK listening 127.0.0.1:46464`；`Origin` 不在名单或没有 `Origin` 回 403，没配对回 401，预检头齐全。
  - 「连接游戏」后游戏弹出「网页工具连接」确认框（写明 `http://localhost:4329`，默认选「拒绝」），点「允许」后网页显示已连上。
  - 打开 W2 的测试包（凯、台词、语音、入队、增援）点「装进游戏并在鉴赏里看」：装进 `<mods>/.web-link/test.webstory/`，新机体 692、凯 465；第一版因为上面的读取时机被拒，修后开始播放：凯开测试高达，名牌「凯」、说网页里写的「上了！」，日志 `SRW64_VOICE line=57344 … .web-link\test.webstory\voice.srw64mod entry=audio/voice/battle/kai-1.ogg`（网页转的语音）。播完回到鉴赏页再点也能再开。「截图」拿回游戏画面（1280×800 PNG）。
  - 没测：入队、增援在关卡里的实际效果（编译结果与 `story.py` 一致，那条路 P8、P9 实机过）；官网上线后 HTTPS 页面的本地网络访问授权；Firefox、Safari；Mac、Linux 版游戏（Android、Switch 不开这个功能）。MOD 页会把试用包和别的包列在一起，还没有单独的标记。

### W4 武器动画

- **行为目录**：380 个行为例程按用途归类（移动、发射、光束、爆炸、cut-in、镜头），每类配原版用例；用例录像用本机游戏录，不放进网站，只放说明和编号。没有目录，编辑器只能抄原版。
- **编辑器**：从一件原版武器的演出起步，改演员表（场景、`h4`／`h5`／`h6`、行为）、镜头、命中、动作、守方反应、音效；场景用包里的图（`scenes` 的 `@图片名`）或原版资源号。
- **预览**：经 W3 在鉴赏里重播；结构错误（引用不存在的场景、行为号越界）在网页里直接报。
- **验收**：不碰 JSON，用工具给终极断空我做出断空砲的完整演出并导出成包（P6 原定的验收）。

## 4. 不做

- 不在网站放任何 ROM 里的图、声音、动画数据；数值和名字照现有工具的做法。
- 不在浏览器里模拟战斗演出。
- 不做账号和云端保存；进度靠导出的包和浏览器本地草稿。
