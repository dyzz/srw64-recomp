# Steam Deck 键位与按键图标

2026-09-25。Steam Deck 版按 **Steam 默认手柄模板**操作，玩家不用改 Steam 输入设置。本页记录现在的键位（以代码为准）、这次补上的设置入口，以及下一步要做的按键图标。上级计划见[三平台移植](three-platform-port.md) X2，构建与安装见 [Linux 构建](../guide/linux-build.md)。

## 原则

- 只用默认模板里 Deck 按键的原始含义：SDL 看到的是标准手柄（Steam 虚拟手柄），按键名与 Xbox 布局相同。
- 同一场景里一个键只做一件事；原版已经占用的组合不改。
- 宿主新增的功能（设置、对白阅读、跳过）优先用原版没用到的键：视图键、L2、R2、背键。L2、R2 给宿主（用户 2026-09-25 同意），游戏本身看不到这两个键。
- 提示跟随玩家最后用的设备：手柄输入后显示手柄提示（`<key>_pad` 词条），键盘、鼠标或触屏输入后换回键盘提示。
- 能点的地方都能用触屏点。

## 现有键位

手柄到 N64 按键的映射在 `src/host/graphics.cpp`（与键盘表共用 N64 掩码）；原生页面通过 `frontend.cpp` 的 `pad_keys` 把手柄转成页面按键；设置窗口是 `settings_pad`，战前确认页是 `battle_buttons`。

| Deck 按键 | 游戏中（N64） | 原生页面（场间、标题、存档、姓名等） | 对白阅读 | 设置窗口 |
| --- | --- | --- | --- | --- |
| A | A | 确定 | 下一页 | 按下当前按钮 |
| B | B | 返回 | — | 关闭 |
| X | B（同 B） | 返回 | — | 关闭 |
| Y | Z 扳机 | Z | — | — |
| L2 | 宿主用：地图空闲时光标到上一个敌方机体 | — | 自动阅读 开／关 | — |
| R2 | 宿主用：地图空闲时光标到下一个敌方机体 | — | 按住快进；R2+菜单 跳过段落 | — |
| L1 / R1 | L / R（地图空闲时切换我方未行动机体） | L / R（翻台、上一首等） | L1 回看；R1 与其他键组合 | — |
| 菜单键 ☰ | START | 确定（部分页面） | R2（或 R1）+菜单 跳过段落 | 按下当前按钮 |
| 视图键 ⧉ | —（宿主用） | 打开设置 | 打开设置 | 关闭设置 |
| 十字键 / 左摇杆 | 十字键 / 摇杆 | 移动光标 | ↑↓ 自动速度 | 在按钮间移动 |
| 右摇杆 | C 键（上下左右） | C 键；战前确认页 ↓ 切换战斗动画 | 上下调字号 | — |
| L4 L5 R4 R5 背键 | 未用 | — | — | — |
| Steam 键、快速访问键 | 归 Steam | — | — | — |

其他：

- **对白：** R2 按住快进，R2+菜单 跳过当前段落，L2 切换自动阅读（打开时沿用上次的速度，第一次为 2 档；↑↓ 仍可调速），L1 打开回看（回看里 ↑↓ 滚动，L1/A/B 返回）。原来的 R1+A、R1+菜单 照旧可用（N64 的 R 键组合）。实现：R2 在 `native_dialogue.cpp` 的 `input()` 里当作 R+A 交给阅读器；L2 的按下调 `Reader::toggle_auto`。
- **姓名输入：** 进入输入框时弹出 Steam 屏幕键盘（`SDL_ENABLE_STEAM_SCREEN_KEYBOARD`）；A 下一项，B 返回。
- **战前确认页：** A 确认，B 返回，L1 换武器，R1 精神，右摇杆↓ 切换战斗动画（原版的全局开关 `D_8015DDA8` bit2，关掉后战斗不进演出）。
- **战术地图：** L1/R1 在我方未行动机体之间切换（原版），L2/R2 在敌方与第三方机体之间切换（现代机战的做法，[`enemy_cycle.cpp`](../../src/host/enemy_cycle.cpp)，见 [L2 / R2 切换敌方机体](../native/enemy-cycle.md)）。
- **启动：** `SteamDeck=1` 时自动全屏；开机 2 秒内按住的 START 被忽略（Pak 管理画面会中止）。

## 设置入口（2026-09-25 补上）

用户反馈：Deck 版没有直接切换语言、HD 和选项的入口。原因是 Mac 上的入口在菜单栏，Deck 上没有菜单栏，只能靠视图键，而画面上没有任何提示。现在加了两处看得见的入口，都打开同一个设置窗口（语言、原版／HD 画面、规则修正、各界面切换）：

- **标题画面**（PRESS START 与环形菜单，标题主状态 2、3）：右下角一个小按钮。手柄提示是「视图键 设置」，键盘下是「设置…」，触屏或鼠标点它也能打开。Mac 有菜单栏，只在手柄输入后显示。代码在 `frontend.cpp` 的 `home_sync`。
- **场间主菜单**：手柄提示末尾加上「视图键 设置」。

曾在标题 オプション 页原版三项下面加过一行「语言／画面／规则…」，用户不要把宿主设置塞进原版的设置页，已撤掉（2026-09-25）。用户要的是「游戏内一键呼出」的设置：见下面「设置界面改版」。

同时修了一处：战前确认页底部提示和原版战斗 HUD 的动画开关提示原来写死成键盘和 N64 键名（「Z / A」「K / C▼」），手柄下现在显示 A、L1、R1、右摇杆↓、B。

以上只在 Mac 上编译过，尚未实机截图检查，也还没在 Deck 上验证。

## 已知问题与待定

- **Z + START 是原版的「退出关卡」**：在战斗演出里按下会回到 BANPRESTO 标志和标题画面，未存档的进度全丢（原版中止分支 `801C97E4` 选模式 7 或 0x11，2026-09-25 由做战斗演出跳过的会话实测回到标题，记录在它的探针代码注释里，尚未提交）。原来 L2 也是 Z，L2+菜单 是左食指加右拇指，很容易误按；现在 L2 归宿主，只剩 Y+菜单（都在右手，要刻意才按得出）。是否再在演出中拦掉 Y+菜单，**待用户决定**。
- **演出中途跳过**：另一个会话在做「演出中按 B 直接到本场结尾」，代码未提交、未完成实机验证。建议手柄上同时认 R2（与对白里「R2 快进」一致，提示写 R2），B 照旧可用；已告知那个会话。
- **背键空闲**：先不用（不是所有手柄都有）。
- **语言、HD 的快捷切换**：键盘有 F7（语言）和 F6（原版／HD）。手柄暂时只走设置窗口，不加组合键，避免误触。
- **设置窗口的手柄导航**：十字键按 Tab 顺序走遍所有按钮，项目多时要按很多次。以后可以加「L1/R1 切换分组」。

## 设置界面改版（待定）

2026-09-25 实机截图：视图键确实一键打开设置，但打开的是整屏、不透明的「选项」页（左列规则、右列语言与各界面开关，要滚动），像桌面程序的设置页，把游戏整个盖住。用户要的是「游戏内一键呼出的感觉」：

- 在游戏画面上叠一层半透明底，中间一个面板，风格与原生页面一致，关掉就回到原处；
- 一个键呼出、同一个键或 B 关闭：Deck 上是视图键，键盘上待定（Esc 现在是退出游戏）；
- 分页（例如 通用：语言、画面；界面：各原版／新版开关；规则：修正与难度；按键：键位图），L1/R1 翻页，十字键选项，A 切换；
- 待定：打开时是否暂停游戏。

「Steam Deck SSH 连接与安装」会话提过同样的方向（分页、L1/R1、与 RecompFrontend 一致），由谁来做待用户决定。

## 按键图标规划

### 为什么要画图标

- 界面字体（随包的 HarmonyOS Sans）里没有 ⧉、☰ 这类符号（2026-09-25 用 fontTools 查过 SC、拉丁与 Condensed 三个字形文件），Deck 上直接写会显示成方框。现在的提示只能写成「视图键」「菜单键」这样的文字。
- Deck 玩家看的是机身上的图形，图标比「右摇杆↓」这样的文字更快认出来。

### 图标集（第一版）

| 组 | 图标 |
| --- | --- |
| 面键 | A、B、X、Y（深色圆形键帽，白字） |
| 肩键 | L1、R1（肩键形）、L2、R2（扳机形） |
| 系统键 | 视图（两个叠放的方框）、菜单（三条横线） |
| 方向 | 十字键（整体，以及上／下／左／右／上下／左右高亮） |
| 摇杆 | 左摇杆、右摇杆（圆形带 L/R，以及上／下／左／右／上下 箭头） |

全部自己画，线条简单，不用 Valve 的原图。

### 画法：一套自绘图标字体

游戏里有两套文字引擎：RmlUi（各页面、设置、提示栏）和对白用的 FreeType + HarfBuzz（`dialogue_scene.cpp`：对白底栏的操作提示、回看）。只有做成字体，两边才能用同一份图标：

- 源文件是每个图标一张 SVG，放在仓库里；构建时用 fontTools 生成一个小字体（Unicode 私用区 U+E000 起），随包分发。
- 两套引擎都把它登记成后备字体，图标会跟着字号缩放、与文字对齐基线。
- 单色字形，颜色随文字；键帽内的字母用镂空，这样深色、浅色背景上都清楚。
- 高度约为文字大写字母高度的 1.15 倍，左右各留 0.1 em 间距。

只在 RmlUi 里用 CSS 画键帽也行（RmlUi 支持 `border-radius`），但对白底栏用不上，所以不选。

### 文字里怎么写

- `_pad` 词条里用记号，例如 `{A} 确定   ·   {B} 返回   ·   {View} 设置`。`label()` 在取词条时把记号换成当前手柄家族对应的私用区字符；对白引擎在同一处（`catalog.ui()` 之后）替换。
- 记号与语言无关，翻译只改周围的字。
- 键盘词条不变。
- 测试检查：每个 `{…}` 记号都在图标表里；三种语言的同一词条用的记号相同；图标字体包含表里的每个字符。

### 在哪里用

- 全部 `_pad` 提示词条（现有 38 条）、战前确认页的按键提示、原版 HUD 的战斗动画开关提示；
- 标题画面的设置入口、场间主菜单的设置提示；
- 设置窗口底部加一行「{A} 选择 · {B} 关闭」；
- 对白底栏的操作提示与回看提示；
- 姓名页提示与屏幕键盘说明。

### 手柄家族

- **Deck 版**（`SteamDeck=1`）固定用 Deck 图标：游戏模式下 SDL 看到的是 Steam 虚拟手柄，按类型判断会得到 Xbox，不能靠它。
- 其他平台按 `SDL_GameControllerGetType` 选：Xbox（字母同 Deck，带颜色）、PlayStation（✕ ○ □ △，视图键换成「Create」、菜单键换成「Options」）、Switch Pro（A/B 位置相反，−/+）。第一版只做 Deck 和 Xbox，另外两种先显示 Xbox 图标。
- 确定键与返回键始终按「下方键确定、右方键返回」，与图标一致（Switch 手柄也按位置，不按印字）。

## 验证计划

- **调试接口的手柄注入：** `pad` 方法（`srw64ctl pad r2 l2`）把虚拟手柄并入真实手柄的状态（与 `srw64_pad_state()` 同一个掩码），在 Mac 上就能截到手柄提示和图标、测 L2/R2。
- **Mac 截图检查：** 标题右下角入口、视图键打开设置、场间提示、战前确认页提示，中日英各一张；键盘与手柄两种状态。
- **Deck 实机：** 游戏模式下只用手柄，从标题打开设置切语言和 HD，走一遍 姓名 → 第一话 → 战斗 → 场间 → 存档；确认视图键在默认模板下确实到达游戏。
