# 回溯（issue #6）

2026-10-17。玩家请求（[dyzz/srw64-recomp#6](https://github.com/dyzz/srw64-recomp/issues/6)）：失误后按键倒回去重打，也就是战斗前的 S/L。本文记静态结论、一次实机试验和实现（§4，Windows 台式机实测通过）。

## 1. 思路

重编译版没有模拟器式的任意时刻即时存档：游戏状态有一部分在重编译函数的本机栈里。能存的时刻只有「状态全在 RAM 数据里、原版自己能写下来」的地方。所以回溯用原版的**中断存档格式**（`80093278(1)`，0x3AE0 字节，见[多存档栏与自动存档](save-slots-autosave.md) §1.3），恢复走原版的**模式 0x11**。宿主只管什么时候存、存到哪个文件，以及什么时候切模式。

重打会出不同结果：命中在确认画面就掷好了，但地图 overlay 每次启动都由 `801E00AC` 重新播种，回溯后再选一遍，骰子就不同了。所以快照的随机数**不写回**，这一点与回合自动存档相反。

## 2. 静态事实

- **顶层模式**（`800801A4`，跳转表 `jtbl_800CFEC8[mode−1]`）：模式 3 新开地图（入口 `801E022C` → `801E00AC(0)`）；0xB 战斗演出回地图（`801E0268` → `801E00AC(1)`）；0x11、0x22 先 `800936A0(1)` 从中断区恢复，再进 `801E028C` → `801E00AC(2)`；0x16 同样恢复，入口 `801E0350`。`801E028C`／`801E0350` 会先把模式写成 0xB。
- `801E00AC(kind)` 把 kind 交给 `801C6DEC`，写进 `D_8022722C`（0 新开、1 战后返回、2 中断恢复；试验里还读到过 3），同时把地图主状态 `80172EB0/EB1/EB2` 清零。
- **地图上切模式**：原版 中断→タイトルへ（`801D22FC`）是 `80080188(7)` 加 `80099814(5,1,2)` 淡出，淡出完成后由地图每帧分发器 `801DFBD0` 做清理并交给顶层分发器。`801DFBD0` 本身也有分支：模式为 1、且 `D_8015D9FA & 0x1000`、且中断区有档时，切到 0x11。
- **战斗演出里**：演出主循环 `801C9710` 在 Z+START 中止（`D_80225810 = 1`）、淡出完成后调用 `800A5138`；若 `D_8015D9FA & 0x1000` 并且 `80093610` 报告中断区有档，就切到 0x11，否则切到 7（回标题）。所以原版本来就有「演出中途→读中断档回地图」这条路，只是被这个标志位挡着。`0x1000` 这个位的含义还没查。
- 战斗 overlay `load_00121560` 和战术 overlay 共用 `801C2600`，每打一仗地图 overlay 都会被换掉再装回来。敌方阶段能接着打，说明敌方的行动进度在常驻内存或名册里；试验证明中断格式也能把它带回来（见 §3）。

## 3. 实机试验（2026-10-17，Mac，迷你关）

试验用的探针和关卡都是临时的，已撤掉。

- 关卡：地图 20，タケル(8,8)，三台敌人紧贴着他（slot 0 ロゼ／ゼーロン、slot 1 ガラリア、slot 2 ムゲ兵／ミニフォー），战斗动画开。
- 流程：我方回合 1 直接フェイズ終了。敌方第一台行动完（`801C29DC` 以敌方句柄调用）后过 10 帧，在地图每帧（`801DFBD0` 之前）用 `SuspendWindow` 调 `80093278(1)` 写到文件。让游戏自然跑到我方回合 2；在第一帧空闲时 `arm_suspend(文件)`，再从地图调 `80080188(0x11)` + `80099814(5,1,2)`。
- 跑了两次：

| | 快照时 | 自然流程 | 读回之后 |
| --- | --- | --- | --- |
| 第 1 次 | 0x62 行动完、还活着（名册 +0xB = 0x81） | 0x62 → 0x61 → 0x60 → 我方回合 2 | 回合 1、敌方阶段；0x62 仍是已行动；被击坠的 0x61 回来了；下一台是 0x60（ロゼ） |
| 第 2 次 | 0x62 反击被击坠、已不在名册 | 0x62 → 0x61 → 0x60 → 我方回合 2 | 回合 1、敌方阶段；0x62 不在；0x61 → 0x60 各行动一次 → 我方回合 2 |

结论：

1. **敌方阶段中途可以回溯。** 中断格式带回了阶段、回合、已行动位（名册 `+0xB & 0x80`）、击坠和 HP／EN（タケル EN 180/200 与快照时一致），读回后原版接着跑敌方阶段，最后正常进入我方回合。
2. **从地图直接切模式 0x11 可行**，不用回标题。从请求切换到地图恢复约 39 VI（0.65 秒），之后约 22 VI 回到空闲。
3. 读回后，剩下的敌人谁先动可能和原来不同（第 1 次是 0x60 先于 0x61）。原因没查，可能是 AI 选人用了随机数。对回溯来说是可以接受的（敌方行动本来就重新算），但没出现重复行动或漏行动。
4. 读回后的空闲帧主状态是 5，敌方阶段内部也会经过 5，所以「我方空闲」不能只看主状态，要另找阶段变量。

## 4. 实现（2026-10-17，Windows 实机已过）

代码在 [`src/host/rewind.hpp`](../../src/host/rewind.hpp)／`rewind.cpp`，接在已有的包装上，没有改 NATIVE_HOOKS：

| 钩子 | 做什么 |
| --- | --- |
| 帧边界 `80085F30` | 收下按键请求；离开地图（模式不是 3／0xB／2／0x11／0x16／0x22）就清空快照；离开中的请求超过 1200 VI 没恢复就放弃并解除改道 |
| 地图每帧 `801DFBD0`，原版分发之前 | 拍快照；在能离开的时刻执行请求；看到改道被解除（`autosave.cpp` 的 `tactical_restored` 解除）就算恢复完成 |
| 演出每帧 `801C9710`，原版循环之前 | 演出中途执行请求；离开期间每帧把 START 写进 `D_8015D9FA` |
| `srw64_keyboard_input` | 从地图离开时游戏收不到任何键；从演出离开时只收到 START |

- **快照**：「安静空闲」连续两帧时拍。安静空闲是主状态 5，并且没有事件在跑（`idle_reason` 除去阶段那一条：引擎 +4 是 0xC0、+0x97C 是 0x80、+0x9AA 是 0，没有败北演出，模式 3／0xB）。按「安静空闲」整段计数，而不是按「进入状态 5」计数，因为开场或回合事件常在主状态已经是 5 的时候跑，事件结束时状态并不变化。如果这一段是从光标移动（状态 6）接过来的，就不拍。先用 `80093278(0)` 只序列化到缓冲 `800FBEF0`，和最新一份比较（不比 +0 的校验字）；有变化才在 `SuspendWindow` 下调 `80093278(1)` 写进 `<运行目录>/rewind/NNNNNN.sus`。最多留 40 份；章节标题号变了就先清空。我方空闲和敌方每台行动后（敌方阶段在单位之间会停在状态 5 约 24 VI）都走这一条。
- **选哪一份**：先序列化当前局面，和最新一份相同（站在它上面、什么都没做）就退到前一份，否则退到最新一份。演出中途一律退到最新一份，也就是这场战斗之前。退回后，比它新的快照全部删掉。恢复后第一次安静空闲，如果阶段和回合与恢复到的那一份相同，就不再拍（它就是刚恢复的局面），所以连按会一步步往前退。只比阶段和回合，是因为恢复到敌方阶段末尾时，游戏不经过空闲就直接切到我方回合；如果无条件跳过「第一次」，就会吃掉新回合开局那一份。实机里出现过：之后从演出回溯，结果退回了敌方阶段末尾。
- **从地图离开**：主状态 5（任何阶段），或者我方阶段的菜单状态（`game_speed::player_input`）；战前确认／敌方攻击应对画面不算（原生页面跟着原版步进，`game_speed::menu_vi` 4 VI 内）。做法是 `arm_suspend`，然后 `80080188(0x11)` 加 `80099814(5,1,2)`。
- **从演出离开**：演出状态 2–20、它自己的淡出还没请求（X 提前结束会请求）、`D_80225810` 还是 0，模式 2（不含标题演示和战斗鉴赏的 0x1C）。做法是 `arm_suspend`，置 `D_80225810 = 1` 加 `80099814(5,1,2)`，并按住 START，原版自己走 `800A5138` → 模式 0x11。
- **其他时刻按键**（敌方正在移动、地图上结算、战前画面、事件中）：请求挂着，等到上面两种时刻之一再执行；离开地图就作废。
- **随机数**不写回；回合自动存档在恢复时照常重设「本回合已存」（`autosave.cpp`），回溯后不会马上多存一份。
- **设置**：设置窗口「存档」页的「回溯 开／关」，默认关，存在 `presentation.json` 的 `rewind`。关着时按键只提示「回溯未开启」。
- **按键**：新动作 `Rewind`（宿主位 `pad_rewind`，bit 27），默认键盘 R、手柄 L4（`Paddle2`，Deck 背键，R4 是 2 倍速）；操作页可以改。调试接口 `pad l4`；状态 `rewind`（开关、阶段、留着的快照）。
- **触屏**：安卓（及 `SRW64_TOUCH_PAD=1`）顶边有「回溯」按钮，开了回溯且在战术地图或战斗演出里才显示，松手等于按 Rewind（`touch_pad.hpp` 的 `Slot::Rewind`、`touch_scene.hpp` 的 `rewind_place`）。
- **提示**：已回溯一步／没有可回溯的记录／回溯未开启，三语。
- **日志**：`<运行目录>/rewind-events.jsonl`（kept／asked／leaving／restored／gave-up）。

离线测试 `make recomp-rewind-test`（`tests/native_rewind.cpp`，105 项）：快照环的去重、容量、目标选择、截断与清空；地图上哪些状态能离开；演出哪些状态能中止；默认按键不和别的动作冲突。

Windows 实机（2026-10-17，家里台式机，GTX 1080 Ti）：`check_rewind.py --run`，挂到 `D:\srw64-rewind` 的测试包，10 项全过（`build/recomp/rewind-check/win-3b`），覆盖：

- 第一份之前没有可退的；
- 我方演出中途回溯，タケル 回到未行动；
- 战斗结束后回溯，再按提示没有更早的；
- 敌方阶段：第一台被反击击坠后，在第二台演出中途回溯，回到敌方阶段同一回合，剩下两台都未行动；
- 从我方下一回合退回敌方阶段末尾，再走到下一回合，开局那一份重新记下。

调试中修过两处：

- 开场事件期间主状态已经是 5，原来按「进入状态 5」计数，结果一份都拍不到；
- 「跳过恢复后第一次空闲」要按阶段和回合判断（见上）。

截图里光标下的单位有时不见，那是原版光标下单位的闪烁（连拍 8 张有 4 张不显示），与回溯无关。

### 安卓（Seeker，2026-10-17）

触屏「回溯」按钮（顶边情报键右边，见 [touch-controls.md](touch-controls.md) 第 2 节）用真实触摸测过：关着回溯时不显示；地图、单位菜单、战斗演出里显示，战前确认页不显示；没有记录时提示「没有可回溯的记录」，移动＋待机后退回原格、未行动，战斗中途退回攻击前。

战斗中途回溯起初 29 场里有 3 场停在 overlay 字节校验（`host.cpp` 的 `8007F704` 包装，「overlay DMA byte mismatch」）。原因与回溯无关：原版按 0x400 字节分块读 overlay，每块都等 DMA 消息，期间帧边界 `80085F30` 照常跑，宿主的帧钩子会在 overlay 还没读完时改它的字节：`menu_widen` 把地图 overlay 的 `D_80217B1C[0]` 从 0xEE 改成 0xDE，`battle_hud` 改战斗 overlay 的 `80222D78`。它们的判断（`801C9D70` 已是地图指令、`80217B1C` 仍是原值）在半载入时就成立，改完后后面的块还没盖到，读完一比就不一致。桌面上整段读取在一帧之内，几乎碰不到；安卓上块间切换慢，回溯中止演出后切回地图（模式 0x11）最容易撞上。10-15 有过一次普通进战斗时的同样停机。

修法：`8007F704` 读取期间设 `overlay_loading`，帧钩子里改 overlay 字节的两项（`battle_hud::frame`、`menu_widen::frame_start`）等读完的下一帧再做。校验不一致时现在会写出每段不同字节的地址、实际值与 ROM 值、当时的模式，并在 100 ms 后再比一次；开发时设 `SRW64_OVERLAY_REPAIR=1` 会按 ROM 修回并继续，用来在手机上连续抓。

修后在 Seeker 上连续 30 场战斗中途用触屏按钮回溯，没有再停；读完后菜单夹限照常是 0xDE。
