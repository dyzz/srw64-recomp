# 振动设计方案

2026-10-26 起草，只有方案，代码未动。标注：**代码确认**＝读过 ROM/宿主代码；**推断**＝按已知结构推出、未实测；**待查**＝还没看。

## 1. 结论先行

- **原版没有振动。** ROM 里调用手柄扩展口写入 `__osContRamWrite`（`800B9790`）的 22 处、选 bank `__osPfsSelectBank` 的 18 处，全部在 libultra 的存档包（osPfs*）和 GB 传输包（osGbpak*）里；振动包驱动 `osMotorInit/Start/Stop`、`__osMotorAccess` 没有链接进来（代码确认，2026-10-26 扫 `rom.z64` 的 `jal` 并按 `config/recomp/n64sym-symbols.txt` 归属）。所以不能"打开原版振动"，什么时候震、震多大全由宿主决定。
- 运行库 N64ModernRuntime 有 `osMotor*` 和 `ultramodern::input::callbacks::set_rumble`，但游戏从不调用，**不用它**。宿主直接调 SDL2 API（桌面是 SDL3 + sdl2-compat，Switch 是 devkitPro SDL2 2.28.5，安卓是 SDLActivity），一套代码覆盖手柄。
- 原则与 HD 特效一样，不比原版更夸张：振动是点缀，短、轻、只跟画面上已经有的冲击走；菜单、光标、对白一律不震。

## 2. 触发点

按优先级排。第一版做 A–C，D–E 视实测再定。

### A. 战斗演出：伤害节拍（命中）

- **在哪：** 演出 overlay `load_00121560`。伤害节拍 `801C87C8(0x45, 0x45)` 每帧由状态处理器调用；相位 0x45 且 `D_80250488 == 0` 时 `801C8D04` 弹出一步，`801C8D6C` 把待定值写进显示 HP（参战记录 +0x22，推断），同时闪守方、`801C94A0` 黑瞬闪（`battle-animation-rendering.md` §6.5，代码确认）。浮游炮这类多段武器每一发都走一次节拍（§6.2 的 136 号例程，代码确认）。
- **怎么接：** 首选包 `801C8D6C`（加进 `NATIVE_HOOKS`，原函数照跑，跑完比较显示 HP 前后差）。备选是不挂钩子、每帧轮询两侧参战记录 +0x22 的下降沿（`D_80178C78`/`D_80178B50` 在状态 11 互换，要按当时指针读）。两种都只读不写，不改演出也不改结算。
- **强度：** 按这一下的伤害占守方最大 HP 的比例分三档（< 15%、15–40%、≥ 40%），见 §3。

### B. 战斗演出：横幅反应（暴击／防住）

- **在哪：** 横幅由反应码查 ROM `0x51546` 的场景表：1 クリティカル 1151、2–5／0xD–0x10 护罩类、6–0xC 分身类、0x11 シールド防御 1150、0x15 ダミー 1158；切り払い、援护、未命中是空白 1141（代码确认）。`8009504C` 已在 `NATIVE_HOOKS` 里（`ui_text.cpp` 的 `banner_number_drawn`）。
- **怎么接：** 在同一钩子里拿到当帧横幅场景号，**取出现的那一帧**（上升沿）发事件；它每帧都画，不能每帧震。
- **对应：** 暴击 → 加一记"重击"叠在 A 上；护罩／盾防 → 一下短促的高频"咔"；分身、未命中、ダミー → 不震（画面上本来就是落空）。切り払い 横幅为空，靠 A 判断不出来，第一版不单独震（待查：切り払い 是否有自己的音效/相位可挂）。

### C. 战斗演出：击坠爆炸

- **在哪：** 主循环 `801C9710`，状态字节 `D_80250000`；状态 22 `801C818C` 是击坠序列，载入 hit 156/157/158，7 个演员跑行为 382 `80220734`（飞散＋`801C95CC` 黑闪＋变色），爆炸场景 1042–1045（代码确认，§6.4）。
- **怎么接：** 每帧看 `D_80250000` 进入 22 的那一帧发"击坠"长振；再在爆炸演员的黑闪（`801C95CC`）上叠一次余震。待实机确认：所有击坠是否都经过状态 22（状态 9/20 的分支里 HP==0 也可能直接去 21）。

### D. 剧情震屏（脚本 3D36）

- **在哪：** 脚本指令 3D36 的处理例程 `8009F880`，战术地图由 `8020D4B0`、世界地图由 `801C5138` 每次调用推进一步（`script_skip.hpp`，代码确认）；效果是镜头 X 摆动，幅度约 15 像素（`deck-16x10.md`，代码确认）。
- **怎么接：** 进入 3D36 时开始低频持续振动，震屏结束时停。时长、幅度参数在指令的哪几个字节里待查（反汇编已随 build/ 清理，要重新生成看）。
- **要注意：** R+START 短跳过和 E+Enter 跳过会让 3D36 当帧完成，此时不震；按住快进（E+Z）时也不震。

### E. 地图上的结算（关演出／MAP 兵器）

- **在哪：** 关演出时 `801D4E6C` 让 `801FCA78` 经 `801FB8B4(handle, damage, flags, reaction)` 把每回合排进队列，宿主已经包了这两个函数（`map_miss.hpp`、`overkill.hpp`，代码确认），子状态 3 → 6 一回合一回合地放。
- **怎么接：** 回合**显示**时（不是排队时）按 A 的规则发事件，强度整体打七折。MAP 兵器多目标时每个目标一次，间隔不足 120 ms 的合并。地图上单位被击坠时的爆炸地址待查。

### 不震的地方

菜单、光标移动、对白翻页、战前确认页、场间画面、标题、精神指令施放（画面上没有冲击）、BGM 节拍。

## 3. 强度与波形

SDL2 的 `SDL_GameControllerRumble(pad, low, high, ms)`：low＝大马达（低频、沉），high＝小马达（高频、脆），0–65535。下面用 0–1 表示，再乘设置里的强度（§5）。

| 事件 | low | high | 时长 | 说明 |
| --- | --- | --- | --- | --- |
| 命中・小（< 15% 最大 HP） | 0.25 | 0.20 | 90 ms | 浮游炮一轮多发都是这一档，必须轻 |
| 命中・中（15–40%） | 0.45 | 0.30 | 140 ms | |
| 命中・大（≥ 40%） | 0.70 | 0.40 | 200 ms | |
| 暴击（叠加） | 0.85 | 0.60 | 220 ms | 与同帧的命中取较大值，不相加 |
| 护罩／盾防 | 0 | 0.35 | 60 ms | 只用小马达，"挡住了"的手感 |
| 击坠 | 0.90 → 0 | 0.50 → 0 | 600 ms | 头 150 ms 满，之后线性衰减（宿主每 VI 重设一次） |
| 剧情震屏 | 0.35 | 0.10 | 持续到 3D36 结束 | 上限 3 秒，防止参数读错一直震 |

- **我方受击与敌方受击：** 我方挨打按表，打敌人乘 0.6——玩家对"自己被打"更敏感，打别人的手感留给命中音效。敌方之间、第三方之间的交战（我方不参与）乘 0.4。
- **合并：** 同一时刻只有一个振动；新事件强于当前剩余量才覆盖，否则丢弃。两次脉冲间隔至少 50 ms。
- **倍速：** 2×/3×/4× 下按真实时间计时长（SDL 的时长本来就是毫秒），但 4× 时命中・小不震，免得变成一直嗡嗡响。
- 数值是起点，最终按 Deck、Xbox 手柄、Switch Pro、手机各摸一遍再调。

## 4. 各平台

| 平台 | 怎么震 | 状态 |
| --- | --- | --- |
| Windows／Linux／Mac 外接手柄 | `SDL_GameControllerRumble`；先查 `SDL_GameControllerHasRumble`，没有就不显示设置行 | Xbox/PS/Switch Pro 经 SDL 都支持（推断，SDL 2.0.18+ 的标准能力） |
| Steam Deck | 同上；Steam Input 的虚拟手柄会把振动转给 Deck 的触控板马达 | 推断；Steam 的"手柄振动"设置要开着，要实机摸 |
| Switch | devkitPro SDL2 2.28.5 的 Switch 手柄驱动走 libnx HID 振动（Joy-Con／掌机／Pro） | 推断；SDL 的双马达值怎么映射成 HD 振动的频率/幅度要实测，可能需要单独调表 |
| 安卓・外接手柄 | 同桌面，经 SDLActivity | 推断 |
| 安卓・手机本机马达 | SDL 的 Android haptic 会把系统振动器当成一个 haptic 设备（推断），或者在 `SRW64Activity` 里自己调 `VibrationEffect.createOneShot(ms, amplitude)` | 清单里**没有** `android.permission.VIBRATE`（代码确认），要加；只有幅度没有双马达，取 max(low, high)；不支持幅度的老机器只按时长震 |
| 纯键盘鼠标 | 无 | — |
| Vita | 机身没有马达，不做 | — |

- **线程：** SDL 调用要在窗口线程（`graphics.cpp` 的事件循环持有 `pad`）。游戏线程发现事件只往无锁队列里放，窗口线程每次轮询时取出执行。
- **必须停振动的时机：** 打开设置叠加面板、窗口失焦／最小化、中止演出（手柄 X）、返回标题、读中途存档、手柄拔出、退出程序。SDL 振动有时长会自停，但击坠和剧情震屏是逐 VI 续的，必须显式发 0。

## 5. 设置项

放在设置的「操作」页，按键表上方。三语词条进 `content/locales/*.json`，新词条要进 UI_KEYS。

| 行 | 选项 | 默认 | 说明 |
| --- | --- | --- | --- |
| 振动 | 关／弱／标准／强（×0／0.5／0.75／1.0） | 标准 | 只在当前手柄支持振动时显示；切换时立刻放一次"命中・中"当试震 |
| 手机振动（仅安卓） | 关／开 | 关 | 用触屏玩时让手机本机震；接了手柄时这一行不起作用 |
| 剧情震屏时振动 | 关／开 | 开 | 只管 D；有人只想要战斗振动 |

- 存在其他展示类设置的同一份文件里，键名 `rumble`（`off`/`weak`/`normal`/`strong`）、`rumble_phone`、`rumble_story`。
- 词条：中「振动」、日「振動」、英「Vibration」（英文菜单里 Rumble 也常见，但 Vibration 对手机也说得通）。
- 战斗查看器共用演出 overlay，A–C 自动生效，跟同一个设置走，不另设。

## 6. 代码结构（实现时）

- 新文件 `src/host/rumble.hpp/.cpp`：`rumble::event(Kind, side, ratio)` 给钩子用；`rumble::frame(ram)` 每帧在游戏线程跑（状态 22 边沿、击坠衰减、剧情震屏续振）；`rumble::apply()` 在窗口线程取队列、乘设置、调 SDL 或安卓。
- 钩子：`801C8D6C`（新加，`NATIVE_HOOKS` 改完要手动 `generate_cpu`）、`8009504C`（已有，加一行）、`801FB8B4` 回合显示处（已有）、3D36 处理例程（待定，可能在 `script_trace` 那层看指令号）。
- 调试接口：每次振动写一行 `SRW64_RUMBLE kind=hit side=player low=… high=… ms=…` 进日志并进 `srw64_events`，这样在 Mac 上没有手柄也能用迷你关验证"该震的时候发了、不该震的时候没发"。
