# 机体标识（地图单位图标）HD：保留像素感的重画方案

2026-09-26。战术地图上每台机体是一张 16×16 的 CI4 SD 头像（资源 688–1009，320 张不同的图，323 条机体记录），阵营颜色完全来自调色板（1010 蓝、1011 红、1012 黄、1013 灰；1–6 号是阵营色阶，7–13 号是眼睛、粉色等固定色，0 号透明）。用户的要求：高清化要**保留像素感**，但不是把原像素单纯放大，最好像一张新画的、分辨率更高的像素画。本文记录试过的路线和定下的做法。工具 [`unit_icon_hd.py`](../../tools/hd_ai/unit_icon_hd.py)，输出与研究材料在 `assets/hd-ai/unit-icons/`（不进 git）。

## 结论（2026-09-26 定案）

**MMPX×2 → 4x-PixelPerfectV4 → 硬量化 32 → MMPX×2，产物 64×64 色号图。** 全程本地，不做模糊、抗锯齿和抖动，每个输出像素只取原图用过的色号：

1. MMPX×2（`pixel_scale.py`，只复制色号）：把台阶顺好，棋盘格抖动缩成 2 像素方块；
2. 4x-PixelPerfectV4（本地 ESRGAN，`build/esrgan-models`）吃这张 32×32，出 128×128 平滑画（颜色与 alpha 分开过模型，透明像素先填最近实色）；
3. BOX 缩到 32×32，每个像素按 CIELAB 距离贴到原图用过的色号，去孤立像素两趟；
4. 再 MMPX×2 到 64×64，只顺 32 像素结果的台阶。

MMPX 放在模型前面是关键：模型直接吃 16 像素会把抖动揉成圆润块面（「涂抹」），吃 MMPX×4 又会被大方块锁死几乎不改；×2 正好让它把抖动变成有方向的明暗、结构不跑。最后一步 MMPX 相比直接硬量化到 64，形状更整、更像手点的像素画。320 张在 MPS 上 17 秒，零费用，没有 IP 过滤问题。

```sh
build/esrgan-venv/bin/python tools/hd_ai/unit_icon_hd.py export --output assets/hd-ai/unit-icons/v2
build/esrgan-venv/bin/python tools/hd_ai/unit_icon_hd.py run --output assets/hd-ai/unit-icons/v2   # --pre 2 --size 32 --post 2
```

`v2/hd/<rid>.idx.png` 是 64×64 色号图，`<rid>-<palette>.png` 是四套渲染；`review.png` 是 9 台样张（原图、平滑、64 px、红、灰），`sheet.png` 是全部 320 张的一览。

**分辨率**：play profile 的 `resolution_scale` 是 4（上限 8），16 像素图标在屏幕上占 64×64 内部像素，所以 64 的母版在默认倍率下 1:1 绘制；倍率 8 时按 2:1 显示。源信息有限，128 的版本只多出斜边上的过渡，没有必要。

**状态（2026-09-27）**：用户确认先按此处理带入游戏（HD／原版用 F6 或设置切换，图标随美术包一起开关），后续可能再调；调整只改 `--pre`、`--size`、`--post`、`--model` 重跑 `run` 与 `pack --bind`，不用动接入。

## 探索过程

### 第一轮：平滑 → 重新像素化 32（被否）

PixelPerfectV4 直接吃 16 像素 → 高斯 0.7 → BOX 到 32 → 贴色号 → 去孤立像素。用户看后：**「都没有像素感了」**，色阶过渡太顺，原作的硬边和棋盘格味道全没了。工具里保留为 `--pre 0 --post 0 --blur 0.7`。

### 第二轮：找回像素感（被否）

- 全图 Bayer 2×2 / 4×4 有序抖动：变成噪点，不像手点的；
- 平整色块 + 1 像素深色描边（majority 滤波）：仍偏平滑，且多数滤波会吃掉单像素高光和眼睛；
- hybrid（内部沿用原像素含棋盘格，只在轮廓和台阶处用重画结果）：像素感最强但几乎没有新细节；
- 用户明确：**要「很高清、重新点出来的」像素画，不要任何涂抹和平滑**。

### 第三轮：硬量化（无模糊、无抖动）

xBRZ×4 源 → 硬 64：台阶干净、块面平整，但 xBRZ 是 GPLv3，且形状偏矢量化；用户转而问 **MMPX + ESRGAN**。

### 第四轮：MMPX 在前

| 链 | 结果 |
| --- | --- |
| MMPX×2 → PPv4 → 硬 64（F） | 结构一一对应，抖动变成有方向的明暗，用户初选 |
| MMPX×2 → PPv4 → 硬 32 | 同链的 2 倍版，块更大 |
| MMPX×4 → PPv4 → 硬 64（G） | 被 4 像素方块锁死，几乎就是原图顺过手；换 UltraSharpV2 / Nomos8kSC / 2x AnimeSharpV3、两趟模型、MMPX×8 都无差别；加多数滤波吃掉高光。用户：「这一轮质量都倒退了」 |
| F 与 G 源图各半（H） | 折中，未选 |
| F 的变体：不去孤立像素、两趟、量化前锐化、Scale2x / xBRZ×2 做前置、UltraSharpV2 组合 | 不去孤立像素多保住几处单像素高光；其余无实质提升或更圆 |

### 第五轮：MMPX×2 与 PPv4 的排列组合

| 组合 | 结果 |
| --- | --- |
| PPv4 → 硬 64（无 MMPX） | 抖动全揉成大块面，最「涂抹」，ドモン 的脸变形 |
| MMPX×2 → PPv4 → 硬 64（F） | 平衡点 |
| PPv4 → 硬 32 → MMPX×2 | 32 像素结果的机械放大，带 PPv4 的圆润 |
| **MMPX×2 → PPv4 → 硬 32 → MMPX×2** | F 的 32 版再用 MMPX 顺台阶；**用户定案** |
| PPv4 两趟 → 硬 64 | 更圆，像插画 |
| MMPX×4 单独 | 保底，几乎等于原图 |

MMPX 放在模型前面才有意义；放在后面只是机械放大，但用在 32 像素的硬量化结果上，比直接硬量化 64 更整齐。

## 首轮全路线对比

样张 9 台：ガンダム 737、マジンガーZ 944、ゲッター1 853、ダンバイン 929、ザクⅡ 779、アーガマ 733、コン・バトラーV 878、暗黒大将軍 838、ドモン 692（生身）。对比图在 `assets/hd-ai/unit-icons/research-2026-09-26/`。

| 路线 | 结果 | 结论 |
| --- | --- | --- |
| 最近邻 ×4 | 原样 | 保底 |
| Scale4x（EPX 两次，色号图） | 斜线变顺，但生出很多小尖角和"毛刺"，抖动区域被放大成花纹 | 不用 |
| MMPX ×4（色号图） | 太保守，几乎就是最近邻 | 不用 |
| xBRZ ×4 / ×6（GPLv3，Zenju） | 最平滑，接近矢量图；抖动区域变成整片色阶 | 单独用没有像素感；作为"重新像素化"的源图效果与下一行相近 |
| **4x-PixelPerfectV4 直接吃 16 px** | 干净的平滑画，明暗过渡自然，结构忠实 | **重新像素化的源图** |
| 4x-PixelPerfectV4 吃最近邻 ×4 | 只是把像素块的边缘锐化，仍是 16 格 | 不用 |
| 4x-deviantPixelHD、4x-Fatality | 过锐、出现裂纹和错位的高光 | 不用 |
| 4x-UltraSharpV2、4x-AnimeSharp、4x-Nomos8kSC | 与 PixelPerfectV4 相近或更硬 | 备选 |
| 4x-NXbrz、4x-Fatal-Pixels（OpenModelDB） | 下载源每秒几 KB，没拿到 | 未试 |
| 重新像素化 32（源图 PixelPerfectV4 + 模糊 0.7） | 像新画的 2 倍像素画；四套调色板直接可用 | 首轮定案，后被用户否掉（没有像素感） |
| 重新像素化 32（源图 PixelPerfectV4 与 xBRZ ×6 各半） | 与上一行几乎一样，边缘噪点略少 | 引入 GPL 代码不值得，改用高斯模糊达到同样效果 |
| 重新像素化 48 / 64 | 逐渐接近 xBRZ 的平滑感 | 不用 |
| qwen-image-3.0，最近邻 ×32 输入 | 照抄 16 格，只把颜色改错（眼睛出现红绿粉杂色） | 否 |
| qwen-image-3.0，双三次 ×32 输入 | 仍然重建成 16 格 | 否 |
| qwen-image-3.0，PixelPerfectV4 平滑图输入 | 画出 48–64 px 的像素画，但造型跑偏（ガンダム 的 V 形天线变成两只角，面部糊掉） | 否 |
| qwen-image-3.0，加同机体立绘作参考图 | 按参考图画了全身像，不再是头像构图 | 否 |

千问 8 次请求共约 1.6 元，记录在 `assets/hd-ai/unit-icons/test-1`、`test-2`。16×16 只有 256 个像素的信息，编辑模型要么照抄网格，要么重新发明造型；本地"超分 + 量化"反而最忠实。**用户随后决定：这类资源一律不用云端模型。** 本机（M4 Max，128 GB）跑 SDXL/Flux + 像素画 LoRA 做图生图是唯一能补出「新细节」的本地路线，但要装环境且逐张过审，没有开工。

## 接入（2026-09-26 已做）

走 RT64 纹理哈希替换，与世界地图、宇宙物件同一条路：

- **键**：图标由 `801C60A4` 建的子槽 0（模式 5）绘制，是单独装载的 16×16 CI4 贴图，调色板参数 `1010 + 阵营`。RT64 v5 的 TMEM 哈希把用到的调色板项也算进去，所以同一图标的四个阵营是四个不同的键，正好对应四套渲染。哈希算法沿用 `worldmap_space.ci4_hash`（TMEM 里奇数行 4 字节对调、用到的色号各 8 字节、再加 宽 16／高 16／tlut 0x8000／line 1／siz 0／fmt 2），**已用真实转储核对**：`--dump-textures` 运行（`Session.launch(dump_textures=True)`，RT64 写 `<run>/textures/<hash>.{tmem,tile.json,rice.json}`）里地图上 3 台机体的 16×16 贴图（tile line 1、fmt 2、siz 0、masks 4）与算出的键一一对应。
- **包**：`unit_icon_hd.py pack --output v2 --pack assets/hd-ai/worldmap-surfaces/pack-v5 --bind` 把 320 × 4 张 64×64 写成 `icon-<hash>.png`（透明像素的 RGB 填最近实色，线性采样不出暗边；像素相同的图标去重后 1256 张）并入 `rt64.json`，在 `content/art/stage1-hd.json` 里登记为 `kind: icon`；`compile_art` 接受这一类，并在编译出的 `rt64.json` 里保留 `kind`（RT64 忽略多余字段）。
- **实机**：`check_unit_icon_hd.py` 在 HD 下进 move-jump 迷你关卡截图、F6 切原版再截一张，并断言转储里的 16×16 机体贴图哈希都在包里。默认倍率 4 下 64 像素 1:1 绘制，阵营色正确，边缘无暗边。
- **公开包**：2026-09-28 起公开 HD 包与自用相同，图标也在里面；NOTICE 写明由原版像素图放大重绘。此前 `build_release.py` 按 `kind` 剔除（`ROM_DERIVED_TEXTURE_KINDS`），已取消。
- 未做：阴影椭圆（资源 687）没有换；1013（灰）对应的阵营含义、"已行动"是否换调色板仍未确认——灰版已经在包里，用到自然生效。
