# 内置 MOD 路线图：基础体验、多语种与 Original / HD

日期：2026-09-12；2026-09-16 补充 Bug 来源登记及 EW 换机预览需求。本文规定后续交付范围、优先级与验收门槛；除“当前起点”明确列出的能力外，均为计划。

范围决定：当前 MOD 指由本项目维护、随同一个程序交付的内置功能模块。模块代码直接编译进宿主，语言与美术继续由仓库内的数据目录和清单配置。当前不接入外部 MOD，不建设通用包加载器、依赖版本求解、动态代码加载或公开 SDK；这些均不属于 M0–M4 的交付门槛。文中的语言包、美术包和规则包仅表示我们维护的内容集合或功能分组。

本文接替[早期增强方案](native-enhancements-plan.md)中的工作顺序与首发范围，尤其将可靠存档管理纳入首发。[扩展架构](native-extensibility-architecture.md)继续说明内容和接口设计，[内容第一批实现](../native/native-content-foundation.md)记录已有功能与历史证据。

## 1. 产品决定

以同一锁定的日版 Rev 0 ROM 和原脚本为运行基线，先让原版流程、操作、阅读和保存可靠，再扩大查询、整备、规则与内容扩展。基础包不默认改变机体强弱，不捆绑攻略提示或回溯。

玩家配置分为互相独立的四个维度：

| 维度 | 选择与边界 |
| --- | --- |
| 语言 | `ja`、`zh-Hans` 先完成产品覆盖；其他语言通过语言包注册。语言不选择另一份 ROM，也不改变路线、规则或随机状态。 |
| 美术 | Original / HD 一键切换；高级设置可分别选择图片与模型。字体、UI 字号、地图缩放、内部渲染分辨率分别配置。 |
| 基础体验 | 战斗演出、分场景速度、阅读、存档、地图操作、输入与可读性。关闭增强后仍能正常启动、游玩和读取兼容存档。 |
| 规则与辅助 | 规则修正、额外信息、自动应对、回溯和内容扩展分别启停；改变持久玩法状态的选项进入存档兼容清单。 |

提供三种基础体验预设：“原味”保持原版演出节奏和规则；“增强”开启已验收的快捷操作、阅读和安全节点保存；“自定义”保留逐项设置。两种预设均默认关闭规则修正、隐藏条件追踪、自动应对和回溯。预设不覆盖玩家已选语言与美术；首次安装的语言和美术单独选择。

“Original”指使用原始美术，不承诺恢复全部原版 UI 或 N64 分辨率。选择中文和 Original 时仍可使用原生中文排版；需要对照原始字图的开发模式单独保留。现有 F6 在完整画质设置落地前继续沿用当前含义，不提前改变其行为。

[退出生命周期记录](../native/native-window-close.md)中的线程回收缺陷已于本轮实现修复，并验证现代姓名→剧情关窗、原版姓名页关窗及 VI 自动退出；具体最终证据和限制见该记录。M0 的安全节点保存、冷启动恢复和其他场景仍须各自验收，不能据此关闭整个 M0，也不把旧截图或第一话结果推广到全游戏。

| M3：规则与辅助包 | 可选规则修正、假身信息、继承提示、隐藏条件、自动应对、撤销/回退 | 默认状态与影响清楚；规则版本可追溯；旧存档兼容和回溯恢复分别验收。 |
| M4：自有内容扩展 | 项目维护的已知字段补丁→原关卡参数→结构化事件→新增单位/战役；联动专项 | 每层先验证写回、容量、引用和存档，仍随本项目构建和交付；不以外部作者接口或 SDK 为前提。 |

M0 内可以分别推进语言内容和适配层调查；M1 的战斗跳过与安全节点恢复各有独立技术门槛，不能为了交付进度降低验收标准。M2 的查询接口调查可提前，但产品发布在 M1 稳定之后。缺陷复现贯穿各阶段；影响基础流程的已确认故障优先修复，不必等到 M3。

暂不报日历工期。先完成 M0 的战斗、保存和单位状态三个纵向原型，再据实际缺口估时。M1 未完成时可以发布明确标注覆盖范围的测试版，不能把局部第一话演示称为完整首发。全游戏发布需要另设各主角、主干路线、分歧、离队再加入与结局覆盖清单。

| --- | --- | --- |
| B01 战斗动画 | 全开/全关；播放中随时请求跳过；按住快捷键临时加速、释放恢复。跳过请求在最近的已验证安全边界完成。 | 完整播放、关闭、不同时间点跳过、临时加速的结算、剧情和随机状态一致；不重复结算，不遗漏战前/战后事件。无法安全跳过的片段应列为未完成项。 |

### 战斗与速度的实现约束

保留一个权威结算路径。演出可以少绘制、缩短等待或在已验证边界推进，但不能根据画面自行模拟一套伤害。若发现随机数或剧情事件在演出期间被消费，必须保留相同的逻辑调用与顺序；单纯快进到结尾帧不满足要求。

对照从同一检查点和随机状态开始，使用相同语义指令；比较 HP/EN/SP、弹药、气力、状态效果、假身计数、击坠、经验、资金、队伍、行动状态、事件旗标与随机状态，并继续执行下一次行动检查隐藏漂移。帧数和纯显示计时可不同；排除字段须有说明。不能通过在结算末尾强行覆盖随机状态来掩盖差异。

输入采用独立于演出速度的按下/释放处理；菜单连发只在允许的导航操作中使用真实时间。音频、消息等待与场景生命周期分别适配，现有全局运行速度探针不能直接成为面向玩家的分场景速度功能。

### 已读记录

采用内容包命名空间、TextKey、结构片段、源版本/控制结构摘要与必要事件上下文标识已读，不只保存“最后一句编号”。含动态参数的句子应保存语义参数签名或采取保守停止策略，避免同模板的新剧情被误跳。只在完整显示并实际推进后标为已读；回看不增加已读。

首版按游戏档案保存已读集合，随检查点恢复；跨周目共享可后续独立开启。切换语言不改变已读身份，选择项始终停止；源文或事件结构变更后相关记录失效。回看记录保存 TextKey、参数及版本，缺少旧内容时可使用保存的显示文本作为记录，不据此重新执行脚本。

### 安全节点保存协议

1. 先核实原生游戏保存例程是否完整覆盖目标节点。若不足，列出并序列化所需扩展状态；不能仅复制 SRAM 就宣称支持任意回合恢复。手动保存首版仅在安全节点开放，其他时刻说明原因。
2. 安全节点要求：无战斗结算、未完成剧情命令、资源/场景切换或待提交指令；在游戏线程取得同一代次的一致状态。自动保存点在回合初事件完成后、玩家可操作前；分歧书签在选择出现前已验证的稳定节点生成，不能稳定截取时使用更早节点并说明位置。
3. 保存集合包含基础游戏数据、必要扩展状态、玩法配置指纹、稳定 ID 映射、已读及辅助元数据；必须覆盖恢复所需的随机、事件、队伍、改造与部件状态。显示话数、回合、已知路线、保存时间、游玩时间及备注；未获知的路线不提前透露。
4. 先写不可变新代次，校验所有成员及摘要，再原子发布指向该代次的索引；失败保留旧索引。不能用两个独立文件各自 rename 代替保存集合的一致提交。并发保存串行处理，同一档案防止多进程覆盖。
5. 手动、自动轮转和书签分池管理；容量可配置。自动池不淘汰手动槽、锁定书签或唯一有效备份；删除旧代次发生在新代次提交成功之后。
6. 加载先检查完整性和玩法兼容，再构建状态；失败不改当前进度。测试必须包括完全退出后的冷启动、异常中断、损坏单个成员、程序不支持存档所需状态以及切换语言/画质后的读取。

更细粒度的战斗后撤销与回合回退归 M3。首发不提供或暗示模拟器式任意时刻即时存档。

## 5. 多语种：平台支持与翻译内容分开验收

| 工作 | 交付要求 |
| --- | --- |
| 文本覆盖台账 | 分列剧情、名称、武器/精神/技能、菜单、战斗文字、存档/设置、烘焙文字；记录是否已提取、已接入、已翻译、已审校、已实机验收。按唯一键统计，同时说明实际显示消费者覆盖。 |
| 语言包协议 | 稳定命名空间和 TextKey；源语言、适用内容版本、源摘要、具名参数、控制屏障、审校状态、字体策略。新增语言不要求修改宿主语言枚举。 |
| 编译与回退 | 基础内容缺译回退对应日文；自有新增内容缺译回退该内容声明的源语言。单条缺译可回退，摘要/控制结构无效则在加载前诊断并拒绝该无效包，不能把事件错误掩盖为普通缺译。 |
| 全文字接入 | 逐个适配菜单、战斗、名称等消费者；源字图只在已接管显示路径抑制。语言贴图单独分类，避免 Original 强制丢失选定语言。 |
| 排版 | Unicode、字体回退、日中禁则、长名称、英文长词、动态参数、分页、UI 缩放及缺字提示；英文已按既有中文范围补齐 153 条草稿和 40 条原生 UI 文案，用于技术验证，不据此宣称完成翻译。复杂书写方向另设验收。 |
| 玩家姓名 | 保留玩家自定义名称与原游戏编码/校验；不能靠与默认字符串相等判断是否被修改。任意 Unicode 姓名需专门持久化方案，后续实施。 |
| 选择与生效 | 启动时选择语言；游戏内 F7 按日/中/英循环切换并记住，无弹窗。目录、分页、回看和输入一起更新；同一片段从头显示，暂停自动推进，不确认下一句。旧渲染帧保留旧目录，热切换不改玩法状态。 |

先把 `ja` / `zh-Hans` 作为产品支持目标，并交付一个第三语言样例包。**语言系统支持中文，不等于全游戏中文完成。** 发布时列出实际覆盖、草稿和缺译回退范围；若宣称完整中文版，则全部宣称范围必须完成翻译、审校和实际流程验证。全语言内容生产按主角/路线与术语表单独排期，可与运行时开发同时推进。

## 6. Original / HD：逐项可回退的呈现系统

资产按“无文字图片、语言相关图片、模型、UI 皮肤”分类。稳定资产 ID 必须带可验证的原资源身份；哈希存在歧义时增加场景/资源上下文。替换包声明覆盖范围、版本与文件摘要，不以替换数量代表完整 HD。

| 设置 | 行为 |
| --- | --- |
| 一键 Original / HD | Original 选择原始美术；HD 选择项目提供并通过校验的替换，缺少单项替换使用原图/原模型。需要模型结构、碰撞或玩法数据变化的包不得归为纯 HD。 |
| 自定义美术 | 后续分别选择图片、模型与 UI 皮肤；混合配置显示“自定义”。从自定义切到 Original 时记住上次配置，切回可恢复。M1 可先沿用联动式切换。 |
| 语言相关图片 | 在所选语言内选择对应风格；缺少该风格时使用同语言替代或原生文字层，再按语言包回退规则处理。不能因关闭 HD 顺带关闭翻译。 |
| 字体/UI/地图/分辨率 | 各自保存，画质快捷键不修改；减少闪白/震屏也独立。设置 UI 显示实际生效模式和未覆盖项。 |

沿用“窗口提交请求→渲染线程在安全边界应用→确认模式”的路径；旧资源等待 GPU 使用完成后释放。模型、纹理与抑制原图的标志须在同一代次切换，避免空白帧或混用尺寸。切换失败保留上次有效配置并报告原因，不能显示已切换却继续使用旧资源。

当前配置引用的整个美术包缺失/摘要不符会使启动报错；M0/M1 要补充可见的诊断和“使用原图继续”入口。程序不支持存档所需的玩法状态时仍阻止不安全读档；美术错误不应让玩家无法恢复原版呈现。普通画质操作不改变存档、剧情或随机状态；用户明确保存设置后才更新下次启动的配置。

验收至少包含 `ja` / `zh-Hans` × Original / HD 的同场景、同检查点对照，再补第三语言样例、缺译、缺资产、长句/大字号、反复切换和切场景。比较玩法状态，并检查画面、文本、透明度、模型、资源释放与输入；静态编译通过不能替代实际原生运行和人工画面检查。

## 7. M2：查询与整备

共同前提是单位快照、可达格、合法行动及指令校验接口。查询是只读的，不消费随机数、不改缓存以外的玩法状态；输出绑定状态代次。玩家确认前在游戏线程重新校验，状态变化后刷新结果，不能直接执行陈旧预览。

| 功能 | 具体交付与边界 |
| --- | --- |
| 目标中心攻击查询 | 选敌人→列出可攻击的我方单位、合法移动位置、武器与消耗→预览→玩家确认；首版不提供未核验的精确伤害数字。 |
| 敌军威胁范围 | 单个或全部已知敌人的合法攻击覆盖；移动时显示能攻击目的地的敌人。明确站定/移动后攻击口径，处理地形、阻挡、EN、弹药、气力、移动后限制与特殊武器；未知规则标记不完整。表示能力，不预测 AI，不泄露未出现的增援。 |
| 全队精神检索 | 按效果/目标找到合法施放者，显示消耗和剩余 SP，进入正常目标选择与确认；不绕过范围、对象或剧情限制。 |
| 整备简化 | 部件直接交换、收藏、锁定，单位/部件筛选与换乘前后对比；以部件实例身份执行交换，失败全部回滚。 |
| 改造预算 | 暂存多机计划、总价和结果，可撤回；统一确认时核对资金、价格及资格，原子提交，取消无消费。 |
| EW 换机预览与确认 | 机体最后一项改造触发换机前，展示能力、武器／射程变化、改造继承、部件槽和部件去向；取消不付款、不改状态。先核验原版映射；满改后保留 TV 形态若另行支持，作为独立行为选项。见[QOL01](../gameplay/original-bug-register.md)。 |
| 编成预设 | 出击队伍、合法换乘和已有部件分配；加载先给差异及缺失/冲突报告，不静默替换。仅安排现有资源，不复制部件、不突破换乘与出击限制。 |
| 精选动画 | 首次武器、收藏单位、指定 Boss/特殊交战优先播放；首次记录在实际交战完成后提交，身份不依赖语言。沿用 B01 同一结算路径。 |
| 回合战报 | 订阅已完成事件，汇总伤害、击坠、资源及重要事件；点击定位有效单位，已离场对象仅显示记录。事件 ID 去重，读档恢复不重复计入。 |

## 10. 最小内置模块架构

保留固定的 recomp 运行时，直接在现有宿主中实现我们自己的功能模块。按实际功能拆出明确接口和配置，不要求先接入 N64ModernRuntime 的外部内容加载机制或 `.nrm`。安全保存、兼容检测、语言回退与诊断属于核心服务；阅读、战斗演出、地图便利操作、信息提示和规则修正按功能分别启用。

首版使用代码中显式的模块装配与初始化顺序即可。各模块调用共享适配层并订阅确有需要的语义事件；不为了模拟插件系统给每个模块强加动态加载、导入导出或独立包格式。内部 C++ 接口可使用类型安全的值对象与不可变快照，不要求跨二进制 ABI 稳定；持久化 schema 和稳定 ID 则需要版本管理。

| 能力 | 最小契约 |
| --- | --- |
| 模块与配置 | 稳定模块 ID、启停、默认值、设置 schema、生效时机、保存影响；随宿主版本统一发布。能力前置条件由代码显式校验，不做外部包依赖版本求解。配置变更须说明是否影响当前存档。 |
| 生命周期 | 区分启动生效、下个安全节点生效和呈现热切换；玩法配置首版启动前冻结。明确初始化、事件顺序、切关/读档重置和退出清理；订阅者不能覆盖现有钩子。模块出错时拒绝未提交请求，已执行的玩法效果不能靠关闭模块自动回滚。 |
| 只读查询 | 单位/驾驶员/武器定义与运行实例分开；单位快照、合法行动、范围和不可用原因使用同一规则来源。句柄带世代，切关/读档后失效，查询不消耗随机状态。 |
| 指令 | UI 提交带状态代次的请求；游戏线程在合法时机重新校验并执行，返回原因与结果。渲染/窗口线程不写 RDRAM，不公开任意内存写入作为普通接口。 |
| 事件 | 回合开始、选择变化、对白片段、战斗完成、关卡进入、保存/加载等语义事件；明确发生前/后、是否可发命令和事件 ID。恢复状态与新发生事件分开，不重放奖励回调。 |
| 字段补丁 | 我们维护的变更按稳定 ID+字段路径表达，附基线值/源摘要断言，校验范围及引用；同字段重复写入在开发/配置检查中报错或显式组合。标明模块来源，由项目定义组合行为，不给玩家任意加载顺序仲裁。 |
| 内容与代码 | 翻译、美术和已支持数据字段沿用本地目录/清单；功能代码与宿主一起编译。游戏地址、符号和 overlay 集中在适配层，模块使用语义接口，不各自维护内存地址。 |
| 诊断 | 记录内置模块启停、有效配置、字段来源、事件与比较结果；提供关闭可选增强的恢复启动预设，能使用源语言与原始美术。该预设不绕过玩法存档兼容校验。 |

内部按游戏适配、内容数据、语言、呈现、存档和功能模块拆责任；[扩展架构](native-extensibility-architecture.md)中相应分层可复用，外部包和公开 API 部分暂不执行。按功能逐步迁移，不为规划一次性搬动宿主或生成代码。语言/显示只从有效内容和快照生成输出，不能另维护一套与结算脱节的属性。

### 存档兼容决策

保存记录游戏基线、宿主构建版本、保存 schema、影响玩法的内置模块及规则配置、有效内容/规则版本、对象 ID 映射和扩展状态 schema；展示设置另存。玩法指纹忽略语言、字体和纯美术；同一模块兼有 UI 与玩法时按实际保存影响处理。构建版本用于追溯，不要求每次重编译就拒绝旧存档，兼容判断依据实际状态与规则协议。

| 差异 | 加载处理 |
| --- | --- |
| 语言、字体、纯 UI、美术变化或缺失 | 允许读档，使用明确回退；报告显示差异，不修改进度。 |
| 同一玩法身份且保存格式兼容 | 允许读取，先验证所有保存成员与 ID 映射。 |
| 内置玩法模块/规则版本变化 | 只有经测试的兼容声明或迁移器才接受；版本号变大不自动等于兼容。迁移前备份，迁移失败保留原档。 |
| 当前程序不支持必要状态、未知单位/关卡 ID、规则不兼容 | 在应用任何状态前阻止加载，列出需要的程序版本、内置内容或规则配置及恢复方式，不自动替代对象。 |
| 旧无 MOD 元数据的 JP 原档 | 按明确的原版导入流程识别并验证；不得猜当前规则就是原档规则。旧补丁 ROM/中文实验存档需专门迁移验证。 |
