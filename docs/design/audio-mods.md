# 音乐替换与战斗语音 MOD

2026-10-20。规划两类音频 MOD：**替换战斗与其他 BGM**、**给人物加战斗语音**。属于 [MOD 包](mod-packages.md) 的 `audio/` 一类（§4 已定：音乐按曲目号、战斗语音按战斗台词号）。音乐按歌号替换已在 `mods` 分支实现（§8），其余仍是设计。原版事实来自静态分析（[战斗鉴赏 §6.7](battle-viewer.md)、[战斗台词选择表](../data/battle-quotes.md)），未实机的地方单独标出。

## 1. 目标与范围

- **BGM 替换**：一个 OGG 顶替原版一个歌号，所有放这首歌的地方（战斗曲、关卡曲、剧情曲、标题、音乐鉴赏、卡拉OK）都跟着换。新曲也这样做：顶替音乐鉴赏里的某一首，可以带自己的曲名。
- **改战斗曲**：可以按人物或机体指定战斗时放哪个歌号。
- **战斗语音**：战斗演出里每显示一句战斗台词，就放对应的语音。
- 不改原版逻辑和节奏：
  - 原版的选曲、换曲时机、播放状态都照常运行，只是换掉听到的声音。
  - 战斗台词照原版的时钟翻页，不为等语音而延长。
- **我们不分发任何音频**：程序只提供机制；歌曲和配音由 MOD 作者自己准备，版权由作者负责。官方包和内置 HD 包不带音频。
- 不在本文范围：剧情语音（按台词记录号，键已在 MOD 包 §4 预留）、音效替换、精神指令和 cut-in 的独立语音（§6）。

## 2. 原版事实

### 2.1 放歌

- `8007E810(歌号)`：
  - 歌号等于当前曲 `D_800FFA6C` 时什么也不做，同一首不会重开。
  - 负数 → `80077B38` 停止。
  - 否则 → `80077868` 开始播放，并记入 `D_800FFA6C`。
- `8007E87C(n)` 淡出，内部调 `80077BD8`。`80077AD0()` 查询是否还在播放（敌增援 jingle 放完后，`801E076C` 靠它换回关卡曲）。
- 开始 `80077868` 和停止 `80077B38` 都**只从 `8007E810` 调用**，所以放歌只有这一个入口。`80077AD0` 除了原版音乐模块内部，还被标题、结局和战术地图（`801E076C`，敌增援 jingle）调用；`8007E87C` 有十来处调用者。
- 音乐是序列（类似 MIDI），由序列播放器 `D_800D1344` 合成，和音效在 RSP 里混成一路。宿主在 `srw64_queue_audio`（`src/host/audio.cpp`）拿到的是混好的立体声，44.1 kHz。
- 歌号共 49 首：标题 overlay 的 `D_801CB290`（ROM `0x1147E0`，49 × {文本号, 歌号}）就是音乐鉴赏的曲目表，曲名是文本 232 起。

### 2.2 战斗选曲

- 由地图 overlay 在交战结算之后、进演出之前选好（`801E085C(句柄A, 句柄B, 单方)`），所以**关掉战斗动画也会换曲**。
- 规则：
  1. 任一方是ヴァル＝ア三人 → `0x22`。
  2. 否则只要有一方是我方，就按**我方主驾驶员的人物曲表**（ROM `0x7D6A0`，361 项）；超级模式、明鏡止水、V-MAX 状态改用硬编码的 `0xB`／`0xA`／`0xD`。
  3. 都不是我方 → 按攻方**机体曲表**（ROM `0x7DF30`，363 项）。
- 没有按剧情变量、关卡、Boss 的分支。
- 关卡曲是地图资源记录 `+0xB`，每个阶段开始重放；战斗结束后不换回关卡曲，战斗曲一直放到下一阶段或下一场战斗。

### 2.3 战斗台词

- 战斗 overlay 为每个交战方准备两条台词：攻击时说、挨打／回避时说（`func_80222050`）。台词按**声部**（`D_800CA9C4[人物号]`，257 个）先查条件台词，再从九种情境（攻击、被击坠、重伤……射程外）的通用段里随机抽。
- 每句都有**台词记录号**：通用段 5813–14226，条件台词 14227–17346。多人对话（合体技等）是连续几条，各自有记录号和说话人。
- 宿主的对白层已经在台词开始显示时拿到记录号（`native_dialogue.cpp`，日志里的 `battle_quote` 事件带 `text_id`）。台词照原版时钟自动翻页，不能手动翻。

## 3. 包格式

放在 MOD 包的 `audio/` 下：

```text
audio/
  music/<歌号>.ogg       顶替原版第 N 首（歌号十进制，如 7.ogg = メインテーマ）
  music.json            可选：循环点、音量、曲名、改战斗曲
  voice/battle/<记录号>.ogg   某句战斗台词的语音
  voice.json            可选：语音设置
```

格式用 **Ogg Vorbis**（体积小、无专利；宿主用单头文件解码库，许可证与 GPL 兼容）。采样率任意，宿主重采样到输出采样率。

### 3.1 `music.json`（可选）

只放 OGG 也能用：整首循环、原音量、曲名不变。要细调时才写：

```json
{
  "schema": "srw64.music.v1",
  "tracks": {
    "7": { "loop": [123456, 2345678], "gain": -2.0,
           "title": { "ja": "…", "zh-Hans": "…", "en": "…" } }
  },
  "battle": {
    "pilot": { "36": 7 },
    "unit":  { "50": 12 }
  }
}
```

- `tracks`：按歌号设循环点（采样数，`[起点, 终点]`）、音量修正（dB）、音乐鉴赏里显示的曲名。也接受文件里的 `LOOPSTART`／`LOOPLENGTH` 标签，这是很多游戏音乐包的惯例。
- 新曲就是顶替某个歌号：放进 `music/<歌号>.ogg`、写上曲名，音乐鉴赏里那一行就变成新曲。
- `battle`：改「谁打仗放哪首」，值是歌号。`pilot` 按人物号，`unit` 按机体号。先按原版规则选出歌号，再查这张表覆盖（§4.2），所以ヴァル＝ア三人、超级模式这些原版规则仍然有效，除非作者明确改。

### 3.2 语音

- 文件名就是战斗台词记录号，和台词文本文件的 `@记录号` 一致；台词文件每条上方的 `# 触发：` 注释说明了这句什么时候出现（[台词文本文件](../guide/dialogue-text.md)），方便配音者对照。
- `voice.json`（可选）：整体音量；台词显示时语音的起始延迟；某个人物在战斗中是否闭嘴（只显示文字）。
- 同一记录号多个包都提供时，按 MOD 包 §3 的顺序后面的赢。
- 不分语言：语音一般只有一种（日语），换阅读语言不影响。

### 3.3 工具

- 导出清单（已做）：`tools/content/export_audio_tables.py` 生成 [给作者的格式说明与对应表](../guide/audio-mods/README.md)：49 首的歌号、曲名、用途，人物与机体的战斗曲，全部战斗台词的记录号、说话人、触发条件与三语文本。
- 校验：文件名能不能对上歌号／记录号、循环点是否在文件长度内、`music.json` 字段是否合法。宿主与 Python 共用规则，坏包不启用（MOD 包 §3）。

## 4. 宿主实现

### 4.1 混音器

- 在 `srw64_queue_audio` 里，原版这一段音频送进 SDL 之前，把替换音乐和语音按同样的样本数混进去。
  - 时间轴跟游戏自己的音频走，不跟墙钟，所以不会漂。
  - 2 倍速、卡顿、暂停时，和原版声音的表现一致。
- 解码放在工作线程：音乐流式解码、按循环点循环；语音整段解码后缓存（短）。
- 两个独立音量：音乐、语音，在设置窗口「声音」一栏；另有「使用 MOD 音乐／语音」的总开关。单声道选项照原版设置一起生效。

### 4.2 音乐替换

直接拿 OGG 混：有替换的歌号，原版停掉不放，宿主放 OGG。具体包三个函数：

- **`8007E810(歌号)`**（放歌的唯一入口）：
  - 歌号有替换：先调原函数停掉原版音乐（`8007E810(-1)`），再把 `D_800FFA6C` 写成这个歌号，宿主开始放 OGG。原版「同一首不重开」照常有效。
  - 没有替换：宿主停掉 OGG，调原函数照常放。
- **`8007E87C`（淡出）**：照常调原函数，宿主同时淡出 OGG。
- **`80077AD0`（是否还在放）**：宿主在放 OGG 时，返回 OGG 是否还在放（循环曲永远是「在放」）；否则照原函数。这样敌增援 jingle（`0x26`）按替换文件的长度放完再切回关卡曲。原版音乐模块内部也调它，但那只发生在宿主没在放 OGG 的时候。

改战斗曲：包装 `801E085C`，在它选出歌号之后查 `music.json` 的 `battle` 表，换成表里的歌号再放。

音乐鉴赏、卡拉OK、战斗鉴赏也走 `8007E810`，自动用替换；音乐鉴赏的曲名按 `tracks` 里的 `title` 显示，没写就用原名。

### 4.3 战斗语音

- 在对白层识别到新的战斗台词时（`battle_quote` 事件、第一页），查 `voice/battle/<记录号>`，有就开始放。
- 同一侧下一句台词开始时，停掉上一句的语音；战斗结束、中止演出（手柄 X）时全部停止。
- 原版台词不等语音：语音比台词框显示得久，就会接着放到下一句开始或战斗结束。v1 不为语音延长台词框，因为那样会改动战斗演出的节奏。
- 关掉战斗动画时没有台词，也就没有语音。

### 4.4 调试与测试

- 调试接口状态加：当前歌号、是否被替换、来自哪个包；正在放的语音记录号。
- 单元测试：重采样、循环点、混音不爆音（饱和截断）、包合并顺序。
- 实机（Windows 台式机与 Mac）：
  - 标题音乐鉴赏放一首替换曲。
  - 迷你关打一场：战斗曲替换、按人物覆盖战斗曲、台词语音按记录号播放。
  - 敌增援 jingle 后能切回关卡曲。
  - 2 倍速与中止演出时声音正常。

## 5. 风险与注意

- **同一首不重开**：原版放同一首时直接返回，宿主也照此处理（`D_800FFA6C` 写成替换的歌号），否则两场战斗之间会从头重放。
- **卡拉OK 的歌词同步**：卡拉OK 按原曲的节奏走字幕，替换后对不上。可以在卡拉OK 模式里不用替换，或者随它（待定）。
- **战斗曲在地图上延续**：替换曲在战后会一直放到下一阶段，和原版一致，作者做循环时要考虑。
- **台词随机性**：通用段是随机抽的，配音者要按记录号配全，否则只有部分台词有声音。导出表格时标明每个人物的台词总数。
- **版权**：只提供机制和格式说明，不收录、不链接任何音频资源。

## 8. 实现进度（2026-10-20，`mods` 分支）

按歌号替换音乐与音乐鉴赏显示已经写好；改战斗曲、语音、音量设置还没做。

- **代码**：`src/host/music.{hpp,cpp}`。
  - 替换表：启用的包里 `audio/music/<1–255>.ogg`，按载入顺序上面的包赢；`audio/music.json` 读 `tracks` 的 `loop`（`[起点, 终点]`，或 `false`＝只放一次）、`gain`、`title`，类型不对的字段忽略。包有变化（安装、启停、删除）时重新读。
  - 解码用 RT64 自带的 `stb_vorbis`（公有领域），在 `music.cpp` 里编译一次。和 §4.1 写的流式解码不同，现在是在工作线程**整首解码**，最近两首留在内存里，关卡曲和战斗曲来回切不用重解；解完之前是静音，从解完开始放。`music.json` 没写循环时用文件里的 `LOOPSTART`／`LOOPLENGTH` 标签。
  - 混音：`audio.cpp` 在原版音频送 SDL 之前调 `srw64_audio_mixer`（`srw64-frame-host` 不带 MOD，指针为空），线性插值重采样到输出采样率，按原版设置的单声道位混成单声道，饱和截断。录像音轨在混音之后，所以录像里听得到替换曲。
  - 三个包装（`generate_cpu.py` 的 NATIVE_HOOKS，原函数改名 `srw64_original_play_song`／`_fade_song`／`_song_playing`）照 §4.2。淡出按游戏 60 Hz 帧数换算成输出样本数。敌增援 jingle（`0x26`）默认只放一次，`music.json` 写了循环才循环。
  - 卡拉OK（模式 `0x1A`）保留原曲。
  - 音乐鉴赏：被替换的行右侧标 `MOD`，包写了 `title` 就按当前语言显示包里的曲名（原版曲名照旧保持日语）。
  - 调试接口状态 `music`：是否在放替换曲、歌号、是否解完、位置、循环区间、是否只放一次。日志 `SRW64_MUSIC_REPLACE song=… file=… package=…`、`SRW64_MUSIC_DECODE_FAILED`。
- **测试**：`tests/native_music.cpp`（`make recomp-music-test`）覆盖 `music.json` 解析、多包覆盖与过滤（非歌号文件名、非 OGG、停用的包）、原速与重采样混音、整首循环与循环区间、只放一次、淡出、增益、单声道、截断、解码中静音。
- **实机（2026-10-20，Mac，分支构建）**：拖入含两首正弦测试音的包（歌号 4 为 440 Hz 并带中文曲名，歌号 3 为 660 Hz 并带 `LOOPSTART`／`LOOPLENGTH`），在音乐鉴赏里依次放 4、3、2（未替换）、4，再按 Esc 停止，同时录像，按半秒分析音轨：
  - 曲目表第 3、4 行标 `MOD`，第 4 行显示「测试替换曲」。
  - 放替换曲时音轨几乎只有测试音（测试音以外的成分约 0.5%），原曲没有声音；第 3 首按标签循环（循环区间 44100–132300，位置已经绕回）。

## 9. 网页 BGM 制作工具（规划，2026-10-26）

用户定：官网提供网页工具，玩家自己做 BGM MOD；**音乐包里只放 Ogg Vorbis，转码在浏览器里做**。语音等宿主支持后另做一页（已做，见 §10）。

### 9.1 为什么只用 Vorbis

- **无缝循环**：Vorbis 的每个包带精确采样位置，长度不差一个采样；MP3 有编码器延迟（约一千多个采样）和整帧补齐，裁剪信息（LAME 头）不是标准，循环接缝会有空白或爆音。`LOOPSTART`／`LOOPLENGTH` 惯例也写在 Vorbis 注释里。
- **解码器零成本**：stb_vorbis 来自 RT64 源码附带的 `RT64/src/contrib/stb/`（RT64 本身不管声音），各平台、GL 构建都在；stb 没有 MP3／Opus 解码器，支持它们要另引库。
- 低码率下同体积音质好于 MP3。宿主与校验只认一种格式，包的质量一致。

### 9.2 工具

- 位置：`web/src/pages/[lang]/mods/bgm/`，三语，纯静态；**音频只在浏览器里处理，不上传**。
- 流程：填包信息（id、三语名称、作者、许可证选允许的几种）→ 49 首列表（歌号、日文曲名、用途，数据来自 `tools/content/export_audio_tables.py`）→ 拖入音频替换某首 → 每首设循环点（波形、吸附过零点、「试听接缝」）、音量（测响度给建议）、三语曲名、只放一次（jingle 38 默认）→ 可选按人物／机体改战斗曲（`battle` 表，宿主要先包装 `801E085C`）→ 导出 `.srw64mod`；也能导入已有包继续改。
- 解码：`decodeAudioData`（mp3、wav、flac、m4a、ogg）。AudioContext 固定采样率（如 44.1 kHz），否则界面上的循环点采样数与写出的文件对不上。解码失败直接提示换格式。MP3 按 LAME 头裁掉首尾补白。
- 编码：浏览器自带的 MediaRecorder／WebCodecs 没有 Vorbis，用 npm 包 `wasm-media-encoders`（MIT，内含 libvorbis，只用它的 `wasm/ogg.wasm`，不带 MP3 那份）在 Web Worker 里一首一首编；已经是 Vorbis 的 `.ogg` 原样放进包、不重编。品质默认 `vbrQuality: 6`（约 190 kbps）。实测见 §9.4。
- 校验：与宿主、`tools/mods/validate.py` 同一套规则，跑 `tests/mods/manifests.json` 的用例。
- 版权：页面写明只能用有权使用的音乐；工具只在本地生成文件，官网不托管歌曲。用原作歌曲的包可以自用、私下分享，不进官方索引（MOD 包 §13）。

### 9.3 顺序

1. 先验证 WASM 编码器在 Chrome、Safari、Firefox 上的速度与兼容性（一首 3 分钟歌的耗时、内存）。
2. 宿主侧（与 2 可并行）：mods 并入 main、`battle` 改战斗曲、设置里「使用 MOD 音乐」与音量、淡出／倍速／Windows 补测、安卓从 `mods/` 文件夹安装；合并后下一版显示 MOD 入口。
3. 网页工具本体；用合并后的宿主装它生成的包实机走一遍。
4. 分发按 MOD 包 §13。

### 9.4 编码器实测（2026-10-26，§9.3 第 1 步）

- 包：`wasm-media-encoders` 0.7.0（MIT）。`ogg.wasm` 440 KiB（gzip 约 158 KiB），JS 约 3 KiB；ES 模块无依赖，用 `createEncoder('audio/ogg', wasm 地址)` 载入单独的 wasm 文件。品质参数即 libvorbis 的 -1～10。
- 测试曲：合成的 3 分钟 44.1 kHz 立体声（和弦、贝斯、鼓、底噪），WAV 31 MB，另用 LAME `-q 2` 转一份 MP3（4.1 MB）。流程：`AudioContext({sampleRate: 44100})` 的 `decodeAudioData` → 复制出各声道 → Web Worker 里每次 4096 帧编码。
- 浏览器：只测了应用内置浏览器（Chromium 152，Mac）。Safari、Firefox 未测。

| 输入 | 品质 | 解码 | 编码 | 实时倍数 | 输出 |
| --- | --- | --- | --- | --- | --- |
| WAV | 6 | 49–58 ms | 1.09 s | 约 165× | 4.2 MB（192 kbps） |
| MP3 | 6 | 约 0.3 s | 1.08 s | 约 166× | 4.1 MB（186 kbps） |
| WAV | 3 | 约 0.2 s | 1.6 s | 约 113× | 2.4 MB（109 kbps） |

- **结果可用**：三个输出都用宿主同一份 stb_vorbis 解码（`check_ogg.c`）：长度 7 938 000 帧，与原曲**一帧不差**，最佳对齐偏移 0，信噪比 24–32 dB（有损编码的正常范围）。MP3 那一路也是 0 偏移、长度一致：Chromium 解码 MP3 时已按 LAME 头裁掉首尾补白，循环点可以照原曲采样数设。
- **内存**：内置浏览器没有 `measureUserAgentSpecificMemory`，改从系统采样渲染进程：三首连续处理时峰值比空闲多约 250 MB。一首的大头是解码后的浮点 PCM（3 分钟立体声约 64 MB）及其副本：读入的文件、AudioBuffer、复制出的声道、发给 Worker 时再复制一份。实做时声道用转移（transfer）而不是复制发给 Worker、读完文件就释放，峰值可降到一首约 130 MB 以内；49 首照样一首一首处理。
- 结论：编码速度不是问题（49 首全换约一分钟以内，主要花在解码与读文件上）。用户 2026-10-26 定：不专门测 Safari 与 Firefox；页面在解码失败时提示换格式即可。

## 11. 语音与台词的同步、加速、关动画（研究，2026-11-02）

用户 11-02：「研究战斗语音和战斗台词的同步，加速机制下如何处理，战斗动画关闭的语音处理」。本节是静态分析加日志统计，没有新代码；结论先行，再列事实。

### 11.1 结论

1. **同步没有结构性问题**。语音在台词框打开的那一帧触发，经游戏自己的音频时间轴混出，和原版音效走同一条路，延迟在一次音频块以内（设备队列上限 100 ms，`srw64_audio_queue_limit`）。台词框只停 32 逻辑帧（约 1.07 秒），语音中位 1.9 秒，所以**语音正常地比框长**，接着盖在攻击演出上放完——后来的 SRW 也是这样，不需要为语音延长框。要修的只有两处小毛病：打断没有淡出（会爆音）；`delay` 从解码前就开始计（解码慢的机器上等于没延迟）。
2. **加速**：游戏逻辑按帧加速、音频线程和混音器仍是实时，所以语音本来永远按原速放，演出和台词在它上面跑快。2 倍速时相邻两句台词的间隔典型 2.2–3.7 秒，3、4 倍速只剩 1–2 秒，多数语音说不完就被下一句切掉。**用户 11-02 定：语音要跟着动画走——变速不变调**，3、4 倍速时语音 2 倍，2 倍速时取能让九成台词在下一句前说完的最低倍速，按 §11.3 的分布算出来是 1.75 倍（1.5 倍只有 84%）。做成设置项「加速时的语音：跟随倍速（默认）／原速／不放」，实现见 §11.8。不让台词等语音（违背加速的目的）。
3. **关动画**：用户 11-02 澄清，这一项问的是**动画中途退出**（手柄 X 中止），不是关闭战斗动画。中止时原来要等 200 ms 没有步进才硬切，改成中止那一帧就随画面 300 ms 淡出（§11.8）。关闭战斗动画的情况仍是事实陈述：原版关动画时演出 overlay 不加载，台词根本没被选出来，所以没有台词也就没有语音；若将来要做，方案见 §11.6，未开工。

### 11.2 原版事实：台词框的计时

- 台词框由演出状态 2/7/13/18（`801C840C`）打开：`801C6F14` → `8008FFAC(槽, 记录号)` → `8008F648` → `8008CD8C` → `8008C9C0`。模式写 2（文字头 `+0x20E`）。
- 停留时间来自**文字记录头**：每条记录头 8 位 ASCII 数字，前 3 位是说话人（`8008CE54`），末 4 位按 `1000·d4 + 10·d5 + 10·d6 + d7` 换成逻辑帧写进 `+0x210`（首页）和 `+0x212`（后续页，`8008CBB0`／`8008CBBC`）。全部 11,534 句战斗台词里 **11,066 句是 `0032`（32 帧），468 句合体技首句是 `0024`（24 帧）**；剧情对白是 `0004`，但剧情用 A 等待模式，这个数不起作用。
- 每逻辑帧 `8008D748` 把 `+0x210` 减 1（模式 2/3 直接进 `L_8008D934`，不等逐字——原版整段一次画出）。减到负数：还有片段（`+0x214`）就翻到下一片段并把 `+0x212` 装回计时器；没有就 `8008D718` 关框。
- `801C840C` 每帧问 `80088ED8`（文字引擎状态 ≥4＝关完）才把演出状态 +1。所以一句台词占 **32 逻辑帧 ≈ 1.07 秒（1 倍速）**，多人对话（合体技 40000/40001 链）逐句各占一次。
- 日志核对（11-01 Mac 1 倍速、`build/recomp/debug/20261101T150513.271622Z`，25 句）：同一场战斗里相邻两句开框的间隔 83–942 VI，典型 270–450 VI（4.5–7.5 秒）；最短 83 VI（1.4 秒）是攻击台词之后对手紧接着的受击反应——32 帧框加状态切换，和静态值相符。

### 11.4 现在的同步机制逐项核对

| 环节 | 现状 | 评价 |
| --- | --- | --- |
| 触发 | 对白层在游戏线程识别到 `loads[slot]` 变化（新一句、不是翻页）即调 `battle_quote_opened`，混音器下一块就开始放 | 对；多页台词只在首页放也对（后页是同一句） |
| 延迟 | 从触发到出声 ≤ 一个音频块＋设备队列（上限 `rate/10`＝100 ms） | 和原版音效同路，不必再对齐 |
| `delay` | 从开框起算，解码期间也在计 | 解码慢时延迟被吃掉；应从解码完成起算，或两者取大 |
| 打断 | 下一句开始时 `stop_speech_locked()` 直接丢弃 | 会爆音；加 10–20 ms 线性淡出 |
| 结束 | 200 ms 没有 `801C9710` 步进（`wide_map::battle_shown()`，steady_clock）就停 | 覆盖战斗结束与手柄 X 中止；4 倍速步进 8 ms 一拍、慢设备隔帧不画时逻辑仍每帧跑，都不受影响 |
| 回地图 | 被击坠台词之后还有状态 22 爆炸、21 收尾、淡出，几秒钟 | 够放完；中止时切得干脆，合理 |
| 旗舰被击坠 5799–5812 | 主程序 `800A2890` 显示，不经演出 overlay | 走不走同一条对白识别路径未验证（§8 也记着） |

### 11.5 加速下的数字

逻辑每秒 30×倍速帧，VI、音频线程、混音器不变（game-speed.md）。换算：

| 倍速 | 台词框 | 相邻两句典型间隔 | 最短间隔 | 语音被下一句切掉的比例（按 §11.3 光盘包估） |
| --- | ---: | ---: | ---: | --- |
| 1x | 1.07 s | 4.5–7.5 s | 1.4 s | 很少（只有紧接的受击反应） |
| 2x | 0.53 s | 2.2–3.7 s | 0.7 s | 约四分之一到三分之一 |
| 3x | 0.36 s | 1.5–2.5 s | 0.5 s | 一半以上 |
| 4x | 0.27 s | 1.1–1.9 s | 0.35 s | 大多数，且前后句几乎连着 |

可选做法与取舍：

| 做法 | 评价 |
| --- | --- |
| A 现状：实时放、允许打断 | 2x 可接受；3x/4x 听感是一串被掐断的半句 |
| B 3x 及以上不放（推荐默认） | 简单；玩家开 3x/4x 时本来就在跳演出。实现：`battle_quote()` 看 `game_speed::running && level≥3` 就不开新句；切到高倍速时正在放的那句放完或淡出 |
| C 变速不变调（WSOLA） | 2 倍可懂、3–4 倍不行；要自写一段时间拉伸，收益小 |
| D 台词状态等语音放完 | 改演出节奏、与加速目的相反，不做 |
| E 不打断、多路叠放 | 两句同时说，不做 |

建议做成设置项「加速时的战斗语音：到 2 倍速（默认）／一直放／不放」。原速与 2 倍速之间切换时正在放的语音不用处理。

### 11.8 实现（2026-11-02，main）

用户：「以上都做」「3、4 倍速语音 2 倍速，2 倍速语音也 1.5？或者你找一个最低倍速适合 2 倍速的」「总之就是要让语音和动画同步」。

- **变速不变调**：`music.hpp` 的 `stretch(pcm, factor)`，WSOLA——25 ms 汉宁窗颗粒、半重叠叠加，每个颗粒在名义位置 ±8 ms 内找与上一颗粒自然延续相关最大的位置（相关用双声道之和、每 4 个采样取 1 个算）。整句解码后在解码线程里一次拉伸，不在混音器里做；1.01 倍以下或不足 4 个颗粒长的原样返回。
- **倍速映射** `music::voice_speed()`：只在 `game_speed::running`（这一帧在加速）时生效，档位 2 → 1.75、3 与 4 → 2.0；在句子开始那一帧定下，中途换速不变。1.75 的依据：2 倍速下典型最短间隔 2.25 秒，光盘包 7,291 句里 1.5 倍能放完 84%、1.6 倍 88%、1.75 倍 92%、2 倍 96%；3 倍速（1.5 秒）2 倍只有 78%、4 倍速（1.1 秒）60%，再快语音就听不清，照用户定的 2 倍。
- **设置** `mod_voice_speed`：`follow`（默认）／`original`（照录音播放，实时，允许打断）／`mute`（加速那一帧不开新句）。设置「通用」页 MOD 语音音量下面一行「加速时的语音」，三语词条＋zh-Hant 重生成，`UI_KEYS` 已加。
- **淡出**：下一句开始、战斗结束（200 ms 无步进）时上一句不再硬切，转成 `tail` 用 20 ms 线性淡出后丢弃；混音器多混一路 tail。
- **中止演出**：`battle_animation_probe.hpp` 在把状态写成 21 的那一帧调 `srw64_game_hooks.battle_aborted`（新钩子指针，host.cpp 接到 `music::battle_aborted`），语音 300 ms 淡出，和画面淡出同步。
- **`delay`**：`mix()` 改为解码完成后才开始计延迟（原来解码期间也在计）。
- **调试状态** `music.voice` 加 `speed`，`music.voice_fading` 是尾音剩余样本数；日志 `SRW64_VOICE … speed=1.75`。
- **测试** `make recomp-music-test`：220 Hz 正弦 2 秒拉 1.75／2 倍，长度误差 <2%、过零数算出的频率误差 <3%、响度误差 <15%；1 倍与过短原样返回；延迟顺序改为「解码→延迟→正文」。
- 玩家文档 `docs/guide/audio-mods/README.md` §3 同步改写。
- **实机（2026-11-01，Mac，`tools/recomp/debug/check_voice_speed.py`，battle-ui 迷你关＋光盘语音包，设置 2 倍速）**：敌方攻击 ショウ 的一场里 12334（0.76 秒）与 12313（1.08 秒）都记 `speed=1.75`，调试状态里语音持续 0.43 与 0.59 秒（期望 0.43、0.62），加速标志全程为真；第二场在演出状态 9、台词 9247 刚解码时按 X，语音 2 毫秒内离开 `music.voice`，`voice_fading` 从约 9600 样本逐块减到 0（约 0.3 秒，混音器比扬声器提前一个队列），演出按 0→…→9→21 收尾。没验：3、4 倍速（代码路径只差常数）、`original`／`mute` 两档、听感。
