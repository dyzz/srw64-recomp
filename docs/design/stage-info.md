# 本关情报页

2026-10-13。在游戏里直接看当前关（场间时是下一关）的隐藏要素和「敌人、零件与撤退」，并显示隐藏要素完成到哪一步。完整攻略仍是离线的 [`guide/srw64-flow-guide.html`](../../guide/README.md)，这一页只取其中一关。

## 1. 用户定的范围

- 内容只有两块：**隐藏要素**（带完成状态）和**敌人表**（强化零件与撤退合成一张表）。胜败条件不放，原版的作战目标窗口已经有。
- 不做剧透开关：这一页只在玩家主动打开时出现，地图上不弹提示。
- 按主角和路线筛选：别的主角、别的路线才有的条目和零件不显示，标题注明「另 N 项属其他主角」。
- 效果图（HTML 示意，未进仓库）按 Deck 界面特大 865×540dp 排版：左栏隐藏要素，右栏敌人表；L1/R1 换栏，↑↓ 滚动。

## 2. 入口与按键

| 平台 | 打开／关闭 | 说明 |
| --- | --- | --- |
| Deck／手柄（含安卓接手柄） | Y | Y 现在只在战前确认页切换战斗动画（`Action::Animation`）；战术地图与场间空着。新增动作「本关情报」，默认也绑 Y，按场景分派；改键时两者要允许共用同一个键 |
| Windows／Linux／Mac 键盘 | I | 键盘默认是 PCSX2 布局，I 就是手柄 Y 的位置；Mac 菜单栏另加一项 |
| 安卓触屏 | 顶边小键「情报」 | 放在「设置」旁，只在战术地图和场间显示（做法同对白里的「跳过」）；`touch_pad::by_scene` 为假时也照此显示 |
| 所有平台 | 设置面板里一个入口 | 兜底 |

关闭：同一个键、B／返回键。游戏不暂停（与设置面板一致）。

## 3. 数据

单一来源是攻略数据 `guide/data/<语言>/progression.json`，游戏用的文件由脚本导出：

```bash
python3 tools/content/export_stage_info.py            # 写 content/stage-info/<语言>.json
python3 tools/content/export_stage_info.py --check    # 与攻略数据不一致时失败（tests/test_stage_info.py 也查）
```

2026-10-13 对攻略数据的改动：

- 每张卡片加 `scene`（场景号 = 关卡标题号 − 281，按日文关名对上）。124 个场景有卡片；场景 123（从此并肩）、124（了断之时）各有 OZ 与独立军两张，按路线挑。
- 撤退补全：用 [`tools/content/scan_retreats.py`](../../tools/content/scan_retreats.py) 扫出全部敌方／第三方的退场指令（`3D46`），带触发条件、外层条件块和主角段，逐条与现有零件备注核对。21 条零件备注补上缺的撤退条件（例：京二撤退后关卡结束、卡多随第三方撤退、蕾森第 4 回合撤退）；不掉零件但会撤退的有名敌人放进卡片新增的 `retreats` 列表（25 组），离线攻略显示为「其他会撤退的敌人」。
- 开场／结束事件里的演出退场、说服、被击坠者本人、我方单位、通关时的收尾清场不算撤退。触发链太绕、对玩家没有操作意义的（S86、S105 阿克西斯裂开后的清场等）没有收。

导出时：

- 去掉攻略徽标 `{≠}` `{+}` `{?}`；
- 备注开头的「仅 X 篇」「仅 OZ 路线」拆成 `protagonists`／`routes`，任意位置的「第三方」拆成 `third_party`，隐藏要素文字开头的「X 篇：」「真实系：」拆成 `protagonists`。限定词按中文判断，译文必须是表里的固定说法，否则导出失败（防止改写后出现两遍）；
- 零件行与撤退行合成 `enemies`：`part` 为空的是只撤退的行，`retreat` 表示备注里有撤退或离场。

## 4. 完成状态

规则手写在 `guide/data/status-rules.json`（与语言无关，选项名带三语），导出时连同关卡流向图写进 `content/stage-info/status.json`。参考求值器是 [`tools/content/stage_status.py`](../../tools/content/stage_status.py)，游戏里的 C++ 照它实现；`tests/test_stage_info.py` 用几种存档状态核对结论（卡茨、卡拉利亚、利修的分路线步骤、路线选择、计数）。

**读的东西**：脚本变量（`8015E818`，0–54 跨关，见 [hidden-elements.md](../gameplay/hidden-elements.md) 第 5 节）、我方驾驶员名册（`80172F40`，100 槽 × 0x4C，`+2` 角色号）与机体池（`8016A210`，140 槽 × 0x54，`+2` 机体号）、驾驶员击坠数（记录 `+0x14`）、主角、当前场景（场间是下一关）。

**判断条件**：`var`（等于／属于）、`pilot`、`unit`（在名册／机体池里，可给多个号）、`kills`（击坠数达到）、`protagonist`、`scene`（当前场景）、`reach`（从当前场景还走得到）、`all`／`any`／`not`。

**四类规则**：

| 类别 | 内容 | 显示 |
| --- | --- | --- |
| acquire（36 个） | `done` 加有序的 `steps`，每步有条件和能做这一步的关卡 `at`；分路线不同的写成几条 `paths`，各带 `applies`。步骤可带计数 `counter`（某驾驶员击坠数／目标） | 已完成；第 N 步（共 M 步）；未开始；已错过；不适用 |
| choice（12 个） | `options` 各带条件与三语名称，`at` 是做选择的关卡；`otherwise` 是关卡已过、一个都没对上时的结果 | 已选「…」；未判定 |
| count（2 个） | 数几项成立（EW 版五台、保住的三台） | N／M |
| info（7 个） | 武器解锁、出击限制、只换台词等 | 不显示状态 |

**错过的判定**：下一步的 `at` 里没有一关从当前场景还走得到，就是已错过。变量值 3 既是「未开始」也是「已失败」，靠这一条区分。走得到与否沿关卡流向图：每位主角按自己能执行的剧情段（共通、本人、本系）取脚本里的 `3D4B` 边；两条专属支线（S123、S124）打完回原路线，`edge_guards` 按变量 10 只留回独立军（S42）或 OZ（S57）的那条边。其他分歧都在选择发生的那一关之后才分开，取并集就不会串线。

**进度**：一个要素在几条路线上的步骤不同时，取 `applies` 成立的路线里进度最多的一条；路线未定（破晓作战之前）时几条都算。`applies` 只排除已经确定不可能的情况（例如完全和平路线上的卡茨），所以分歧之前不会误报「不适用」。
