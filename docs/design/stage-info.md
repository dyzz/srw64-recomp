# 本关情报页

2026-10-13。在游戏里直接看当前关（场间时是下一关）的隐藏要素和「敌人、零件与撤退」，并显示隐藏要素完成到哪一步。完整攻略仍是离线的 [`guide/srw64-flow-guide.html`](../../guide/README.md)，这一页只取其中一关。

## 1. 用户定的范围

- 内容只有两块：**隐藏要素**（带完成状态）和**敌人表**（强化零件与撤退合成一张表）。胜败条件不放，原版的作战目标窗口已经有。
- 不做剧透开关：这一页只在玩家主动打开时出现，地图上不弹提示。
- 按主角和路线筛选：别的主角、别的路线才有的条目和零件不显示，标题注明「另 N 项属其他主角」。
- 效果图（HTML 示意，未进仓库）按 Deck 界面特大 865×540dp 排版：左栏隐藏要素，右栏敌人表；L1/R1 换栏，↑↓ 滚动。

## 2. 入口与按键

| 平台 | 打开／关闭 | 说明 |
| --- | --- | --- |
| Deck／手柄（含安卓接手柄） | Y | 不另设动作：用战斗动画那个动作（`Action::Animation`，默认 Y）。新旧两种战前确认页上它仍是战斗动画，其他画面（战术地图、场间各页）打开或关闭本页；改键表里这一行改名为「战斗动画开关／本关情报」 |
| Windows／Linux／Mac 键盘 | I | 键盘默认是 PCSX2 布局，I 就是手柄 Y 的位置，同上 |
| 安卓触屏 | 顶边小键「情报」 | 新槽位 `Slot::Info`，在左上 2× 键右边；固定全套按钮的画面都有，标题画面没有 |
| 所有平台 | 设置面板「通用」页「本关情报」一行 | 兜底 |

关闭：同一个键、B／Esc 或「关闭」。游戏不暂停（与设置面板一致）。姓名页、Link Battler 页上不响应。从触屏键在战前确认页上打开时，Y／I 也能关闭本页（这时原版战前画面不会顺带切换动画）。

**键盘在我们的页面上**：场间、改造、存档等原生页面占用键盘时，宿主不读键盘状态（`graphics.cpp` 的 `editing_name`），按键只以事件交给页面，所以 I 在这些页面上由 `frontend.cpp` 的按键事件处理：绑定为「战斗动画／本关情报」的键在这些页面上打开或关闭本页，战前确认页上仍交给页面当动画键（K）。手柄的 Y 不受影响，走宿主按键位。

**实现**：页面是设置面板框架里的一个子模式（`frontend.cpp` 的 `stage_open`，与图鉴同样做法），游戏输入照样被设置面板挡住。界面线程不读游戏内存：打开时 `stage_info::want(true)`，游戏线程在 `get_input` 里每 10 帧采样一次（`src/host/stage_info.cpp`），算出全部规则的状态，作为快照交给界面线程；快照变化才重建页面，两栏的滚动位置保留。每次打开都重新读：`want(true)` 给这次打开编号，快照带上编号，界面只显示这次打开之后读到的快照，所以不会先闪一下上次的内容（可能是别的关）。战术地图、战斗、世界地图和场间（模式 2/3/0xB/12/13/0x11/0x16/0x1A/0x1C/0x22，场间是 4，从标题读档进来的场间停在读档模式 0x12–0x15）读 `8010F5F0` 的场景号；其他画面显示「在战术地图或场间打开」。主角未定（从标题直接进迷你关）时只显示本关文字，不显示状态，也不按主角筛选。

**断行**：RmlUi 只在 ASCII 空格处断行，中日文长段落会溢出。页面先排版一次，再用元素自己的字体量宽（`Rml::GetFontEngineInterface()->GetStringWidth`），按列宽自己断行插 `<br/>`（`src/native/ui/text_wrap.hpp`：中日文逐字可断、西文按词，句读和右括号不放行首，左括号不留行尾）。

**数据位置**：每关一份元数据（§3）。本篇在发布包的 `stages/` 目录（Windows、Linux 在程序旁边，Mac 在 `Contents/Resources`，安卓随资源解包），启动器经 `SRW64_STAGE_META` 告诉宿主；开发运行（`run_host_probe.py`）直接指向仓库的 `content/stages`。自定义战役的关卡把元数据带在战役包里，战役运行时只用战役的，没有元数据的关显示「找不到这一关的情报数据」。

## 3. 数据

单一来源是攻略数据 `guide/data/<语言>/progression.json`，游戏用的文件由脚本导出：

```bash
python3 tools/content/export_stage_info.py            # 写 content/stages/scene-NNN.json 与 status.json
python3 tools/content/export_stage_info.py --check    # 与攻略数据不一致时失败（tests/test_stage_info.py 也查）
```

2026-10-13 对攻略数据的改动：

- 每张卡片加 `scene`（场景号 = 关卡标题号 − 281，按日文关名对上）。124 个场景有卡片；场景 123（从此并肩）、124（了断之时）各有 OZ 与独立军两张，按路线挑。
- 撤退补全：用 [`tools/content/scan_retreats.py`](../../tools/content/scan_retreats.py) 扫出全部敌方／第三方的退场指令（`3D46`），带触发条件、外层条件块和主角段，逐条与现有零件备注核对。21 条零件备注补上缺的撤退条件（例：京二撤退后关卡结束、卡多随第三方撤退、蕾森第 4 回合撤退）；不掉零件但会撤退的有名敌人放进卡片新增的 `retreats` 列表（25 组），离线攻略显示为「其他会撤退的敌人」。
- 开场／结束事件里的演出退场、说服、被击坠者本人、我方单位、通关时的收尾清场不算撤退。触发链太绕、对玩家没有操作意义的（S86、S105 阿克西斯裂开后的清场等）没有收。

2026-10-13 用户看了实机页面嫌字太多：每关的隐藏要素说明另写一句话精简版（攻略数据的 `short`，219 条），过长的零件／撤退备注也写了精简版（`short_note`，49 条），中日英三语。精简版写进攻略数据本身，游戏和网页攻略共用一份；页面显示精简版，限定词仍按全文判断。

导出时：

- 去掉攻略徽标 `{≠}` `{+}` `{?}`；
- 备注开头的「仅 X 篇」「仅 OZ 路线」拆成 `protagonists`／`routes`，任意位置的「第三方」拆成 `third_party`，隐藏要素文字开头的「X 篇：」「真实系：」拆成 `protagonists`。限定词按中文判断，译文必须是表里的固定说法，否则导出失败（防止改写后出现两遍）；
- 零件行与撤退行合成 `enemies`：`part` 为空的是只撤退的行，`retreat` 表示备注里有撤退或离场。

**关卡元数据格式**（`srw64.stage-meta.v1`，本篇和自定义战役同一格式）：一关一个文件，三语文字都写成 `{语言: 文字}`（也可以只写一个字符串），缺的语言依次退到日文、英文、任意一种。

```json
{
  "schema": "srw64.stage-meta.v1",
  "scene": 41,
  "title": {"zh-Hans": "混沌的地球圈", "ja": "混沌の地球圏", "en": "Earth Sphere in Chaos"},
  "cards": [{
    "route": "ia",                       // common／ia／oz／cp：一关几张卡片时按当前路线挑
    "lane": {"zh-Hans": "独立军路线"},    // 卡片角上的路线名
    "secrets": [{"ref": "secret-katz",   // 对应 status.json 的规则 id，没有规则就不显示状态
                 "title": {…}, "text": {…}, "protagonists": ["brad"]}],
    "enemies": [{"part": {…} 或 null, "from": {…}, "note": {…},
                 "protagonists": […], "routes": […], "third_party": true, "retreat": true}]
  }]
}
```

`protagonists`／`routes` 省略表示都有。本篇文件另带 `guide_card`、`episode`、`title_ja`，只供核对，页面不读。完成状态的规则与流向图是另一个文件 `status.json`（`srw64.stage-status.v1`，§4）。

自定义战役：`campaign.json` 的关卡项加 `"meta": "stages/<关>.meta.json"`，战役本身加 `"status": "status.json"`；`mini_stage.py compile` 把两者编进战役镜像（元数据核对格式、补上 `scene`）。战役的 `status.json` 可以不写 `graph`，编译时按各关结束事件里的 `3D4B` 自动画出（四位主角同一张）。元数据没写 `title` 时用 `campaign.json` 里这一关的标题。示例见 `config/recomp/campaigns/sample`（第 2 关「岔路」的结局分支）。

## 4. 完成状态

规则手写在 `guide/data/status-rules.json`（与语言无关，选项名带三语），导出时连同关卡流向图写进 `content/stages/status.json`。参考求值器是 [`tools/content/stage_status.py`](../../tools/content/stage_status.py)，游戏里的 C++ 照它实现；`tests/test_stage_info.py` 用几种存档状态核对结论（卡茨、卡拉利亚、利修的分路线步骤、路线选择、计数）。

**读的东西**：脚本变量（`8015E818`，0–54 跨关，见 [hidden-elements.md](../gameplay/hidden-elements.md) 第 5 节）、我方驾驶员名册（`80172F40`，100 槽 × 0x4C，`+2` 角色号）与机体池（`8016A210`，140 槽 × 0x54，`+2` 机体号）、驾驶员击坠数（记录 `+0x14`）、主角、当前场景（场间是下一关）。

**判断条件**：`var`（等于／属于）、`pilot`、`unit`（在名册／机体池里，可给多个号）、`kills`（击坠数达到）、`protagonist`、`scene`（当前场景）、`reach`（从当前场景还走得到）、`all`／`any`／`not`。

**四类规则**：

| 类别 | 内容 | 显示 |
| --- | --- | --- |
| acquire（36 个） | `done` 加有序的 `steps`，每步有条件和能做这一步的关卡 `at`；分路线不同的写成几条 `paths`，各带 `applies`。步骤可带计数 `counter`（某驾驶员击坠数／目标） | 已完成；第 N 步（共 M 步）；未开始；已错过；不适用 |
| choice（12 个） | `options` 各带条件与三语名称，`at` 是做选择的关卡；`otherwise` 是关卡已过、一个都没对上时的结果 | 已选「…」；未判定 |
| count（2 个） | 数几项成立（EW 版五台、保住的三台） | N／M |
| info（7 个） | 武器解锁、出击限制、只换台词等 | 不显示状态 |

**错过的判定**：下一步的 `at` 里没有一关从当前场景还走得到，就是已错过。变量值 3 既是「未开始」也是「已失败」，靠这一条区分。走得到与否沿关卡流向图：每位主角按自己能执行的剧情段（共通、本人、本系）取脚本里的 `3D4B` 边；两条专属支线（S123、S124）打完回原路线，`edge_guards` 按变量 10 只留回独立军（S42）或 OZ（S57）的那条边。其他分歧都在选择发生的那一关之后才分开，取并集就不会串线。

**进度**：一个要素在几条路线上的步骤不同时，取 `applies` 成立的路线里进度最多的一条；路线未定（破晓作战之前）时几条都算。`applies` 只排除已经确定不可能的情况（例如完全和平路线上的卡茨），所以分歧之前不会误报「不适用」。
