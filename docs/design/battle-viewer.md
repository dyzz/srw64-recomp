# 战斗鉴赏（Battle Viewer）设计调研

2026-10-03。纯静态分析（反汇编 `build/recomp/cpu-scan/*/rom_*.text.s`、ROM 数据），**没有跑游戏、没有构建**。目标：标题画面在「Library」「MOD」旁加一个「战斗鉴赏」入口（参考 SRW Z スペシャルディスク 的 Battle Viewer），玩家选攻方机体＋驾驶员、武器、守方机体＋驾驶员、是否反击及反击武器、守方的防御反应（命中／回避／分身／切り払い／S防御／护罩）、伤害量、是否击坠、两侧战斗背景、BGM，然后用原版演出 overlay `load_00121560` 播放，结束后回到鉴赏页。同时当作我们自己的演出测试工具。

凡写「推断」的都没有实机核对；行号指 `build/recomp/cpu-scan/` 下的反汇编文本（`resident/rom_80076610.text.s` 简称 resident，`load_00121560/rom_801C2600.text.s` 简称 battle，`load_000AB160/rom_801C2600.text.s` 简称 map，`load_0010DA50/rom_801C4500.text.s` 简称 title）。

相关文档：[战斗演出渲染机制](battle-animation-rendering.md)、[战斗演出中途退出](../native/battle-animation-skip.md)、[战斗计算](../gameplay/battle-formulas.md)、[Library](../native/library.md)、[标题菜单](../native/native-title-menus.md)。

## 0. 结论先行

**原版自己就有「不进关卡、直接播一场演出」的路径**：标题待机的演示战斗（游戏模式 `0x1C`）和カラオケモード 的背景战斗（模式 `0x1A`）。两者都只装演出 overlay，由常驻函数 **`8009C2DC`** 按 ROM 里 32 字节一条的演示记录（ROM `0x83110` 起）直接填两侧参战记录 `D_800F97E0 + side×0x1074`，不需要地图 overlay、名册、关卡、存档。播完由演出主循环自己切回标题 overlay。

所以战斗鉴赏不必做隐藏迷你关卡，也不必伪造地图结算：**沿用模式 `0x1C` 的入口与返回，宿主在 `8009C2DC` 上挂钩，按鉴赏页的选择改写参战记录**。命中／回避／分身／切り払い／S防御／护罩、伤害量、击坠全部由参战记录里的几个字段决定，演出 overlay 自己不掷任何决定结果的骰子（结算在地图 overlay 里，这条路径根本不跑）。

### 2.1 武器演出号

- `800AB470(机体号, 武器号)`（resident:61973）：查常驻表 `D_800CB7BC`（ROM `0x561AC`，89 条 {武器, 机体, 演出号}，{0,0,0} 结尾），命中则用表里的演出号，否则**演出号 = 武器号**。例：(34, 7) → 38、(130, 308) → 1191。鉴赏页列武器时必须过这张表，否则同名武器在特定机体上会放错动画。
- `801C3C9C(id, kind)`（battle:1674）：kind 0 → `id == 0x1000` 用内存记录 `D_80250010`，`id ∈ {−2, −3}` 用空记录 `D_80222D40`，其余 `801C3128(id)`（weapon 库，ROM `0x11FC80` 偏移表＋`0x184990`）；kind 1 → reaction 库 `801C3230`；kind 3 → hit 库 `801C31E8`。`801C3D38` 在 id == −1 时直接不载入。
- 武器名文本 `1370 + 武器号`，机体名 `527 + 机体号`，人物名 `4382 + 人物号`（`src/host/battle_page.cpp:194-196`）。

### 2.3 击坠

状态 9/20 `801C7960`（battle:6180）在扣血队列放完后调 `801C5AF4(守方, 0xA)`（battle:3974）：守方 `+0x22 == 0` 时，攻方武器演出号 == `0x4A6` → 状态 21（不爆炸），否则 → **状态 22 击坠**；守方还活着时 `+0x18 != 0` → 状态 21，否则进反击轮（状态 10）。状态 22 `801C818C` 按机体战斗记录列 6 == 2 选 hit 156，否则尺寸 `+0xD == 2` 选 157，否则 158。

所以「击坠」= 攻方 `+0x1A ≥ 守方 +0x22` 且反应码属于扣血的那几种。`801C5AF4` 里「0x14 且 0x15」的分支条件恒假，是死代码。

### 2.4 背景

`80084A78(a, b, side)`（resident:16807）：背景记录号 = `D_800C5940[a] × 101 + b`（ROM `0x5BC30`，0x26 字节一条），a = 参战记录 `+0xB`、b = `+0xA`。状态 0 `801C6FE8` 用**攻方**那份；开火状态 5/16 `801C76A0` 经 `801C2AD0(side)`（battle:343）换成**另一方**那份。也就是说 **SRW64 本来就是每侧一份背景**，攻击飞到对面时切换，与 Z 鉴赏页每侧一行地形对得上。

**演示记录**：ROM `0x83110` 起先是 42 个 u32 偏移（前 19 个 = カラオケ 19 首歌各 6 条，后 23 个 = 标题演示各 1 条），每条 32 字节 = 两侧各 8 个 s16：

```
[机体号, 人物号, 被击坠标志, 武器演出号, 反应码, 背景 a(+0xB), 背景 b(+0xA), +0xC]
```

例：标题演示 #29 `(196,145,0,778,−1,0,100,1) / (300,150,1,1165,−1,0,100,1)` 守方被击坠；#24 守方反应码 18（切り払い）；#26 守方 13（护罩被击穿）。被击坠标志的写法见 §2 +0x1A。

`8009C2DC(arg)`（resident:43956）的全部动作：分配临时缓冲 `80089970`，DMA 演示记录；对每侧 `8009C218`（resident:43902）写默认值（+0x18=0、+0x1A=`rand(3000)+10`、+0x20/+0x22=5000、+0x1070=−1、+0x1064/+0x106C=`&D_8016A210` 等）、DMA ROM 机体记录（`0x71B80 + 机体×0x24`），按 §2 表写字段；再按被击坠标志定 +0x1A；最后写攻守下标。**它不读名册、不读存档、不需要地图**。

**返回**（battle `801C98CC..801C99D8`）：

- 模式 0x1C：`D_80161566++`、`D_801614EA++`；若 `D_801614EA == 5` 且 `D_80161310 == 1` → 清零、`8007E87C(0xB4)`、**模式 7（重新开机画面）**；否则 `D_80161310 != 0` → 清零、`8007E87C(0xB4)`、模式 0x1E；`== 0` → `D_801614EA = 0`、`8007E87C(0xB4)`、**模式 0x1D**。

## 5. 推荐方案

**沿用标题演示（模式 0x1C）的整条路径，只把 `8009C2DC` 的数据换成鉴赏页的选择。**

1. **鉴赏页**：RmlUi 面板，入口与 Library 同一处（`home_sync` 角落加一个按钮、设置「通用」页加一行）。数据全从 ROM 读，复用 `library.cpp`。
2. **开始**：在标题仍在运行的某一帧（帧边界钩子，与迷你关卡同一位置）：
   - 可选 BGM：`8007E810(歌号)`（§6.6）
   - `D_80161310 = 0`、`D_801614EA = 0`、`D_801CC3A3 = 0`
   - `80080188(0x1C)`、`80099814(5,1,2)`，让标题 overlay 的 `801CA9CC` 照原版收尾并交给分发器（与 `801CA230..801CA250` 同一做法）；
   - 宿主置「鉴赏中」标志，鉴赏面板关闭、输入交还。
3. **填参战记录**：给 `resident_func_8009C2DC` 加宿主包装（`NATIVE_HOOKS` 加项、改后手动 `make recomp-cpu`）。鉴赏中时：先调原函数（`D_8018B87C` 置 0，保证它走一遍 `8009C218` 默认值、写攻守下标与占位指针），再按选择覆盖：
   - 两侧 `+2 = D_800CA9C4[人物]`、`+4 = 机体`、`+0xD` 按 ROM 机体记录 +4 换算尺寸（同原函数 `8009C490..8009C4E4`）
   - `+0x20/+0x22`、`+0x24/+0x26`：ROM 机体 HP/EN，或鉴赏页自定 HP
   - 攻方 `+6 = 800AB470 规则下的演出号`；守方 `+6` = 反击武器演出号（不反击时随便放一个合法值）
   - 守方 `+8` = §2.2 的反应码；攻方 `+8` = 反击轮里原攻方的反应码（不反击时 −1）
   - 守方 `+0x18`：反击 0；不反击时 1（HUD 显示「防御」）或 2（「回避」）
   - 攻方 `+0x1A` = 伤害；要击坠就 ≥ 守方 `+0x22`，不击坠就 < 它；守方 `+0x1A` = 反击伤害，同理决定原攻方是否被击坠
   - 两侧 `+0xB/+0xA/+0xC` = 背景（§6.5）
   - 演示调用 `8009C2DC(1)` 前已重播种，若要每次台词一样，可在包装末尾用固定种子再调一次 `800821B0`。
4. **回来**：`D_80161310 == 0`，演完走模式 0x1D → `801CAB50(2)` 回标题；宿主看到「鉴赏中」标志且标题主状态回到 2/3 时清标志、重新打开鉴赏面板（保留上次选择）。
5. **中止**：模式 0x1C 下任何键（`D_80178A08 != 0`）都会淡出，正好当「按任意键返回」。现有 X 中止（`battle_animation_probe.hpp`，置状态 21）也能用；它的地图侧回放（状态 24 子状态 4）不会触发，因为地图 overlay 不在。若要允许按 A 推进台词而不退出，需要在 `801C9710` 包装里对 0x1C+鉴赏中屏蔽那一处判断（例如只在调用 `801C9778` 那段前暂时清 `D_80178A08`），待实机确认 A 推进台词读的是哪个字。

**为什么不用别的办法**：

- 隐藏迷你关卡：要装地图、单位、剧本，还会跑地图结算与 `801FCA78` 写名册，结果还要靠覆写结算来强制；且进出各要十几秒。
- 直接切模式 2：能用，但 `801C9BD4` 在模式 2 不填参战记录（要宿主在切换前写好），收尾按 `D_8015DD60` 选 0xB/0x10（回地图），必须另挂钩改返回模式；Z+START 中止会走 `800A5138` → 模式 7/0x11。0x1C 的返回路径现成。
- カラオケ 模式 0x1A：没有 HP 窗与 HUD，还会画歌词、播卡拉OK，不适合。

**不会碰存档与名册**：这条路径不调 `800A5138`、不跑地图、不调任何 SRAM 写入例程；演出只写参战记录区与自己的 BSS。宿主改写的只有 `800F97E0..800FA868`。

#### 规则（确认）

1. A 或 B 的主驾驶员人物号是 **33–35（0x21–0x23：ヴァル＝ア、アヴィ＝ルー、ジェイ＝レン）** → 歌 `0x22`「狂った飢餓戦士」，不看其他条件。

#### 武器 ROM `+8`（必要技能）= 2 的含义（确认）

- 复制：`800A6A68` 把武器 ROM 记录 `+8` 写进武器实例 **`+0xF`**（实例步长 0x24；ROM `+0xF` 标志字节另进实例 `+0x22`，二者别混）。
- 判定：**`801E6214(阵营, 主驾驶员, 武器实例, 机体实例, 跳过消耗检查)`** 返回 0 可用、1 必要技能不满足、2 气力不足（`+0xE` > 驾驶员 `+0x20`）、3 EN 不足（`+0xD` > 机体 `+8`）、4 弹数为 0（`+0xC ≠ −1` 且 `+0xB == 0`）；必要技能先判。调用者 `801E6410`（状态页武器列表 `801E6650`、详情 `801E6B0C`）、`801F8B38`／`801F8DB0`（`801F8BA0`／`801F8EB8`）、`80200530`（`802008E0`）、`80201D98`（`80201E68`），全都传机体 `+0x38` 即**主驾驶员**。
- `+0xF` 按跳转表 `jtbl_8021EBF0`（17 项，下标 值−1）：

| 值 | 条件（不满足即返回 1） | 显示文本（0xFBA + 值） | ROM 中用到的武器 |
| --- | --- | --- | --- |
| 0 | 无 | — | 绝大多数 |
| 1 | 阵营 = 0（只有我方能用） | 不显示（详情只在 ≥2 时显示） | 79 曼陀羅円陣・極楽往生 |
| **2** | **主驾驶员 `+0x1C` 位 30（`0x40000000`）已置** | 「明鏡」 | **15–19** |
| 3 | 同 2 | 「HP」 | 无 |
| 4 | 同 2 | 「Sモード」 | 30、53、62、71、76（シャイニングS 与 シャッフル同盟 四机 S 形态的必杀） |
| 5–11 | 驾驶员等级 `+5` ≥ 10／15／20／25／30／35／45 | 「LV10」…「LV45」 | 150–159、1177–1183、1219 等 |
| 12／13 | 技能 `+0x36 & 0x18`（NT 或 強化人間）且等级 `+6` ≥ 1／4 | 「NT1」「NT4」 | ファンネル 类／ファンネルMAP 类 |

- **所以 `+8 = 2` 只要求主驾驶员的状态位 30**，代码与 `4`（Sモード）、`16`（V-MAX）完全相同，「明鏡」只是显示文字。**不读**剧情变量 45、不读 `800A4BB8`，也不另看气力或技能。`800A4BB8` 全 ROM 只有三个调用者 `load_0008F4B0:801CA27C`、`801E59D0`、`801E5BE8`，都只是在 ドモン 技能栏追加「明鏡止水」文本；`801FF1BC`／`801FEDF4` 里也没有变量读取。
- 位 30 的来源：`801FF1BC`（由 `801D61C8`、`801D92E4` 调用）对我方 ドモン（以及 アルゴ、サイ・サイシー、ジョルジュ、チボデー；東方不敗 任何阵营）气力 ≥ 130 → `801FEDF4`：在形态表 `D_80218A34`（ROM `0x101594`，行 0 = {1, 2}）找到当前机体，就把机体号改成强化形态并置位 30。对ゴッドガンダム，这一步就是 1 → 2（H）。位 30 只在击坠处理 `801FF4E0` 清掉，不随气力回落。
- 另外武器 15–19 在机体武器表（`0x7E210`）里的形态槽只有机体 2，机体 1 的列表本来就不出这 5 件；位 30 是第二道门。实际效果：**ドモン 驾驶、气力 ≥ 130 自动变 H 后才能用**，与「明鏡止水」剧情变量 45 无关（45 只决定技能栏文字与 シャッフル同盟 必杀台词，见 [hidden-elements.md](../gameplay/hidden-elements.md) §5.1）。之后的气力门槛照常：15 无、16／17 ≥ 110、18 ≥ 130、19 ≥ 150（ROM `+7`）。
- 对鉴赏页：演出路径不调 `801E6214`，参战记录可以直接填 15–19，不必管位 30（推断：演出 overlay 不读这个字段）。

## 7. 风险与限制

- **援护（0x14）与假身（0x15）**：`801C3E7C`、`80222B14`、`801E40B0` 会经 `+0x106C`（及其 `+0x38` 驾驶员指针）读真正的机体实例；演示里这两个指针指向占位 `D_8016A210`，内容不保证有效。要做就得宿主在空闲内存里造一个机体实例（+4/+6 HP、+8/+A EN、+0x38 指向造好的驾驶员实例，驾驶员 +2 = 人物号）。第一版不提供。
- **`8022245C` 的条件台词**：0x1388–0x2710 那段（关卡专用、恋人等）只在前一模式 `D_8015DD60 == 3`（地图）时才判，并会解引 `+0x1064 → +0x38`；鉴赏走标题模式，这段被跳过，只放通用台词——安全，但与正篇里的台词不完全一样。
- **盾与切り払い 的道具图**：reaction 记录 17/18/19 的演员登记号是 17（推断按本机图集取盾／剑零件）。给没有盾／剑的机体选这两项可能画出空的或错的零件。鉴赏页应只在机体有对应装备位时提供（ROM 机体记录 +0x18 装备位，Library 已解析「盾」）。
- **按键**：模式 0x1C 任何键都中止；Deck 上碰一下摇杆也算不算，取决于 `D_80178A08` 的来源，待实机看。
- **RNG**：鉴赏不影响任何存档内容；台词选择会随帧计数变，必要时固定种子（§5 第 3 步）。
- **与 X 中止钩子共存**：`battle_animation_probe.hpp` 挂在 `801C9710`，鉴赏不需要它的地图侧逻辑；确认它在没有地图 overlay 时不读 `D_80172EB0` 之类的地图变量出错。
- **HD 替换**：演出画面与正篇同一套绘制，机体立绘、cut-in、地面贴图的 HD 替换自然生效。
- **宽屏**：`battle_hud.cpp` 贴边逻辑按演出 overlay 生效，不依赖地图，推断无需改。

### 9.1 原型实测（2026-10-03）

### 9.3 选择页（2026-10-03）

画布的 UnitPicker / PilotPicker / BgmPicker 三张图做成了游戏内的选择页，另按同一版式加了场景选择页；武器仍是原来的列表。

鉴赏页只用 RmlUi（`src/native/ui/frontend.cpp`，项目唯一的 UI 工具包；不做 AppKit 等系统界面）。版式参考 Z 的左右两栏，风格沿用战前确认页的定稿：斜边（`slant` 装饰器）、顶部页签、大机体图、大字号；以 Steam Deck「特大」界面为基准排版（同 Library），离线审计 `run_audit.py` 要覆盖新页面。新词条进 `content/locales/*.json` 并登记 `src/srw64_native/profile.py` 的 `UI_KEYS`。调试接口沿用 `ui.click --id …`。
