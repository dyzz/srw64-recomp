## 1. 改造：左右加减段数，最后确认一次

2026-10-08 已实现，做法与操作见[改造画面接管](../native/native-upgrade-screens.md)的「现代操作」一节，检查脚本 `tools/recomp/debug/check_upgrade_plan.py` 实机 13 项通过。实际做法和最初设想的差别：

- 武器列表里 ←→ 仍是翻页，段数改在武器改造确认画面里用 ←→ 增减。
- 五项画面可以几行同时有计划，A 打开确认窗、はい 一次付清；B 先清计划，再按一次才返回。
- 满改追加武器、EW 换装、資金不足时都在那一段停下，后面的段不付。

## 2. 60 帧

研究结论和试验步骤都在 [60 帧研究](60fps.md)。要点：逻辑固定每秒 30 帧，不能改；能做的是让 RT64 在两帧之间插帧显示。3D 绘制大多可以直接插帧；战术地图全是矩形绘制，需要给 RT64 打补丁，这是工作量最大的一块。2026-10-01 用户决定暂不开工，重新开始时从该文档第 7 节的试验做起。

## 3. 启动直接进全屏

玩家反馈（2026-10-08）：每次启动都回到窗口。现在桌面版一律以 1280×800 窗口启动（`src/host/graphics.cpp` 里只有 Steam Deck 带 `SDL_WINDOW_FULLSCREEN_DESKTOP`），设置页的「窗口／全屏」和 F11 只当场切换，不存。

决定：默认保持窗口，不记住上次的状态；加一个设置项，打开后启动直接全屏。

## 4. 战斗 HUD 适配宽屏

玩家反馈（2026-10-08）：开「填满屏幕」时，战斗演出和 HUD 仍是 4:3。实际情况是战斗画面已经扩到 16:9，战斗 HUD 还是原版 4:3 布局，没调。宽屏的整体做法见 [Steam Deck 16:10](deck-16x10.md)。

## 5. 滤镜参数调节

玩家反馈（2026-10-08）：想改 crt-lottes 的弯曲度。现在只能选预设，不能调 RetroArch 的 shader parameters（[框体与滤镜](../native/bezels-and-filters.md)「没做」里也列着）。玩家要的是 `warpX`（默认 0.031）和 `warpY`（默认 0.041），范围都是 0–0.125，0 是不弯。

做法待定。起点：librashader 能读到每个预设的参数表（名字、默认值、范围、步长），设置页给每个参数做滑条，改过的值按预设存下来。

在这之前可以给玩家的临时办法，**还没实机验证**：把包里 `filters/crt` 复制到数据文件夹的 `filters/`，在副本 `crt-lottes.slangp` 里加

```
parameters = "warpX;warpY"
warpX = "0.031"
warpY = "0.041"
```

再在滤镜列表里选这份副本。发给玩家前要先确认 librashader 会读这些值，以及同名的副本在列表里怎么区分。

## 6. 战斗鉴赏的场景缩略图换成 HD 画面

鉴赏里实际播放的战斗已经自动用 HD 背景（天空、地面贴图、机体），但选场景时的 21 张缩略图还是 2026-09-30 从原版画面渲染的 480×270 截图（`tools/hd_ai/cutin_hd.py scenes`，取自 `assets/hd-ai/battle-backgrounds/catalog/thumbs`，进 HD 包的 `battle_sprites` 清单 `scenes` 一节），HD 1.1 不会让它们变清晰。

已完成（2026-10-09，用户改为随 HD 1.1 一起发）：`tools/hd_ai/viewer_scenes.py` 在游戏里实拍，藏掉战斗窗口与机体（开发开关 `SRW64_DEV_HIDE_BATTLE_HUD`／`_SPRITES`），960×540，`cutin_hd.py scenes --shots … --into assets/hd-ai/cutins/pack-v2 --bind`。实拍时发现宽屏下静态天空（kind 10/11）的 HD 整图在本体与左右副本交界露缝，静态天空也改为一次铺满整屏（不放大）。原定做法：Mac 上用调试接口逐个强制 21 个场景（`VIEWER_SCENES` 的块与地形，写 `800F97EA/B`），静止镜头下截 HD 画面，裁成同尺寸替换 `scene-<key>.jpg`，重跑 `cutin_hd.py scenes --bind`。

## 7. 开场等飞入文字的残影太糊

用户反馈（2026-10-15）：开场版权页等文字飞入时很糊。在 Seeker 上逐帧截图看，每一层字本身是清楚的，糊来自原版的帧回授残影（`80083744`，见[原生标题与剧情图片](../native/native-title-and-story-images.md)）：每帧把上一帧画面以 primitive alpha 贴回屏幕，几层字错开叠在一起。章节标题卡、序章、结局页走同一套残影。

- 强度：`800836CC(1–3)` 把 `D_8016A208` 设为 200（约 78%）；状态 2、3 每帧减 4 或 8 淡出，减到 0 时关掉（`D_8010F5B6` 清零）。
- 已排除：把这类文字的栅格密度从每 N64 像素 8 texel 提到 16、采样时偏向更清晰的 mip，飞入时看不出差别，已撤回。
- 用户选的方向是减弱残影：包装 `800836CC`（`generate_cpu.py` 的 `NATIVE_HOOKS`），原函数写完 200 后改成更低的值，影响所有用残影的画面。另一条路是让宿主画的文字不进回授（画在残影之后），只影响我们画的字，要改 RT64 的绘制顺序。
- 试验：调试接口在 `D_8016A208` 刚被设成 200 时改成 110，整段开场只改到一次，两次运行的截图帧也没对齐，还不能下结论。重做时用钩子或每帧写入，截飞入过程中的同一批 VI 对比。
