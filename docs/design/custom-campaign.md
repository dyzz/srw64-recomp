# 自定义战役：多关串联、新台词与整张绘制的新地图

2026-10-01。用户定的目标：mod 能把多关自定义关卡连成一个战役；新地图按「整张自由绘制」做：HD 模式下宿主整张绘制作者的大图，原版模式显示塞进原版格式的近似版。本文是**静态分析**（读生成代码与 ROM、Python 原型），没有开宿主跑过；地址以 main 94f110b 的生成代码为准。标 [实机] 的条目有既往运行记录，其余都待实机核对。上级规划见 [mod 路线图](mod-roadmap.md) 与[扩展架构](native-extensibility-architecture.md) §6。

## 1. 已有基础

- **单关**：[迷你关卡](../script/mini-stage.md)用 JSON 写地图、事件、部署和初始资源，编译后在内存里替换一个场景，完整流程（开场、出击、回合事件、胜利、结束、结算存档）[实机]跑通。剧本 1812 个事件全部解到结束符，73 条普通指令都对上代码（[剧本探索](../script/stage-script-exploration.md)）。
- **虚拟文本记录**：宿主已经在给游戏供应 ROM 里没有的文本记录。改造画面的槽位文字就是这样做的：`host.cpp` 包装了记录查找 `8008C510` 和 ROM 读取 `8007F704`，`upgrade_rules.hpp:415-451` 把描述符指到假 ROM 区（`0x03000000 + id×0x40`）再供字节。新台词沿用这个做法（§5）。
- **整张绘制的地图**：HD 战术地图已经是宿主按布局号整张绘制（`native_map.cpp`，131 张）。
- **多存档栏与自动存档**：`saves/` 库与自动存档旁的 `.json` 已有（[多存档栏](save-slots-autosave.md)）。

## 2. 原版关与关之间怎么走

| 步 | 代码 | 做什么 |
| --- | --- | --- |
| 过关 | `3D4A` → `8020DB08` | 清阶段与回合（F5E8/F5EA），累计总回合（F5EC），话数 `8010F5EF` 加一，当前场景 F5F0 抄到 F5F1（已过关场景），转模式 0x24；然后在世界地图上跑结束事件（类型 14） |
| 指定下一关 | `3D4B n` → `800A0260` | `F5F0 = F5F2 = n`；n＝500 时把 F5F2 抄回 F5F0。所以 F5F2 总是上一次明确指定的目标 |
| 场间 | 结束事件后 `8009EDB8` 置模式 4 → `801D8F74(0)` | 过关后先问存档（[实机] 截图「第1話…クリア」），「次のマップへ」经 `801D8D20` → 模式 0xC → `801C2B9C(0)` |
| 载入下一关 | `801C2B9C(0)` → `8009DD58(F5F0, 0)` → `8009DE7C` | F5F1 = F5F0；**F5EF 为 0 时改由路线变量 `801602EE` 推出场景号**；按场景 DMA 部署与事件 |
| 世界地图剧情 | 关卡自己的开场事件（类型 12） | 开场在世界地图上跑（`3D32`/`3D33`、`3D3A` 放曲），`3D4D` 切到战术地图；没有单独的「世界地图场景表」 |

按场景号查的表：地图 `802195B0[场景×2]`（`80209D6C` 写进 F5EE）、标题卡 `802195B1[场景×2]`（`801C72C8`）、标题文本 281+F5F1（场间 `801CE0F8`、存档列表 `801C6944`/`801C754C`）、只剩「存档／下一关」两项的场间菜单（F5F1 在 `D_801DC6D4` 里：13 个「（前）」场景加 132）、リンク 关卡 109–122（`D_801DCABC`）、宇宙场景表 `D_801DCAD8`。

关卡开始时 `8009DE7C` 把变量 100–114、128–139 重置为 3、变量 54 置 1；开场结束时 `80093278(0)` 在内存里拍一张快照（`800FBEF0`），游戏结束后重试就从这里恢复。

## 3. 战役包

```text
mods/<战役>/
  mod.json              名字、作者、版本
  campaign.json         关卡表、开局、标题、所借场景号
  stages/<关>.json      迷你关卡格式（srw64.mini-stage.v1）
  text/<语言>.txt       新台词，台词文本格式，记录号用 mod 段（§5）
  maps/<图>/            新地图：整张底图、地形格、可选水面色号图（§6）
```

`campaign.json` 示意：

```json
{
  "schema": "srw64.campaign.v1",
  "start": "prologue",
  "stages": {
    "prologue": {"scene": 1, "file": "stages/prologue.json", "title": "序章　新しい風"},
    "ch2":      {"scene": 2, "file": "stages/ch2.json",      "title": "第2話"}
  }
}
```

关与关的连接写在各关自己的结束事件里（`3D4B <下一关借的场景号>`），分支用条件块和剧情变量，和原版一样；`campaign.json` 只登记「哪个场景号对应哪一关」。

## 4. 宿主要做的

### 4.1 借场景号

- **每关借一个不同的原版场景号（0–142）**。原版先按场景号 DMA 事件与部署，宿主在 `8009DE7C` 换掉，所以借的号必须真实存在；各关借不同的号，存档里的场景字节就能唯一指回哪一关。
- **避开**：「（前）」场景与 132（场间菜单会少项）、リンク 关卡 109–122（リンク 页会乱）。
- **宿主改动**：`mini_stage.hpp` 现在只有一个 `Image`，锁定第一个登记的场景，其他场景记「skipped」，而且只能在标题菜单装载。改成「场景号 → Image」表，`register_hook` 与 `map_hook` 按 `8010F5F0` 取。表随战役固定：コンティニュー、游戏结束重试、地图中途返回都会重新登记（`8009DD58(场景, 1/2)`，调用点 `800803D4`/`8008046C`/`80080594`），这时也要换对。
- **リンク 菜单**会改写 F5F0/F5F2，战役中要禁用或拦住。

### 4.2 开局与结局

- **开局**：直接进入（`800A5138` 后写 F5F0 与 F5EF＝1）[实机]。`800A5138` 经 `800814F0` 清 F5EF–F5F2、经 `800A4F94` 清名册，所以开局是空名册、无姓名、无路线变量。**F5EF 必须非 0**，否则下一关由路线变量推出（直接进入后未设时得到场景 253）。
- **初始部队**：开场事件里用 `3D5A 驾驶员,0,机体,500` 登记（机体 999＝只登记驾驶员）[实机]、`3D5B` 加资金、`3E13` 设变量；玩家方部署记录本身也会永久入队（リンク 关卡就是这样加人）[实机]。坑：`3D5A … 4000` 对还在地图上的单位会留下悬空名册，之后 SIGBUS，要先 `3D46` [实机]；`3D49` 在角色不在地图上时崩溃 [实机]。`SRW64_STATE_FIXTURE` 只对齐随机数，不能给战役播种。调试菜单「SAMPLE DATA」的建档代码（`load_000856D0:801C39C4…`）可作参考。
- **结局**：`3D71` 必须在世界地图 overlay 上跑（在战术地图上会让宿主中止）[实机]。结局 overlay 置通关位（`8015DDA8` 位 3）、写存档头、回标题。战役最后一关的结束事件里放 `3D71`。
- **游戏结束**：`3D4C` → GAME OVER → 恢复开场后快照、重新登记场景，等于重打本关；开场中途 `3D4C` 时还没有快照，会登记场景 0 [实机]。

### 4.3 剧情变量

200 个两位变量在 `8015E818`，存档 +0x2 起 26 个半字。0–54 是原版持续读取的，关卡开始会重置 100–114 与 128–139。战役自己的旗标要用原版剧本不读写的变量，具体空闲区间待统计（扫一遍全部事件里的 `3E13` 与条件）。

### 4.4 存档

- 原版存档记录（0x1F00，`800924D8` 写）：+0x2 变量，+0x48 进度块（+0x4E 地图、+0x4F 话数、+0x50 下一关 F5F0、+0x51 标题场景 F5F1、+0x52 F5F2、+0x53 基准等级、+0x54 资金），+0x110 机体、+0x9D0 驾驶员、+0xE80 部件。中断存档 0x3AE0 另含地图状态。
- **战役存档的识别**：存档本身只有借来的场景号。宿主在旁边写一个附加文件（战役 id、版本、场景表），读档时据此装回战役；附加文件缺失或战役没装时**拒绝读档并说明**，不能悄悄按原版场景载入。
- 落点：`saves/` 库里自动存档已有 `.json`（`save_store.cpp` 的 `sidecar()`）；手动扩展栏和卡带 1/2 栏还没有，原版界面写卡带栏时没有文件路径，按记录 SHA-256 作键。建议每个战役一个独立的存档库，与本篇分开。

### 4.5 标题与界面文字

标题卡（`sprite_text.cpp:365-391`）、场间章节行（`intermission_page.cpp:30`）、存档列表（`save_page.cpp`）都经宿主词条表取字，不读 ROM，所以能按战役覆盖：宿主加一张「借的场景号 → 战役标题」表。原版界面模式下标题卡的图另算（标题卡表 `802195B1`）。

## 5. 新台词

- **记录号段**：剧本里的文本号是 u16，表 0 共 50,975 条（最大 `0xC71E`），号码越界时游戏不检查，会把正文当描述符读出乱长度。**mod 用 `0xC800`–`0xFFFF`**，由宿主在查找处先接住。跳过路径直接调 `8008CE54`（`game_hooks.cpp:433`），也要接。
- **宿主要伪造的**（沿用改造画面的虚拟 ROM 区，换一段地址，并允许只读前 4 字节的部分读取）：
  - 8 字节 ASCII 头：说话人三位（000–360，即人物号）、模式一位、等待四位；
  - 正文占位：恰好「页数−1」个 `0xFFFD`，以 `0xFFFF` 结尾，不超过 255 个字（原版拷贝没有边界检查）；
  - 词条表里**每种语言都有**这条，包括 `ja`，`<STOP>` 数与页数一致（宿主按 `ja` 的 STOP 数驱动翻页）。
- **加载层**：`dialogue_text::compile` 拒绝 ROM 里没有的记录，mod 台词要走单独一层（`Catalog::with_translations`）。
- **说话人与头像**：头像由说话人号经 ROM `0x84220 + 人物×4` 取；可以任意借用现有人物的头像和名字。新名字：宿主把名牌记录号（`0x111E + 说话人`）换成虚拟号。新头像：游戏画的仍是借来的那张，HD 层（`native_portrait.cpp`，按像素与调色板哈希识别）要改为按 mod 说话人或台词号覆盖；原版图像模式下会露出借来的脸。
- **选择肢**：`3D44 槽, 项数, 文本号`，最多 3 项，结果写 `+0x994` 供 `3E10`–`3E12` 判断。显示时 `ui_text.cpp:307` 只在 `ja` 词条等于游戏解出的字形时才换译文，mod 号要么让占位字形对上，要么改成信任 mod 号。
- **战斗台词**（后做）：按 `D_800CA9C4[人物]` 取语音槽，表在 ROM `0x1161C0` 与 `0x121150`。给新人物配台词要么接管 `800A3DD0` 返回虚拟行，要么接管挑选函数 `80222B14`/`80222050`；`5813 + 偏移` 能否到达 `0xC800` 以上未确认。

## 6. 新地图

### 6.1 原版格式（已核对）

- **地图记录**：158 条 × 12 字节，表在 `0x80219B1C`（ROM `0x10267C`）：`u16 布局, 图集, 调色板, aux1, aux2; u8 模式; u8 BGM`。由 `801C6EFC` 读 `8010F5EE`（地图号）后装载：`80098158(0x3B, 0, 8, 0x93, 布局, 图集, 调色板, 0)`，aux 进调色板循环通道，模式 1 另装殖民地帧。`3D34` 换图（`8020A874`）走同一套。
- **布局**：8 字节头 `(7, 组数, 宽, 高)`（8 像素单位），然后每 16×16 格 4 字节：`u16 (翻转 0xE000 | 地形号)`、`u16 图块号`，然后是绘制组。154 份布局、285,974 格全部核对：格里的图块号、翻转位与绘制组一致。图集 CI8 512×512，最多 1024 个 16×16 图块（图块坐标 12 位）。
- **地形**：取地形 `801E213C(x格, y格, 0x3B, 0)` 只读格记录的 +1（低 8 位），没有越界检查。属性表 `0x802196D0`（ROM `0x102230`），100 条 × 11 字节：

| 字节 | 含义 | 读者 |
| --- | --- | --- |
| +0 | 地形名（表 0 文本号 0–59） | 地形窗 `801CABAC` |
| +1 | 防御：伤害 ×(100 − 值)/100 | `801F424C` 选 0（飞行中恒 100） |
| +2 | 命中修正，有符号（多为负） | `801F424C` 选 1 |
| +3 / +4 | 回合开始 HP / EN 回复 % | `801FA3DC` → `801FA260` |
| +5..+10 | 六种移动方式的移动消耗，0xFF 不可进入 | `801C3E50` 用 `801EEA14(单位)` 选列；0＝地面、1＝空中、3＝水中、5＝宇宙（推断），2 与 4 未定 |

  地形 63 是墙（全 0xFF，名「壁」），99 是外圈边框，100 是战斗背景用的「天空」伪地形。水地形号表 `0x802180D4`：31–36、87–89、91。
- **按地图号的表**（各 158 项）：宇宙标志 `0x802180E0`（1＝宇宙移动规则；非 0 时战斗地形适应按宇宙算；2 只改战斗环境字节，像「宇宙中的地面型地图」，地图 37、39、49、50、60、64、72）；网格线颜色 `0x80218510`（0 黑、1 灰、0xFF 无，设置位 `8015DDA8 & 2` 打开网格时用）。
- **战斗背景由调色板号决定**：`801F68E8` 把格子地形（飞行时 100）和环境字节写进战斗上下文，环境字节取自按调色板资源号查的表（`0x80218A57 + 调色板号`，覆盖 6237–6263）。新地图要借一个现有调色板号来选背景。

### 6.2 尺寸

地图尺寸完全由布局头决定（`801C6394` 写 `80172EC4/EC8`），找不到按格开的定长数组：移动范围是以单位为中心的 31×31 局部格（`801C3E50`，射程上限 15 格），占位按单位像素坐标扫描。约束只有三条：外圈 2 格边框不可进入（可玩范围 x、y ∈ [32, W−48]）；总览缩放 `800943E0` 在宽约 4256、高约 3200 像素以上会除零陷阱；图集上限 1024 图块。原版最大 960×720。

### 6.3 装进游戏

- **资源读取只有一个入口**：`80089E9C(资源号) → 句柄`。号码 ≥ `0x1924` 直接拒绝；同号已在内存就只加引用计数；否则 `80089BBC` 读 ROM `0xA20BD4 + 号×8` 的描述符与解压后大小，`800897AC` 从 ROM LZ 解压进堆（区域 6，`0x80277800`，约 1.6 MB）。这两个内部函数只被 `80089E9C` 调用。
- **做法**：借一张原版地图的地图号，战役关卡里宿主把它的布局、图集、调色板换成 mod 的字节：接管 `80089BBC` 报 mod 的大小、`800897AC` 改为拷贝（按刚写进句柄表 +2 的资源号判断是哪一个）。同一号码驻留期间替换要保持一致。新资源号不能用（≥ `0x1924` 被拒），所以只能借号；借哪个号由战役包决定，调色板号同时决定战斗背景（§6.1）。BGM、宇宙标志、网格颜色这几张按地图号的表也按借来的地图号改写。
- **HD 冲突**：HD 地图按布局号认（`native_map.cpp` 的 `find_asset`），借来的布局号会被画上原版那张图的 HD 底图。宿主要在战役关卡里改按 mod 地图取图。

### 6.4 整张绘制与原版降级版

- **HD**：作者画一张原版尺寸 4 倍的大图（与现有 HD 地图相同），宿主整张绘制。水面要动的话，再给一张色号图标出水面区域（现有 HD 地图就是底图加色号图）。
- **原版降级版**：工具把大图缩到原版尺寸，切 16×16 格，用 k-means 聚到不超过 1024 个图块（允许水平、垂直翻转复用），再量化到 256 色，生成布局、图集和调色板。原型（2026-10-01，scratchpad 里的 Python 脚本，未进仓库）拿地图 56 的 HD 底图试：864×800、2700 格挤进 1024 块，相对目标图 PSNR 35.8 dB（只做 256 色量化是 42.4 dB）。地貌、海岸线、森林、山都保住了，草地纹理被平均得偏糊。小于 1024 格的地图（例如地图 20，896 格）不用聚类。
- **水面循环**：原版的水面靠调色板循环（色号 0xC0–0xD0），降级版要把水面区域的颜色映射进这一段，并在 aux 里挂水面循环资源。
- **地形**：作者在编辑器里给每格刷地形号（0–98，外圈自动填 99）。属性表只有 100 条，暂不支持新地形种类。

## 8. C1 实现（2026-10-01，worktree custom-campaign）

用户定：测试战役只用现有资源（原版地图、台词、人物、部署），新地图、剧情对话背景、新人物与新机体以后再研究。

| 部分 | 做法 |
