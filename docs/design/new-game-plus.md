# 周目继承：隐藏要素

2026-10-16，未实现。原版没有周目继承。我们只加一项：**上周目完成过的隐藏要素，下一周目在原入队关之后补登记**，并跨周目记录完成了多少。事实来自静态分析，未实机。

## 1. 范围

- 补登记照抄原版入队指令，**不改脚本变量**。
- 这一周目到不了原入队关的要素不给。
- 击坠数、资金、改造都不继承（第 6 节）。

## 2. 原版事实

- **只有通关标记**：结局 `801C26A4` 置 `D_8015DDA8` bit3 并写回 SRAM 头，唯一用途是解锁音乐鉴赏里的「緑の大地の上で」（`801C82BC`）。卡带上的「见过」位图也只用于解锁曲目。
- **新游戏从零开始**：主角选择调 `800A4790`，200 个脚本变量全写成 3；名册清空。没有任何地方读上周目的数据。Akurasu 也没有二周目的记载。
- **名册**（`80172F40`，100 条 × 0x4C）：登记 `800A84F8` 先按人物号找已有记录，找到就沿用，找不到才新建。所以对已在队的人重复登记无害。

## 3. 历代记录

- 文件 `saves/legacy/legacy.json`：要素 id → 完成时满足条件的人物号／机体号（マシュマー／キャラ二选一、ヒルデ有两条记录，补登记时给对应的那个）。只增不减，与存档栏无关，开关关着也照样记。
- 时机：打开本关情报页时、进场间时，用现有求值器（`src/host/stage_info.cpp`），把判成「已完成」的获得类要素并入。
- 只管本篇剧情，自定义战役不读也不写。

**本关情报页**：
- 每个获得类要素旁边加「历代已完成」标记，标题处加「历代达成 N/33」。
- 规则判成未完成、但这个要素在历代记录里、而且记下的人或机体本周目在队里时，显示「已完成（继承）」。ガトー的完成条件是 `var37 == 0`，补登记不改变量，所以需要这条，否则会显示「已错过」。

## 4. 补登记

### 4.1 规则

开关开着时，在场间菜单每一步检查（`801CE19C` 包装里作弊改等级的同一位置，等淡入结束）。四条都满足就登记，并在场间顶上提示「继承：XX 加入」：

1. 要素在历代记录里；
2. 当前场景（场间时是下一关）是原入队关 X 的**直接后继**，也就是刚打完 X；
3. 补登记项的 `applies` 成立（主角、路线）；
4. 这个人或这台机体不在队里（看名册和机体池）。

由此得到：
- 没打 X 不给；
- 剧情之后删掉这个人，也不会再加回来；
- 在那次场间存档再读档，不会重复登记；
- 不另存周目状态、不占脚本变量，读的是当时的历代记录。

### 4.2 登记方式与数据

照抄原入队事件的 `3D5A 人物, 偏移, 机体, 500`（调 `800AAD28`，等级照原版按基准加偏移算；只给机体时人物号写 999），以及随后的 `3D6C 机体, 段数`（调 `800ACA1C`）。对白、变量、换乘等其他指令一概不执行。

每项写进 `guide/data/inherit-grants.json`（与语言无关，导出到 `content/stages/` 旁边）：

```json
{"id": "secret-quess",
 "grants": [{"after": [105], "applies": {}, "variant": {"pilot": 284},
             "commands": [["3D5A", 284, 0, 0, 500], ["3D6C", 0, 6]]}]}
```

参数在实现时从原事件抄，这里只是示意。不同路线入队关不同就写几条，各带 `applies`。

### 4.3 33 项

- **人物（带机体）**：カーツ、アイシャ、エルリッヒ、リーズ、アイナ、アレンビー、ガラリア、エマ、エリカ、ナイーダ、キリカ、アポリー＆ロベルト、ゲイル、フォウ、銀鈴、ロザミア、ヒルデ、ガトー、ゼクス＋エピオン、トッド＆シルキー、ロゼ、プル、プルツー、マシュマー／キャラ、キラル、クェス。
- **只有机体**：Mk-III＆メタス改、ミネルバX、量産型グレート、ファの百式、ノイエ・ジール、量産型ν、トールギスIII。
- **不做**：牛剣鬼（效果是敌方增援，不是入队）、シュバルツ（没有效果）、キュベレイMk-II 改色（属于选项）。

カーツ和エルリッヒ的入队关是支线 S124／S123，条件不满足就进不去，按第 2 条不会补。以后想改，可以把 `after` 换成分歧点。

## 5. 不改变量的代价

- 对白仍按「没入队」写，说服过的人后面不会有说服后的台词。
- 后续事件看变量的要素（ガトー var37 决定路线和 S97／S138 离队，ガラリア var4 决定 S33／S48／S63 开场是否「确保在编」）：原版的编成、离队、改造可能不发生，人会一直留在队里。实现时逐项查清楚，写进本节。
- 原版「下一关开场入队」的要素，会早一个出击准备画面拿到。
- 补登记进来的人击坠从 0 开始，和原版新入队一样。

## 6. 不做：击坠数继承

讨论过的做法：删除前记下击坠，结局合并，新周目入队时带上，离队再入队时补回。技术上可行（钩 `800AA62C`、`800A5054`、`801C26A4`）。用户决定不做，原因是原版拿击坠数当「本周目用得多不多」的判据，继承会破坏它。

典型例子是千鹤手术线（var51，未实机）：
- **触发**：OZ 线 S138 关末豹馬击坠 ≥15（`001da000@524`），或 S97 让孔巴特拉V 出击（`001d8b64@928`），就会进入。
- **剧情**：千鹤隐瞒心脏病，S97 战斗中差点解除合体，S98 晕倒、诊断出心脏瓣膜病，S99 手术、关末醒来和好。
- **代价**：S99 豹馬不能出击（`001db3d0@882`）。

銀鈴（大作）、トッド＆シルキー（マーベル）、カーツ（ブラッド）的击坠门槛也是同样的道理。

## 7. 待查与验证

- **不经场间的关卡衔接**：有的话，那条边的补登记要延到下一次场间，或者改在下一关载入后、开场事件前做（要另外核实能不能安全登记）。
- **抄录**：33 项逐一从原事件抄 `3D5A`／`3D6C`，记下偏移，写测试比对布局锁。
- **第 5 节逐项影响**：每项列出它的变量还被哪些后续事件读。
- **实机**：完成要素后进场间看 `legacy.json`；在 X 之后的场间存档，改变量让要素变成未完成，再读档，看补登记、提示和情报页状态。
- **测试**：Python 参考实现加「直接后继」和补登记判定，`tests/test_stage_info.py` 加ガトー的「已完成（继承）」；C++ 单元测试覆盖记录合并与变体选择。
