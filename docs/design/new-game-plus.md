# 周目继承：隐藏要素

2026-10-16。原版没有周目继承。我们只加一项：**上周目完成过的隐藏要素，下一周目在原入队关之后补登记**，并跨周目记录完成了多少。已实现，单元测试通过；2026-10-17 在 Windows 台式机实机验证（§7）。原版事实来自静态分析。

## 1. 范围

- 补登记照抄原版入队指令，**不改脚本变量**。
- 这一周目到不了原入队关的要素不给。
- 击坠数、资金、改造都不继承（第 6 节）。

## 2. 原版事实

- **只有通关标记**：结局 `801C26A4` 置 `D_8015DDA8` bit3 并写回 SRAM 头，唯一用途是解锁音乐鉴赏里的「緑の大地の上で」（`801C82BC`）。卡带上的「见过」位图也只用于解锁曲目。
- **新游戏从零开始**：主角选择调 `800A4790`，200 个脚本变量全写成 3；名册清空。没有任何地方读上周目的数据。Akurasu 也没有二周目的记载。
- **名册**（`80172F40`，100 条 × 0x4C）：登记 `800A84F8` 先按人物号找已有记录，找到就沿用，找不到才新建。所以对已在队的人重复登记无害。
- **每关之后都有场间**：过关 `3D4A` 把当前场景 `8010F5F0` 抄到 `8010F5F1`；结束事件后 `8009EDB8` 一律置模式 4 进场间（[custom-campaign §2](custom-campaign.md)），前篇只是菜单剩两项。所以场间里 F5F1 是刚打完的关、F5F0 是下一关；读档进场间时两者也随存档恢复。
- **登记指令的处理函数**：`3D5A` → `800A0B3C`：先 `800A3A1C` 映射主角机体号，再 `800AAD28(人物, 机体, 参数, 模式)`；模式小于 2000 且不是 500／999 时是旧机体号（换乘）。`3D6C` → `800ACA1C(机体, 段数)`；`3D70` → `800ACFAC(主驾, 同乘)`；`3D64 500,500` → `800AB96C()`（アイシャ转进マナミ的母舰）。都在常驻段。
- **出击记录入队**：玩家侧的部署组（`3D45`）或转阵营（`3D58`）入队时，等级＝基准＋记录 +9，改造段数＝`D_800CB5DC[记录 +0xC]`（`8020ABB4`，五项同值；ROM `0x55FCC`）。

## 3. 历代记录

- 文件：有存档库时是 `saves/legacy/legacy.json`（主库，不随自定义战役切换），调试运行在运行目录 `legacy.json`，不碰玩家的。格式 `srw64.legacy.v1`，`elements`：要素 id → 完成时在队里的相关人物号／机体号（规则 `done` 里的号加补登记会登记的号）。マシュマー／キャラ、量産型ν F／I 靠这个决定补哪一个。
- 只增不减，与存档栏无关，开关关着也照样记；自定义战役不读也不写。
- 时机：打开本关情报页时（采样时），以及场间菜单每 30 VI 一次，用现有求值器把判成「已完成」的获得类要素并入，有变化才写文件。

**本关情报页**（`frontend.cpp` `stage_panel`）：
- 历代记录里的要素旁边加「历代已完成」标记，隐藏要素栏标题处加「历代达成 N/33」。
- 规则判成未完成、但这个要素在历代记录里、而且它的「已拥有」条件成立时，显示「已完成（继承）」。ガトー的完成条件是 `var37 == 0`，补登记不改变量，所以需要这条，否则会显示「已错过」。

## 4. 补登记

### 4.1 规则

规则页难度调整「周目继承」（`inherit-hidden`，默认关）开着时，在场间菜单每一步之前检查（`801CE19C` 包装，紧跟作弊之后，等淡入结束，每 30 VI 一次）。四条都满足就登记，并在顶上提示「周目继承：XX 加入」：

1. 要素在历代记录里；
2. 补登记项的 `after` 含 F5F1（刚打完的关），或 `before` 含 F5F0（下一关，用于原版在开场事件里登记的要素）；
3. 要素规则和补登记项的 `applies` 成立（主角、路线），带 `variant` 的还要和历代记录里的号对上；
4. 「已拥有」条件不成立：默认是第一条 `3D5A` 的人物，没有人物时是它的机体；可以用 `owned` 另写（ヒルデ 86／266、アポリー＆ロベルト两人、トールギスIII 看机体）。

由此得到：
- 没打 X 不给；只在紧挨着 X 的那次场间检查，剧情之后删掉这个人，也不会再加回来；
- 在那次场间存档再读档，第 4 条已不成立，不会重复登记；
- 不另存周目状态、不占脚本变量，读的是当时的历代记录。同一周目读档重打、别的存档刚完成的要素，也会在 X 之后补上。

换乘指令（如 `3D5A 286,0,136,123` 把エピオン换成トールギスIII）只在旧机体在队时执行，否则跳过这一条（`runnable`）。

### 4.2 数据与出处

`guide/data/inherit-grants.json`，导出时并进 `content/stages/status.json` 的 `grants`。每项写原版指令和出处：

- `event:<事件>@<偏移>`：照抄该事件里包住这条指令的条件块中的 `3D5A`／`3D6C`／`3D70`／`3D64`；
- `deploy:<记录>`：地图上入队的，按出击记录造 `3D5A 人物, 等级偏移, 机体, 500`，有改造索引时加 `3D6C 机体, D_800CB5DC[索引]`。

`tests/test_inherit_grants.py` 逐条核对：指令必须出自所写的事件块或出击记录，`after`／`before` 的关必须是出处所在的关，`before` 只用于开场事件（类型 12），关卡必须在该要素规则的 `at` 里；33 项正好覆盖除 3 项外的全部获得类规则。

### 4.3 33 项

- **照抄事件（26 项，另加アイシャ的一条）**：カーツ、エルリッヒ、リッシュ、アイナ、アレンビー、エマ、エリカ、ナイーダ、キリカ、ゲイル、フォウ、銀鈴、ロザミア、ヒルデ、Mk-III＆メタス改、ミネルバX、量産型グレート、ガトー、フルアーマー百式改、ゼクス＋エピオン、ロゼ、プルツー、ノイエ・ジール、量産型ν、トールギスIII、クェス；以及アイシャ的 OZ 线（S57 关末，连同マナミ换乘スイームルグS 与 `3D64`）。
- **按出击记录（地图上入队，6 项另加アイシャ的两条）**：アポリー＆ロベルト（S2／S3 组 4）、ガラリア（S20，`3D58`）、アイシャ的独立军／完全和平线（S40／S69）、トッド＆シルキー（S81／S92 组 3／6，再照抄シルキー的 `3D5A` 与 `3D70`）、プル（S85／S98，`3D58`）、マシュマー／キャラ（S103 组 4／5）、キラル（S104 组 6）。
- **在开场登记、用 `before`**：リッシュ（S40、S51、S108）、ナイーダ（S77、S91）、ゲイル（S52）、銀鈴（S107）、ゼクス＋エピオン（S76）、フルアーマー百式改（S59，换乘百式）。
- **不做**：牛剣鬼（效果是敌方增援，不是入队）、シュバルツ（没有效果）、キュベレイMk-II 改色（属于选项）。

カーツ和エルリッヒ的入队关是支线 S124／S123，条件不满足就进不去，按第 2 条不会补。フルアーマー百式改是把百式换乘过去，没有百式就不补。

## 5. 不改变量的代价

- 对白仍按「没入队」写，说服过的人后面不会有说服后的台词。
- **后续看变量的要素**（hidden-elements §5.1）：
  - ガトー（var37）：补登记后路线仍按 var37=3 走 S108（基地失守线），S54／S60／S98 的编成和 S97／S138 的离队都看 var37==0，所以他会一直留在队里。
  - ガラリア（var4）：S33／S48／S63 开场的「确保在编」不触发（已在队无所谓）；原版シルキー要 var4==0，补登记的トッド＆シルキー照抄时不看这个条件，シルキー一起加入。
  - ナイーダ（var23）：S77／S91 开场的二选一只在 var23==0 时出现，补登记后不出现，她留在队里，没有自爆那条分支。
  - アイシャ（var13）：独立军／完全和平线只补她和エルブルス；原版由 var13 决定的スイームルグS 换乘时机不触发。OZ 线照抄 S57 整块，换乘和转入母舰都会做。
  - プル（var27）、プルツー（var30）：プルツー的说服门槛和キュベレイ改色看这两个变量，补登记不打开它们；プルツー有自己的补登记项。
- 原版「下一关开场入队」的要素，用 `before` 在开场前的场间补，比原版早一个出击准备画面。
- 补登记进来的人击坠从 0 开始，和原版新入队一样。

## 6. 不做：击坠数继承

讨论过的做法：删除前记下击坠，结局合并，新周目入队时带上，离队再入队时补回。技术上可行（钩 `800AA62C`、`800A5054`、`801C26A4`）。用户决定不做，原因是原版拿击坠数当「本周目用得多不多」的判据，继承会破坏它。

典型例子是千鹤手术线（var51，未实机）：
- **触发**：OZ 线 S138 关末豹馬击坠 ≥15（`001da000@524`），或 S97 让孔巴特拉V 出击（`001d8b64@928`），就会进入。
- **剧情**：千鹤隐瞒心脏病，S97 战斗中差点解除合体，S98 晕倒、诊断出心脏瓣膜病，S99 手术、关末醒来和好。
- **代价**：S99 豹馬不能出击（`001db3d0@882`）。

銀鈴（大作）、トッド＆シルキー（マーベル）、カーツ（ブラッド）的击坠门槛也是同样的道理。

**实机验证（2026-10-17，Windows 台式机，测试数据目录，玛娜米第 1 话通关档）**：预置历代记录（アイナ、エリカ、ガトー），开「周目继承」，读档进场间后用调试接口改 `8010F5F1`／`8010F5F0`：
- F5F1=24：アイナ（51 号，1 级）进名册、アプサラス（84 号）进机体池，顶上横幅「周目继承：爱娜 加入」，`legacy-events.jsonl` 记下 `grant`。
- F5F1=23：エリカ只登记驾驶员，2 级（原版只登记驾驶员时是基准＋1）。
- F5F1=49：ガトー（52 号）＋GP02A（75 号，五项 3 段）。F5F0=49 时本关情报页 S49 卡显示ガトー「已完成（继承）」「历代已完成」，栏标题「历代达成 3/33」。
- 场间调 `800AAD28` 登记新机体没有问题：存到存档 2、重开游戏读回，三人两机都在，机师能力页正常列出；再把 F5F1 设成 24、49 不会重复登记。

未实测：带 `3D70`／`3D64`／换乘的项（トッド＆シルキー、アイシャ OZ 线、トールギスIII、フルアーマー百式改）和 `before` 项，逻辑由单元测试覆盖。
