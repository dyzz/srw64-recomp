## 2. 四条接入路径

### 宿主整张绘制

用于"原版把一张大图拆成很多块画"的场景：头像、场间背景、标题帧、战术地图。

- 游戏照常发出分块命令。
- 宿主认出这次绘制是哪张图，把原来的块抑制掉，在 RT64 同一个 command buffer 的同一位置、同一绘制顺序里，用 Metal 一次画整张高清图。
- 好处：块之间没有接缝；调色板不同的版本不用逐块做哈希；画面不受原版切块方式的限制。
- 识别走 RT64 的原生绘制钩子（`NativeMeshHooks`）。TRI1／TRI2 和 texrect 都会调用 classify，各模块按链式挂在后面。
- 实现：
  - 头像：`native_portrait.cpp`
  - 场间背景：`native_background.cpp`
  - 标题等场景精灵：`native_sprite.cpp`
  - 战术地图：`native_map.cpp`

### RT64 纹理哈希替换

用于本来就是独立小纹理、哈希稳定的场景：世界地图地表的 64 px 块、宇宙物件、对话框切片。

- 键是 RT64 v5 内容哈希，由 [`rt64_hash.py`](../../tools/hd_ai/rt64_hash.py) 离线计算。
- 清单只允许 `worldmap`、`frame`、`space` 三类。
- 调色板会变、同一块在多处出现、或按块替换会留下接缝的内容，不用这条路。

### 原生模型

用于 3D 显示列表：5600 标记、世界地图舰船与地标。`native_marker.cpp` 识别原 DL，抑制它，然后画宿主网格。

### 原生文字

用于图片里烘焙的文字：标题菜单、章节标题卡、序章、结局、制作人员名单。文字按阅读语言重新排版，原版的缩放、旋转、翻面动作保留。

## 3. 战术地图

地图有调色板循环（水面、灯光、熔岩）、殖民地贴图帧和 3D34 整张换图，详见[战术地图清单](../data/tactical-maps.md)。这些区域的纹理每跳都在变，哈希替换在这里行不通，所以走宿主整张绘制，颜色取游戏当帧的调色板。

### 运行时（`src/host/native_map.cpp`）

1. **钩子**：地图绘制函数 `800945D4` 执行完后，`game_hooks.cpp` 把本次写入的显示列表范围、槽位和子记录交给宿主。
2. **识别**：宿主从子记录读布局号，只接管有 HD 资产的地图布局；集中线等同一绘制器画的其他精灵不动。
3. **改写**：原版模式、没有资产或识别失败时一律不改写。否则：
   - 读出 TLUT 地址，抓下当帧 256 色；
   - 用各块矩形的包围盒和镜头偏移（槽位原点 + `8010F5D4/D8`）算出地图坐标；
   - 在显示列表里留一条带标记的矩形，其余矩形置空，贴图载入和状态命令保持不动。
4. **绘制**：RT64 处理到这条矩形时回调宿主，宿主用 Metal 按像素计算 `底图 + (当帧色 − 参考色)[色号]`。调色板不变时就是底图原样；水面换帧、换调色板时颜色跟着游戏走。
5. **资产**：`SRW64_HD_MAPS` 指向 `tools/hd_ai/tactical_map_hd.py export` 的输出目录。每张地图一个子目录，包含 4 倍底图 `base.png`、4 倍色号图 `index.png` 和带参考调色板的 `meta.json`。

踩过的坑：RT64 给矩形绘制的 `screenScale`/`screenOffset` 是相对这个矩形自己的范围，不是整个画面。整张地图要直接按全画面的 N64 坐标换算，否则会被横向拉伸，卷动时还会"呼吸"。

地图 20 样板的验证：
- 同一位置、卷到底后各截一次图，HD 与原版的配准偏移全画面都是 0。
- 上屏节奏与原版一致：每 33 ms 一帧，最长 38 ms。
- 判断流畅度要用 `--diagnostics light`。调试会话默认的完整诊断会周期性截 5K 图，HD 画面压缩慢，会造成 200–270 ms 的卡顿。

### 离线制作（`tools/hd_ai/tactical_map_hd.py`）

1. **`prepare`**：按布局拼出 1 倍的色号图和原图，生成动画掩码和边框掩码，用 MMPX 把色号图放大 4 倍，并冻结一条请求。
2. **请求**：`python -m tools.hd_ai.aliyun` 发一次，每个输出目录有预算上限。
3. **`compose`**：
   - 按两轴拟合模型输出的整体放大并反向变换。千问会把内容放大约 0.2–0.5%。
   - 保色：只取模型的高频细节，低频颜色沿用原图。
   - 动画区域和外圈边框不用模型的结果。
   - 输出比对报告和水面循环预览。
4. **`export`**：写出运行时资产。

地图 20（448×512）一次请求就能出整张 1792×2048；最终选 `qwen-image-3.0-pro`。

### 待做

- **岸线平滑**：色号图按像素放大，岸线仍呈阶梯状。要把边界平滑后再和 AI 画的陆地对齐。
- **大图分窗口**：155 份布局里有 135 份放大 4 倍后超过 2048²，要分窗口生成、带重叠，再在保护区里合成。
- **殖民地精灵**：一套 8 帧，帧号读 `80178C6D`。
- **3D34 变体**：以前一步为基础，只重画变化的格子。
- **总览缩放与地形面板**：总览缩放（`800943E0`）和地形面板（`801E2D54`）仍画原版格子。
- **推进顺序**：先做水面面积大的地图（56、13、16、46、15），再做两段连环画序列。

## 4. 制作工具

| 工具 | 用途 |
| --- | --- |
| [`aliyun.py`](../../tools/hd_ai/aliyun.py) | 冻结请求的单次发送：写好请求记录再发，不重试 POST，每个输出目录有预算上限；`load_env` 读 `.env` 里的 DashScope 密钥 |
| [`rom_images.py`](../../tools/hd_ai/rom_images.py) | ROM 调色板与色号贴图解码 |
| [`pixel_scale.py`](../../tools/hd_ai/pixel_scale.py) | 只复制原色号的像素画放大（MMPX、Scale2x），供色号图与机体标识使用 |
| `portrait_batch.py`、`build_portrait_images.py`、`build_portrait_review_site.py`、`portrait_matte.py` | 头像：2×2 拼图生成、逐格配准、抠图、整张输出与审图站 |
| `background_hd.py` | 场间背景 |
| `title_hd.py`、`flat_scene_hd.py` | 标题 Logo、火焰与平面色块场景 |
| `worldmap_surfaces.py`、`worldmap_space.py` | 剧情世界地图地表与宇宙 |
| [`dialogue_frame_asset.py`](../../tools/hd_ai/dialogue_frame_asset.py) | 对话框边框切片 |
| `tactical_map_hd.py` | 战术地图 |

共同流程：冻结请求 → 单次发送 → 配准和保色 → 保护区合成或抠图 → 导出 → 更新清单（附 SHA-256）→ 实机对照。生成图、请求记录和中间文件都放在不进 git 的 `assets/hd-ai/`，目录说明见 `assets/README.md`。

## 5. 后续

1. **战术地图**：先提交地图 20 样板，再按 §3「待做」逐项推进。
2. **机体标识**：从最近邻、MMPX、Scale4x、xBR 里定一种风格。结果从本地 ROM 算出，不需要分发美术文件。
3. **战斗**：暂缓。恢复时，精灵和特效按图集做母版再切零件，3D 背景走贴图替换加原生几何。
4. **宽屏**：整张绘制的图以后可以画得比 4:3 更宽，但要等宽屏容器落地后再做。
