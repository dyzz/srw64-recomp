# 快速读档与统一武器改造（规划）

2026-10-17。用户提出两项新功能，本文记静态结论和已拍板的方案，实现前以此为准。

## 1. 地图上快速读档（SL）

### 1.1 原版事实

- 原版的组合是 **Z+START**，不是 Z+R+START：`80085EF8` 判「按住 Z 且按下 START」，淡出（`80099814(5,1,2)`）。淡出结束时，若 START **仍按住**、且 `80093610` 报告卡带中断区（SRAM `0x3E10`）有档，就切模式 `0x11` 从中断存档读回地图；否则回标题。R 不参与。地图 `801DFBD0`、世界地图 `801C2968`、场间 `801D8DDC`、演出 `801C97E4` 都有这条分支（[原版按键](../gameplay/original-controls.md) §2，[回溯](rewind.md) §2）。
- 本版默认**没有给 Z 绑键**（`input_bindings.hpp` 的 `default_bindings`，手柄和键盘都没有），所以原版组合按不出来。
- [回溯](rewind.md)（issue #6）已经实现了「离开地图／离开演出 → `arm_suspend` → 模式 `0x11`」，随机数不写回。快速读档复用这套机制，只是读的存档不同。

### 1.2 方案（已定）

| 项 | 决定 |
| --- | --- |
| 两个新动作 | **读中断存档**：读卡带里玩家在地图菜单手动存的中断存档。**读回合存档**：读最新一份回合开始自动存档（`saves/auto/turn-*.sus`）。两个都进操作页，可以改键 |
| 恢复原版 Z+START | 给 Z 一个默认键，原版「按住 Z＋按住 START」读中断档就能用。默认只给键盘（建议 Z 键）；手柄没有空键，由玩家自己绑。**不要**把 Z 叠到 L1 上：演出里 Z+START 会中止战斗、场间 Z+START 会重置，L1+START 误触代价太大 |
| 随机数 | 两个动作都**不写回**随机数，读回后由地图重新播种，SL 才能刷出不同结果。回合存档从存档页读取时仍照现在恢复随机数，只有快速读档这条路径不恢复 |
| 能执行的时刻 | 与回溯相同：地图安静空闲或我方菜单、战斗演出状态 2–20；其他时刻请求挂起，离开地图作废 |
| 没有存档时 | 提示「没有中断存档」／「没有回合存档」，三语 |
| 回溯快照 | 读档后清空回溯快照（读回的局面和快照无关） |

### 1.3 实现要点

- 在 `rewind.cpp` 里把「离开」做成通用的：目标文件由请求带进来（回溯＝快照文件，读中断＝卡带中断区即不改道，读回合＝最新 `turn-*.sus`）。读中断不调 `arm_suspend`，原版本来就读卡带。
- 读回合存档时 `autosave.cpp` 的 `restored()` 会按 `.json` 恢复随机数，要给它一个「这次不恢复」的标记。
- 新动作位要避开 `pad_rewind`（bit 27）等已用位；触屏要不要加按钮另定。
- `rewind.cpp` 目前工作区里还有另一个会话没提交的改动，等它提交后再动，或在 worktree 里做。
- 实机：迷你关存一份中断档 → 打几步 → 两个动作各读一次，核对回合、HP、位置与存档一致，连续读两次战斗结果不同（随机数没写回）；Z+START 按住读回、提前松开回标题。

## 2. 统一武器改造

### 2.1 原版事实（[改造段数与上限](../gameplay/upgrade-limits.md)）

- 每件武器单独记段数（武器实例 `+0x16`，存档每件 4 位），上限是所在机体 `+0x51`。
- 价格只看改造类型（武器实例 `+0x15`：1–4）和当前段数，类型 1 是 5000×(n+1)，类型 4 是 2000×(n+1)；类型 0 不能改。
- 武器改造列表按形态分开列，各形态的武器实例各自独立。
- 改造确认走 `801D1318` 一系；满改追加武器 `D_801DC87C`、EW 换装 `D_801DC6E4` 都在这条路径里判定。

### 2.2 方案（已定）

| 项 | 决定 |
| --- | --- |
| 开关 | 设置「武器改造方式：统一／逐件（原版）」，**默认统一**；随时可切，切换不改存档 |
| 范围 | **一台机体的所有形态联动**，共用一个统一段数 |
| 统一段数 | 全部形态里可改武器（类型 1–4）段数的最小值 |
| 升级 | 计划升到 L 段：把所有低于 L 的武器补到 L，只付缺的段（每件按原版价格表），总价一次付清。每件实际改造都走原版付款分支，满改追加、EW、属性传播、15 段突破照常 |
| 后加入的武器 | **自动免费同步**到当前统一段数（剧情新增、满改追加、换装后新出现的武器实例都算），不扣钱 |
| 存档 | 格式不变，仍是每件 4 位；与原版、模拟器互通不受影响 |

**状态（2026-10-17）**：已实现并在 Mac 实机验证，细节见[改造画面](../native/native-upgrade-screens.md)「武器统一改造」。「同步的基准」最后定为统一段数取计入武器里最多的那个段数（并列取高），不另存状态。

### 2.3 实现要点（规划时）

- **界面**：武器改造的机体列表照旧；进入后不再先选单件武器，直接是统一改造页：统一段数、刻度、下一段价格、计划合计，←→ 定计划，A 一次付清；下方列出每件武器当前／计划后的威力。逐件模式保持现在的页面。
- **付款**：沿用现有「多段一次付清」的做法（同一帧连调原版付款分支，第二次起转场字节 `8015E9C5` 写 −1，最后只有一次淡出），循环范围从一件武器扩大到全部形态的全部武器。遇到 EW（下一画面 2）或满改追加提示（11）时停下，处理完再继续剩下的。
- **免费同步**：时机选在进场间菜单（`intermission_enter`）和改造页打开时：统一模式下把低于统一段数的武器段数直接写上去，再调 `800A5254` 系重算威力，不经付款分支、不扣钱。要确认「直接写 `+0x16`」后满改追加的判定是否需要手动触发（静态先查 `801D1318` 里满改判定的入口）。
- **同步的基准**：统一段数取同步前的最小值会被新武器拉低，所以同步要用「除去新加入武器以外的最小值」。需要记住哪些武器是「新加入」的：可在宿主侧按机体记上次见过的武器集合，或把统一段数单独存一份（存档旁的宿主文件，不改原版存档）。实现前先定这一点。
- **敌方机体**不受影响（只处理我方名册）。
- 检查脚本：受控存档里一台多形态机体（如 ダイターン3）＋ 混合段数武器，验证升级只付缺段、各形态联动、满改追加武器出现并被同步、切回逐件模式数值不变。
