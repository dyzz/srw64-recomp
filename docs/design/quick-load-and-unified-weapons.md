# 快速读档与统一武器改造（规划）

2026-10-17。用户提出两项新功能，本文记静态结论和已拍板的方案，实现前以此为准。

## 1. 地图上快速读档（SL）

2026-10-17 用户收窄范围：**先只做「读手动中断」**。读回合自动存档和回溯（`rewind` 分支）以后再说，本节不再依赖回溯分支的代码。

### 1.1 原版事实

- 原版的组合是 **Z+START**，不是 Z+R+START：`80085EF8` 判「按住 Z 且按下 START」，然后淡出（`80099814(5,1,2)`）。淡出结束时，若 START **仍按住**、且 `80093610` 报告卡带中断区（SRAM `0x3E10`）有档，就切模式 `0x11`，从中断存档读回地图；否则回标题。R 不参与。地图 `801DFBD0`、世界地图 `801C2968`、场间 `801D8DDC`、演出 `801C97E4` 都有这条分支（[原版按键](../gameplay/original-controls.md) §2）。
  - 地图上逐条核对过（2026-10-17，`801DFBD0`）：地图状态 `80172EB0`≠0 时调 `80085EF8`（原始按住字 `8015D9FA` 有 Z、原始边沿字 `8015CAF0` 有 START），成立就 `80080188(1)`＋`80099814(5,1,2)`。之后每帧 `80099B30` 报告淡出完成（返回 3）时，若下一模式 `8015DA02`＝1、`8015D9FA` 仍有 START、`80093610()` 为真，就 `80080188(0x11)`；否则走标题。`80093610` 经 `80090E5C` 读 SRAM `0x3E10` 起 0x20 字节，返回首个半字的 bit15。
  - 所以玩家要按住 Z 再按 START，并且**一直按住 START 到黑屏结束**；提前松开就回标题。R 不参与，N64 上 Z+R+START 能用只是因为多按一个 R 无妨。
  - 「有档」就是中断记录 +0 的 bit15（已用位，[多存档栏](save-slots-autosave.md) §1.3）。原版按键文档里原来写「零售卡带该位为 0」，只对没中断过的卡带成立，已改正。
- **读完不清除**（`8009365C`，存档设计 §1.3）：同一份中断档可以反复读，SL 循环成立。
- 原版中断档不存随机数，战术 overlay 每次启动都由 `801E00AC` 重新播种：读同一份档，后面的战斗结果本来就会变。快速读档不需要再做什么。
- 地图菜单的「中断」（中文界面叫「保存」）存完后，原版会问「保存完毕。要继续游戏吗？」：选「是」留在地图上接着打，选「否」才回标题（`801D21D0` 写卡带、`80172F09=1`，`801D1534(4,0)` 就是这个提问窗）。所以存一个新的 SL 点不用回标题，原版本来就是这样。
- **实机核对（2026-10-17，Mac，迷你关）**：地图菜单「保存 → 是」→ 提问窗「是」，留在地图；接着用调试键按住 Z（space）、按下 START 并按住 4 秒：战术 overlay（ROM `0xAB160`）重新载入一次，中间没有载入标题 overlay，地图回到存档时的样子，光标回到机体上。原版组合确实直接读中断回地图。
- 中断记录里的进度块在 +0x26C（`save_page.cpp::turn_json` 已经这样读）：+2 回合、+9 关卡标题号、+0xC 资金。
- 本版默认**没有给 Z 绑键**（`input_bindings.hpp`，手柄和键盘都没有），所以原版组合按不出来。

### 1.2 方案（2026-10-17 已实现）

| 项 | 决定 |
| --- | --- |
| 入口 | **确认后才读**（用户 2026-10-17）。触屏顶边「情报」右边一个「读档」键；本关情报页（手柄 Y、键盘 I）底部一个「读取中途存档」按钮；操作页的「读取中途存档」动作，键盘默认 **F9**，手柄暂不给默认（组合键以后再说，§1.4）。三个入口弹同一个确认窗 |
| 确认窗 | 「读取中途存档」：回到第 N 回合、资金多少，「地图现在的进度会丢失」，读取／取消 |
| 做法 | **宿主替玩家按原版的 Z+START**：先单按 Z，再加 START，被接受后只按住 START，直到模式变成 `0x11`；这期间玩家的按键不送进游戏。淡出、判档、切模式、读档、重新播种全是原版代码，存档改道照常生效 |
| 能用的地方 | 战术地图（模式 3／0xB／0x11／0x16／0x22，地图界面状态不为 0：原版只在这时判组合）和战斗演出（模式 2，演出状态 2–20、没有淡出、没在中止）。别处触屏键不出现，情报页没有按钮 |
| 先检查 | 卡带中断区已用位为 1，否则提示「没有中途存档」；记录里的关卡标题号（+0x26C+9）和当前关卡不同则提示「中途存档不是本关的」（用户 2026-10-17） |
| 提示 | 读回后「已读取中途存档（第 N 回合）」；没成功「中途存档没有读取成功」。三语，用词跟现有的「中途存档／中断セーブ／suspend save」 |

为什么不照回溯分支那样直接调 `80080188(0x11)`：读卡带中断档用原版组合就够了，不用新钩地图帧，地图和演出共用一条路径，原版允许的时机也全部可用。

### 1.3 实现

- `src/host/quick_load.hpp`、`src/host/quick_load.cpp`：`usable()`、`saved()`（有存档库读 `save_store::cartridge_bytes`，没有读运行时的存档文件）、`request()`、`frame()`（`host.cpp` 的 `frame_start`）、`filter_input()`。
  - 阶段：按 Z → 按 Z+START → 只按 START → 读档中 → 地图界面回来后提示。「被接受」在地图上是模式变 1（`801DFE0C`），在战斗演出里是中止标志 `80225810` 变 1（`801C9A18`，演出不切模式 1，淡出结束直接 `0x11`）。8 帧没被接受就松开重来；1200 VI 没完成就放弃。
  - **输入过滤必须放在 `get_input` 整条链的最后**：确认窗关闭时设置窗口的「松键闸门」（`settings_window::filter_input`）要等所有键松开才放行，组合放在它前面就一直按着、永远过不了闸门。第一次实机就卡在这里。
- 前端：`quick_load_ask_open` 确认窗（仿首次启动的更新询问窗），`choose("quick-load-ask")` 先查能不能用、有没有档、是不是本关。触屏 `touch_pad::Slot::Load`（55.5 mm，宽 9 mm），`usable()` 为假时清掉。
- 调试状态 `quick_load`（阶段、能否使用、卡带记录），事件 `quick-load-events.jsonl`。
- F9：`input::Action::QuickLoad`，宿主位 `pad_quick_load`（bit 28，27 留给回溯分支的 `pad_rewind`），操作页一行 `controls_row_quick_load`；frontend 在设置窗口没开时按下即 `choose("quick-load-ask")`。

### 1.4 以后再做

- 手柄组合键：用户要仿 PS 系的按法、并兼顾安卓触屏。PS 版机战软重置是 L1＋L2＋R1＋R2＋START＋SELECT，触屏按不出来；手柄上 SELECT（View）会开设置窗口，要改成松开时才开。
- 读最新的回合自动存档、回溯（`rewind` 分支）。

## 2. 统一武器改造

### 2.1 原版事实（[改造段数与上限](../gameplay/upgrade-limits.md)）

- 每件武器单独记段数（武器实例 `+0x16`，存档每件 4 位），上限是所在机体 `+0x51`。
- 价格只看改造类型（武器实例 `+0x15`：1–4）和当前段数，类型 1 是 5000×(n+1)，类型 4 是 2000×(n+1)；类型 0 不能改。
- 武器改造列表按形态分开列，各形态的武器实例各自独立。
- 改造确认走 `801D1318` 一系；满改追加武器 `D_801DC87C`、EW 换装 `D_801DC6E4` 都在这条路径里判定。

### 2.2 方案（已定）

| 项 | 决定 |
| --- | --- |
| 开关 | 设置「武器改造方式：统一／逐件（原版）」，**默认统一**；随时可切，切换不改存档 |
| 范围 | **一台机体的所有形态联动**，共用一个统一段数 |
| 统一段数 | 全部形态里可改武器（类型 1–4）段数的最小值 |
| 升级 | 计划升到 L 段：把所有低于 L 的武器补到 L，只付缺的段（每件按原版价格表），总价一次付清。每件实际改造都走原版付款分支，满改追加、EW、属性传播、15 段突破照常 |
| 后加入的武器 | **自动免费同步**到当前统一段数（剧情新增、满改追加、换装后新出现的武器实例都算），不扣钱 |
| 存档 | 格式不变，仍是每件 4 位；与原版、模拟器互通不受影响 |

**状态（2026-10-17）**：已实现并在 Mac 实机验证，细节见[改造画面](../native/native-upgrade-screens.md)「武器统一改造」。「同步的基准」最后定为统一段数取计入武器里最多的那个段数（并列取高），不另存状态。

### 2.3 实现要点（规划时）

- **界面**：武器改造的机体列表照旧；进入后不再先选单件武器，直接是统一改造页：统一段数、刻度、下一段价格、计划合计，←→ 定计划，A 一次付清；下方列出每件武器当前／计划后的威力。逐件模式保持现在的页面。
- **付款**：沿用现有「多段一次付清」的做法（同一帧连调原版付款分支，第二次起转场字节 `8015E9C5` 写 −1，最后只有一次淡出），循环范围从一件武器扩大到全部形态的全部武器。遇到 EW（下一画面 2）或满改追加提示（11）时停下，处理完再继续剩下的。
- **免费同步**：时机选在进场间菜单（`intermission_enter`）和改造页打开时：统一模式下把低于统一段数的武器段数直接写上去，再调 `800A5254` 系重算威力，不经付款分支、不扣钱。要确认「直接写 `+0x16`」后满改追加的判定是否需要手动触发（静态先查 `801D1318` 里满改判定的入口）。
- **同步的基准**：统一段数取同步前的最小值会被新武器拉低，所以同步要用「除去新加入武器以外的最小值」。需要记住哪些武器是「新加入」的：可在宿主侧按机体记上次见过的武器集合，或把统一段数单独存一份（存档旁的宿主文件，不改原版存档）。实现前先定这一点。
- **敌方机体**不受影响（只处理我方名册）。
- 检查脚本：受控存档里一台多形态机体（如 ダイターン3）＋ 混合段数武器，验证升级只付缺段、各形态联动、满改追加武器出现并被同步、切回逐件模式数值不变。
