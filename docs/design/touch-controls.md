# 手机触屏操作（按场景设计）

2026-10-03。安卓手机没有手柄时的操作方案。上一版是固定的虚拟手柄（`src/host/touch_pad.hpp`，main 1c55cd9），所有画面都显示同一套 N64 键。这一版按场景显示写着功能名的按钮。按键在底层仍是 N64 键和宿主键，所以游戏、我们的页面、按键提示都不用另改。

## 1. 用户定的目标

- **像 MOBA 手游：** 左边不固定方向键，手指在左侧区域按在哪里，方向键的中心就在哪里，拖动即可。
- **按钮尽量少：** 每个场景只显示这个场景用得到的按钮。
- **显示功能名：** 按钮写「确定」「快进」「下一个单位」，而不是 A、R2、R1。文字跟游戏语言（中、日、英）。
- **不割裂：** 我们自己的页面（战前确认、整备等）也至少保留方向、「确定」「返回」，不能一进页面就只剩中间能点。

## 2. 布局骨架

所有场景共用同一副骨架，场景只决定每个槽位放什么、显示与否。位置固定，字会变。

| 槽位 | 位置 | 尺寸 | 用途 |
| --- | --- | --- | --- |
| 方向区 | 游戏画面：左侧约 42% 宽、顶边条以下的整块。我们的页面：左下角约 34 mm 见方 | 按下处出现摇杆，半径约 10 mm，死区 2.5 mm | 四向。不碰时左下角显示一个淡的摇杆，提示可用 |
| 主键 | 右下角，中心距右边 12 mm、距底边 14 mm | 直径约 16 mm | 本场景的「确定」类动作 |
| 副键 1 | 主键左边，弧上 180° | 直径约 11 mm | 「返回」类动作，永远在这里 |
| 副键 2、3 | 主键左上 135°、正上 90° | 直径约 9 mm | 本场景的两个常用动作（上一个／下一个、快进等） |
| 顶边小键 | 顶边一条，左上、右上各两格 | 约 12×5.5 mm | 不常用的动作；左上第一格固定是「设置」 |
| 点画面 | 方向区、按钮以外的画面 | 全屏 | 只在对白、任意键窗口里有效，等于主键 |

规则：

- 不显示的槽位不占触摸，手指落在那里就是“点画面”或方向区。
- 同一个场景里，一个动作只出现一次。
- 按钮的手感沿用现有实现：多指同时按；手指在方向区内拖动换方向；从一个按钮滑到另一个按钮会切换；点按至少保持 80 ms。
- 用实体手柄或键盘时整套隐藏；一碰屏幕就出现。

**战前确认页的触屏排版**（用户 2026-10-03 选定，只在触屏按钮显示时这样排，三种战前界面风格都换成这一版）：底部那排按钮和按键提示不显示，功能交给右手按钮组（绿色「开始战斗」在主键位）；下方两块机师信息栏往中间收，左下让给方向区、右下让给按钮组；整页下移约 8 mm，顶边放「设置」和「动画 开／关」。从回避或防御切回反击时，照原有流程先进原版武器列表选反击武器。

说明：

- **战前确认页**上，「开始战斗」「选择武器」「精神」「战斗动画」本来就是页面上的按钮，直接点；虚拟按键只保留方向、确定、返回，满足“不割裂”。
- **对白**最常用的动作是翻页，所以点画面任意处翻页；方向区仍然接收拖动，用来回看，只是不画摇杆，避免遮挡。
- **战术地图·空闲**是按钮最多的场景（5 个加设置）。L2、R2（切换敌人）放到顶边，因为用得少。
- **识别不了的画面**退回完整一套，保证任何画面都不会缺键。实施时把每次落到这一行的场景记进日志，再逐个补进表里。
- 返回键和返回手势在所有场景都等于副键 1（B）；在设置窗口、图鉴、MOD 管理里关闭窗口。

## 4. 场景识别

界面线程不读游戏内存（`frontend.cpp` 的规矩），所以新增一个游戏线程模块，每个游戏帧读一次下面这些值，算出场景编号和几个标志，用一个原子量发布：

| 依据 | 来源 | 已确认 |
| --- | --- | --- |
| 顶层模式 | `8015DA02`（`800801A4` 分发表下标，见原版按键文档第 3 节） | 静态 |
| 标题阶段 | `intro::title_major()` | 实机 |
| 战术主状态、子状态 | `0x80172EB0` `+0`、`+2` | 实机（战术 UI 状态表） |
| 对白等待翻页 | 原生对白阅读器（`native_dialogue.cpp`）当前帧 | 实机 |
| 选择肢 | 脚本引擎当前指令（`8009EFDC` 轮询的 vm），`3D44` | 待实机 |
| 序章页 | `intro::title_major()` 为 13（公共序章与各路线序章，0.4.0 后补上） | 待实机 |
| 结果画面、战败提示 | 对应函数的钩子，或其状态表下标 | 待实机 |
| 我们的页面 | 各页请求的 `visible`，界面线程自己就有 | 实机 |

识别结果只决定显示哪些按钮。按钮发出的仍是 N64 键，所以即使识别错了，也只是按钮少了或者标签不对，不会让游戏收到错误的操作。

## 6. 实施顺序

1. **骨架：** 方向区（游戏画面任意位置、我们的页面左下角），主键加副键弧，顶边小键，点画面。场景先只分三类：我们的页面、设置这类全触屏窗口、其他（完整一套）。验收：现有流程（开场 → 标题 → 迷你关卡 → 战斗）只用触摸走通。
2. **识别层：** 游戏线程模块和场景编号，调试接口 `status` 里能看到当前场景，便于检查。
3. **逐场景接入：** 先接对白、战术地图（空闲、菜单、移动选格），它们占了游戏时间的大头；再接标题、战斗演出、结果和任意键窗口；最后接列表、信息窗、能力页。每接一个场景，用调试接口进到那里截图核对。
4. **收尾：** 识别不了的场景从日志里逐个补；三语词条过一遍；在 Seeker 上完整玩一话（开场 → 第一话 → 一场战斗 → 存档），只用触摸。
