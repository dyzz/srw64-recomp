# UI 与纹理高清化：阿里云 AI 选型调查

调查日期：2026-09-08。结论：采用字体／规则图形重建、保真超分、受约束生成式重绘的组合，优先验证过场背景与少量装饰资产。

后续状态：用户确认后已完成首轮 42 张模型输出及地图单帧回放。看图后头像首选 Qwen 3.0 候选 2；机械单位图标不处理，森林等地图 tile 暂缓，过场地图与 UI 边框可见提升不明显，暂缓继续生成。见 [实测结果与人工看图决定](hd-ai-benchmark.md)。本文以下保留调用前的调查与计划，实际数量、费用和限制以实测记录为准。

本次完成官方文档核对、既有百炼业务空间的认证模型目录查询及当前项目检查。没有提交图像推理任务，没有将游戏图像上传云端；以下质量判断是候选方案，尚无本游戏的模型效果对照。

## 按资产选择方法

| 资产 | 首选方法 | AI 的用途 | 必须保留的内容 |
| --- | --- | --- | --- |
| 正文、名称、数值、菜单标签 | 轮廓字体与确定性排版 | 辅助识别尚未登记的图片文字 | 原文本、控制符、字距规则、显示时机 |
| 边框、窗口、光标、数值条 | 矢量或参数化重建，再生成需要的纹理 | 装饰方案参考 | 精确尺寸、对齐、九宫格边角、状态差异 |
| 过场世界地图背景 | 保真超分对照＋受约束重绘候选 | 补充山脉、地表、海面等纹理细节 | 海岸线、城市／路线位置、画幅、投影与色板 |
| 室内、天空、地面等静态背景 | 图像编辑／超分 | 补充绘画细节与材质 | 构图、透视、物体数量、原作画风 |
| 头像、人物立绘、机械图标 | 超分优先；有角色设定参考再尝试重绘 | 清理锯齿、补充线条 | 五官、服装、徽记、机械结构、轮廓与透明度 |
| 战术地图图块 | 图块类型和拼接关系确认后分别处理 | 地表纹理候选 | 地形可读性、格子边界、重复平铺与邻接缝 |
| 动画精灵、闪烁光标、战斗特效 | 按整组动画处理与复核 | 经验证后的局部辅助 | 帧间身份、姿态、配色、透明度与节奏 |

首次试验以独立静态资产为主。生成式模型逐帧改画动画容易产生闪烁和造型漂移，单张好看不足以证明动画可用。

## 接入时应注意的真实限制

1. **小图输入**：普通超分最低32×32，最大长边1920／短边1080，文件不超过5MB；生成式超分最低64×64，长边不超过5000、短边超过1080会自动调整，比例不超过2:1。窄条和极小图标不能原样提交给所有服务。
2. **透明通道**：万相编辑输入规格明确写明PNG不支持透明通道。透明资产应保留独立原始蒙版，只将需要生成的RGB区域送入模型，再按已登记的轮廓规则合成和验收；不能把生成的白底图直接当成透明纹理。
3. **超分输出格式**：普通超分通常应显式指定PNG；文档说明输入RGBA时会强制PNG，但输出分辨率超过3840×2160时可能自动改为JPEG。需验证实际格式、尺寸和Alpha，不只检查文件扩展名。
4. **框选不等于像素锁定**：万相的`bbox_list`是编辑引导，不能据此承诺框外逐像素不变。必须把允许改动的区域作为独立蒙版合成，受保护区域从确定性基线复制，并做差异检查。
5. **请求接口**：已有文本任务的OpenAI兼容`chat/completions`路径不能直接当成图像编辑接口。千问编辑指南给出DashScope `MultiModalConversation`，万相给出`ImageGeneration`及多模态生成接口；每个适配器按对应当前文档构造请求。
6. **尺寸与提示词**：按模型API选择输出尺寸、宽高比和输入尺寸；需要补边时保留裁剪变换。对支持`prompt_extend`的模型，忠实复刻试验应显式关闭自动扩写，避免改变已审查的提示词。不要假设所有模型共有一个“重绘强度”参数。
7. **可复现性**：固定快照、输入哈希、请求参数和seed有助于追踪，但官方明确说明相同seed不保证相同输出。发布使用已经审核并保存哈希的图像，不在生产构建时重新请求模型。
8. **额度与批量**：官方卡片列出的北京默认限流分别为千问3.0 Pro 5 RPM、千问3.0 20 RPM、千问2.0 Pro快照2 RPM、万相2.7 Pro 300 RPM；实际以账号返回为准。“批量推理不支持”不妨碍客户端按限流逐个提交普通请求，但不能套用批量推理折扣。

上述规格以各模型文档为依据；旧版千问编辑API参数表尚未完整覆盖3.0，3.0请求实现应以当前3.0示例和实际校验为准。[千问编辑API](https://help.aliyun.com/zh/model-studio/qwen-image-edit-api)

## 过场地图背景的具体流程

1. **提取完整底图**：定位原资源和RT64实际采样，不用包含文字、人物、标记、光标的最终屏幕截图作为生产输入。如果底图分块上传，先恢复完整图及每个块的裁剪、翻转和调色板关系。
2. **建立结构保护层**：把海岸线、道路、河流、边界与关键标记分开登记。能用矢量或原始蒙版重建的结构单独绘制；地表材质、海面和云层作为可编辑区域。原图中已经烘焙的文字也要单独重建。
3. **同源对照**：同一原图分别做普通插值、普通超分、生成式超分、千问编辑和万相编辑。普通插值作为不增加新语义的视觉基线。
4. **限定重绘任务**：保持原画色板和手绘风格，只补充可编辑区域的纹理；不要求模型把地图变成写实卫星照片。配套参考图用于统一美术，不用于替换空间布局。
5. **确定性合成**：将审核通过的材质按保护层合成，重新绘制地名、路线和标记。按原采样关系切回高清图块，统一比例、边缘扩展和过滤方式。
6. **运行时验收**：绑定到确认的RT64纹理哈希，在平移、缩放、转场和淡入淡出中检查接缝、错位、色差、透明边及采样闪烁。过场底图与战术地图图块分别验收。

建议的无字底图提示词起点（空间约束最终仍由结构层和人工审查保证）：

> 以图1为唯一空间布局基准，保持相同画幅、投影、相机方向与原画色板。保留海岸线、河流、道路、岛屿及城市的位置、形状和数量。在原有二维手绘科幻战略地图风格下，提高地表与海面纹理的清晰度，细化已有山脉和植被。保留大块颜色关系与地形辨识度。输出不含文字、标签、单位、光标和界面的地图底图，不增加新的地物。

## 首轮对照建议与成本

待提取并登记6份原始资产：两张不同风格的过场地图、一张场景背景、一张头像、一张机械图标、一块UI装饰纹理。这里是样本类别建议，尚未将6份资源定位并填入可执行清单。

每份样本：

- 千问3.0 Pro、千问3.0、万相2.7 Pro各独立请求2个候选（每次1张输入、1张输出）。
- 千问2.0 Pro固定快照请求1个对照。
- 普通超分、生成式超分各1个对照，确认其开通和输入条件后再加入。
- 本地普通插值作为额外基线，不计云端出图数。

共54张云端输出。以千问3.0 Pro的2K价、全部请求单输入、其他模型上述价目估算：

`6 × [2 × (0.52 + 0.20 + 0.50) + 0.50 + 0.02 + 0.06] = 18.12元`。

这是未执行的参考试验成本，不是账单或预算授权。没有计入重试、额外参考图、存储流量，也没有扣除免费额度；不需为这轮试验先购买GPU实例或训练模型。

通过标准按资产预先定义：

- **结构正确**：地标、海岸线、机械部件、角色身份没有被擅改；错误候选即使更锐利也淘汰。
- **工程正确**：尺寸与纹理映射一致，受保护区域通过差异检查，透明轮廓无白边，图块接缝正确。
- **视觉有效**：在目标游戏显示尺寸比较可读性、风格一致性和细节，不只查看放大的静态预览。
- **运行正确**：完成目标场景的滚动、缩放、叠加和动画对照；静态图片通过不等于实时渲染验收。
- **成本有效**：统计审核通过率、每张合格资产的请求次数和人工修图时间，再决定批量模型。单次API价格不是完整生产成本。
