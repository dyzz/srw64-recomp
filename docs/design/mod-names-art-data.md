# 两个 MOD 的规划：原创人物名字、人物与机体数据

2026-10-27。规划两类 MOD 包，接在[MOD 包](mod-packages.md)的格式与[数值 MOD](mod-packages.md)（§5 末尾，`src/host/mod_data.hpp`）之后。MOD 一、MOD 二都已实现（2026-10-27）：名字 `src/host/mod_names.hpp`，数值 `src/host/mod_data.hpp`，头像 `src/host/native_portrait.cpp`。玩家文档在官网「数值 MOD」「名字与头像 MOD」。

- **MOD 一：原创人物与部队的名字**。改 64 原创的八个人（四条路线的主角和搭档）和部队名。
- **MOD 二：人物、机体、武器**。改任何人物的姓名和头像，机体名、武器名，人物能力、机体能力、武器威力。

两者都只放数据，按现有的层级合并：原版 → 内置（译文、HD 包）→ 用户包（MOD 管理里上面的赢）。

## 1. MOD 一：原创人物与部队的名字

### 现状

[默认姓名](../native/default-names.md)已经做成「存储不变、显示时替换」：

- 姓名区 `8010F5F8` 起和部队名 `8010F698` 只存 ROM 默认名的日文字形，存档与原版兼容；
- `DefaultNames`（`src/native/game_adapter/default_names.hpp`）判断字段是否还是默认名，是就按阅读语言显示译名，译名来自词条表 `default_names`（记录 487–502）与界面词条 `unit_default_name`；
- 所有显示处都经过它：台词占位符 `{HeroName}` 等、说话人与回看、原生页面（`record_text` 把记录 4407–4414、4768–4775 换成姓名字段）、原版界面的文字覆盖层（`label_text`）、存档列表、选角卡片。

台词正文里主角的名字一律是占位符（原版允许玩家改名），所以**改名只需要换掉 `DefaultNames` 里的译名表**，台词、说话人、各页面都会跟着变。

### 包的写法

```text
yourname.heroes/
  mod.json
  dialogue/names.json
```

```json
{
  "schema": "srw64.mod-names.v1",
  "heroes": {
    "super-male":   { "hero":    { "zh-Hans": { "name": "龙", "surname": "天野", "nickname": "龙" },
                                   "en": { "name": "Ryu", "surname": "Amano", "nickname": "Ryu" } },
                      "partner": { "zh-Hans": { "name": "…", "surname": "…", "nickname": "…" } } },
    "real-female":  { "hero": { "ja": { "name": "サクラ", "surname": "…", "nickname": "サクラ" } } }
  },
  "unit": { "zh-Hans": "疾风", "en": "Gale", "ja": "ハヤテ" }
}
```

- 四条路线 `super-male`／`super-female`／`real-male`／`real-female`，每条的 `hero`（主角）和 `partner`（搭档），共八人；部队名 `unit`。
- 每种语言给名字、姓氏、昵称，全名由宿主按该语言的分隔符拼（中文「·」、英文空格、日文「・」）。
- 没写的人、没写的语言照旧显示我们的译名。几个包改了同一个人时，上面的包赢。

### 宿主

- 收集启用包的 `dialogue/names.json`，盖在 `DefaultNames` 的译名表上。名字的判断（字段内容等于默认名的日文才替换）不变，所以旧存档、改过名的原版存档行为不变。
- 包有变化时重建表（`mods::revision()`，和音乐、数值 MOD 一样），页面按现有的 `relocalize` 重建，对白和回看按切换语言的做法重排。
- 不写存档：停用 MOD 就回到我们的译名。

### 要定的事

1. **只在显示时替换，不写存档**（用户 2026-10-27 定）。姓名区、部队名、存档头始终是 ROM 默认名的日文；停用 MOD 或拿到原版游戏里，名字都是原样。
   唯一要补的显示处是**日文＋F6 原版图**：那时文字覆盖层关着（`ui_text.cpp` 的 `active()`），原版用 ROM 字模直接画姓名区，画出来是默认名。做法：有 MOD 名字生效时，覆盖层在这一模式下也开，但只重画姓名字段对应的标签（`label_text` 里 `entered_name` 命中、且 MOD 换了名字的），其余仍是原版字模。代价是这几个名字用的是我们的字体，不是 ROM 字体。
2. **长度**（用户 2026-10-27 定）。名字不写存档，原版字段的格数（名字、姓氏各 7，昵称 5，全名 17，见[主角选择与确认页](../native/native-name-entry.md)）约束不到它；限制只来自显示：
   - **只警告、不拒绝**：超过原版格数，或显示宽度超过我们现有同一类译名里最宽的那个时，宿主日志提示。宽度按「宽字 2、拉丁字母数字和半角假名 1」估算，不按字数（中文一字约占英文两个字母），没有用字体实测。
   - **硬上限防极端值**：名字、姓氏、昵称各 16 个字符，部队名 24 个字符；超过就整份 `names.json` 不用，和数值 MOD「坏文件整份不用」一致。
   - 最挤的是原版界面的覆盖层标签（战术地图、战斗画面，字号最多缩 1.5 号）和战斗演出的名字条，显示的多是昵称；文档建议昵称控制在原版 5 格左右。原生页面有自动缩字号，对白说话人行很宽。
3. **与「不许改名」的关系**。玩家仍然不能在游戏里输入名字；名字只能由 MOD 包给。

### 部队名

- 原版只在对白里显示部队名（字形 `0x12C`，台词文件写作 `{HeroMech}`，全文 2555 处），别处不画。缓冲 `8010F698` 最多 10 字（`801C4C40`），长度规则同上：超过 10 格或现有最长译名宽度只警告，硬上限 24 个字符。
- **命名那一场的台词是写死的**。第 33、46/58、62 场景里 アムロ 提议「マーチウィンド」、解释「三月の風、四月の雨……」，大家接话都直接写着这个名字（每种语言 33 句），不是占位符。MOD 改了部队名后，如果照现在自动答第 1 项「就用这个吧」，剧情会定下「三月风」，后面却一直叫 MOD 的名字。
- **做法：装了改部队名的 MOD 时，自动答第 2 项「我不喜欢」**。原版这条分支就是玩家自己起名：主角嫌「三月风」不合适 → アムロ 问「那你觉得叫什么好呢？」→ 主角说「叫{HeroMech}怎么样？」→ 忍、ブライト 接话定下来。分支里的名字全是占位符，自然显示 MOD 名字。分支中间的 `3D5E`（原版输入名字的页面）照旧是空操作，缓冲不写，存档里仍是 マーチウィンド。
- 所以部队名**不做整名替换**：写死「三月风」的那几句，在这条分支里本来就是指被否掉的名字，应当保留。
- 停用 MOD 后：已经看过的那场剧情不重演，之后的台词回到「三月风」。
- 改动在 `unit_name.cpp` 的 `answer_choice`：有 MOD 部队名时写 `0x3DDA`（第 2 项）而不是 `0x3DD9`。迷你关卡 `unit-name.json` 已经能重放两条分支，用来实机验证。

### 实现

- `src/host/mod_names.hpp`：`parse`（一份文件，全对才用）、`collect`（启用的包从下往上，同一人同一字段同一语言上面的赢）、`refresh`。没写昵称时昵称取名字；繁体中文没写时用简体那份。
- `names::DefaultNames`（`default_names.hpp`）加了 MOD 层 `set_mod_names`／`mod_text`：`default_text` 和 `display` 先看 MOD。日文原本原样返回缓冲内容，现在有日文 MOD 名字时也替换；但对白适配器拿日文记录和游戏画出的字比对的三处（说话人、覆盖层标签、选项正文，`native_dialogue.cpp` 的 `guest_record_text`）放在 `names::GuestText` 里，照旧看到缓冲原文。
- `names::default_names()` 每次取表时调 `mod_names::refresh`（`set_default_names_refresh`，宿主启动时装上）：MOD 版本号或游戏版本变了才重读，游戏线程、界面线程都可能触发。日志 `SRW64_MOD_NAMES`、`SRW64_MOD_NAMES_WARNING`、`SRW64_MOD_NAMES_PROBLEM`，运行目录写 `mod-names.json`。
- 部队名：`unit_name.cpp` 的选择钩子在阅读语言有 MOD 部队名时答第 2 项（写 `0x3DDA`），事件日志 `choice-answered` 的 `answer` 记 2。
- 日文＋F6 原版图：`ui_text.cpp` 的 `names_only()`，有日文 MOD 名字时覆盖层照样走一趟，但只留 `name_label` 判定为姓名字段、且文字确实变了的标签，正文、数字、宿主自加标签都不画。
- MOD 管理页的内容一栏多一项「主角与部队名字」（`Contents::names`、词条 `mod_has_names`）；`mod_not_applied` 改成也列出名字。
- 示例包 `config/recomp/mods/hero-names`（超级系男主角、搭档、部队名三语，要求游戏 ≥0.5.2）。`tools/mods/validate.py` 按宿主同样的规则检查 `dialogue/names.json`。
- 测试：`make recomp-mod-names-test`（规则、长度、包的顺序、刷新）、`tests/native_content.cpp`（MOD 层与 `GuestText`）、`make recomp-unit-name-test`（第 2 项）、`tests/test_mod_validate.py`。

### 工作量

小：一个解析器、`DefaultNames` 加一层、刷新时机、测试（`tests/native_content.cpp` 已测 `DefaultNames`）。约半天到一天，加一次 Windows 实机。

## 2. MOD 二：人物、机体、武器

六类内容，分三种机制。

| 内容 | 机制 | 键 |
| --- | --- | --- |
| 人物姓名、机体名、武器名 | 文字层，盖在语言目录上 | 人物号、机体号、武器号 |
| 头像 | 图片层，接 HD 头像的整张绘制 | 人物号 |
| 人物能力、机体能力、武器威力 | 数值层，扩展 `mod_data.hpp` 的 ROM 字节补丁 | 人物号、机体号、武器号 |

### 2.1 名字

**已实现**：`names.json` 的 `pilots`／`units`／`weapons` 分区进 `mod_names::record`，`native_dialogue.cpp` 的 `record_text` 先查它（比对画面原文的 `GuestText` 下不查）；武器菜单名把语言目录里的菜单名中纯名那一段换掉，前后的 格／射、P／B／MAP 原样保留。日文＋F6 原版图下，覆盖层的 `name_label` 也认这些记录。人物号 25–32（原创八人）在这里报错，要写进 `heroes`。实机：中文状态页、武器页显示了 MOD 的机体名、武器名（2026-10-27）。

```json
// dialogue/names.json（与 MOD 一同一个文件，另几个分区）
{
  "schema": "srw64.mod-names.v1",
  "pilots":  { "1":  { "zh-Hans": { "name": "…", "full": "…" }, "en": { "name": "…", "full": "…" } } },
  "units":   { "184": { "zh-Hans": "…", "en": "…" } },
  "weapons": { "731": { "zh-Hans": "…", "en": "…" } }
}
```

- 对应的文字记录：人物简称 4382＋人物号、全名 4743＋人物号；机体名 527＋机体号；武器纯名 1370＋武器号、菜单名 2699＋武器号。
- 武器只写一个名字，菜单名由宿主照原版加上 格／射 与 P／B／MAP 标记（和词条表 `weapon_menus` 的推法相同）。
- 接入点是 `native_dialogue.cpp` 的 `ui_text`：那里已经有追加剧本改章节标题的先例（`campaign::title`）。原生页面、战前页、图鉴、文字覆盖层都从这里取字。
- 原创八人的名字仍由 MOD 一的 `heroes` 管（他们的显示走姓名区）。

**要定的事**：

1. **台词正文里提到的名字不会跟着变**。说话人会变，但台词里「アムロ」这样的称呼是正文。可以第二步再做：按我们的 `renames.json` 那样，在中文、英文台词里按整名最长匹配替换（日文正文不动）。
2. **日文、原版界面**仍用 ROM 字模，显示原名。
3. **长度**。同 MOD 一：超过原版格数或现有最长译名宽度只警告；硬上限人物名、机体名、武器名各 24 个字符，超过整份不用。太长的武器名在战斗演出的武器名条上会挤。

### 2.2 头像

**已实现**：`native_portrait.cpp` 的 `install()` 不论有没有 HD 包都装上绘制钩子；`refresh_mods()` 在包变化时读 `art/portraits/<人物号>.png`，人物号经 `battle_assets.portraits` 找到原版 (图像, 调色板)，再按 `content/art/portrait-identities.json`（从 HD 包清单抽出的摘要，`tools/content/portrait_identities.py` 生成 `portrait_identities_table.hpp`）认出画面上的头像。MOD 头像先于 HD 包查，F6 原版图也显示（用户定）。原生页面经 `frontend.cpp` 的 `portrait_path` → `portraits::mod_picture` 取同一张。正方形 96–2048、96 的倍数；不合格的报 `SRW64_MOD_PORTRAITS_PROBLEM`。实机：状态页、驾驶员页在原版图模式下显示了 MOD 头像。

```text
art/portraits/<人物号>.png     768×768（或 96 的整数倍），RGBA，直通 alpha
```

- 用人物号做键，宿主经 `battle_assets.portraits[人物号]` 找到原版图像号，再接上 `native_portrait.cpp` 的整张绘制：对白、战斗、原生页面、图鉴都是同一套精灵模式 7，一处接入全都生效。
- 现在头像替换只在装了 HD 包、图片设为 HD 时启用（`configure` 读 HD 包的清单）。要改成：MOD 头像不依赖 HD 包。

**要定的事**：

1. **F6 切到原版图时 MOD 头像要不要保留**。推荐保留：F6 只关我们的 HD 包，MOD 是玩家主动装的。
2. **以后的机体立绘、地图图标**（键分别是 场景-图集-调色板、RT64 贴图哈希）放到下一步，不在这次范围。

### 2.3 数值（第一批已实现）

2026-10-27 实现于 `src/host/mod_data.hpp`：`data/units.json`、`data/pilots.json`、新增 `data/weapons.json`。规则同地形适应：仍是改 ROM 记录、并进拷贝补丁表，严格校验、坏文件整份不用、上面的包赢。图鉴读同一组字节，自动一致。

```json
// data/units.json
{ "184": { "hp": 5200, "armor": 1300, "move": 7, "terrain": { "sea": "A" } } }
// data/pilots.json
{ "133": { "melee": 160, "sp": 90, "terrain": { "space": "A" } } }
// data/weapons.json
{ "731": { "power": 3600, "hit": 10, "range_max": 4, "ammo": -1 } }
```

**这些表都不常驻内存**：每次用都经 `8007F704` 从 ROM 现读一条记录（机体 `800A52B8` 等，武器只有 `800A642C`，人物 `800A6398`），读完宿主打补丁，所以改的字节下一次读就生效。读场间存档和关内中断存档时，宿主不必做任何事：`800A8CE8` 对每台机体、`800A8E5C` 对每件武器、`800A8E0C` 对每个人从 ROM 重建（静态分析，2026-10-27）。

**机体**（ROM `0x71B80 + 号×0x24`）：

| 字段 | 记录 | 生效 |
| --- | --- | --- |
| `hp`、`en` | +0、+2（u16） | 每次能力重算（`800A5254`，进地图、进场间时全体重算）；读档时当前值回满 |
| `move` | +6（1–30） | 每次重算 |
| `mobility`、`armor`、`limit` | +8、+A、+C（u16） | 每次重算 |
| `repair_cost` | +14（u16） | 每次重算（图鉴当修理费显示；+16 约为它的一半，哪个才是修理费未实测） |
| `upgrade_cap` | +20（0–15） | 每次重算；改造规则文件的同一字节在下面 |
| `terrain` | +E..+11 | 每次重算 |

**人物**（经 `D_800CA9C4` 找到能力记录 `0x7A1A0 + 记录×0x10`，整套重建 `800A7F8C`：读档、升级、新建）：

| 字段 | 记录 | 说明 |
| --- | --- | --- |
| `melee`、`ranged`、`evade`、`hit`、`reaction`、`skill` | +1..+6 | 1 级的值；每升一级再加 1/1/2/2/1/1（`800A6238`） |
| `sp` | +C | 1 级的 SP 上限；每级 +2 |
| `double_move` | +E | 达到这个等级可以再动 |
| `terrain` | +7..+A | |

**武器**（ROM `0x74E90 + 号×0x10`）：

| 字段 | 记录 | 生效 |
| --- | --- | --- |
| `power` | +1（÷100 存，0–25500，100 的倍数） | 每次重算；改造增量照加 |
| `range_max` | +3（1–30） | 每次重算 |
| `range_min` | +2（0–30，不大于最大射程） | 读档、新建 |
| `hit`、`critical` | +4、+D（−128–127） | 读档、新建 |
| `ammo` | +5（−1 表示不用弹数，0–99） | 读档、新建；关内中断存档读档后当前弹数取存档里的 |
| `en`、`morale` | +6、+7 | 读档、新建 |
| `terrain` | +9..+C | 空：每次重算（装飞行部件时变 A）；陆海宇：读档、新建 |

一句话：机体和武器威力、最大射程装上 MOD 后进地图或场间就生效；武器其余字段和人物能力要读一次档（或新开），人物升级时也会更新。

**第二批（同日）**：机体 `abilities`（+1C，只动 13 个可命名的位，变形／合体／分离保持原版）、`size`（+4 低五位，高两位是每台的状态）、`shield`／`sword`（+18 位 2／1）、`parts_slots`（+19，0–4）；人物 `skills`（+F 位与阈值表 `0x7B1B0` 的行：NT、强化人、圣战士、超能力、底力共用第 0 行只能有一个，切落第 1 行、盾防第 2 行）、`spirits`（映射 `D_800CA6F4` → `0x7CFB0` 六对，没写的对写等级 255，`800A63E0` 数到的就不会多）。

宿主自己直接读这些表的地方（`cheats.cpp` 的部件槽、`spirit_learning.hpp`、战斗查看器、能力页的合体技威力、改造页的上限）改走 `upgrades::game_byte`：拷贝补丁表的同一份字节，任何线程可读（`publish_patches`）。

**存读档实测**（Mac，2026-10-27）：装着包在关内中断存档 → 读档，数值全是 MOD 的；停用包回标题读同一个中断存档，机体 HP 10000、移动 5、装甲 1400、无特殊能力，武器威力 1700、射程 1–5，人物格斗 148、技能位 0x5、精神原版，全部回到原版；再启用包读档又全是 MOD 的。查出并修好两处：部件槽被作弊的槽位回收按原始 ROM 写回 0（改走 `game_byte`）；精神没写的对原来写 0，被当成 1 级已学会（改写 255）。

**仍没做**：武器标记（+0 格斗／MAP、+F 合体）、武器改造类型（+E，改造规则文件里有）、加新武器或改武器列表。

**共用**要在工具和文档里写明：

- 人物能力记录可能几人共用（ドモン 4／273／274 等），ID 表已列出共用者；
- 武器号在多台机体的武器列表里共用（363 台机体只有 266 种列表），改一件武器，所有带它的机体都变；
- 机体的形态各有编号，改一个形态不影响别的形态。G 高达的模式切换（`801FEDF4`）就地改机体号、只重算，所以只读档、新建时才复制的字段要到下次读档才跟上。

**范围限制**：不加新武器、不改武器列表、不改精神指令本身的效果，这些是规则或剧情类改动。

### 2.4 工具与网站

- `tools/mods/validate.py`：认识新文件和字段，检查范围（u8／u16、威力是 100 的倍数）。
- ID 表加武器页（1329 件，武器号、名字、威力、射程、带它的机体）；人物页加能力，机体页加 HP 等。CSV 同步加列。
- 示例包：MOD 一做一个「原创主角改名」示例；MOD 二做一个小的平衡示例（例如把某几件武器的威力调高）。

## 3. 顺序与工作量

1. **MOD 一**（半天到一天）：`dialogue/names.json` 的 `heroes`／`unit`、`DefaultNames` 加层、测试、示例包、文档。
2. **MOD 二·数值**（一到两天）：先核实武器其余字段与机体「只在建时复制」的字段在读档时是否重建，再扩 `mod_data.hpp`、校验器、ID 表、测试。
3. **MOD 二·名字**（一天）：`pilots`／`units`／`weapons` 文字层、武器菜单名推导、图鉴缓存失效。
4. **MOD 二·头像**（一到两天）：头像替换脱离 HD 包、按人物号映射、尺寸与透明度检查。

每一步都在 Windows 台式机上实机验证一次（[数值 MOD](mod-packages.md) 的做法：迷你关卡＋运行时记录逐字节比对＋截图）。
