# 关卡编辑器：统一关卡格式、新地图与网页编辑器

2026-11-20。只是设计，没有实现，也没有为它做新的静态分析或实机；引用的地址与限制都来自[自定义战役](custom-campaign.md)与 [MOD 包](mod-packages.md) §7 的既有结论。标「待核实」的是这次新提出、还没看过代码的点。

## 1. 已定与待定

| 项 | 状态 |
| --- | --- |
| 编辑器是官网上的网页工具，和 BGM、图标工具并列 | **已定**（用户 2026-11-20：「肯定是网页工具」） |
| 新地图只做整张自绘，不做「用原版图块拼」 | **已定**（用户 2026-11-20：「只做整张自绘」，与 2026-10-01 的路线一致） |

## 2. 现状的问题

- **两套写法**。改主线用剧情脚本（`srw64.story.v1`：`when`／`if`／`do`，宿主触发，见 [MOD 包](mod-packages.md) §7.6）；追加剧本的关卡仍是迷你关卡格式（`srw64.mini-stage.v1`）：原版指令字、28 字节出击记录、手工借场景号。后者作者写不了，编辑器也没法对着它做。
- **新地图只有设计**（[自定义战役](custom-campaign.md) §6，阶段 C3 未做）。那份文档写「新资源号不能用，只能借号」；新机体那条线之后包已经能带自己的资源号（`mod_tables.hpp` 的 `publish_resources`、`80089BBC` 包装、`80089E9C` 上限放宽），这个前提过时了。
- **没有试玩回路**：要打包、装包、进战役、从头打到那一关。

## 3. 统一的关卡格式

一关四层，每层都能引用原版。改主线的剧情 MOD 是「只有事件层、其余引用原版」的特例，写法不变。

| 层 | 内容 | 编辑器里 |
| --- | --- | --- |
| 地图 | 尺寸、地形格、底图、战斗背景、BGM、宇宙标志 | 选原版地图、裁一块，或导入自绘底图（§4） |
| 部署 | 按组摆单位：人物、机体、等级、阵营、行动方式 | 在格子上拖；行动方式先用「照抄某条原版记录」（现有 `template`） |
| 事件 | 现有剧情脚本，`scene` 换成关卡名 | 开场、回合、击破、说服、胜败、结束 |
| 流程 | 关卡图、分支、开局部队、标题 | 连线；场景号由编译器从可借的号里自动分配 |

- **事件走宿主触发**：战役关卡的事件也按 §7 的方式由宿主触发，原版的 63 个事件／0x1A00 字节限制只剩开场、配置、结束三个原版位要守。
- **原版指令保留**：高层动作没覆盖的照旧直接写指令。
- **场景号不给作者看**：编译器从可借的号里分配（避开「（前）」13 个与 132、109–122），一个战役的关数上限因此约 115。
- **编译产物不变**：仍是 `srw64.campaign-image.v1` 与 `srw64.story-image.v1`，宿主的战役与剧情两套代码不用合并。
- **出击记录的未解释字节**（`byte8`／`raw14`／`raw16`／`raw18`／`raw26`）：编辑器不暴露，靠模板带过去；要做「行动方式」下拉得先解释这些字节，待核实。

### 3.1 源格式（第 1 步已做，2026-11-20）

源目录和以前一样是 `mod.json`、`campaign.json`、`stages/`，由 `tools/mods/pack.py` 打包；也可以单独 `python tools/mods/stage.py compile <源目录> -o <输出目录>` 看每关占了多少。示例在 `config/recomp/campaigns/sample`。

`campaign.json`（`srw64.campaign.v2`）：`id`、`name`、`description`、`author`、`version`、`start`（开局关卡名）、`route`（主角路线 0 布拉德／1 真奈美／2 阿克／3 赛莲，必写）、`stages`（关卡名的数组，顺序就是分配场景号的顺序）、可选 `status`（本关情报页的状态规则文件）。

`stages/<关卡名>.json`（`srw64.stage.v1`）：

```json
{
  "schema": "srw64.stage.v1",
  "title": {"ja": "第2話　分かれ道", "zh-Hans": "第2话　岔路", "en": "Crossroads"},
  "map": 19,
  "units": {
    "copy_from": "base:stage_auxiliary:001e449c",
    "place": [{"template": "base:stage_deployments:001e43b8", "group": 6, "x": 14, "y": 14}]
  },
  "events": [
    {"when": "opening", "do": [{"bgm": 49}, {"to_map": true}, {"deploy": 0}, {"say": 4, "text": {"ja": "「行くぞ」"}}]},
    {"id": "boss-down", "when": {"defeated": 18}, "do": [{"win": true}]},
    {"when": "end", "do": [
      {"choose": {"text": 18402, "options": [[{"next": "ending-a"}], [{"next": "ending-b"}]]}}
    ]}
  ]
}
```

- **`map`**：原版地图号，或 `maps/` 下自己的地图名（§4.3）。
- **`units`**：`copy_from` 整块复制一关原版的出击记录，`place` 追加。字段沿用迷你关卡的（`group`、`x`、`y`、`unit`、`upgrade`、`faction`、`behavior`、`template` 等），人物写 `pilot`、等级偏移写 `level`。不带 `copy_from` 时每个阵营最多 30 个。另有三个好写的字段（2026-11-20，含义见 §5.4）：`ai`（`{"mode": "attack"|"accurate"|"hunt"|"goto"|"flee"|"guard", "wait": 回合, "target": 人物号, "to": [x, y]}`）、`drop`（被击破时掉的强化部件号，`null` 或不写＝不掉）、`entry`（登场时的 HP／EN，1–7）。**不写 `drop`、也没有 `template` 时掉落字节是 0xFFFF（不掉）**；以前编成 0，等于每个敌人都掉 0 号部件。
- **`events`** 的 `when` 有两种：
  - 字符串 `"opening"`／`"setup"`／`"end"`：这一关自己的开场、配置、结束事件，各最多一个，总会执行，不写 `id` 和 `if`（条件写在 `do` 里的 `if`）。每关必须有开场。它们编进原版的事件位。
  - 对象：和[剧情 MOD](../guide/story-mods/README.md) 完全一样的写法（`turn`、`defeated`、`hp_below`、`battle`、`enemies_gone`、`remaining`、`persuade`、`after`），要有 `id`，不写 `scene`。由宿主触发，不占原版的 63 个事件和 0x1A00 字节。`fired`／`not_fired` 指同一关的事件。
- **`do`** 在剧情 MOD 的动作之外多了：`{"win": true}`（`3D4A`）、`{"lose": true}`（`3D4C`）、`{"next": "关卡名"}`（`3D4B`）、`{"ending": true}`（`3D71`，写在最后一关的结束事件里）、`{"to_map": true}`（`3D4D`，开场里从世界地图切到战术地图）。这五个只能写在战役关卡里。另有两个剧情 MOD 也能用的：`{"line": 原版文本号, "mode": 0–5}` 显示一句原版台词；`{"choose": {"text": 原版选项文本号, "options": [[…], […]]}}` 选项，2–3 项。新写的选项文字还不支持。原版指令照旧可以写 `{"op": "3D32", "args": [4]}`。
- **`scene`**（可选）：指定借哪个场景号。不写时编译器按 `stages` 的顺序从可借的号里发，跳过 0、4–9、105、106（§6 的线索）。**存档里记的是场景号**，所以发布后要加关就加在 `stages` 末尾，或给新关写 `scene`，否则旧存档会指到别的关。
- **`setup`**（可选）：`route`、`story_vars`、`last_choice`、`initial_resources`，含义同迷你关卡。
- **`raw_events`**（可选）：迷你关卡写法的事件（`type`／`header`／`commands` 或 `copy_from`），进原版的事件位。用来整段复制原版事件，或者在宿主触发还没验证过的地方先用原版的触发。
- `stages/<关卡名>.meta.json` 存在时就是这一关的情报页元数据。

编译出两个文件，都在包的 `campaign/` 下：

- `campaign.json`（`srw64.campaign-image.v2`）：每关的原版事件位、出击记录、地图，结构同 v1。改了版本号是为了让旧版游戏不认它：旧版不会跑宿主触发的事件，载入了也过不了关。
- `story.json`（`srw64.story-image.v1` 加 `campaign` 与 `patches`）：宿主触发的事件、全部新台词、以及开场／配置／结束事件里每句新台词在事件块里的位置（台词号由宿主运行时分配，登记场景时填进去；填之前那里是 `0xFFFE`）。放在 `campaign/` 而不是 `story/`，旧版游戏就不会把它当成主线的剧情 MOD。

宿主的改动（`story_mod.hpp`、`campaign.hpp`、`mini_stage.hpp`、`game_hooks.cpp`）：

- 以前战役运行时剧情模块整个停用。现在事件带「属于哪个战役」：战役里只跑这个战役的事件，主线里只跑主线包的事件。战役借的是主线的场景号，不分开的话两边会串。
- 战役镜像旁边的 `story.json` 随战役载入；`8009DE7C` 登记后按 `patches` 把台词号写进 `8019B400` 的事件块。
- 「已触发」和标记在战役里也随存档旁注走；从「开始战役」进第一关时清空（主线是在选主角时清）。
- v1 的战役镜像和 `mini_stage.py campaign` 照旧能用（`config/recomp/campaigns/retry` 还是 v1）。

## 4. 新地图

### 4.1 运行时（第 2 步已做，2026-11-20）

**新地图顶替一张原版地图**（作者在 `map.json` 里写 `like`）。游戏照旧按那张原版地图的地图号装载，所以它的 BGM、宇宙标志、网格颜色、战斗背景（按调色板资源号查表）、水面的调色板循环都原样保留，不用改任何按地图号的表。宿主只在这一关登记期间，把那张原版地图的三个资源——布局、图集、调色板——换成新地图的字节：

- `80089BBC`（资源描述：解压后大小、流的位置）对这三个资源号返回资源窗口顶端的三个 1 MiB 槽（`0x0BD00000` 起），`8007F704` 读到那里时由宿主供应只有字面量的 LZSS 流。做法同包自带资源（`mod_tables.hpp`），代码在 `src/host/map_mod.hpp`。
- 登记场景时（`8009DE7C` 的包装，`game_hooks.cpp`）按关卡镜像的 `custom_map` 换上或撤下；撤下后同样的资源号又是 ROM 的。
- 资源装载器对已经在内存里的资源号只加引用计数，不会再问描述符。实机上「自绘地图一关 → 原版同一张地图一关」两边都画对了，说明换关时地图资源会释放；同一关里用 `3D34` 换图还没试。
- HD 模式：HD 地图按布局号认（`native_map.cpp` 的 `find_asset`）。`hdmap::set_override(布局号, 目录)` 让这个布局号改画新地图自己的大图；新地图没有大图（`scale` 1）时这个布局号不画 HD，保持游戏自己画的格子。新地图的资产不参与平常的查找，回到主线后原版地图不受影响。

没做的：

- 同一关用 `3D34` 换到另一张自己的地图（现在一关只能有一张）。
- 模式 1 的原版地图（带殖民地动画，158 张里 77 张）不能当模板，工具直接拒绝；宇宙地图只能挑模式 0 的那几张（66、74、112、137、157）。
- 自己的水面：现在只是避开模板地图会循环的调色板项，水面不会动。
- 存档与中断记录里记的是模板地图号，读档重新登记后照样换上，逻辑上成立，未实机。

### 4.2 两种做法

| 做法 | 作者成本 | 原版模式 | HD 模式 |
| --- | --- | --- | --- |
| 引用原版地图（`"map": 20`） | 最低 | 现成 | 现成 |
| 整张自绘大图（`"map": "地图名"`） | 高 | 工具降级成原版格式 | 作者的大图整张绘制 |

不做图块拼图（用户 2026-11-20）。裁剪原版地图的一块还没做（可以用现成的 HD 底图裁一块当自绘图交给工具，效果相同）。

### 4.3 自绘地图的源与工具（已做）

`maps/<地图名>/map.json`（`srw64.map.v1`）和一张底图放在一起：

```json
{"schema": "srw64.map.v1", "like": 20, "image": "base.png", "scale": 4,
 "terrain": [[99, 99, 99], [99, 5, 1]]}
```

- **`image`**：整张地图。尺寸＝格数 × 16 × `scale`（`scale` 默认 4，和现有 HD 地图一样；1–8）。28×32 格、`scale` 4 就是 1792×2048。
- **`terrain`**：每格一个地形号 0–98（[自定义战役](custom-campaign.md) §6.1 的表，63 是墙），行数列数与底图的格数一致。最外两圈是地图的边框，写什么都按 99。
- **`like`**：顶替哪张原版地图（§4.1），挑同一类场所的。
- 大小：20×15 到 128×128 格（布局头的宽高是字节对），像素不超过 4240×3184。

`tools/mods/map_tool.py`（关卡编译器和 `pack.py` 会自动调；单独跑 `map_tool.py build <目录> -o <输出>` 另出一张 `preview.png`，是原版模式下的样子）：

1. 底图缩到游戏尺寸，量化到模板地图调色板里空着的色号：不用 0 号（原版地图调色板里是透明），不用模板的循环资源会改写的那几段（资源第 2、3 字节是起始色号和个数，地图 20 是 `0xC0` 起 17 个和 `0x15` 起 3 个）；那几段保留模板原来的颜色。
2. 切成 16×16 的格，一个图块和它的三种翻转算一种。不超过 1,023 种就原样放进 512×512 图集（0 号图块原版不画，从 1 号起）；超过时按颜色做 k-means 合并，每组用最靠中间的那一种来画（需要 numpy；没有时报错）。
3. 生成布局：头 `(7, 组数, 列×2, 行×2)`、每格 `u16 翻转位|地形号`＋`u16 图块号`、每种图块一个绘制组和它的放置表。
4. `scale` ≥ 2 时另出 HD 用的三个文件：`base.png`（作者的原图）、`index.png`（每个像素的色号，合并图块之前的，淡入淡出和循环靠它跟着走）、`meta.json`（`srw64.hd-map-runtime.v0`，和内置 HD 地图同一种）。

编译结果在包的 `campaign/maps/<地图名>/`：`map.json`（`srw64.map-image.v1`，三个资源的十六进制）、`meta.json`、`base.png`、`index.png`。关卡镜像里 `map` 是模板地图号，另有 `custom_map`。

### 5.3 条件扩展（2026-11-20 已做，Windows 实机过主要几项）

目标：作者想到的常见条件都能直接写，不用拼原版指令。条件分三处：**时机**（`when`，什么时候检查）、**事件条件**（`if`，检查时还要满足什么）、**动作里的「如果」**（一步步动作中间分支）。三处用同一套条件词汇，编辑器也只做一个条件编辑器。

#### 现有的

- 时机：回合开始、击破、HP 低于、交战前／后、敌方全灭、残存数（敌方／第三方）、说服、开场／配置／结束之后。
- 事件条件（全部「且」）：剧情变量、击坠数至少／不到、本关事件已／未触发、名册有／没有某人某机、长期标记有／没有。
- 动作里的「如果」：只有「变量等于」（编成 `3E03`）。

#### 新增的时机

| 写法（草案） | 意思 | 做法 |
| --- | --- | --- |
| `{"reach": {"who": 18, "area": [x0, y0, x1, y1]}}` | 某人进入矩形区域；`who` 换成 `"side": "player"／"enemy"` 表示该阵营任意一台 | 宿主自己判：名册 `8015E100 + 阵营×0x258 + 槽×0x14`，`+0` 为 1 的槽读 `+4`／`+5` 的格坐标（原版类型 8 的 `800A4288` 就是这样比的，待核实 `+4`／`+5` 确是 x／y）。挂在类型 8 的扫描时机（移动结束后），原版类型 8 自己的编码把宽高限在 0–9 格，宿主不受限 |
| `{"defeated": 18, "by": 4}` | 被某人击破 | 类型 2 触发时交战记录 `+0x9A0`／`+0x9A4` 应该还在（原版 `3E16` 就读它取「交战的另一方」），待实机核实 |
| `{"defeated_any": "player"}` | 某阵营任意一台被击破 | 宿主每次轮询记各阵营在场数，减少且不是离场就成立；离场与击破靠人物状态表 `8015DE90`（击破写 0、`3D46` 离场写 2）区分 |
| `{"group_gone": 3}` | 某组（如增援组）全部被击破 | 原版名册没看到组号，宿主在「登场」那一刻比对名册前后新占的槽，记下槽属于哪组；之后按槽判。同人物号的杂兵（多台共用驾驶员）也分得开 |
| `{"remaining": {"side": "player", "at_most": 2}}` | 我方只剩几台 | 原版类型 7 只数敌方／第三方，我方由宿主数名册 |

「撑到第 N 回合」「第 N 回合内击破某人」不需要新时机，用现有时机加下面的回合条件。

#### 新增的事件条件

| 写法（草案） | 意思 | 做法 |
| --- | --- | --- |
| `"turn": {"from": 3, "to": 5}` | 当前回合在范围内 | 读 `engine+0x9AC` |
| `"on_map": [18]`／`"defeated": [18]`／`"absent": [18]` | 某人在场／已被击破／不在场（含离场） | `800A293C` 与 `8015DE90`，和原版 `3E1B` 同一张表 |
| `"hp": {"who": 18, "below": 50}` | 某人 HP 百分比低于 | `800A293C` |
| `"count": {"side": "enemy", "at_most": 3}` | 某阵营在场数 | `engine+0x9B1`／`+0x9B2`，我方数名册 |
| `"in_area": {"who": 18, "area": [...]}` | 某人此刻在区域内 | 同 `reach` |
| `"route": [0, 1]` | 主角路线 | 迷你关卡的 `setup.route` 写的同一处，读法待核实 |
| `"choice": 2` | 本关上一个选项选了第几项 | 原版选项结果（`3E10`–`3E12` 读的那个），地址待核实 |
| `"funds": {"at_least": 50000}` | 资金 | 地址待核实 |
| `"any": [ {…}, {…} ]`、`"not": {…}` | 或、非 | 宿主求值，条件可以嵌套 |

#### 动作里的「如果」

和事件条件同一套写法：`{"if": {…条件…}, "then": [...], "else": [...]}`。

- 旧写法 `{"var": n, "is": v}` 照旧编成原版的 `3E03` 条件块。
- 其余条件都由宿主判断：编成 `3E14 0xFFFC; 3E08 1; …then…; 3E14 1; 3E1D; 3E08 0; …else…; 3E1D`，宿主把 `0xFFFC` 换成 0 或 1。换的时机是事件启动时和**每一步执行之后**（`8009EFDC` 的包装），所以条件看的是「执行到它之前那一步结束时」的状态；同一步里紧挨着的前一条指令（例如同一帧里的 `join`）还看不到。编辑器在这一步旁边写了「在执行到这一步前判断」。
- 宿主事件的这些位置在事件的 `checks` 里（`[字号, 条件]`）；战役关卡的开场／配置／结束事件编进原版事件块，位置记在 `patches` 里带 `test` 的项（块内字节偏移），登记场景时和每一步之后写。

（原先设想把 HP、回合、在场状态等编成原版的 `3E01`／`3E04`／`3E1B`；后来统一由宿主每步求值，两套语义不必对齐，就没做。）

#### 编辑器

- 一个条件编辑器，三处共用：先选种类（回合、某人状态、HP、数量、区域、选项、名册、标记、事件、路线、资金），再填对象（人物用图鉴选择器、区域在地图上拖框、阵营下拉、数字）；「全部满足／任一满足」切换，每条可以取反。

### 5.5 新写的选项文字与作战目标文字（2026-11-20）

静态分析（子代理做，关键点我在生成代码里核对过）：

- 选项（`3D44 0,项数,文本号`）走的是台词同一条读文本的路：`8009FA94` → `8008FF04` → `8008CD8C` → `8008C9C0`，后者调 `8008C510`（描述符）和 `8007F704`（读 ROM），宿主对 0xC800 起的号已经在这两处供给记录。**选项记录里只有选项**，每项一行、行首一个空白字形（留给绿色光标条），行间 `FFFE`，`FFFF` 结束，头 `02500004`；问题句是前面一条普通台词。项数来自操作数，不读记录。
- 作战目标窗口 `801C688C` 画文本 5567＋胜利号、5593＋败北号，也经 `8008CD8C` → `8008C9C0`。`8008C9C0` 入口的 a2 就是文本号（`8008CA20` 存进 s2、`8008CA2C` 写进正文槽 +0），已有包装。5694（5567＋127）与 5720（5593＋127）原版是调试菜单文字，正常游玩不显示。
- 这两种正文在玩家语言下由界面文字覆盖层画（`ui_text.cpp` 扫正文槽，`native_dialogue.cpp` 的 `body_page` 按正文槽 +0 的号取译文）。覆盖层要求这一页有墨的字形数和画出的矩形数对得上，所以记录里不能全是空白字形。

做法：

- 编译器：`choose.text` 可以写 `{"ja": [选项…], "zh-Hans": [...]}`（每项不超过 24 字），编成种类 `choice` 的新文字（选项间 `<BR>`），`3D44` 的第 3 个操作数等宿主填号（台词号填入的同一套，只是操作数位置不同）。关卡源 `objective: {"win": {...}, "lose": {...}}`（每句不超过 30 字）编成两条种类 `objective` 的文字和 story 镜像的 `objectives`，开场必须写 `3D65 127,127`（编辑器自动写）。
- 宿主：`text_record` 按种类生成原版格式的记录，日文逐字换成 ROM 字库的字形（`native_dialogue` 的字形表反查，字库没有的字用「・」），所以日文原版画面也能显示；`body_page` 遇到 0xC800 起的号直接取包里该语言的文字；`8008C9C0` 包装里，当前是写了自己目标的战役关卡时把 5694／5720 换成那两条文字的号。

### 5.8 对照原版各关脚本（2026-11-20）

## 6. 主线中间插新关（先不做，静态可行）

间章、外传关这类需求要「真正的新场景号」：场景号是一个字节，ROM 只有 0–142，新关用 143–255（113 个）。

**静态结论（2026-11-20，读 `build/recomp/cpu-bound/generated`，没有运行）：可行，而且比新机体编号简单，不用给表开窗口。** 原因是一关的数据几乎都经 `8009DE7C` 进引擎，宿主本来就在那里整块替换；按场景号的其他读者大多是「在名单里找这个号」，新号找不到就走普通分支。

直接读 `8010F5F0`／`F5F1`／`F5F2` 的指令全部看过（约 20 处读），按对新号的影响分：

| 读者 | 做什么 | 新号 143+ |
| --- | --- | --- |
| `8009DBE4`（只被 `8009DD58` 调） | 出击记录：`80233698[场景×4]` 减首项得 ROM 偏移，DMA 0x2000 字节 | **越界**，偏移是垃圾。要包装：新号不 DMA |
| `8009DC58`（只被 `8009DD58` 调） | 事件：在 `80250A88` 的指针链里数到第「场景」项；找不到时用未初始化的 `s2` 当偏移 DMA，栈上的指针表也不写结束符 | **越界**。要包装：新号不 DMA，指针表只写 −1 |
| `80209D6C` | 地图号＝`802195B0[场景×2]` | 读到表外（144 起落进地形属性表），值无意义但随后被宿主的地图钩子改写，无害 |
| `80209D90`（`801C7310` 调） | 标题卡号＝`802195B1[场景×2]` | 表外。原生标题卡已按战役标题画；原版界面模式要包装它 |
| `801CE0FC`、存档 `80091938` 起 | 标题文本 281＋`F5F1`；场景三个字节原样进存档 | 文本号落到别的词条上，宿主已有「场景号 → 标题」覆盖（`ui_text`），存档字节照存 |
| `801CDFB8`、`801D9F20`／`801D9F8C`／`801DA218`、`801C3174`、`801C3254`、`8020D920`、`801F498C`／`801F4F7C` | 14 项与 17 项名单、リンク 区间 0x6D–0x7A、等于 0x69／0x6A、区间 4–9 | 都是比较，不做下标，新号走普通分支 |
| `800A2574`、`800A027C` 起、`8020DB48`、`800803D0` 等三处 | 脚本取场景号、`3D4B`、过关抄 `F5F1`、读档重新登记 | 只搬字节；重新登记都走 `8009DD58`，同一个包装盖住 |

经基址 `8010F5E8` 访问的 6 处里没找到拿场景号做下标的；没搜到和 143 比较的指令。

要做的：

- **包装 `8009DBE4`、`8009DC58`**（新 `NATIVE_HOOKS`）：新号跳过原函数，返回空的出击块与只有 −1 的指针表，内容照旧由 `8009DE7C` 的钩子填。
- **包装 `80209D90`**，原版界面模式下给一张中性标题卡。
- **接进主线**：前一关的结束事件之后由 MOD 事件再写一次 `3D4B 新号`（后写的生效），新关的结束事件写 `3D4B 原来的下一关`。不用改任何表。
- **话数**：`3D4A`（`8020DB08`）每过一关 `8010F5EF` 加一。插入的关由宿主减回去，按间章显示，否则后面每一话的话数、按话数算的东西都会错位。
- **存档**：停在新关或它前后的场间时，存档里的场景字节是新号；没装这个 MOD 就读会走到上面的越界。宿主要在读档时拦住：没装时拒绝并说明，或按旁注里记的「原来的下一关」跳过这一关。只有这一段的存档依赖 MOD，过了下一关就恢复成原版号。

顺带的发现：

- **追加剧本也可以改用新号**，不再借原版场景号，借号的副作用（リンク 区间、「（前）」名单）就没有了，关数上限 113。
- **借号有硬编码副作用的线索**：`801F498C`／`801F4F7C`（战斗 overlay）在场景 4–9 且驾驶员号为 0xC4／0xC5 时提前返回 0；`8020D920` 对场景 0x6A、`801C3254` 对场景 0x69 有特判。示例战役借的是 1–4。这些分支具体做什么没读，只是线索。
