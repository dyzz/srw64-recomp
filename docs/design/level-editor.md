# 关卡编辑器：统一关卡格式、新地图与网页编辑器

2026-11-20。只是设计，没有实现，也没有为它做新的静态分析或实机；引用的地址与限制都来自[自定义战役](custom-campaign.md)与 [MOD 包](mod-packages.md) §7 的既有结论。标「待核实」的是这次新提出、还没看过代码的点。

## 2. 现状的问题

- **两套写法**。改主线用剧情脚本（`srw64.story.v1`：`when`／`if`／`do`，宿主触发，见 [MOD 包](mod-packages.md) §7.6）；追加剧本的关卡仍是迷你关卡格式（`srw64.mini-stage.v1`）：原版指令字、28 字节出击记录、手工借场景号。后者作者写不了，编辑器也没法对着它做。
- **新地图只有设计**（[自定义战役](custom-campaign.md) §6，阶段 C3 未做）。那份文档写「新资源号不能用，只能借号」；新机体那条线之后包已经能带自己的资源号（`mod_tables.hpp` 的 `publish_resources`、`80089BBC` 包装、`80089E9C` 上限放宽），这个前提过时了。
- **没有试玩回路**：要打包、装包、进战役、从头打到那一关。

## 3. 统一的关卡格式

一关四层，每层都能引用原版。改主线的剧情 MOD 是「只有事件层、其余引用原版」的特例，写法不变。

| 层 | 内容 | 编辑器里 |
| --- | --- | --- |
| 地图 | 尺寸、地形格、底图、战斗背景、BGM、宇宙标志 | 选原版地图、裁一块，或导入自绘底图（§4） |
| 部署 | 按组摆单位：人物、机体、等级、阵营、行动方式 | 在格子上拖；行动方式先用「照抄某条原版记录」（现有 `template`） |
| 事件 | 现有剧情脚本，`scene` 换成关卡名 | 开场、回合、击破、说服、胜败、结束 |
| 流程 | 关卡图、分支、开局部队、标题 | 连线；场景号由编译器从可借的号里自动分配 |

- **事件走宿主触发**：战役关卡的事件也按 §7 的方式由宿主触发，原版的 63 个事件／0x1A00 字节限制只剩开场、配置、结束三个原版位要守。
- **原版指令保留**：高层动作没覆盖的照旧直接写指令。
- **场景号不给作者看**：编译器从可借的号里分配（避开「（前）」13 个与 132、109–122），一个战役的关数上限因此约 115。
- **编译产物不变**：仍是 `srw64.campaign-image.v1` 与 `srw64.story-image.v1`，宿主的战役与剧情两套代码不用合并。
- **出击记录的未解释字节**（`byte8`／`raw14`／`raw16`／`raw18`／`raw26`）：编辑器不暴露，靠模板带过去；要做「行动方式」下拉得先解释这些字节，待核实。

## 4. 新地图

### 4.1 运行时

每关声明用到的地图，包括 `3D34` 换图的变体。登记关卡时宿主把它们填进地图记录表（`0x80219B1C`，158 条×12 字节）和按地图号的表（宇宙标志 `0x802180E0`、网格颜色 `0x80218510`、BGM），布局、图集、调色板用包自带的资源号。同一时刻只有当前关的地图有效，所以占用哪些地图号由宿主按关分配，不用作者借。

待核实：

- 战斗背景按调色板资源号查表（`0x80218A57 + 号`，只覆盖 6237–6263），包自带的调色板号落在表外，要另给环境字节。
- HD 地图按布局号认（`native_map.cpp` 的 `find_asset`），要能按 MOD 地图取图。
- 存档与中断记录里的地图号字节在读档重新登记后是否仍对得上。

### 4.2 两种做法

| 做法 | 作者成本 | 原版模式 | HD 模式 |
| --- | --- | --- | --- |
| 引用或裁剪原版地图 | 最低 | 现成 | 现成（裁剪时裁同一块底图） |
| 整张自绘大图 | 高 | 工具降级：k-means 到 ≤1024 图块＋256 色，原型 35.8 dB | 作者的大图整张绘制 |

- **不做图块拼图**（用户 2026-11-20）。编辑器里新地图就是「导入底图」：作者在别的软件里画好（或用图像生成），编辑器负责定尺寸、对齐网格、刷地形、标水面，并预览降级后的原版模式效果。
- **底图规格**：原版尺寸的 4 倍，与现有 HD 地图相同；水面要动时另给色号图（[自定义战役](custom-campaign.md) §6.4）。
- **地形**：每格刷地形号 0–98，外圈自动 99；属性表只有 100 条，不加新地形种类。
- **尺寸**：外圈 2 格边框；总览缩放在宽约 4256、高约 3200 像素以上除零；原版最大 960×720。

## 5. 网页编辑器

- **位置**：官网 `mods/` 下的静态页面，全部在浏览器本地运行，不上传任何东西。
- **源文件是纯 JSON**：可以直接交给 AI 写，编辑器负责可视化和校验；编辑器和 `tools/mods/` 的编译器对同一份源要给出同样的结果（校验规则只写一份，或用同一份测试用例对照）。
- **素材**：官网不放 ROM 里的素材。游戏用玩家自己的 ROM 导出一份编辑器素材包（地图缩略图、图块、单位图标、头像），编辑器从本地文件夹读。人物、机体、场景的编号与名称表官网已有（`mods/ids`）。
- **试玩回路**：编辑器把源目录直接存到游戏的 mods 文件夹（浏览器的本地文件夹访问只有 Chrome／Edge 支持，其他浏览器退回下载 zip）；游戏认未打包的开发包，F5 热重载，MOD 页加「从这一关试玩」，带预设部队直接进关。
- **页面**：地图（选原版图／导入底图、刷地形、标水面）、部署、事件（时机、条件、动作的表单，台词带头像预览）、流程（关卡图）。

编辑器当场校验的限制：

- 每阵营地图上最多 30 个单位（`8015E100` 表 3×30）；出击记录块不超过 0x2000 字节。
- 地图尺寸上限；原版模式最多 1024 个图块、256 色。
- 选项最多 3 个；台词每页 3 行、每行 14 字。
- 名册最多 140 台机体实例。
- MOD 台词号段 `0xC800`–`0xFFFF`，所有启用的包合计 14,336 句。

## 6. 主线中间插新关（先不做，静态可行）

间章、外传关这类需求要「真正的新场景号」：场景号是一个字节，ROM 只有 0–142，新关用 143–255（113 个）。

**静态结论（2026-11-20，读 `build/recomp/cpu-bound/generated`，没有运行）：可行，而且比新机体编号简单，不用给表开窗口。** 原因是一关的数据几乎都经 `8009DE7C` 进引擎，宿主本来就在那里整块替换；按场景号的其他读者大多是「在名单里找这个号」，新号找不到就走普通分支。

直接读 `8010F5F0`／`F5F1`／`F5F2` 的指令全部看过（约 20 处读），按对新号的影响分：

| 读者 | 做什么 | 新号 143+ |
| --- | --- | --- |
| `8009DBE4`（只被 `8009DD58` 调） | 出击记录：`80233698[场景×4]` 减首项得 ROM 偏移，DMA 0x2000 字节 | **越界**，偏移是垃圾。要包装：新号不 DMA |
| `8009DC58`（只被 `8009DD58` 调） | 事件：在 `80250A88` 的指针链里数到第「场景」项；找不到时用未初始化的 `s2` 当偏移 DMA，栈上的指针表也不写结束符 | **越界**。要包装：新号不 DMA，指针表只写 −1 |
| `80209D6C` | 地图号＝`802195B0[场景×2]` | 读到表外（144 起落进地形属性表），值无意义但随后被宿主的地图钩子改写，无害 |
| `80209D90`（`801C7310` 调） | 标题卡号＝`802195B1[场景×2]` | 表外。原生标题卡已按战役标题画；原版界面模式要包装它 |
| `801CE0FC`、存档 `80091938` 起 | 标题文本 281＋`F5F1`；场景三个字节原样进存档 | 文本号落到别的词条上，宿主已有「场景号 → 标题」覆盖（`ui_text`），存档字节照存 |
| `801CDFB8`、`801D9F20`／`801D9F8C`／`801DA218`、`801C3174`、`801C3254`、`8020D920`、`801F498C`／`801F4F7C` | 14 项与 17 项名单、リンク 区间 0x6D–0x7A、等于 0x69／0x6A、区间 4–9 | 都是比较，不做下标，新号走普通分支 |
| `800A2574`、`800A027C` 起、`8020DB48`、`800803D0` 等三处 | 脚本取场景号、`3D4B`、过关抄 `F5F1`、读档重新登记 | 只搬字节；重新登记都走 `8009DD58`，同一个包装盖住 |

经基址 `8010F5E8` 访问的 6 处里没找到拿场景号做下标的；没搜到和 143 比较的指令。

要做的：

- **包装 `8009DBE4`、`8009DC58`**（新 `NATIVE_HOOKS`）：新号跳过原函数，返回空的出击块与只有 −1 的指针表，内容照旧由 `8009DE7C` 的钩子填。
- **包装 `80209D90`**，原版界面模式下给一张中性标题卡。
- **接进主线**：前一关的结束事件之后由 MOD 事件再写一次 `3D4B 新号`（后写的生效），新关的结束事件写 `3D4B 原来的下一关`。不用改任何表。
- **话数**：`3D4A`（`8020DB08`）每过一关 `8010F5EF` 加一。插入的关由宿主减回去，按间章显示，否则后面每一话的话数、按话数算的东西都会错位。
- **存档**：停在新关或它前后的场间时，存档里的场景字节是新号；没装这个 MOD 就读会走到上面的越界。宿主要在读档时拦住：没装时拒绝并说明，或按旁注里记的「原来的下一关」跳过这一关。只有这一段的存档依赖 MOD，过了下一关就恢复成原版号。

顺带的发现：

- **追加剧本也可以改用新号**，不再借原版场景号，借号的副作用（リンク 区间、「（前）」名单）就没有了，关数上限 113。
- **借号有硬编码副作用的线索**：`801F498C`／`801F4F7C`（战斗 overlay）在场景 4–9 且驾驶员号为 0xC4／0xC5 时提前返回 0；`8020D920` 对场景 0x6A、`801C3254` 对场景 0x69 有特判。示例战役借的是 1–4。这些分支具体做什么没读，只是线索。

待实机：新号下的世界地图开场、过关存档、读档、GAME OVER 重试、自动存档、本关情报页；`801C3174` 那张 17 项名单的用途；话数减回去后场间与存档列表的显示。
