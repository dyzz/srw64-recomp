# SRW64 原版 Bug 与易混淆行为登记

调查日期：2026-09-16。范围：网上公开的《スーパーロボット大戦64》报告，供本项目日版 Rev 0 原版对照和复现使用。**这是报告清单，不是本项目已经验证或修复的 Bug 清单，也不宣称收全。** 本轮没有运行游戏复现、确认代码原因或更改游戏规则。

来源包含玩家直接报告、个人攻略及社区 Wiki。多站记载不等于独立验证；转载关系、ROM 版本和使用实机／模拟器往往不明确。攻略中的“本来应当”也不能直接作为修正公式，尤其不能套用其他机战作品的规则。来源均于上述日期检索；视频仅核对到说明和章节信息，未逐帧核验。

“+64”“+32”等沿用资料记法，本轮没有确认它们是内部能力值、最终命中率百分点还是中间修正项；不能在实现中直接乘百分比。底力的暴击加成也必须独立测量，不能从命中／回避问题推断暴击同时有 Bug。

**2026-09-17 更新（BUG01–04）**：已在代码里找到原因，并做成默认关闭的可选规则修正，见[可选规则修正](rule-fixes.md)。要点：超能力、圣战士的补正函数是空函数，调用方拿到的是技能标志位本身（64、32），直接加减在命中率百分点上，与等级无关，等级 0 也生效；超能力攻守两侧都有，圣战士只有守方；两者在伤害公式里都没有攻击力项。限界只用于状态页警告色、改造和 EW 条件，命中公式不读。底力表最高 90，HP 档位比两份资料提前一档，命中、回避、暴击三处取同一个值；“2 倍”的说法与代码最大值对不上，减半修正只作为弱依据选项提供。实机探针已按公式核对各修正的数值变化。

**2026-09-18 更新（BUG05）**：已复现并在代码里确认原因，**作为默认生效、没有开关的基础修复**，见[基础修复](base-fixes.md)。要点：敌方单位的驾驶员记录 `+0x14` 是假身次数，我方单位的同一字段是击坠数；W 系五名驾驶员另有持久击坠备份表 `801614E0`，`800A5054` 在新建驾驶员记录时把备份写回 `+0x14`，用于离队再加入后保留击坠数，但它不检查阵营。五飞的两条敌方部署记录都没有假身位，所以他敌对时的假身次数就是此前在我方的累计击坠数（上限 999，不是固定 21）。消耗假身不影响备份，再加入时击坠数照常恢复。

## 3. 复现设计（本项目拟定，尚未执行）

| 对象 | 最小实验与需要保留的证据 |
| --- | --- |
| BUG01 超能力 | 同一交战条件逐一改变技能等级，分离驾驶员成长、地形、气力、精神、恋爱／友情补正；记录命中显示值、实际结算输入、回避和非暴击伤害。必须覆盖有技能／无技能及敌我双方，避免 0%／100% 钳位掩盖差异。 |
| BUG02 圣战士 | 独立测试回避、指定武器攻击力、屏障阈值；技能 L1/L5/L9 的对照不能只靠一次命中或一次伤害。保留基础武器值与结算补正，核对屏障的适用武器和资源条件。 |
| BUG03 底力 | 技能等级与 HP 比例二维对照，在 10%、20% 等边界前后各取一值；排除取整差异，分别记录命中、回避、暴击，不预先写死 +90 或 +100。 |
| BUG04 限界 | 选总能力低于／高于限界的反例，单独改变限界；对照红字、交战预览、实际结算及 EW 全改造资格。 |
| BUG05 五飞 | ~~建立不同击坠数的离队前检查点，经同一路线敌对事件，统计实际假身消耗~~；已用迷你关卡 `wufei-dummy.json` 在一关内走完「我方击坠→离队→敌方登场」并核对字段，见下方更新。原路线上不同击坠数的对照与再加入后的结果仍未覆盖。 |
| BUG06 万丈 | 男女真实系×OZ 为报告正例，超级系×OZ、真实系×独立军为候选反例；保留加入事件前后名单、可出击列表、路线旗标和后期分歧状态。 |
| BUG07 施皮格尔 | 离队前分别设置可区分的机体／武器改造段数，记录部件实例；逐次再加入后核对，检查新旧单位实例与初始化调用，不用一份备份覆盖所有再加入。 |
| BUG08 武器继承 | 在旧机不同武器上设置不同改造级数，经真实换机脚本逐一比对武器 ID、名称、改造值和基础威力；至少覆盖攻略列出的 OZ／独立军换机路径。 |
| BUG09 部件越界 | 使用隔离存档，在部件数大于槽位数的整备页面测试 A／上同帧及相邻帧输入。先观测光标与写入边界，再核对部件库存、机体／驾驶员字段；不以是否死机为唯一判断，不对常用存档运行。 |

共同要求：锁定 ROM 身份，记录宿主构建、输入、检查点及原版参考环境；区分原版缺陷和 recomp 引入的缺陷。诊断中修改单一变量必须标注为受控实验，不能伪装成正常流程取得的状态。保留原版随机时序；呈现时间导致的 RNG 差异单独报告。

## 4. Wing→EW：先拆清“换机”和“继承”

### LEAD01：具体哪件武器出错仍未知

Reddit 转述没有给出武器名称。当前资料足以建立核查表，**不足以声称已经找到“EW 武器继承 Bug”的具体原因**。

| 情形 | 现有资料与处理 |
| --- | --- |
| W 前期机→TV 后期机 | Akurasu 记载不继承旧改造、后期机自带三段。这是换机规则候选，不等同于后期机→EW 的丢失。[S8] |
| TV 后期机→EW | 日文攻略记载机体全项改满触发。武器变化与部分继承并存；应逐项核查，不能只比较总战力。[S11] |
| EW 中消失的武器 | 重点核对沙漠的远程武装、死神的 Buster Shield、重装的 Army Knife、双头龙的 Beam Cannon；“无后继武器”不直接等于程序漏拷贝。[S11] |
| EW 自带额外 MAP 武器 | 零式和重装的追加 MAP 武器可能在机体全改后直接取得，不以先改满对应武器为前提；列为原版行为核查，不擅自去掉。[S11] |
| 自动出击后部件不在机体上 | Akurasu 记载换机并自动出击时会卸下部件。应先检查库存，不能把“卸下”误报为“销毁”。[S8] |

### QOL01：换机预览与确认（计划）

EW 并非对所有使用方式都单向变强：资料记载部件槽可能减少，沙漠／死神射程缩短，双头龙失去远程炮。[S11] 这支持增加确认页，但不证明这些变化本身是 Bug。

设计要求由本项目提出：

- 在触发换机的最后一项改造付款前，显示前后能力、武器增减、射程／消耗、武器改造继承和部件去向；允许隐藏后继机名称。
- 取消时资金、改造、武器、部件、旗标均不改变；确认时重新校验实际条件，一次性提交。
- 默认仍按原版门槛触发；如果另提供“机体已全改，但暂不换 EW”，这是额外的行为选项，需要定义资格保留、再次触发和存档，不悄悄混入确认页。
- 预览只展示已核验映射；未知项目明确标记，不默认全继承，不自动退款，不复制消失的武器或部件。
