# Link Battler 联动：F91、ゴーショーグン、ザンボット3 如何开放

2026-09-19。本文基于锁定的日版 Rev 0 `rom.z64` 做静态分析：常驻代码的 GB Pak 驱动层、整备画面 overlay `load_0008F4B0`（ROM `0x8F4B0`，VRAM `801C4500`；表的 ROM 偏移 = VRAM − `0x801C4500` + `0x8F4B0`），以及 `assets/original-data/records` 里场景 109–122 的脚本和部署记录。社区资料对照 [Akurasu Wiki：Link Battler Units][wiki]（同日检索）。**本轮没有运行游戏，也没有 Link Battler 的卡带或存档可以对照**，需要运行才能定论的条目列在第 8 节。

## 1. 结论摘要

| 结论 | 依据 |
| --- | --- |
| 游戏里没有"解锁标志"。联动做的是**把下一关改成一个插入关**：原定的下一关存进 `8010F5F2`，`8010F5F0` 改成联动关；打完联动关，脚本用 `3D4B 500` 回到原定的下一关 | `801D9F80`；场景 109–122 的结束事件 |
| 开放单位是**按作品**判定的，共 3 位：F91 系（位 1）、ゴーショーグン（位 2）、ザンボット3（位 4）。7 种组合各对应一个联动关，每个联动关有两个版本（按原定下一关是否在宇宙选择，推断为地面版和宇宙版），共 14 个场景 | 表 `D_801DCABC` |
| 某作品要开放，需同时满足：64 这边还没有该作品的机体；GB 存档里有该作品的机体位或主角驾驶员位之一 | `801D9F80` |
| 联动关里以我方部署登场：F91＋シーブック、ビギナ・ギナ＋セシリー；ゴーショーグン＋真吾；ザンバード＋勝平、ザンブル＋宇宙太、ザンベース＋恵子（开场合体为ザンボット3） | 场景 109–122 的部署组 1 |
| 进度变量 var48（F91）、var49（ゴーショーグン）、var50（ザンボット3）在联动关结束时写 0，之后主线 23 个事件只用它们来加一段已加入角色的对白 | `3E13 48/49/50,0`；`3E03`／`3E02` 的读取点 |
| 同一次联动还会做两件事：两边都有的驾驶员经验值取较大者（"等级对齐"）；把 64 的 12 名驾驶员和 18 台机体写进 GB 存档 | `801D975C`、`801D992C`；`801D9B54`、`801D9D70` |

## 2. 流程

1. 整备画面选中联动项并确认（`load_0008F4B0:801CE318` 分支，画面状态 8）。先清空 4 KB 缓冲区（`801D9300`），再调用 `801D93C4` 检查卡带，只有返回 0 才进入联动画面，否则转入错误画面（状态 `0x16`）。
2. 联动画面初始化（`801D6FF4`）调用主流程 `801D5B10`：
   1. `801D9544`：读取 GB 数据块并校验（第 3 节），再由 `801D975C` 列出两边都有的驾驶员；
   2. `801D9B54`／`801D9CF4`、`801D9D70`／`801D9ECC`：把 64 有而 GB 没有的驾驶员、机体登记进数据块，只要有新增，就由 `801D966C` 写回卡带（第 6 节）；
   3. 再读一次数据块；
   4. `801D9F80`：判定要开放哪些作品，并改写下一关（第 4 节）；
   5. 按等级降序排列共有驾驶员的列表，每页 7 人。
3. 玩家在列表里确认等级对齐（`801D70FC` → `801D62D0` → `801D966C`），对齐结果随即写回卡带（第 6 节）。

第 2.4 步不依赖第 3 步：只要读卡成功，下一关就已在内存里改好，之后的等级对齐做不做都一样。

## 3. 卡带识别与数据块

**卡带识别**（常驻 `80090F44` → `osGbpakInit`、`osGbpakReadId`；`800910C4` 比较）：卡头标题区 16 字节必须等于 `S ROBOT LB\0AL6J\x80`（标题、产品码 `AL6J`、CGB 标志 `0x80`），厂商码两字节必须是 `44 39`（ASCII "D9"）。期望值存放在常驻数据 `800C69E0`。

`801D93C4` 的返回值：

| 值 | 含义 |
| --- | --- |
| 0 | 是 Link Battler |
| 1 | 卡头不符（不是 Link Battler） |
| 2 | 其他 Pak 错误（例如未插 Transfer Pak） |
| 3 | Pak 在，但没有插 GB 卡带（`osGbpakInit` 返回 12） |
| 5 | 通讯失败（返回 4） |

2、3、5 的含义按 libultra 的 PFS 错误常量推断，未对照错误画面文字。

**SRAM 访问**：常驻 `80091120` 先往 GB 地址 `0x6000` 写 `0x01`，再往 `0x0000` 写 `0x0A`（打开卡带 RAM）。`80091284(读/写, 线性地址, 缓冲, 长度)` 把线性地址拆成 RAM bank（地址 >> 13，写 `0x4000` 切换）和 `0xA000` 窗口内偏移，按 8 KB 分段读写。联动固定传入线性地址 `0xA000`、长度 `0x1000`，也就是 bank 5 开头的 4 KB。Link Battler 实际的 SRAM 容量没有核对，bank 编号在卡带上如何回绕未确认。

**数据块格式**（缓冲区 `801DDAA0`）：

| 偏移 | 内容 | 使用者 |
| --- | --- | --- |
| `+0x000` | 魔数 `ROBOT_TAISENN_GB`（16 字节） | `801DAEAC` 校验 |
| `+0x010` | 64 → GB 的驾驶员位图（12 位） | `801D9CF4` 写 |
| `+0x018` | 64 → GB 的机体位图（22 位） | `801D9ECC` 写 |
| `+0x020` | GB 持有的驾驶员位图（92 位，按表 `D_801DCB90` 对到 64 的角色编号） | 等级对齐、开放判定 |
| `+0x02D` 起 | GB 持有的机体位图 | 开放判定、`801D9D70` |
| `+0x138 + 2i` | GB 第 i 名驾驶员的经验值，u16 小端 | 等级对齐 |
| `+0x9B9` | 魔数 `LINK_BATTLER_V00`（16 字节） | `801DAEAC` 校验 |
| `+0x9C9` | 前 `0x9C9` 字节之和，u16 小端 | 写回前由 `801D98EC` 计算 |

读取时只检查首尾两个魔数，不核对校验和。

## 4. 开放判定：`801D9F80`

1. **沿用已排定的联动关**：如果 `8010F5F0` 已经是 109–122 之一（本次整备之前联动过），先把该场景对应的作品位并入本次结果。
2. **64 已有的作品**：扫描我方机体实例表 `8016A210`（140 × 0x54），机体编号 42 F91 或 289 ビギナ・ギナ → F91 系已有；184 ゴーショーグン、206 ザンボット3 同理。已有的作品不再检查 GB。
3. **GB 条件**：对还没有的作品，以下任意一位为 1 即开放：

| 作品 | 位 | GB 机体位（`+0x2D` 起，字节／掩码） | GB 驾驶员位（`+0x20` 起） |
| --- | --- | --- | --- |
| F91 系 | 1 | 3／`0x10`、16／`0x02` | 第 23 位 シーブック、第 80 位 セシリー |
| ゴーショーグン | 2 | 11／`0x40` | 第 55 位 真吾 |
| ザンボット3 | 4 | 12／`0x08` | 第 59 位 勝平 |

   驾驶员位经表 `D_801DCB90` 确认对应 64 的角色 41、230、133、152。F91 系的两个机体位按结构推断为 F91 与ビギナ・ギナ，Link Battler 的机体编号没有核对。常量在 `D_801DCD04..D_801DCD13`。

4. **改写下一关**：结果非 0 时，若第 1 步没有沿用旧联动关，先把 `8010F5F0` 保存到 `8010F5F2`；再按 `D_801DCABC` 选场景写入 `8010F5F0`：

| 作品位 | 场景 | 标题 |
| --- | --- | --- |
| 1 | 109／110 | F91発進 |
| 2 | 111／112 | ゴーショーグン発進せよ! |
| 4 | 113／114 | ザンボット3出現! |
| 1+2 | 115／116 | 合流 |
| 1+4 | 117／118 | 合流 |
| 2+4 | 119／120 | 2つの大きな力 |
| 1+2+4 | 121／122 | 新しき同志 |

   选前一个还是后一个由 `801D9F1C` 决定：原定的下一关（已处在联动关时取 `8010F5F2`）若在表 `D_801DCAD8` 的 52 个场景中，就用后一个。这 52 个场景从「偽りの平和」「激闘!ラビアンローズ」到「決戦宙域 （後）」，按标题看都在宇宙。前一个版本用地图 52，后一个用地图 114，世界地图终点分别是地点 117 和 122。因此推断前一个是地面版、后一个是宇宙版，地形未实机确认。

同一次整备里多次联动，作品位只会累加，`8010F5F2` 保留的始终是第一次联动前的下一关。

## 5. 联动关与后续

场景 109–122 共用 7 套脚本（每对共用一套），结构相同：

- **开场**：按当前场景索引选择世界地图起点和终点；新加入的角色对话后切换到战场；胜利条件、败北条件为 `3D65 17,41`；部署敌方组 0，再部署我方组 1。有ザンボット的版本最后执行 `3D5C 152,1`，让勝平的ザンバード合体。
- **败北**：シーブック（41）、セシリー（230）、真吾（133）等新加入角色被击破时游戏结束（类型 2 触发）。
- **胜利**：敌全灭 → `3D4A`。
- **结束**：给参战作品写 `var48`／`var49`／`var50` = 0，然后执行 `3D4B 500`，从 `8010F5F2` 恢复原定的下一关。

主线读取这三个变量的位置只有 `3E03 变量,0`／`3E02 变量,0` 条件对白，例如「宇宙の呼ぶ声」「悪夢、再来」「生命、散って」等关；「悪夢、再来」结束时チャム会按三者的组合说出 7 种台词中的一种。三个变量都不控制入队，入队由联动关的我方部署完成。

## 6. 双向的数据交换

**等级对齐**（`801D975C` 列表，`801D992C` 执行）：对 GB 驾驶员位图里的每一位，按 `D_801DCB90` 在我方驾驶员表 `80172F40`（100 × 0x4C）中找同一角色。表中有两对别名：36 アムロ 也匹配 262，96 ミリアルド 也匹配 286 ゼクス。比较的是驾驶员 `+0x12` 的经验值：

- GB 较低 → 把 64 的值写进数据块；
- 64 较低 → 64 的经验改为 GB 的值，等级 `+5` 改为联动画面预先算好的值，再由 `800A7F8C` 重算能力。合体机的队友加上同样的经验差，由 `800A630C` 按新经验换算等级，队友分组见表 `D_801DCA88`：忍（沙羅、亮、雅人）、豹馬（大作、ちずる、小介、十三）、勝平（恵子、宇宙太）、真吾（キリー、レミー）、マナミ（ローレンス、アイシャ）。

`801D62D0` 可以只对齐光标所在的一人，也可以按列表 `D_801DD5D0`（以 `0xFF` 结尾）批量对齐；这张列表如何填写没有追踪。确认后 `801D966C` 重算校验和并写回卡带。

**64 → GB**：

- 驾驶员（`D_801DCC48`，12 名）：アーク、セレイン、ブラッド、マナミ、エルリッヒ、リッシュ、カーツ、デューク、マリア、ひかる、キリカ、ナイーダ；
- 机体（`D_801DCC78`，22 槽中 18 台有效）：ソルデファー、アシュクリーフ、ノウルーズ、スヴァンヒルド、ラーズグリーズ、シグルーン、スイームルグ、スイームルグS、アルトロンガンダム、ウイングゼロ、ガンダムサンドロック改、ガンダムデスサイズH、ガンダムヘビーアームズ改、グレンダイザー、真・ゲッター1、アースゲイン、スーパーアースゲイン、ヴァイローズ。

条件是 64 的我方表里有，而 GB 的持有位图（`+0x20`／`+0x2D`）里没有；满足时写入 `+0x10`／`+0x18`。跳过带 `0x80` 标记的驾驶员槽和 `+0xC` 带 `0x40` 标记的机体实例。Link Battler 如何使用这两张位图不在本 ROM 内。

## 7. 与攻略的对照

| Akurasu 的说法 | 代码 |
| --- | --- |
| 在 Link Battler 里买下单位，接上 Transfer Pak，在整备画面选联动 | 一致。实际条件是 GB 存档里有对应的机体位**或**主角驾驶员位，任意一个就会带来该作品的全部角色和机体 |
| 联动会让两边共有驾驶员的等级持平 | 一致，比较和改写的是经验值；需要玩家在列表里确认 |
| 下一关是介绍新单位的特别关「新しき同志」，会随开放数量变化 | 一致。「新しき同志」只是三作齐全时的标题，其他组合分别是 F91発進、ゴーショーグン発進せよ!、ザンボット3出現!、合流、2つの大きな力；另有地面、宇宙两个版本 |
| 新加入的驾驶员等级按部队平均调整 | 部署记录有"等级偏移"字段（0／1），平均等级的计算没有在本轮追踪 |
| 解锁后可以使用这些作品的 BGM 和卡拉 OK | 本轮没有追踪 |

## 8. 需要运行或外部资料才能确认

- 地面、宇宙两个版本的实际地形。
- 选联动时的画面文字，以及错误码 2、3、5 各自对应的提示。
- 64 这边"已拥有"只认机体编号 42／289／184／206。如果这些机体全部被出售或离队，再次联动是否会重新排入联动关；ザンボット3在整备时是否始终以 206 号实例存在（而不是分离后的三机）。
- Link Battler 存档是否真在 RAM bank 5，以及 `+0x2D` 机体位图的编号。这些需要 Link Battler 的 ROM 或存档。
- 原生宿主原先没有 Transfer Pak，`osGbpakInit` 依赖的部分 SI／ContRam 例程在生成代码里是显式中止陷阱（`funcs_unsupported.c`），选联动静态看会让宿主中止。第 10 节的虚拟卡带替换了整个驱动层，这些例程不再被调用。

`801DA52C..801DAA28` 另有一组读卡、校验、写回函数，由 `801DABE4` 经函数表 `D_801DCB10` 驱动。全 ROM 找不到对 `801DABE4` 的调用或地址引用，可能是未接入的测试入口，本文不计入流程。

## 9. 对 M2 的含义（规划时）

对应[原生增强方案](../design/native-enhancements-plan.md)的 M2：

- **可选内容开放 Mod**：所需的脚本、部署、地图和对白都在 ROM 里，不依赖 GB 数据。在整备画面按第 4 节的规则写 `8010F5F2`／`8010F5F0`，就能排入联动关，之后由原脚本完成加入、写变量和回到主线。这个做法不涉及 Transfer Pak 协议，也不会有等级对齐和 64 → GB 的写回。
- **兼容原联动**：需要让宿主提供 Transfer Pak，并模拟 `osGbpak*` 下层的 SI 读写；数据层面只涉及上表的 4 KB 数据块、两个魔数和写回时的校验和。

最终采用的是第 10 节的做法：保留原版联动画面，只把读卡换成玩家勾选。

## 10. 原生版的处理

2026-09-19 实现，已编译并通过单元测试，同日用调试接口实机核对了联动页、原版画面和返回（见本节末）。

**流程**：整备菜单选「リンク」→ 原生联动页（版式同主角选择页）→ 玩家勾选作品 →「进入联动」后运行原版联动画面（共有驾驶员列表、オートリンク）→ B 返回菜单。下一场战斗前插入对应的联动关，打完回到主线，与原版一致。「返回」按原版 B 键的路径回到整备菜单，不改变下一关。

**联动页**（`link_page.cpp`，RmlUi 页面在 `src/native/ui/frontend.cpp`）：三张作品卡片，分别显示主驾驶员大头像、作品名、机体和同行驾驶员小头像。←→ 切换，空格／Z 或点击卡片勾选，Enter 继续，Esc／X 返回。卡片有三种状态：

| 状态 | 判定 | 显示 |
| --- | --- | --- |
| 已加入 | 变量（48／49／50）为 0，或我方有该作品的机体 | 变灰，不能勾选 |
| 已排定 | 下一关已是包含该作品的联动关 | 锁定为勾选 |
| 可选 | 其余 | 可勾选 |

"已加入"比原版多看一个变量：原版只看机体，机体卖掉后再联动会重新排入联动关；这里以变量为准，不会重复加入。头像由 `name_assets.py` 从 ROM 头像表（按角色号）解出：シーブック、セシリー、真吾、キリー、レミー、勝平、宇宙太、恵子，其中シーブック和セシリー是 97×97。

**时机**：联动画面的初始化 `801D6FF4` 会读卡。钩子先不执行它，而是打开联动页，每帧更新 `801D70FC` 在等待期间跳过。玩家确认后生成数据块，再调用原版初始化。取消时照 `801D7148` 的 B 键处理：播放音效 `0xB8`，把 `801DECB8` 写成 0，调用 `80099814(5,1,2)` 转场回菜单。

**虚拟卡带**（`link_battler.hpp`，`game_hooks.cpp`）：常驻驱动的 6 个函数被替换：`80090F44` 初始化、`80090FA0` 状态、`80090FC4` 电源、`800910C4` 卡头比较、`80091120` 打开 RAM，都直接返回 0；`80091284` 的读写落在宿主内存里的 4 KB 数据块上。数据块内容：

- 首尾两个魔数；
- 驾驶员位图和经验值镜像玩家自己的驾驶员（按 `801D975C` 的匹配规则，包括アムロ、ゼクス别名），所以原版列表照常出现，等级对齐不会改变任何人；
- 勾选且未加入的作品，置其主驾驶员位（シーブック 23、真吾 55、勝平 59），交给原版 `801D9F80` 判定和改道；
- 四个作品关键位（23、80、55、59）不参与镜像，机体位图全为 0。
