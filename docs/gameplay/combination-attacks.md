# 合体技：数据、判定与显示

日期：2026-10-21。状态：**静态分析（代码与 ROM 表）＋场间能力页与地图状态页已实现；地图状态页 2026-10-21 实机通过，场间页只过了离线排版审计**。本文回答「机体的数据里什么情况才会显示合体武器」，并记录把它改成「一直显示、提示缺的搭档」的做法。地址均为原版（`load_000AB160` 战术 overlay，vaddr − `0x801C2600` + ROM `0xAB160`）。

## 1. 什么是合体技

- 武器 ROM 记录（`0x74E90`，16 字节）`+0xF` 标志字节的 **位 0x02** 标记合体技；`800A6A68` 把它抄进武器实例 `+0x22`（位 0x04 是「未解锁」，两位相邻）。ROM 里带这个位的是 1215–1217、1219–1232、1237–1244 共 25 件（1218 無影脚、1233–1236 不是）。
- 合体技在机体武器表（`0x7E210`）里和普通武器一样列着，带五个形态槽。所以 ゴッドガンダム（1）和 ゴッドガンダムH（2）都「有」ダブルゴッドフィンガー，但只有 H 形态能用（见 §2 的参加者表）。
- 合体技不走改造：改造类型 `+0xE` 为 0，威力每次打开武器列表时重算（§2），ROM 里的基础攻击力（1215 为 3800 等）只是没有搭档数据时的占位。

## 2. 判定流程（地图上）

**入口 `8020178C(handle, unit, 0)`**：每次打开武器列表时调用——机体状态页 `801CD718`（`機体データ`）和攻击列表 `801F8F1C` 各一处。对机体武器数组里每件带 0x02 的武器：

1. 在 25 项武器号表 `D_80218A6C`（u16）里找到它的下标 i；
2. 机体当前 EN（`+8`）≥ 武器消費EN（`+0xD`）才继续，否则结果 0；
3. 调用函数表 `D_80219444[i]`（每件合体技一个包装函数 `80200AB4`…`80201724`，都转调 `80200530`，石破ラブラブ天驚拳 的 `80200B1C` 另加一步）；
4. 返回值非 0：写进武器实例威力 `+0x06`，并**清**锁定位 0x04；返回 0：**置**锁定位。

所以合体技的「可用／不可用」就是锁定位，每次开列表重写；剧本 `3D6F 1215` 的解锁没有持久效果（[隐藏要素](hidden-elements.md) §6.5）。

**`80200530(handle, unit, weapon, rows, i)`**：

- `rows` 是参加者表，每行 14 字节：`s16 id`、`u8 by_pilot`、`u8 搭档数`、`s16 搭档[4]`、`s16 机体`，`-1` 结束。首行的 `by_pilot` 决定整张表怎么读：0 按**机体号**找本机那一行；1 按**主驾驶员号**找行，且本机机体号必须等于行的 `+0xC`（ジェットストリームアタック 等敌方组合技用这种）。找不到行 → 0。
- 每个搭档用 `801E9514(阵营, by_pilot, id)` 在**同阵营句柄表**（`0x8015E100 + 阵营×0x258`，30 项 × 0x14，`+0`＝1 在场、`+0xC` 机体实例）里找**第一个**在场的该机体（或该驾驶员；此时它的机体号也要等于行 `+0xC`）。找不到 → 0。
- 把本机和各搭档的坐标（`0x800FFA74 + 句柄×0xC4` 起的两个 float，格 16）两两比较，|Δx|≤16 且 |Δy|≤16 算相邻（八方向），`801E966C`／`801E95DC` 做连通检查：全员连成一片即可，三台以上不必两两相邻。不连通 → 0。
- 每个参加者（含本机）：机体 EN ≥ 武器 `+0xD`、主驾驶员气力 ≥ 武器 `+0xE`；武器 `+0xF`（必要技能号）≥ 2 时还要 `801E6214` 通过。任一不满足 → 0。
- 威力：`D_80218AA0[i]`（24 字节：5 组 `(机体号, 该机的组成武器号)` ＋ float 倍率）。对每个参加者找它的组成武器，在它的武器数组里取**当前威力**（含改造），求平均再乘倍率，截断为整数。机体不在 5 组里，或它的武器数组里没有那件武器 → 0。

**附加条件**：

- マジンガー／ゲッター／ダンバイン 系的包装函数再调 `80200404(表)`：表是若干行驾驶员组合（10 字节：`u8 人数`、`s16 驾驶员[4]`），参加者的**主驾驶员**里必须凑齐其中一行。
- 石破ラブラブ天驚拳（`80200B1C`）还要求武器池（`0x80178F80`，700 × 0x24）里第一件在用的 石破天驚拳（19）没有锁定位——即跟着 `3D6F 19` 的剧情解禁走。

## 5. 能力页的做法（已实现，未实机）

- 数据读取：[`combo_attacks.hpp`](../../src/host/combo_attacks.hpp) 从 ROM 读武器号表、函数表、参加者表、威力表与驾驶员组合表（25 个包装函数到各自表的对应写死在表里，函数表只用来定下标）。
- 列表：[`ability_page.cpp`](../../src/host/ability_page.cpp) `weapon_indexes` ＝ 原列表 ＋ 武器数组里带 0x02 且五个形态槽含本机号的武器；翻页、光标按合并后的件数算。
- 每件合体技的 `combo` 字段：`forms`（本形态不在任何领队行时，列出能领队的形态）；否则 `partners[]`（名字、`present`、`pilot`）、`pilots_ok`、`ok`、`power`。「在部队」按 `801C4FB0` 的口径：机体实例在、`+0xC` 没有 0x40；按驾驶员找时，驾驶员记录在、所乘机体号等于行 `+0xC`。威力按 §2 的平均×倍率算，不在部队的搭档用 ROM 基础值代入。石破ラブラブ天驚拳 另需的解禁**不提示**（用户 10-21：不用处理）。
- 画面（用户 10-21 定稿）：用不了的行灰字；六行武器与详情之间的空带一行小字「搭档：A、B（需在 1 格内）」——搭档名红色，整行在用不了时灰、能用时白；本形态不能领队时改为「仅 X 可用」；驾驶员组合不符时第二行写明。详情面板的「必要技能」格显示「合体技」。离线排版审计（`run_audit.py --only ability-weapons`，样例 `weapons-combo`）三语无溢出。
- 词条 `ability_combo`／`_with`／`_forms`／`_pilots`／`_sep`／`_range`（三语，`profile.py` 的 `UI_KEYS`）。
- 攻击列表 `801F8F1C` 不改：它只列打得到目标的武器，列出用不了的合体技反而误导。

### 5.1 地图 機体データ 武器页（已实现，实机通过）

- 钩子：`generate_cpu.py` 的 `NATIVE_HOOKS` 新增 `801E6410`→`srw64_original_weapon_page`、`801E61BC`→`srw64_original_page_reset`、`801E7430`→`srw64_original_status_pages`（三页的分发器，换页时清提示；机体页 `801E55FC` 不经过 `801E61BC`）；包装在 [`game_hooks.cpp`](../../src/host/game_hooks.cpp)，逻辑在 [`map_combo.hpp`](../../src/host/map_combo.hpp)。
- `801E6410(enemy, page, row, weapons; unit, pilot, flag)` 每次重画整页（光标移动走 `801E79B8` 也重画）。包装在调用前找出本机（栈 `+0x10`）的合体技（`+0x22` 位 0x02、形态槽含本机号），逐件算状态，再清掉锁定位 0x04 让原函数列出来，返回后把标志字节恢复原样。
- 状态按 `80200530` 的顺序算：领队行（没有→「仅 X 可用」）；搭档用原函数 `801E9514(阵营, 按驾驶员, 号)` 找同阵营第一个在场的（按驾驶员找时还要坐在行里的机体）；全员按句柄坐标（`0x800FFA74 + 句柄×0xC4`，取整，±16 含）连通；每人 EN、气力、必要技能（`801E6214`）；驾驶员组合表。任一不满足即「用不了」。本机句柄从句柄表反查（`0x8015E100 + 阵营×0x258 + 槽×0x14`，`+0xC` 机体；句柄＝0x42／0x60／0x7E＋槽）。
- 重画：原函数把每行四个句柄放在 `802271DE + 行×4`（名／威力／射程／命中），本页行序＝数组顺序里本形态的、非敌方的 kind 1、未锁定的武器，每页 7 行，y = 0x2F + 16×行。不可用的合体技行用同样的文本号 `0xA8B+武器号` 和格式串（`%4d`、`%d_%2d`、`$%2d`／`+%2d`／`-%2d`）以调色板 2（资源 4 的暗灰）重画四格——这页自己的「不可用」调色板 1 画出来是红色，实机确认。
- 提示：`ui_text::set_extra_line`（新加的多色一行，分段各自量宽后依次排开，超宽整体收缩）在 (0x1C, 0xE0) 宽 0x10C 画「搭档：A、B（需在 1 格内）」，搭档名红、其余灰（用不了）或白（能用）；必要技能格 (0x108, 0xBC) 用 `set_extra` 写「合体技」。清除时机：`801E61BC` 页面重置、`801E7430` 换页、驾驶员页 `801E6C5C` 画过、每帧发现不在战术模式。多段排版的量宽要减去描边边距（`width(a)+width(b)-width(ab)`），否则段间空隙过大（实机第一次看到）。日文原版字体模式下 `ui_text` 不画宿主文字，提示不出现，行仍列出。
