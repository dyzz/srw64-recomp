# 可选规则：修正与难度调整

日期：2026-09-17（2026-09-18 增加菜单栏实时切换、试玩默认开启修正类，加入头目假身与改造上限的难度调整，补上圣战士奥拉武器威力，加入离队退款）。对应[原版 Bug 登记](original-bug-register.md)的 BUG01–04 与 BUG08；BUG05（五飞假身）已定为默认生效、没有开关的[基础修复](base-fixes.md)，不在本页。修正共七个独立开关（BUG08 的武器继承尚未实机验证），另有若干难度调整（见 §1 表）；**试玩入口首次启动默认开启全部修正、关闭难度调整**，任何一项关闭时宿主只调用原函数，行为与原版一致。

## 1. 使用

默认：`scripts/Play SRW64 Native.command` 首次启动时**修正全开、难度调整全关**。游戏运行中有两处入口，二者共用同一份设置、互相实时同步：

- 菜单栏 **「选项 → 游戏性调整」**：「修正」与「难度调整」两组勾选项（组名为不可点击的标题），下面是「恢复默认（修正开启、难度关闭）」「全部关闭（原版规则）」「全部开启」三个预设。
- **「选项 → 设置…」（⌘,）**：设置窗口，含同样的规则开关与三个预设，另有语言（ja／zh-Hans／en）和画面（Original／HD）。窗口打开期间游戏收不到键盘输入，关闭后要等按键全部松开才恢复。

改动立即生效并写回设置。菜单与窗口的标题跟随当前语言，F7 或窗口里切换语言后立即改用新语言。

也可以在启动时选择：

```sh
./Play\ SRW64\ Native.command --rules fixed          # 全部修正（难度调整仍关闭）
./Play\ SRW64\ Native.command --rules all            # 修正 + 难度调整
./Play\ SRW64\ Native.command --rules original       # 原版规则
./Play\ SRW64\ Native.command --rule-fixes esp-level,limit-cap   # 自选
./Play\ SRW64\ Native.command --rule-fixes ''        # 自选为空，等同 original
```

| ID | 内容 |
| --- | --- |
| `esp-level` | 超能力的命中/回避补正按技能等级，原版固定 64 |
| `seisenshi-level` | 圣战士的回避补正按技能等级，原版固定 32 |
| `limit-cap` | 驾驶员命中/回避与机体运动性之和不超过机体限界，原版不限制 |
| `potential-bands` | 底力按 HP 档位对齐：90% 以上不加成，低于 10% 才到最高档；原版整体提前一档 |
| `potential-half` | 底力的命中/回避补正减半，暴击率不变 |
| `weapon-inherit-map` | 换机时补上三件漏登记的武器改造继承：レイズナー 的火炎放射器与グレネードランチャー、アルトロン 的ドラゴンファイヤー（原因与依据见[改造继承分析](upgrade-inheritance.md)；尚未实机验证） |
| `aura-slash-power` | 圣战士：L3 解锁的ハイパーオーラ系武器按技能等级加威力 +200…+1500（原版完全缺失），见 §2.2 |

以上六项是**修正**：原版代码与自身数据或界面口径矛盾，默认开启，`--rules fixed` 指的就是这六项。`weapon-inherit-map` 与其余五项不同，它在换机的那一刻把段数写进名册，是持久状态：之后关掉开关不会撤回，打开也不会追溯补回已经发生过的换机。以下四项是**难度调整**：原版行为本身正常，只是让玩家选择强弱，默认关闭，要开需要 `--rules all` 或逐项指定。

| ID | 内容 |
| --- | --- |
| `boss-dummy-half` | 头目的假身次数减半，至少保留 1 次 |
| `boss-dummy-none` | 头目不再拥有假身；与减半同时勾选时以本项为准 |
| `upgrade-cap-break` | 改造上限突破：改造画面里所有机体可改到 15 段（原作按机体 6～15），刻度用 ●／☆ 标出原作上限之外的格子；EW 换装、满改追加武器、出售价仍按原作上限。改上去的段数是持久状态，关掉后保留但不能再改。详见[改造段数与上限](upgrade-limits.md)第 7 节，同页还有可改每段增量、价格、上限与武器类型的升级规则文件（`--upgrade-rules`） |
| `upgrade-refund` | 离队退款：剧情让机体离开部队（离队、换乘后旧机被删除、ゴッドマーズ合体）时，按现价退回玩家花在这台机体上的改造资金，并在画面顶部和对话回看里提示；换机被继承的段数、剧情用 `3D6C` 赠送的段数不退。见 §2.6 |

- 选择写入试玩目录下的 `rules.json`（统一 profile 入口为 `build/recomp/profile-play/rules.json`，schema `srw64.rule-settings.v1`），之后不带参数启动时沿用。**没有该文件时按默认全开**；文件里是空列表表示明确选择了原版规则，不会被当成“没选过”。启动时终端打印当前规则。
- 无窗口的诊断／探针宿主不走启动器：直接运行 `run_host_probe.py` 时没有 `SRW64_RULE_FIXES` 即原版规则，保证有界运行的证据可复现。
- 菜单里的改动立即写入同一个 `rules.json`，并在运行目录追加 `rule-fixes-events.jsonl`（schema `srw64.rule-fixes-change.v1`，含 VI），运行报告里是 `rule_fix_changes`。
- 切换在**下一次结算**生效：已经算好命中率的这一次交战不受影响，战斗演出途中切换不会改变本次结果。
- 修正只改变结算时读取的数值，不写入存档，也不改变存档格式，已有进度可以直接换规则继续。每次会话的 `report.json` 记录 `rule_fixes`（`rules_version` 与启用项），宿主另写 `rule-fixes.json` 并在日志打印 `SRW64_RULE_FIXES`。继续某个会话的存档时，如果它上次按不同规则游玩，启动器会提示。冻结初始备份和本功能之前的会话都按原版规则计。
- 菜单只在带界面的宿主里出现（macOS 菜单栏，`rule_menu_macos.mm`）。无窗口的诊断宿主仍只用启动参数。
- 修正对敌我双方同样生效，与原代码的调用方式一致：敌方超能力、圣战士、底力驾驶员同样按新规则计算。
- 底层开关是环境变量 `SRW64_RULE_FIXES=<逗号分隔的 ID>`；`run_host_probe.py` 会校验 ID，未知 ID 让启动直接失败。

## 2. 原版代码与修正内容

地址均在战术 overlay `load_000AB160`（VRAM `801C2600` 起，ROM `0xAB160` 起）。

### 2.1 实际命中率

`801F4384`（实战，结果写回参战表 `8018B6E8` 每项 `+0x12`）与 `80204254`（选目标、选武器时的估算，由 `80201D98`、`80204564`、`8020500C` 调用）的公式相同：

```
(命中a + 反应a + 武器命中补正 + 100 + 运动性a) − (回避d + 反应d + 运动性d)
  × 地形补正 × 机体尺寸补正
  ± 集中类状态 30
  + NT/强化(a) − NT/强化(d)          801E1EDC，表 80218080，L1–L9 为 10,14,18,21,24,26,28,29,30
  + 底力(a) − 底力(d)                801E1D64
  − 圣战士(d)                        801E1F08（只有防守方的调用）
  + 超能力(a) − 超能力(d)            801E1F10
  → 之后才处理两种减半条件；80204254 另外把负值钳到 0
```

驾驶员运行记录（步长 0x4C）：`+05` 等级，`+06` 特殊技能等级（NT、强化人间、底力、圣战士、超能力共用），`+26` 回避，`+28` 命中，`+2A` 反应，`+2C` 技量，`+36` 技能标志（`04` 底力、`08` NT、`10` 强化人间、`20` 圣战士、`40` 超能力）。机体运行记录（步长 0x54）：`+04/+06` HP 与最大 HP，`+10` 运动性，`+14` 限界。

### 2.2 超能力、圣战士：空函数（`esp-level`、`seisenshi-level`）

`801E1F08` 与 `801E1F10` 的函数体只有 `jr $ra; nop`，不写 `$v0`。调用前刚执行过 `andi v0, v0, 0x20`（或 `0x40`），所以调用方拿到的“补正”就是技能标志本身：

- 超能力：攻击时命中 +64，被攻击时敌方命中 −64；
- 圣战士：只在被攻击时让敌方命中 −32，攻击时没有补正；
- 两者都只判断标志，不看等级。技能等级为 0 时也生效，例如ガラリア在驾驶员 Lv7 前、バーン和黒騎士在 Lv6 前，状态页不显示圣战士，但仍有 −32。

修正后两个函数改为按 `+06` 查 NT 的等级表（`801E1EDC` 使用的 `80218080`），即 L1–L9 为 10…30，L0 为 0。调用位置不变：超能力仍是攻守两侧，圣战士仍只有防守侧。

选这张表的依据：NT 表的命中行与回避行相同；紧接其后、没有任何代码引用的三行表 `802180B4` 前两行也是这条曲线，第三行 0,20,40…150 正好是奥拉屏障表 `80218930`（0,200…1500）的十分之一，像是为圣战士准备后没接上的数据。原作意图的数值没有更直接的证据。

**2026-09-18 更正并补上（`aura-slash-power`）。** 资料所说的缺失项：圣战士应提升**ハイパーオーラ斬り等奥拉武器的威力**，超能力应提升全武器攻击力。全 ROM 检查圣战士标志的只有 5 处（两个武器解锁条件、两处命中率、奥拉屏障），检查超能力标志的只有命中率函数里的 4 处；实战伤害 `801F5628` 与 AI 伤害估算 `80203418` 都不读驾驶员技能标志（`tests/test_rule_fixes.py` 按字节确认）。所以**两项攻击力加成在原版代码里都完全不存在**，不是数值错误。

数值依据：ゲームカタログ@Wiki 引述「バグがなかった場合、L9で命中、回避＋30、攻撃力+1500」。ROM 里 NT 表后面那几行没人读的数据正好对应：

| 表行 | L0–L9 | 对应 |
| --- | --- | --- |
| `80218080` 第 0–2 行、`802180B4` 第 0–1 行 | 0,10,14,18,21,24,26,28,29,30 | 命中/回避，L9 = +30 |
| `8021809E`、`802180C8` | 0,20,40,60,80,100,120,130,140,150 | ×10 = 攻击力 +200…+1500，L9 = +1500 |
| `802180A8` | 0,20,30,40,50,60,70,80,90,100 | ×10 = +200…+1000，与攻略本印的屏障值一致 |

`aura-slash-power` 在调用 `801F5628` 与 `80203418` 期间，把攻方武器威力（武器运行记录 `+0x06`，与界面显示同单位）临时加上 `802180C8`[技能等级]×10，调用后恢复。只作用于**圣战士驾驶员**使用的**武器条件 15**（要求圣战士 L3）的武器：ハイパーオーラ斬り、ハイパーオーラキャノン、ハイパーオーラショットアーム、ツインオーラアタック，共 20 条武器记录；普通オーラ斬り（条件 14）不加。条件 15 本身要求 L3，所以实际加成是 L3 +600 到 L9 +1500。界面上的武器威力数字不变，加成体现在交战预览和结算里。

超能力的全武器攻击力加成同样缺失，用同一条曲线就能补，**用户未要求，本轮没有加开关**。

奥拉屏障：游戏实际用 +200…+1500（`80218930`，就是攻击力那条曲线），攻略本印的是 +200…+1000（上表最后一行）。按用户决定**保留原版**，视为攻略本有误，不做开关。

圣战士等级在原版里另外还影响：武器条件 14/15（`801E6214`）分别要求 L1/L3；奥拉屏障值为 3000 + `80218930`[等级]（`801F6EE0`）。

### 2.3 限界：结算不读（`limit-cap`）

驾驶员状态页（`801E6C5C`，`801E7174`／`801E71C8`）把回避、命中显示为 `%3d+%3d`（驾驶员值 + 机体运动性），和大于限界时用警告色绘制。但上面的命中公式直接相加，全 ROM 读取限界字段的只有显示、加载复制、改造与部件加算（`800A5254`，限界改造每段 +10/+20）和特殊模式加值（`801FE9CC` 等）。原版里改造限界、装备限界部件对战斗没有作用。

修正后，调用两个命中函数期间，攻击方的「命中 + 运动性」、防守方的「回避 + 运动性」各自不超过所乘机体的限界，反应不计入上限，与状态页的比较口径一致。实现方式是在原函数调用期间临时降低这两个字段（先降驾驶员值到不超过限界，再让运动性补足到限界），调用后原样恢复，原公式其余部分完全不变。

注意：多数机体的限界比运动性高 100 以上，但低级机体（例如ミニフォー：运动性 95、限界 140）或高等级驾驶员很容易超出，开启后这些组合的命中/回避会明显下降。

### 2.4 底力：档位提前一档、三种用途同值（`potential-bands`、`potential-half`）

`801E1D64(用途, 驾驶员, 机体)` 查 `80217F90` 的 10×10 表：行是技能等级，列是 HP 档位，L 行第 c 列为 max(0, c+L−9)×10，L9 最高 90。档位由 HP/最大HP×100 决定：

| HP | 原版档位 | 修正档位 |
| --- | ---: | ---: |
| 90% 以上 | 1 | 0 |
| 80–90% | 2 | 1 |
| … | … | … |
| 20–30% | 8 | 7 |
| 10–20% | 9 | 8 |
| 10% 以下 | 9 | 9 |

原版第一个比较就把 90% 以上记为档位 1，第 0 列永远读不到，所以 L9 满血已有 +10，最高值在 HP 低于 20% 时就出现。两份资料（S-RPG navi、Akurasu）都把最高档写在 HP 10% 以下，而且表的第 0 列全为 0、正好对应“满血无加成”，因此判断为少了一档的偏移。`potential-bands` 改用右列的档位（比较仍用同样的单精度运算）。

三个调用点分别传入用途 2（攻击方命中）、1（防守方回避）、0（暴击率，只有我方攻击时调用，敌方暴击另除以 4），但函数一开始就把这个参数覆盖成表地址，三种用途拿到同一个值。两份资料都说底力的命中/回避补正“比本来高”，Akurasu 说是 2 倍。`potential-half` 把用途 1、2 的结果减半，暴击率不变。**这一项只有社区资料和未使用的参数作依据，证据弱于其他几项**；资料给的具体数字（“L9、HP 10% 以下本应 +50、实际 +100”）与代码的最大值 90 也对不上。

### 2.5 头目假身次数（`boss-dummy-half`、`boss-dummy-none`）

这一项不是 Bug 修正，原版机制本身正常：部署记录（28 字节）行为字 `+0x16` 位 14 置位且阵营非我方时，`8020ABB4` 把 `+0x18` 写进新建驾驶员记录的 `+0x14`，交战中由 `801F6E3C` 判定、`801FCA78`／`801FE068` 逐次消耗，游戏里不显示剩余次数。原版共 42 条记录带这一位，全部属于ハマーン、シャア、シロッコ、グレミー、ミリアルド、ギュネイ、ガトー、ル・カイン，取值 2、3、5、7。字段与判定的完整说明见[基础修复](base-fixes.md)（那里处理的是五飞被误写入次数的缺陷，与本项无关）。

修正方式是在 `8020ABB4` 处理**这一条记录**期间改写它的 `+0x18`，调用结束后原样还原：

| 规则 | 2 | 3 | 5 | 7 |
| --- | ---: | ---: | ---: | ---: |
| 原版 | 2 | 3 | 5 | 7 |
| `boss-dummy-half` | 1 | 1 | 2 | 3 |
| `boss-dummy-none` | 0 | 0 | 0 | 0 |

减半取整后至少保留 1 次，让机制仍然出现；两项同时开启时以取消为准。改写只作用于部署记录在 `80199400` 的**本关副本**，不写 ROM、不写存档，登场之后再切换规则不会改变已经在场单位的剩余次数——下次登场才按新规则生成。没有假身位的记录（例如五飞敌对时的两条）完全不受影响。

### 2.6 离队退款（`upgrade-refund`）

原版剧本用 `3D5A …,4000`（或 3000）删除离队的机体，换乘时删除旧机，ゴッドマーズ合体时删除ガイヤー；机体实例连同全部改造一起消失，玩家投进去的资金也就没了。[改造继承分析](upgrade-inheritance.md)第 6、8.3 节列出了哪些“改造丢失”属于这一类。本项在删除发生前把这台机体的改造按现价折算退回资金，不改变任何机体的强弱。

**什么时候退**：只有剧情例程里的删除。宿主包装了四个函数：

| 函数 | 作用 | 包装 |
| --- | --- | --- |
| `800AA464` | 驾驶员离开机体，并删除编号等于参数的实例（`3D5A` 模式 3000/4000 经 `800A3540` 调用；登记新机时删除脚本给的旧机） | 标记“剧情移除”范围 |
| `800AB808` | `3D6A` 模式 3，ゴッドマーズ合体删除ガイヤー | 标记“合体”范围 |
| `800AAD28` | 登记新机；第 4 步取前任表（`D_800CA3A0`，经 `800AA814`）对应的第一台在用实例并保存它的段数 | 先按同样规则找出这台实例，记为“被继承” |
| `800AA3C4` | 释放机体实例（全部删除都经过这里） | 在上述范围内、宿主按下表结算，再调用原函数 |

出售（出售画面 `801C3678`，自带含改造的售价）和战术地图上的移除（`800A7DEC`）也调用 `800AA3C4`，但不在这些范围里，不退款。只处理我方实例池（`8016A210` 起 140 台，分配器 `800A6E68` 的第 0 池），其他池的实例不会被退款。

**退多少**：五项按各自价格表、武器按改造类型（实例 `+0x15`，类型 0 不可改造、不计）的价格表，把 0…当前段数−1 的单价相加；价格来自当前生效的表，所以带 `--upgrade-rules` 时按规则文件的价格。不退的部分：

- **被继承的实例**：换机时前任的段数已经搬到新机（如サンドロック→改），删除前任不算损失。
- **剧情赠送的段数**：26 台机体在原剧本里会被 `3D6C` 直接写成 N 段（38 条指令，最多 8 段，表在 `upgrade_refund.hpp`，`tests/test_upgrade_refund.py` 对照 ROM 校验）。`3D6C` 把五项和全部武器写成同一值（不超过该机上限），所以拿到赠送的实例没有任何可改造项低于 N：宿主只在五项与可改造武器全部 ≥ N 时把这 N 段算作免费，只要有一项低于 N 就说明这台实例没拿到赠送（另一条路线，或段数是从前任继承、在前任上买的），全部照退。同一台机体在不同路线可能拿到也可能没拿到赠送（如ウイングゼロ）；唯一会少退的情况是没拿到赠送、而玩家又把每一项都改到 N 以上，这时前 N 段不退。

资金（`D_8010F5F4`，u32）加上退款，溢出时停在最大值。原版加资金的路径（`3D5B`、战斗收入）都不设上限，本项也不另设。

**提示**：退款不为 0 时，游戏窗口顶部出现约 6 秒的提示条（当前语言），对话回看里同时加一行（三种语言都存，F7 切换后跟着变），例如「サンドロック 已离开部队，退回改造资金 17,000」。机体名保持日文原名。提示依赖原生对白模块，只在统一 profile 入口出现；无窗口宿主照样退款，只写日志。

**持久性**：退款写进资金，随游戏存档保存；之后关闭本项不会收回，打开也不会追溯已经发生过的删除。开启期间每次剧情删除（包括不退款的）都在运行目录追加 `upgrade-refund-events.jsonl`（schema `srw64.upgrade-refund.v1`：机体、来源、是否被继承、免费段数、五项与武器金额、前后资金），调试接口可用 `srw64ctl events refunds` 读取。
