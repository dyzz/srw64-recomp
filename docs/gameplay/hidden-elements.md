# 隐藏要素、说服与路线分歧：脚本与代码实现

2026-10-01，第二轮全面静态核查。对象是锁定的日版 Rev 0 `rom.z64`：脚本 IR（`assets/original-data/records/stage_events.jsonl`）的**全部 1,812 个事件**逐条扫描（条件块、主角与系别段、选择肢、类型 2/7/9 表头门槛），并把涉及的判定读到常驻代码（`build/recomp/cpu-scan/resident/`）和 overlay（战术 `load_000AB160`、战斗 `load_00121560`、场间 `load_0008F4B0`、世界地图 `load_000A7EC0`、主角选择 `load_001090A0`）。第一轮（2026-09-17）留下的「前置未见」「未核对」「推断」已全部改成代码或脚本结论。**本轮没有运行游戏，也没有写回 ROM**；结论已定、但值得用一次存档复核的点集中在第 10 节。

社区攻略 [Akurasu Wiki：Super Robot Wars/64/Secrets][wiki] 与其 Flow Chart 只作对比，不作依据。第 6 节逐项标出 **一致**、**不同**、**Akurasu 未载**；第 7、8 节分别汇总后两类。

写法约定：

- `S49` 是场景号（关卡标题 id − 281），关卡名用 ROM 解码出的日文原名，便于在数据浏览器中搜索。
- 事件地址是 ROM 偏移（如 `001bf55c`），`@520` 是事件内指令偏移。
- **回合一律写画面回合**（游戏 HUD 上的数字）。脚本里的原值从 0 起算，画面回合 = 原值 + 1，见 4.1 节。
- `varN` 指 2 位脚本变量 N。

## 1. 结论摘要

- 游戏没有专门的隐藏要素系统。全部条件都用 200 个 2 位脚本变量（`8015E818`）实现：0–54 跨关保存，是隐藏要素和路线的进度；100–139 是单关临时变量。**新游戏时 200 个变量全部置 3**（`800A4790`，代码事实），所以 3 普遍表示「未开始／已失败」。
- **说服的前置条件写在类型 9 事件头里**：`[9, 说服者, 对象, 门槛变量, 门槛值]`，`FFF8` 表示无门槛。常驻函数 `800A4634` 负责检查和挑选：说服者是行动单位的主驾驶员、事件未执行、门槛满足、双方上下左右相邻，按登记顺序取第一个。全部 71 个说服事件的门槛链都已读出（第 3 节）。
- 类型 2（击破）与类型 7（残存数）的门槛变量是**等于 3 时不触发**；类型 6（敌全灭）表头第 1 字是**最晚**回合；`3E04 n` 等于「画面回合 ≤ n」（第 4 节）。
- 变量表补全到 0–54 每一个变量的全部写入点与读取效果；45、53、54 由原生代码读取（明鏡止水显示、要塞バルジ地标、旗舰击坠台词），46 实际没有效果（第 5 节）。
- 逐项对照 Akurasu Secrets 页约 60 项（第 6 节）：结论不同 30 处（第 7 节），Akurasu 未载的条件、分歧与结果 40 余项（第 8 节，含全量扫描新发现 N1–N17）。
- 合体技不靠剧情解锁：`8020178C` 每次列武器都会重写合体技的锁定位，`3D6F 1215`（双重神之指）没有持久效果；石破ラブラブ天驚拳另要求石破天驚拳已解锁（6.5 节）。
- 静态上真正无法定论的只剩两项（10.1 节）。

## 3. 说服机制

### 3.1 「説得」出现在指令菜单的条件

光标单位的**主驾驶员**还有行动次数（驾驶员 `+0x35 ≠ 0`；移动过也可以），并且本关登记的某个类型 9 槽同时满足：

1. 表头第 1 字（说服者）等于该单位主驾驶员的角色号；
2. 槽未执行（状态 `< 0x2000`），且当前没有事件在执行（`engine+0x97C < 0x2000`）；
3. 门槛满足：第 3 字为 `FFF8`，或 `var[第 3 字] == 第 4 字`；
4. 第 2 字（对象）的单位在地图上（任何阵营都行，对象单位上任意一位驾驶员匹配即可），并与说服者**上下左右相邻**（曼哈顿距离正好为 1，斜向不算）。

证据：菜单构建 `load_000AB160:801C9DFC`。`801C9EB8`–`801C9EC8` 把主驾驶员角色号写进 `engine+0x9A8`（`D_801602F8`），调用 `800A4634`；返回值 ≠ −1 且剩余行动数 ≠ 0 时追加菜单项 `D_8021DD88`（命令 1，文本 `0x1FF`「説得」）。`移動` 项还要求尚未移动，说服不看。

### 3.2 `800A4634` 的挑选

类型 9 分组在 `engine+0x6F8`（分组基址 `engine + 0x14 + 类型×0xC4`）。组内：`+0` 条数；`+4` 16 个事件指针；`+0x44[i]` 对象；`+0x64[i]` 说服者（执行后改为 `0x2000`）；`+0x84[i]` 门槛变量；`+0xA4[i]` 门槛值（登记 `8009DFA0`–`8009DFE8`）。

函数按登记顺序循环，取**第一个**满足 3.1 条件的槽，把槽号写进 `engine+0x992`，返回对象主驾驶员的角色号；一个都没有时写 −1（`800A475C`）。门槛读变量走 `800A2A84 → 800A496C`（下标 ≥ 0xC9 返回 −1）；双方名册项由 `800A2BF4 → 800A2C18` 查找（我方状态 2 的槽跳过）；相邻比较在 `800A4704`–`800A4738`。

所以说服对象由程序决定，玩家不能挑：同一说服者同时贴着两个可说服对象时，只会说服表里靠前的那个。例：共同戦線（S61）／兄と弟と（S76）中タケル同时贴着マーグ和ロゼ时只会说服マーグ；アクシズの攻防（前）（S88）中ジュドー同时贴着マシュマー和キャラ时只会说服マシュマー。

### 3.4 执行流程与行动消耗

1. 菜单命令 1 → `801DECE8`：再调一次 `800A4634` 写 `+0x992`，按双方坐标选特效 0x35／0x36，`801EE838` 播放朝向特效，状态置 0x52。
2. `801DF22C` 等特效结束 → `801DEBF4`：状态置 0x53，`D_80172F0A = 1`，轮询阶段 `engine+0x9AA`（`D_801602FA`）= **6**，记下说服者句柄。
3. 事件轮询 `8009E180` 在阶段 0、6、1、2 用 `8009E3B0(8,10)` 轮询类型 8、9。类型 9 处理函数 `8009EC3C`（`jtbl_800D0610[9]`）只在 `+0x992 ≠ −1` 且 `+0x9AA == 6` 时执行：槽状态改为 `0x2000`，`+0x97C = 0x2000`，`8009EE98` 启动事件，`+0x992` 复位为 −1。
4. 事件结束后 `801DFF40`–`801DFF7C` 检查完成，调用 `801DEC68`：`+0x9AA` 归 0，`801C29DC(说服者)` 扣一次行动，回到地图。

一次说服消耗说服者一次行动，不论事件内容是否生效。

### 3.5 多步说服、跨关与存档

- **关内**：执行过的槽不再匹配，同一对角色的下一次说服自然落到下一个门槛满足的槽。第二步的门槛变量由第一步的事件写入。例：悲しみのホンコンシティ フォウ ×2、戦いの意味は ミネルバX ×2、ランタオ島／絶望 ドモン→レイン。
- **跨关**：每关开始重新登记，执行标记不跨关。跨关前置只靠门槛变量（var0–54）。
- **中断存档**：`80093278 → 80091ED0 → 800A4148` 把 12 个分组里状态为 `0x2000` 的槽按位存进 `D_8016A1F0`，继续游戏后已执行的说服仍算执行过。
- 每组最多 16 槽（`8009DF8C`）；说服事件最多的场景（S57、S66）只有 4 个。

### 3.7 代码层面没有说服效果
