# 战斗计算：伤害、命中、暴击、防御判定与精神指令

日期：2026-09-20。本文记录一次交战里游戏实际执行的全部计算：伤害与命中公式、暴击、五类防御判定、防御方的三个指令，以及精神指令如何改写这些值。**除特别标注外，结论均为静态代码确认**（反汇编 `build/recomp/cpu-scan/load_000AB160/rom_801C2600.text.s`，表值从 `rom.z64` 直接读出）；伤害公式另有 24 行运行数据吻合。演出（动画）侧见[战斗动画与自定义机体](../data/battle-animation.md)，图像资源见[战斗图像](../data/battle-graphics.md)。

写这份文档的直接动机是战前界面：原版只显示命中率，玩家看不到伤害、暴击率、对方的分身／切り払い／护罩概率，也看不到剩余假身次数。要把这些补上，就得先把公式确认到可以自己复算的程度。

## 0. 一次交战的执行顺序

```
801F7D6C  结算驱动（命中 801F4384 与伤害 801F5628 各三次：攻击／反击／二次攻击）
  └ 801F7204  判定顺序：命中掷骰 → 分身 → 切り払い → 假身 → 护罩 → S防御
```

`801F7D6C` 内部的全部调用都落在 `801E*`／`801F*` 逻辑区，**没有到常驻图形／等待例程的调用，也没有阻塞原语**；运行数据里一轮交战的攻击与反击记录在**同一个 VI**（`rules-battle-1` 的 5316／6956／8336）。据此推断结算与演出分离、且一轮结算不可分割——但该次运行**没有播放战斗动画**，所以「结算先于演出」尚未被运行证据直接覆盖。另一侧的证据是 `801F7204` 设定的**防御反应代码**正是动画播放时读取的（见[战斗动画](../data/battle-animation.md)的反应代码表），两者一一对应。

## 1. 伤害

全程 IEEE 单精度浮点，最后 `trunc.w.s` 取整。`80203418` 是不掷暴击的估算版（**不消耗随机数**，战前界面可安全调用），`801F5628` 是实战版，两者**直到爱情补正与下限 10 之后**逐指令相同（估算版同样施加恋爱补正，只是不掷暴击；2026-09-22 反汇编复核 `802035C8..80203644` 与 `801F5884..801F5928`）。

```
stat = (武器[+0x04] & 0x80) ? 驾驶员[+0x22] 格斗 : 驾驶员[+0x24] 射击

A = 武器攻击力 × 武器地形适应 × stat/100 × 攻方气力/100 × 机体地形适应
D = 装甲 × (鉄壁 ? 2 : 1) × 守方气力/100 × 守方机体地形适应
R = (A − D) × 地形效果                    # 地形效果 = (100 − 地块防御)/100
R = R + (爱A ? R×0.3 : 0) − (爱D ? R×0.3 : 0)
R = max(R, 10)                            # 下限 10
if 攻方精神 魂:   R ×= 3
elif 攻方精神 熱血: R ×= 2
else【仅实战】暴击命中: R ×= 1.5
【仅实战】防御指令: R ÷= 2
【仅实战】守方机体 id == 149 → R 固定 10；R = min(R, 65535)
```

关键点：

- **气力**在攻防两侧各乘一次（`80203528` 攻方 `lhu 0x20($s2)`、`80203578` 守方），基准 100。
- **地形适应是乘法，不是加法**。倍率表 `D_80218744`（ROM `0x1012A4`）与 `D_8021874C`（`0x1012AC`）均为 `{0, 60, 80, 100, 120}`，即 `-`/D/C/B/A → 0/60/80/100/120%。武器 A ＋ 机体 A 合计 **1.44 倍**。
- **机体侧取机体排名与驾驶员排名之和再分档**（`800A6194`：和 0→0%，1–3→60%，4–5→80%，6–7→100%，**≥8→120%**）；武器侧是单排名（`801F40A4`）。
- **地形通道由机体 handle 决定**，不读参战表 `+0x10`：`801F3FA8` 依次判断 全图宇宙→宇、高度类=1→空、水地块→海、否则→陆。
- **尺寸不进伤害公式**。尺寸（0/80/100/120/140）只在命中率函数 `801F4568`／`801F4580` 里是真倍率；伤害里只有一个对真实机体永不触发的退化分支。
- **爱情／友情补正 ±30%**（`801F4908`：判「搭档在当前镜头可见窗口内」——以镜头为锚的 31×31 格窗口再裁到视口，不是围绕单位的半径；仅我方；配对表 VRAM `0x80218754`，47 行 × 8 字节）。攻方持有 +30%，守方持有 −30%，只影响伤害、不影响命中。

### 排名字节位置

| | ROM 表 | stride | 行内偏移 | 顺序 |
| --- | ---: | ---: | --- | --- |
| 机体 | 465792 | 36 | **14–17** | 海／空／陆／宇 |
| 武器 | 478864 | 16 | **9–12** | 同上 |

同表其他字段：机体 `armor` 在行内偏移 10（u16）；武器 `power` 在 1（×100）、`hit_modifier` 在 4（**有符号**）、`en_cost` 在 6、`will_required` 在 7、`critical_modifier` 在 13（有符号）。注意 `config/data/original-jp-v1.json` 的 `numeric_fields` 偏移是**ROM 表行内偏移**，不是运行时记录偏移——按运行时偏移读会取到无关字段。

### 运行验证

`build/recomp/mini-stage/rules-aura-1/rule-probe.jsonl` 的 24 行 `damage`（探针调用真实 `80203418`）在代入上式后**24/24 精确吻合**，残差 0。该关卡地形为空、双方气力恒 100。

> **方法论警告。** 同一份数据用「`1.2 × (攻击力 − 装甲) + 每攻方常数`」拟合**也是 24/24 精确**，但结构完全错误——因为该数据集里气力恒为 100、攻方武器地形适应恒为 A，两个变量都被吸收进了常数项。真实形式是纯乘法后相减，没有任何加性常数。**拟合吻合不等于公式正确**；必须让变量真正变化过，或与代码／攻略交叉验证。

气力项至今**没有被运行数据覆盖**（现有全部数据集气力恒 100）。为此准备了 [`config/recomp/mini-stages/damage-morale.json`](../../config/recomp/mini-stages/damage-morale.json)：对 `rules.json` 的单命令改动，在第一条 `3D38` 前插入 `3D5F`（全体气力 100→70），预测值与实测的比较尚未完成。

## 2. 命中率

```
base = (攻方命中 + 攻方反应 + 武器命中修正 + 100 + 攻方运动性)
     − (守方回避 + 守方反应 + 守方运动性)
       再乘尺寸与地形倍率（801F4568 / 801F4580）
```

短路与修正（`801F4384`，按代码出现顺序）：

| 条件 | 效果 | 位置 |
| --- | --- | --- |
| **守方** 精神 ひらめき（`+0x1C & 0x20`） | **直接返回 0**，并置「回避！」提示标志 | `801F4460` |
| **攻方** 精神 必中（`& 0x80`） | **直接返回 100**（延迟槽 `addiu $v0,$zero,0x64`） | `801F44A0` |
| **攻方** 精神 集中（`& 0x10`） | `hit += 30` | `801F4584` |
| **守方** 精神 集中 | `hit −= 30` | `801F45A4` |
| **攻方** `+0x1C & 0x800000`（精神 id 23） | `hit ÷= 2` | `801F472C` |
| **回避指令**（halve 参数） | `hit ÷= 2` | `801F4750` |

最后两项**互相独立、可叠加**（最多 ÷4）。注意 MIPS 延迟槽：`801F473C` 的 `andi $v0,$s7,0xFF` 在前一条分支生效**之前**执行，所以第二次判断用的是参数而不是精神位。

掷骰在 `801F7204`：`hit` 钳 0–100，`r = rand(99)+1`（**1..99**），`hit >= r` 命中。因此**命中率 99 与 100 效果相同**，命中率 0 永不命中。

> 本式对 `rules-aura-1` 的 24 行只有 2 行精确吻合，残差随武器与守方机体系统性变化——尺寸／地形倍率的具体取法尚未逐项确认。**战前界面应直接调用游戏的估算函数 `80204254`**（同样不消耗随机数，`rule_probe.hpp` 已封装参战表保存／恢复），而不是自行复算。

## 3. 暴击

`801F47B0`：

```
rate = 攻方技量[+0x2C] − 守方技量 + 武器暴击修正[行内偏移 13, 有符号]
阵营 0（我方）：rate += 底力补正（801E1D64，0–90）
阵营 1、2（敌／第三方）：rate /= 4        ← 且不加底力
rate = max(rate, 1)
暴击 = rand(100) < rate     →  伤害 ×1.5
```

阵营由攻方 handle 决定：`801E510C` 按 `<0x60 / <0x7E / 其他` 分三类，而 handle 编码就是 `0x42/0x60/0x7E + 槽位` 对应阵营 0/1/2（见 `src/host/rule_probe.hpp:27`）。

**敌方几乎不会暴击。** 武器暴击修正全表只有 `-20/-10/-5/0/10/15/20/30` 八种；头目基础技量 95–117，对技量 120 左右的我方：

| 敌方 | 基础技量 | 武器 +0 | +20 | +30 |
| --- | ---: | ---: | ---: | ---: |
| ギュネイ | 117 | 1% | 4% | 6% |
| ガトー | 110 | 1% | 2% | 4% |
| ハマーン | 108 | 1% | 1% | 4% |
| シャア／シロッコ | 105 | 1% | 1% | 3% |
| キラル・メキレル | **155** | 8% | 13% | 16% |

全 257 名驾驶员基础技量最高的是キラル・メキレル（155），即便配 +30 武器也只有 16%。同条件下我方可达 29–32%。

**熱血／魂 生效时不掷暴击**：`801F5A14` 只在两位都未置位时才调用 `801F47B0`，否则暴击标志强制 0。即「熱血 ×2」与「暴击 ×1.5」**不能共存**。

## 4. 防御判定（命中之后，早退串联）

顺序：**分身 → 切り払い → 假身 → 护罩 → S防御**。每项只对「本该命中」的攻击生效，所以显示概率时它们是**条件概率**。攻方驾驶员 `+0x1C & 0x80`（必中）置位时**跳过前三项**。

| 判定 | 概率／效果 | 条件 | 位置 |
| --- | --- | --- | --- |
| **分身** | **固定 50%** | 机体 `+0x28 & 0x163011` 且驾驶员气力 `+0x20 ≥ 130` | `801F6C44` |
| **切り払い** | `等级 / (16 × scale) × 100%`，`scale=2`（武器 id < 0x60）否则 1 | 机体 `+0x20 & 0x01`、驾驶员 `+0x36 & 0x01`、等级非 0 | `801F6D10` |
| **假身** | 确定性，不掷骰 | 阵营非 0、名册 `0x80` 置位、驾驶员 `+0x14 ≠ 0`；生效后该字段 −1 | `801F6E3C` |
| **灵气屏障** | **阈值吸收**：阈值 `3000 + 表[圣战士等级]`，地形 2 时 ×2。伤害 ≤ 阈值 → **归零**；> 阈值 → **原样通过** | 机体 `+0x28 & 0x4000` | `801F6ED0`/`801F6EE0` |
| **通用护罩** | **减法且可叠加**：`2000·[0x800 行星防御] + 2000·[0x20 I力场] + 1000·[0x200 光束涂层]`，地形 2 ×2；`residual = max(伤害 − 护罩, 10)` | 机体 `+0x28` 对应位 | `801F6F3C` |
| **S防御** | 概率同切り払い（用驾驶员 `+0x08` 等级 / 技能位 `0x02` / 机体装备位 `0x02`）；效果是**伤害减半并向下取整到 10 的倍数，最低 10**，伤害 < 20 不处理 | 同上 | `801F6FDC` |

分身掩码 `0x163011` 已与 `config/data/original-jp-v1.json` 的 `unit_abilities`「回避」族七项核对：分身 `0x10`、马赫特殊 `0x1000`、真马赫特殊 `0x2000`、神之分身 `0x1`、盖塔幻影 `0x20000`、瞬幻足 `0x40000`、超级干扰器 `0x100000`，并集**正好**为 `0x163011`。灵气屏障表 `80218930`（ROM `0xab160 + 0x80218930 − 0x801c2600`）已从 ROM 读出：`0, 200, 400, 600, 800, 1000, 1200, 1300, 1400, 1500`。

几点值得注意：

- **分身与等级、技量无关**，只看气力是否到 130。
- **灵气屏障是悬崖效应**：差一点打不穿就完全无效，打穿了则全额通过。战前界面显示「再加 N 伤害可击穿」很有价值。
- **假身剩余次数原版游戏内不显示**（见[基础修复](base-fixes.md)）。
- 护罩在伤害算出**之后**评估，所以要预测护罩结果就得连伤害一起算。

未解：`801F6D10` 第一个门槛 `(participant+0x08 指向记录)+0x04 & 0x08` 语义不明；护罩的消息码重映射有一条不可达分支。均不影响伤害算术。

## 5. 防御方的三个指令

选择器是**有符号字节 `D_8018B754`**：`-1` 未选、`0` 反撃、`1` 回避、`2` 防御。
（`D_8018B74C` 是**反击武器指针**，0 表示不反击，不是指令选择器。）

`801F84D4` `bnez $v1` 分流，延迟槽把 `$v0` 置 1 作为比较值：

| 指令 | 命中率 | 伤害 | 反击 |
| --- | --- | --- | --- |
| **反撃**（0） | 原值 | 原值 | ✓（`801F69D8` 选武器） |
| **回避**（1） | **÷2** | 原值 | ✗ |
| **防御**（2） | 原值 | **÷2** | ✗ |

回避分支（`.L801F86DC`）**只调用 `801F4384`**，防御分支（`.L801F870C`）**只调用 `801F5628`**——各自完全不碰另一个函数。两者都把 `D_8018B74C` 置 0 取消反击。

`801F7D6C` 自己的第三参数 `$s7` 全函数只出现 6 次，**从不作为参数传给命中／伤害**；六个调用点的 `a2` 都是硬编码字面量，只有回避／防御两条分支传 1。

**AI 自动选择**（`801F7B34`）：`slti 0x15` —— 预测命中率 **< 21 选回避，否则选防御**；另在 `801F849C`，若防御后仍会被击坠（`伤害>>1 ≥ 攻方武器+4`）则**改选回避**。

攻略佐证：SRW 系列 wiki 载「回避指令下命中率减半」，与代码一致。SRW64 的防御具体数值攻略无记载，以代码为准。

| 9 | `0x200` | 鉄壁 | 守方**装甲 ×2** | `801F57D8` |
| 11 | `0x800` | 熱血 | 伤害 ×2 | `801F59CC` |

- 一次移动后清：`0x4` 加速（`D_80218054`）
- **回合结束**清：`0x10` 集中、`0x200` 鉄壁、`0x80` 必中、`0x800000`、`0x40000`（`D_80218058`）

## 7. 对战前界面的意义

上述全部量都是**可读状态的纯函数**，战前界面可精确显示而不消耗随机数——前提是**自己复算公式，不要直接调用判定函数**：`801F6C44` 一进门就先掷一次随机数，不管目标有没有回避能力。伤害用 `80203418`、命中用 `80204254`，两者都不掷暴击、不动 RNG。

原版界面只给命中率。可补齐的信息：预计伤害与暴击伤害、暴击率（区分我方／敌方 ÷4）、分身／切り払い／S防御 概率、假身剩余次数、护罩阈值与击穿差额、必要气力不足导致武器不可用的原因、以及当前生效的精神。

界面草案（沿用原版双面板布局、战场背景与配色，含战斗动画 ON／OFF 与三个指令的结果并排）见会话记录中的 artifact；实现时机体朝向应复用原版的**顶点镜像组**（`vertex_mode 0` 每零件 8 个顶点，后 4 个是 x 取反的镜像组，绘制时 `+0x40` 选用），按 side 选组即可，不必预烘焙两份图像。
