# 设置窗口：从热键和菜单走向「选项」

日期：2026-09-18。**第一版已实现，见 §6；2026-09-27 改成游戏内叠加的分页面板，见 §7；其余仍是规划。** 目前玩家能调的东西分散在热键（F6 图像、F7 语言）、菜单栏的「规则」菜单、启动参数和 profile 文件里；规则已有七项、以后还会增加，需要一个集中的入口。本文定下入口结构、分类、每项的生效时机和验收要求，具体实现另排。

## 1. 现状盘点

| 现有入口 | 覆盖内容 | 问题 |
| --- | --- | --- |
| F6 | Original / HD 图像 | 只有循环切换，看不到当前值与可选值 |
| F7 | ja / zh-Hans / en 循环 | 同上 |
| 菜单栏「规则」 | 修正、难度调整两类规则与预设，实时生效并写回 `rules.json`（规划时的入口，已由 §6 的「选项」取代） | 条目会随规则增加一直变长，没有分组和说明文字 |
| 启动参数 | `--rules`／`--rule-fixes`、`--language`、`--images`、`--resolution-scale`、`--font-size` 等 | 只在启动时可用，普通玩家不会用命令行 |
| profile／设置文件 | `play-profile.json` 的 `presentation`（locale、images、model_5600、resolution_scale、font_size）、试玩目录下的 `rules.json` | 手工编辑，没有界面 |

## 2. 入口与结构

菜单栏改为**「选项」**一个顶层菜单，下面按分类给出子菜单，另有「设置…」打开弹出窗口。窗口与菜单共用同一份设置模型，任何一处改动立即反映到另一处。

```
选项
├─ 游戏性调整…      规则修正、难度调整（现在的「规则」菜单内容）
├─ 显示…            Original / HD、分辨率缩放、字号、减少闪白
├─ 语言与文本…      界面与剧情语言、阅读速度、已读跳过
├─ 存档…            历史会话、自动保存节点（M1 落地后）
└─ 设置…            打开完整设置窗口（以上分类为标签页）
```

- **「选项 → 游戏性调整」是本轮确定的路径**：现在的「规则」菜单整体搬到这里，内部再分「修正」（默认开启，修的是原版自相矛盾的地方）和「难度调整」（默认关闭，改变强弱）两组，组名之间用分隔线和不可点击的说明项。
- 默认生效、没有开关的[基础修复](../gameplay/base-fixes.md)不进入设置界面，只在文档和「关于」里说明。
- 窗口用标签页承载同样的分类，每项带一行说明、当前值、默认值，以及「恢复默认」。

## 3. 每项设置要写清的元数据

沿用规则目录的做法，把设置定义成数据，界面由它生成，新增一项不改 UI 代码：

| 字段 | 用途 |
| --- | --- |
| id、分类 | 稳定标识与归类 |
| 控件类型 | 开关、单选（原版／减半／关闭这种互斥组）、数值、下拉 |
| 标签键 | `content/locales/*.json` 的 UI 键，三种语言必须齐全（`profile.py` 的 `UI_KEYS` 已按规则目录派生，缺一项就拒绝启动） |
| 默认值 | 首次启动的取值；修正类默认开、难度类默认关 |
| 生效时机 | 立即／下次结算／下次登场／下次进关／下次启动——现在规则是「下次结算」，头目假身是「下次登场」，这类差异必须显示在界面上 |
| 写入位置 | `rules.json`、presentation 设置或 profile |
| 存档影响 | 是否改变持久玩法状态；改变的要进入存档兼容清单 |

互斥组（例如头目假身的原版／减半／关闭）在数据层仍可以是两个布尔开关，但界面按单选呈现，避免现在「两个都勾时以取消为准」这种需要解释的状态。

## 4. 技术方案

- 第一版做 **AppKit 弹窗**，和当时的菜单栏代码同层，能直接复用语言标签与实时切换机制，不影响游戏渲染。（后已整体改为 RmlUi 页面，见文末。）
- 游戏内叠加 UI（RT64 层）留到需要手柄操作或跨平台时再做；那时设置模型不变，只换呈现层。
- 设置模型放在宿主的一个头文件里（类似 `rule_fixes.hpp` 的 `catalog`），Python 侧继续从同一份定义派生启动参数与校验，保证两边不会漂移。

## 5. 验收要求

- 每个分类、每项控件在三种语言下都有标题与说明；切换语言时窗口和菜单同时重绘（菜单已有这条，窗口沿用）。
- 改动写入对应文件并追加事件日志（现有 `rule-fixes-events.jsonl` 的做法），运行报告能还原「这次运行用了什么设置」。
- 提供 QA 控制钩子：像 `rule-control.json` 那样按下某一项，写出控件状态，供有界运行核对。
- 「恢复默认」与「原版」预设分开：前者回到默认值（修正开、难度关），后者是全部关闭的原版行为。
- 窗口开启时游戏暂停与否要明确；改动的生效时机按 §3 显示，不能让玩家以为战斗中途的切换会影响这一次结算。

## 7. 分页叠加面板（2026-09-27）

用户 2026-09-25 反馈整屏不透明的「选项」页像桌面程序，要「游戏内一键呼出」的面板（见 [Steam Deck 键位](../design/steam-deck-controls.md)「设置界面改版」）。2026-09-27 定下五个分页、叠加面板、记住上次的分页，实现在 `src/native/ui/frontend.cpp` 的 `settings_sync`。

**外观**：游戏画面照常运行、压暗（半透明底），中间一块与战前确认页同一套配色的直边面板（用户 2026-09-27：框体不要斜边，页签也是直边矩形）：顶部标题与六个页签（2026-10-01 加「存档」页），中间是可滚动的当前页，底部是按键提示和「关闭」。界面逻辑尺寸不小于 960×720 dp（界面大小放大时不小于 800×540 dp，见下），面板占 88%、最宽 1040 dp，窗口缩放时一起缩放。**游戏不暂停**，输入仍由 `ModalInputRelease` 挡住。

| 页（`settings_page` 值） | 内容 |
| --- | --- |
| 通用 `general` | 语言（日／简中／英）、画面（Original／HD，HD 素材缺失时两个按钮都灰掉）、画面比例（自动：随屏幕 4:3–16:9／4:3 原版，写 `presentation.json` 的 `aspect`，见 [宽屏画面](../design/deck-16x10.md)）；桌面平台另有显示方式（窗口／全屏）与窗口大小（1×–4×），见 §8 |
| 界面 `interface` | 界面大小（标准／大／特大）；战前确认界面（新版／高清原版／原版）、场间画面、主角选择与姓名输入、标题菜单画面，各一行分段按钮；显示帧率（关／开，写 `presentation.json` 的 `show_fps`）：右上角每半秒更新「游戏每秒帧数 · 这半秒里最长的一帧」，按游戏交给图形线程的显示列表计（`src/host/frame_rate.hpp`） |
| 规则 `rules` | 顶部三个预设与生效说明，下面「修正（默认开）」「难度（默认关）」两组，每条规则一行开关 |
| 存档 `saves` | 2026-10-01，见[多存档栏与自动存档](../design/save-slots-autosave.md) §8：自动存档开关；场间、回合两种自动存档各保留 1／3／5／10 份；把卡带写成 ares、Project64、mupen64plus、RetroArch 四种文件（存档库的 `export/`）；列出存档库 `import/` 里的模拟器文件，逐栏导入为扩展栏（校验和不符的栏要再按一次，修复后导入）。设置存在存档库的 `settings.json`，不进 `presentation.json`。调试会话没有存档库时只显示一行说明 |
| 操作 `controls` | 改键页（2026-09-28，见[改键](controls-remapping.md)）：识别到的手柄、键盘默认（PCSX2 布局）说明、按功能列出的改键表（键盘与手柄各一列，选中后按新键即改）、固定快捷键与恢复默认 |
| 关于 `about` | 版本号（取自根目录 `CMakeLists.txt` 的 `project(... VERSION)`，编译时经 `SRW64_VERSION` 传入）、HarmonyOS Sans 字体声明 |

每个开关由 `settings_choice(键, id 前缀, 模式列表, 当前模式)` 生成一行：上面是 `label(键)` 和右侧一个模式一个按钮，下面整行是 `label(键+"_note")`，id 为 `前缀:模式`（与 §6 相同，如 `battle-ui:native`、`images:hd`）。新增一个原版／新版开关只要在「界面」页加一行调用，再在刷新 stamp 里加上它的当前值。

**操作**

| 输入 | 键盘 | 手柄 | 鼠标／触屏 |
| --- | --- | --- | --- |
| 打开／关闭 | Ctrl/Cmd+, 打开；Esc 或 X 关闭 | 视图键打开／关闭；B 关闭 | 标题左上角入口（2026-10-02 前在右下角）、菜单栏；点「关闭」 |
| 换页 | Q／E、PageUp／PageDown、Ctrl+Tab／Ctrl+Shift+Tab | L1／R1 | 点页签 |
| 选择 | ↑↓（或 W/S）在行间移动；←→（或 A/D）在一行的选项间移动；焦点在页签上时 ←→ 直接换页 | 十字键／左摇杆，同左 | 直接点 |
| 确定 | Enter、Z、Space | A、菜单键 | — |

「行」是页签栏和每一个设置（带 `nav` 类的元素）；没有可选项的页（操作、关于）上 ↑↓ 改为滚动。换页后焦点落在新页第一个设置上（焦点在页签上换页时留在页签上）。用鼠标时不显示焦点框（`body.pointer`）。一个值改变后整页重建，焦点和滚动位置保留。

**记住分页**：每次换页写入 `presentation.json` 的 `settings_page`（`settings::set_settings_page`），下次打开（包括重启后）回到这一页。启动器用 `--language` 改写这个文件时照样带上它（`launch.cpp`）。

**调试接口**：`ui.click` 按 id 点一个不在当前页的设置控件时，会先翻到它所在的页再点（与玩家的操作一致），所以 `settings-control.json` 的 `press` 和按 id 点击的旧脚本不用改；页签本身的 id 是 `settings-page:<页>`。`ui.key` 送 `q`／`e`／`pageup`，`pad` 方法送 L1／R1 都能换页。

**中日文断行**：RmlUi 只在 ASCII 空白处断行，没有空格的中文、日文句子是一整段，放不下就溢出（09-27 实机：日文「インターミッション画面」的说明压到了按钮下面）。所以说明文字单独占整行宽。`word-break: break-word` 能强行断开，但会让 RmlUi 的断行循环卡死（`ElementText.cpp:508` 断言刷屏，窗口线程不再响应），**不要用**。`tests/test_settings_window.py` 按最小窗口估算每段不含空格的文字（说明、规则名、键位表两列、页签、名称加按钮一行）都放得下，新加或改长词条时会报出来。

**检查**：`tests/test_settings_window.py`（页与键位行两份列表一致、三语词条齐全、按最小窗口估算各列不溢出、分页写回与 `--language` 保留、换页的键位）。实机：`tools/recomp/debug/check_settings_pages.py`（标题画面上打开设置；中英日五页各截一张 960×720；Q/E、PageDown 与手柄 L1/R1 换页，行间、行内移动与确定；按 id 点别页的规则会先翻页；关闭后重开回到上次的页；手柄提示、B 关闭、视图键打开；1600×1000 大窗口截图），2026-09-27 全部通过，截图在该次运行目录。

另修了一处：旧版刷新 stamp 漏了「主角选择与姓名输入」「标题菜单画面」两个开关，点了以后按钮的选中状态不会更新；现在 stamp 包含全部开关。

## 界面大小

2026-09-28 用户在 Steam Deck 上反映：底部操作提示、标题画面的设置键提示、战前确认页的字都太小。原因：以 dp 排版的界面（设置窗口、战前确认新版、标题右下角设置按钮、通知）一个 dp 就是一个点，窗口大于 960×720 点时只多出空间、不放大；Deck 的 7 英寸 1280×800 屏上一个 dp 只有桌面的一半左右大。按原画 320×240 比例画的页面（场间各页、高清原版战前页）随画面缩放，不受影响。

- **设置**：「界面」页第一行「界面大小」：标准／大／特大＝1／1.25／1.5 倍（`settings::UiSize`，存为 presentation.json 的 `ui_size`，玩家选过才写）。没选过时 Steam Deck（`SteamDeck=1` 或固件报 Valve Jupiter／Galileo，`src/host/steam_deck.hpp`）为特大，其他为标准。
- **怎么放大**：`frontend.cpp` 的 `sync`：dp 先照旧（窗口小于 960×720 点时缩小），再乘界面大小，但放大后逻辑尺寸不小于 800×540 dp（Deck 上大＝1024×640，特大≈864×540）。页面据此必须在 800×540 dp 下排得下：设置窗口各列文字按 800 宽检查（`tests/test_settings_window.py`，日文页签「インターフェース」因此改为「画面」，长的日文说明加了空格作断行点）；战前确认页宽度不足 1000 dp 时加 `narrow`（头像 64 dp、按钮内边距变小），数字不再折行。
- **对白底栏**（宿主画在 320×240 坐标里）：随界面大小放大（最多 1.4 倍，到下方对白框的下沿为止），右侧操作提示在剩余宽度里放不下时缩小字号而不是截断。
- **按键图标**：SRW64Prompts 的图标原来按拉丁大写字母高度缩放，放在中文旁边小一号、LB/RB 只有一条细缝；现在每个图标放大到一个汉字高（约 930/1000，居中于 380，最多放大 1.4 倍，见 `build_prompt_font.py`）。
- **提示随设备**：没有手柄版本（`_pad`）的词条，手柄在用时其中的动作记号也显示手柄图标（原来一律显示键盘键）；战前确认页底部提示改用记号（原来写死 `Z / A`、`K / C▼`）。

实机（Mac，1280×800 点窗口模拟 Deck 的逻辑尺寸，2026-09-28）：标准／大／特大下看过标题、对白底栏、战前确认页、设置窗口与操作页；特大下战前确认页数字不折行、按钮一行、提示为按键图标。

## 8. 全屏与窗口大小（2026-09-29）

桌面平台都能切全屏、把窗口设成原版的整数倍；掌机（Steam Deck，按固件识别，游戏模式或桌面模式都算）一律直接全屏，不给这两项。

| 入口 | 做法 |
| --- | --- |
| Mac 菜单栏「显示」 | 「全屏」⌃⌘F（打勾＝当前全屏）；「窗口大小 1×–4×」⌘1–⌘4（打勾＝窗口正好是这一档）。SDL 自带 Window 菜单里的英文 Toggle Full Screen 同键，已隐藏。`src/host/macos/app_menu.mm` 只记请求，窗口线程在 `frontend.cpp` 里处理。 |
| Windows／Linux | F11 切全屏（无修饰键）。没有 Alt+Enter：游戏按扫描码读键盘，Enter 会同时按下 START。 |
| 设置「通用」页 | 「显示方式」窗口／全屏、「窗口大小」1×–4×，所有桌面平台都有。 |

- 全屏用 `SDL_WINDOW_FULLSCREEN_DESKTOP`（Mac 上是独立空间的原生全屏）。
- 窗口大小 n× ＝ 240n 点高，宽为当前比例下画面宽度的 n 倍（`frame::width`）：16:10 的 2× 是 768×480，16:9 的 2× 是 853×480，设为 4:3 时 2× 是 640×480。换档时保持窗口中心不动，并收在屏幕可用范围内；放不下（算上标题栏）的档位和全屏时的各档都不可选。
- 全屏状态不保存，每次启动都是窗口。
- 调试接口：`menu path=["显示","窗口大小 2×"]` 按下菜单项；`status.window.fullscreen`。

实测（`build/recomp/debug/20260929T132807.116292Z`，16:10 窗口起步）：菜单 1×–4× 依次得到 384×240、768×480、1152×720、1536×960；「全屏」得 2560×1440，同时四档变灰、「全屏」打勾；在设置页点「窗口」回到 1536×960，点「2×」回到 768×480；退出正常。
