# 改键

2026-09-28。用户要求：按键设置加 N64 手柄图对照，加上本作的附加按键，按一下就能识别并设置。定下来的做法：

- 改键后原生页面跟着新键走，Enter、Esc、方向键始终可用；
- 手柄图用用户给的图（`content/ui/n64-controller.png`，1448×1086，用户 2026-09-28 提供）：灰色三叉手柄，L、R 顶视小图，Z 底视小图，每个键一条引线连到一个空的彩色标签。

## 数据

[`input_bindings.hpp`](../../src/host/input_bindings.hpp)（不依赖 SDL，键码与手柄编号照 SDL，`graphics.cpp` 里 `static_assert` 核对）：

- **动作**：N64 的 A、B、Z、START、L、R、C 四向、十字键四向、摇杆四向，加三个本作按键——设置窗口（手柄视图键）、功能 1（L2：对白自动阅读开关、地图上一个敌人）、功能 2（R2：对白快进、地图下一个敌人、战斗中结束演出）。
- **绑定**：每个动作一张键盘键列表（扫描码）和一张手柄输入列表（按键，或某个轴的一个方向，过 16000 算按下）。默认值就是改动前 `graphics.cpp` 写死的表：Z/X/空格/Enter/Q/E/IJKL/方向键/WASD；手柄 A、B+X、Y、START、LB/RB、右摇杆作 C、十字键、左摇杆，视图键与两个扳机。键盘默认没有附加按键（设置窗口另有固定的 Ctrl/Cmd + ,）。
- **抢占**：把一个输入给某动作时，它替换该动作在这个设备上的全部输入；原来占着它的动作失去它，如果因此没键了，就拿到本动作原来的第一个键——等于互换，不会有键丢失。
- **存盘**：`input.json`（启动器放在用户目录，`SRW64_INPUT_SETTINGS`；开发运行放在 presentation 设置旁），只写与默认不同的动作，按 SDL 名字（`"Z"`、`"Return"`；`"a"`、`"leftshoulder"`、`"righty-"`）。读到不认识的名字就丢掉。
- **每帧**：`graphics.cpp` 按绑定算 N64 位和宿主位；调试接口按住的虚拟键按同名物理键算。读 L2/R2/视图键的三处（对白、敌方切换、设置入口）读合并后的状态，所以绑到键盘也能用。

## 提示与页面

- 提示词条的记号是动作（`{A}` `{Start}` `{L}` `{CUp}` `{DPad}` `{Settings}` `{AuxL}` …），显示当前绑定：手柄提示显示按键图标（按手柄家族），键盘提示显示键帽图标或键名（跟键盘布局）。组合记号在默认时显示一个整体图标。页面固定键 `{Enter}` `{Esc}` `{Tab}` 和方向键图标不随绑定变。见 [`button_prompts.hpp`](../../src/native/text/button_prompts.hpp)。
- 原生页面：键盘事件进来时，绑到某 N64 键的键翻成该键在页面上的默认键（A→Z、L→Q、十字键／摇杆→方向键…，`frontend.cpp` 的 `follow_bindings`）；Enter、Esc、Tab、方向键不翻；绑到设置窗口的键开关设置窗口；绑到功能 1、2 的键在页面上不起作用。手柄经 `pad_keys` 已经按 N64 位走，天然跟随。
- 对白底栏提示在宿主拍帧快照时展开（`Frame.controls_text`），可移植的场景绘制不需要 SDL。

## 操作页

`frontend.cpp` 的 `controls_page`：

1. **设备**：键盘／手柄两个按钮，手柄按钮写着 SDL 报告的手柄名（没有手柄时写“未连接”）。手柄图显示所选设备的绑定。
2. **手柄图**：图宽取页面宽的 80%（最多 860 dp），每个空标签上盖一个同色按钮：N64 名（十字键、摇杆按语言）加当前绑定（浅色底块）。按钮从引线那头往外长（`callouts[]` 记着图上每个标签的像素框和生长方向），所以绑定再长也不压住手柄。
3. **附加按键**：设置窗口、功能 1、功能 2 三个按钮。
4. **固定快捷键**与**恢复默认按键**：Ctrl/Cmd + , 设置、F5 重载台词、F6 原版／HD、F7 语言、Esc 退出，不可改。
5. 下面是原来的四组键位说明表，右列文字随绑定变化。

**改键**：点选（或手柄 A）一个按钮，弹出“请按下给「A」的新按键”，下一个键盘键或手柄键（按键或把摇杆、扳机推到底）就绑给它；从哪个设备按的就改哪个设备，图随之切到该设备。十字键和摇杆依次问上、下、左、右。Esc 取消，6 秒没按也取消；F5–F8 被拒绝。手柄按下后要等全部松开，页面才重新接受手柄导航，避免刚绑的键立刻触发别的按钮。
