# 部队名固定为默认名（3D5E）

2026-09-27 用户定：人名和部队名都不许玩家改，原版页面也不开（设置里选原版时同样）。部队名因此始终是游戏默认的 マーチウィンド，显示时按阅读语言换成「三月风」「March Wind」。人物默认名与显示替换是另一项改动（默认名三语，文档 default-names.md），这里只记部队名。

## 行为

- 第 33、46/58、62 场景开场，アムロ 提出「マーチウィンド」后的选择「それでかまわない／気に入らない」不再出现，直接按第 1 项继续：主角说「マーチウィンドか……いいんじゃないか」，接着是 ブライト 拍板。「気に入らない」分支（主角嫌名字、アムロ 问叫什么、`3D5E` 打开部队名输入、主角提出新名字）不再执行。
- `3D5E` 万一被执行到（迷你关卡、调试脚本），什么都不做：不切到模式 6，不开任何页面，`8010F698` 原样，脚本立刻继续。
- 部队名缓冲只存原版字形。默认名三语登记 `Field::Unit`：`ja` 为 マーチウィンド，其他语言取语言目录的 `unit_default_name`（zh-Hans「三月风」、en「March Wind」，与 `content/translation/story-terms.json` 一致）。对白里 `<G:012C>`（台词文件写作 `{HeroMech}`，名字起得不对，其实是部队名）按语言显示由默认名三语那边接到对白展开处。旧版本里改过名的存档显示原样。
- 只在带 RT64 的游戏宿主里生效；CPU-only、固定帧诊断宿主不装这两个回调，保持原版流程。

## 原版流程（静态分析）

| 地址 | 作用 |
| --- | --- |
| 事件 `001AB86C`（第 33 场景）、`001AC6F0`（62）、`001BC304`（46/58） | 开场事件里 `3D44 0,2,<文本>`（窗口槽 0、2 项，文本 24045／24417／32003，都是「それでかまわない／気に入らない」），之后 `3E10`（第 1 项）分支与 `3E11`（第 2 项）分支；`3D5E` 只在第 2 项分支里。 |
| `8009FA94` | `3D44` 的处理函数，参数是脚本 VM 上下文：`+0x1C` 为越过操作码的 PC（三个参数），`+0x26` 首帧为 0（首帧开窗并置 1），`+0x24` 忙标志（VM 每帧调用处理函数直到它清零），`+0xC` 指向引擎 `+0x994`。确定时释放窗口精灵 0x23、`+0x24=0`、PC+6、`*(+0xC)=0x3DD9+光标`。`3E10`／`3E11` 比较的就是这个值。 |
| `800A1050` | `3D5E` 的常驻处理：调用世界地图 overlay 的 `801C517C`，随后 `+0x24=0` 完成命令。 |
| `load_000A7EC0:801C517C` | `801C58C4=2`，`80080188(6)` 切到模式 6，`80099814(5,1,2)` 淡出。 |
| `800801A4` → `800CFEC8[模式-1]` | 模式 6 走 `8008032C`：`80080038` 把 ROM `0x1090A0–0x10DA50` 装到 `801C2600`（与主角选择、姓名页同一个 overlay），登记 `801C69B4` → `801C6814(1)`。 |
| `801C6814(a0)` | 公共初始化；`a0=0` 是新游戏命名（状态 0，`801C5004`），`a0=1` 把状态 `801C6FB0`／`801C7144` 置 4 并调用 `801C6034`。每帧任务 `801C657C` 按状态查 `801C6F74` 的 {初始化, 每帧} 表，状态 4 是 `801C6034`／`801C62D8`。 |
| `801C6034` | 画假名选字盘；编辑区 `801C71E0` 清零后前 7 格填 `801C6F54` 的字形（マーチウィンド），显示用 `801C6F64` 的选字表 TEXT id（同为 マーチウィンド）；光标格 `801C7228`，插入位置 `801C721C`。 |
| `801C62D8` | 每帧：A 在「決定」格（0x7D）上时调用 `801C4C40`，非 0 则弹窗 0x92、`801C71DC=1` 等再按一次；为 0 则 `801C70F4=2` 并淡出。其他格 A 调 `801C4308` 写一个字（写满第 10 格后停在第 10 格），B 调 `801C465C` 删当前格并左移。 |
| `801C4C40` | 确认：把 `801C71E0` 至多 10 个字形拷进 `8010F698`（末尾的空格即字形 0 不拷，中间的算字），一个字都没有返回 1；再把 `8010F698` 的 10 个半字逐一和 `801C6EC8` 的 6 个保留名（每条 10 个半字）比较——OZ、オズ、スペシャルズ、ホワイトファング、アクシズ、ネオジオン——全等返回 1；否则在名字后写 `0xFFFF` 返回 0。 |
| `801C657C` 淡出结束 | `801C70F4==2` 时：模式 5（新游戏）走 `801C69D0` 定首话、模式 0x1F、`801C5FCC` 把默认部队名（`801C6F54`，7 字加 `0xFFFF`）写进 `8010F698`；其他情况（部队名页）切模式 0xD，回世界地图。 |

- `8010F698` 共 12 个半字（`801C5FCC` 清 12 个），名字最多 10 字加结束符；对白用字形 `0x12C` 引用它。
- 保留名比较的原版毛病：`801C4C40` 拷贝时不清除名字之后的旧内容，却比较全部 10 个半字。新游戏后缓冲是 マーチウィンド＋`0xFFFF`，所以只有 8 字以上的保留名（ホワイトファング）真会被拒，「OZ」「アクシズ」这类短名能通过。现在玩家到不了这一页，留作记录。
- `801C6034` 里还有一处 `801C3634(801C6F64[i]+0x14D0, i, 0)`，按一个无关的 TEXT id 写 `801C71E0[i]`，随即被 `801C6F54` 的字形覆盖，不影响结果。

## 实现

- `src/host/unit_name.hpp`／`unit_name.cpp`，由 `host.cpp` 在对白目录加载（`dialogue::configure`）之后配置：
  - `answer_choice`：在 `3D44` 首帧（`+0x26==0`）遇到 2 项、文本为 24045／24417／32003 的选择，照原版确定路径写 `0x3DD9`、PC+6、`+0x24=0`，原处理函数不运行，窗口不打开。经 `srw64_game_hooks.choice_step` 由 `game_hooks.cpp` 的 `resident_func_8009FA94` 包装调用。
  - `3D5E`：`generate_cpu.py` 的 `NATIVE_HOOKS` 把 `load_000A7EC0_func_801C517C` 改名为 `srw64_original_unit_name_command`，包装经 `srw64_game_hooks.unit_name_page` 直接返回。改了 `NATIVE_HOOKS` 要手动重跑 `generate_cpu.py`。
  - `add_default`：从每种语言目录的 `unit_default_name` 取名字登记进 `names::default_names()`；不看姓名页开关，`SRW64_NATIVE_NAME_ENTRY=0` 时对白也按语言显示。
- 事件日志 `unit-name-events.jsonl`（调试接口 `events unit_name`）：`default`（登记的各语言名字）、`choice-answered`（文本、第 1 项）、`page-skipped`。
