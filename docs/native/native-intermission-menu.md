# 场间主菜单：原版逻辑与原生接管

![原生场间主菜单（日文）](images/intermission-ja.png)


日期：2026-09-21。状态：**已实现，完整菜单已在实机验证；两项菜单和 RNG 对照尚未运行验证**（见第 9 节）。第 1–3 节是对 `load_0008F4B0` 和常驻段的静态分析结论（反汇编与 ROM 数据表）；第 4 节以后是接管方案。画面基线是 `sdl-link-01` 运行留下的原版截图，运行目录不保留。

## 1. 原版画面

背景是一张随进度挑选的大图，上面叠四块深蓝半透明、蓝色细边的直角面板，菜单当前项用绿色高亮条表示，白色点阵字。坐标均为 320×240：

| 面板 | 矩形（左上–右下） | 内容 |
| --- | --- | --- |
| 标题 | (120,25)–(199,39) | `0xFCC` インターミッション，文字起点 (124,25) |
| 菜单 | (33,41)–(103,183)；两项菜单为 (33,41)–(103,71) | 文字 x=34，y=41+16×n；高亮条 x=33、宽 70、高 16 |
| 信息 | (145,49)–(287,79) | `0xFD6` 総ターン数／資金 在 (146,50)；数值右对齐，`%4d` 在 (254,49)，`%8d` 在 (222,65) |
| 章节 | (34,193)–(287,207) | `0xFD7` 第␣␣話 在 (34,193)；话数 `%2d` 在 (48,193)；标题文本号 `8010F5F1+0x119` 在 (82,193)，其后接 `0xFE0` クリア |

矩形来自布局的显示列表（F3DEX2 `G_FILLRECT`，10.2 定点），不是从截图量的。のりかえ 弹窗（布局 0x86）矩形 (109,121)–(155,160)，两项 `0xFEC` パイロット (112,123)、`0x1002` 妖精 (112,143)，光标步长 20。

菜单项文本号 `0xFCD`–`0xFD5`：データセーブ、ユニット改造、武器改造、ユニット能力、パイロット能力、のりかえ、強化パーツ、リンク、次のマップへ。

## 2. 调度框架

- 入口 `801D8F74(mode)`：清 `D_801DECB8`（下一画面）、`D_801DECCC`（当前画面）、`D_801DD540`（退出码）、`D_801DD548`（主菜单光标），调主菜单初始化，`8007E810(0x21)`，把 `801D8D20` 注册为每帧任务。
- `801D8D20` 每帧读转场状态 `80099B30()`：
  - 3（淡出结束）：退出码 2 → 进下一关（`80080188(0xC)` 后 `801D9F74`）；退出码 1 → 软复位；否则清精灵和文字槽，按 `D_801DECB8×8` 查 `D_801DC9D0` 调新画面初始化。
  - -1（空闲）且 `D_8015D9FA & 0x3000 == 0x3000`（同时按住两个键）：退出码 1，转场。
  - 不是 0 也不是 2：调当前画面每帧函数。
- 画面表 23 项 {初始化, 每帧}：0 主菜单；1–8 对应菜单第 1–8 项；9–22 子画面（10 改造详情，20/21 妖精のりかえ，22 由リンク可达）。各画面 B 写 0 回主菜单，转场一律 `80099814(5,1,2)`。
- `801D796C`–`801D8CC8` 是无人引用的遗留测试画面链。

## 3. 主菜单（画面 0）

| 函数 | 作用 |
| --- | --- |
| `801CDF30` 初始化 | 首次进入（`D_801DC240==0`）：`80085B94(0,0)` 放亮背景，`D_801DD5CC=30` 帧延时；再次进入：`80085B94(0,1)` 放暗背景、不延时。清 `D_801DEC50`（已构建标志），`80099814(4,2,0)` 淡入。 |
| `801CDFB0` 构建 | 查 `8010F5F1` 是否在 `D_801DC6D4`（13 个「（前）」场景＋132「アクシズの攻防（中）」）：命中用布局 0x8D、`D_801DECD8=10`；否则布局 0x69、`D_801DECD8=0`。画数值与章节标题，建光标（精灵槽 0x14、图 0x8E、动画 `801C45F4`），`80085B94(0,1)`，`D_801DEC50=1`。 |
| `801CE19C` 每帧 | 已构建时先跑光标 `801C4A20`（读 `D_801DD62C` 的 0x800/0x400，循环，音效 0xB9），并**每帧**把 `D_801DECB8` 写成光标+1（两项菜单：0→1，1→9）。空闲且未构建：倒计时后调构建。空闲且已构建：见下。 |

空闲时的按键处理（`D_80178A08`：A=0x8000，B=0x4000）：

- `D_801DECD8==0`（完整菜单）按 A，音效 0xB7：
  - 下一画面 9：`D_801DD540=2`，转场（进下一关）。
  - 下一画面 8（リンク）：`801D9300`、`801D93C4` → `D_801DD114`；0 则进画面 8，非 0 进画面 22。
  - 下一画面 6（のりかえ）：建布局 0x86 弹窗和槽 0x15 光标，`D_801DECD8=1`，不转场。
  - 其余：`801CDE9C`（清各子画面的选择缓存）后转场。
- `D_801DECD8==1`（のりかえ 弹窗）：B 关弹窗（0xB8）；A 先 `801CDE9C`，光标 0 调 `801C5618`、光标 1 调 `801C5E64` 建候选表，返回 0 则蜂鸣 0xB8 留在弹窗，否则 `D_801DEC60=光标`，妖精另把下一画面改成 0x14，转场。A 分支不碰弹窗精灵。
- `D_801DECD8==10`（两项菜单）按 A：同「下一画面 9」或普通转场。

两点会约束接管方式：

1. `80085B94` 每次都调 `80082334`（随机上限），**消耗 RNG**，见下。初始化和构建里对它的调用必须原样保留。
2. `801C5618`／`801C5E64` 只写覆盖段内的候选表（无 `jal`），就是のりかえ画面随后要用的表，可以就地调用。

### 背景图

共 **8 张**，每张是 320×240 的 8 位索引图（资源 `0x155E`–`0x1565`），各配亮、暗两套 256 色调色板（`0x1566`–`0x156D`、`0x156E`–`0x1575`）。已用项目的资源解码器全部解出确认。

`80085A24` 扫我方机体池（`8016A210`，140 槽 × 0x54，机体号在 `+2`），取第一台主角机决定类别；`80085B94(槽, 暗)` 按类别查 `D_800C59AC`（8 字节/项：图、亮调色板、暗调色板、候选数）：

| 类别 | 主角机 | 图 |
| ---: | --- | --- |
| 0 | アシュクリーフ `0x1F` | `0x155E` |
| 1 | ソルデファー `0x1E` | `0x155F` |
| 2 | スヴァンヒルド `0x20` | `0x1560` |
| 3 | ラーズグリーズ `0x21` | `0x1561` |
| 4 | アースゲイン `0x22` | `0x1562` |
| 5 | スーパーアースゲイン `0x132` | `0x1563` |
| 6 | スイームルグ `0x24` | `0x1564` |
| 7 | スイームルグS `0x133` | `0x1565` |
| 8 | 找不到主角机 | 同类别 0 |

所以背景不随话数变，只随主角机（含后期换乘的两台强化型）变。每项候选数都是 1，`80082334(1)` 恒得 0，但调用本身仍推进 RNG；类别 9 的「九选一」分支在本作到不了。首次进入用亮调色板，菜单构建时和从子画面返回时换暗调色板，图本身不变。背景画在精灵槽 0，`80098158(槽, 0, 4, 0xA4, 0, 图, 调色板, 0)`。

## 4. 接管目标

1. **观感不变，清晰度和语言现代化。** 保留背景图、四块面板的位置比例、深蓝半透明底、蓝色细边、绿色高亮条和白字；用矢量字体、跟随窗口缩放，文字走中／日／英目录。不改成卡片式新设计（リンク页那种整页重排不适用于此）。
2. **流程零改动。** 选中哪一项之后发生什么（检查、音效、转场、RNG、退出码）仍由原函数决定；适配层只替换「画」和「读键」。
3. **鼠标与键盘都能完成全部操作**，B／Esc 行为与原版一致（主菜单上 B 无效，弹窗里 B 关闭）。
4. 可关：设置页「场间画面」选原版（`presentation.json` 的 `intermission_ui`，调试接口 `settings {"intermission_ui": "original"}`），下一次画面构建时生效，已打开的原生页面在离开时关闭；`SRW64_NATIVE_INTERMISSION=0` 或不加载 profile 则整次运行保留原画面。验证脚本 `tools/recomp/debug/check_intermission_ui_switch.py`（2026-09-23，`build/recomp/debug/20260923T025544.572614Z/`，8 项通过、退出码 0：原生菜单开着时切原版，进 ユニット改造 出现原版列表、B 回到原版菜单；切回新版后 Z 进原生列表、B 回原生菜单且光标仍在 ユニット改造；`presentation-settings.json` 随之写 `intermission_ui`）。

不在本页范围：八个子画面仍是原版（リンク前置页除外）。从原生主菜单进入原版子画面会有一次观感切换，这是分阶段接管的已知过渡状态。

## 5. 接管方案

沿用战前页的模式：游戏线程适配器发布 JSON 快照，`frontend.cpp` 只读快照、回传带 serial 的语义动作，不读 RDRAM。

**钩子**（`generate_cpu.py` 的 `NATIVE_HOOKS` 新增两项，改后需重新生成 CPU 代码）：

| 原函数 | 包装行为 |
| --- | --- |
| `801CDFB0` 构建 | 不调原函数。照抄它的非绘制部分：判定两项菜单并写 `D_801DECD8`，`80085B94(0,1)`，`D_801DEC50=1`。不建布局、文字和光标，所以原版面板不会出现，也不占精灵槽与文字槽。然后发布快照、页面可见。 |
| `801CE19C` 每帧 | 页面可见期间输入已被过滤成 0，原函数照常调用（它只会空转并刷新 `D_801DECB8`）。收到 `choose:N`：写 `D_801DD548=N`，给 `D_80178A08` 一次 A 边沿，调原函数，恢复 `D_80178A08`。收到 `move:N`：写光标并播放原版移动音 0xB9，光标因此留在游戏里，从子画面返回时停在原项。 |

初始化 `801CDF30` 不钩：背景、30 帧延时、淡入都保持原样。

注意原每帧函数在已构建时会对槽 0x14 调 `801C4A20`。它只有 `0x800`、`0x400` 两个分支，都不命中时直接返回、零写入（已对反汇编确认）；注入 A 边沿的那一帧 `D_801DD62C` 仍为 0。因此不建光标精灵是安全的。

原函数只在 `80099B30()==-1` 时处理 A。适配器要在同一条件下才消费动作，否则留到下一帧，不能丢。

**のりかえ**：原生页自己显示「驾驶员／妖精」二级菜单，原版弹窗不创建。确认时适配器写 `D_801DECB8=6`、`D_801DECD8=1`、`D_801DEC58=选择`，注入 A，调原函数；它完成检查、`D_801DEC60`、画面号和转场。返回后若没有开始转场（候选为空，原版已播蜂鸣），把 `D_801DECD8` 复位为 0，页面保持打开并提示不可用。进阶：打开二级菜单时先就地调两个候选表函数，把空的一项置灰。

**リンク**：不特殊处理，A 边沿后原函数自己走 `801D9300/801D93C4` 分支，随后由现有リンク页接手。

**快照字段**：`serial`、`visible`、`restricted`（两项菜单）、`cursor`、`turns`（`8010F5EC` u16）、`funds`（`8010F5F4` u32）、`episode`（`8010F5EF`）、`scene`（`8010F5F1`）、`title_key`（`base:t00_{281+scene}`）、`submenu`（のりかえ 二级菜单状态）。

**可见时机**：`D_801DECCC==0` 且已构建且退出码为 0 时可见；动作提交（转场开始）即隐藏并进入按键释放门控。淡入淡出仍是游戏画面里的原版效果，页面自己做一个短的不透明度过渡与之对齐；不追求逐帧同步。

**输入**：`host.cpp` 过滤链加 `intermission_page::input`；`frontend.cpp` 的 `sync/choose/dispatch/summary` 各加一路，与 link／battle 并列。方向键和 Tab 循环移动（保留原版首尾循环），Enter／Z 确认，Esc／X 只在二级菜单里有效。

**软复位组合键**：原版在调度器里读按住状态 `D_8015D9FA`。页面拥有输入时这个组合会被吃掉。方案：过滤器对「两键同时按住」放行，不做原生替代入口。

## 6. 视觉规格

- 以 320×240 为设计坐标，按窗口短边等比缩放，四块面板用第 1 节的矩形；4:3 以外的窗口比例下整体居中，背景仍由游戏画。
- 面板：深蓝半透明底（取原版观感，约 `rgba(10,14,60,0.78)`，实现时对着截图调）、1 设计像素的蓝色边（约 `#3A78E0`），直角。
- 高亮条：原版绿（约 `#00C800`）实心条，宽度同菜单面板内宽，文字保持白色；鼠标悬停用同色低透明度，避免与当前项混淆。
- 字体：沿用共享 UI 的字体发现；字高按 16 设计像素行距取约 13–14。中文和英文若超宽，先收紧字距再缩小，不换行、不撑宽面板（英文「Pilot Abilities」是最长项，需实测）。
- 数值右对齐到原位置；资金保留 8 位宽度的对齐基线，不加千分位（与原版及改造画面一致）。
- 章节行格式走目录模板，如 `第{n}话 {title} 通关`，标题未翻译时回退日文。
- 现代化只加两样：底部一行很淡的按键提示（与リンク页同款），以及可选的当前项一句话说明；二者都不进入四块面板，关掉后与原版逐块对应。

## 6a. 资金直接修改（2026-09-22）

主菜单和改造画面里的資金数字是一个按钮：点击后原地变成输入框（旧数字已选中），输入 0–99999999 的整数后 Enter 立即写入 `D_8010F5F4`，Esc 取消。写入在游戏线程完成（适配器动作 `funds:N`，`intermission_menu.hpp::parse_funds` 校验），页面和随后的改造判断都读到新数字；事件日志记 `{"kind":"funds"}`。这是内置 MOD 的便利功能，不受规则开关控制，也不做上限之外的合法性判断（原版显示宽度 8 位，故上限 99,999,999）。

调试接口：`ui.click --text intermission-funds`（改造画面 `upgrade-funds`）→ `ui.type 900000` → `ui.key return`；`tools/recomp/debug/check_funds.py` 覆盖主菜单修改、Esc 取消、五项画面修改后的 資金が足りません／確認窗、以及扣款基于新数字（8 项通过，运行 `build/recomp/debug/` 见脚本输出）。
