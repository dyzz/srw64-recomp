# 战前 UI：攻击与反击设计说明

日期：2026-09-21。本文用于界面设计评审与后续调整。下方两图是当前 native build 在自制迷你关卡中的实机截图，作为现状基线；设计目标与验收要求不代表每项视觉细节已经达到最终效果。

## 设计目标

1. **确认前能作出战斗决策。** 玩家能够快速比较双方命中、暴击、伤害与防御能力，并在当前页面完成换武器、使用精神及选择应对方式。
2. **左右对称，交战关系明确。** 敌方固定在左、我方固定在右；攻击与反击沿用同一套布局。机体朝向中央，同类信息处于相同高度，主要数值容易横向比较。
3. **延续原版观感，吸收机战 Y 的信息组织。** 保留深蓝面板、青色边框与战场地图；参考 Y 的双方镜像、驾驶员信息区、精神状态格和居中操作区。
4. **显示可信且能解释的结果。** 命中、暴击、伤害与实际结算保持一致。精神、技能、护罩等影响应能被玩家看懂；界面不预先揭示随机判定结果。
5. **保留战场位置感。** 面板之间及下方仍能看到地图和单位，避免战前确认完全遮断战场。

## 图一：我方主动攻击

![主动攻击实机界面](images/battle-ui-attack.png)

场景：右侧万丈主动攻击左侧敌机。已使用必中与大根性，SP 剩余 18，HP 恢复至 3000/3000，底力转为未发动。该图用于评审主动攻击的双方信息、精神状态与操作入口。

**操作需求**

- 主操作为“开始战斗”；辅助操作包含“选择武器”“精神”“战斗动画开／关”“返回选择”。
- 选择武器应直接打开武器列表。保留射程、弹药、EN、气力和移动后可用性限制；选定武器与合法目标后重新计算预览。
- 使用精神后回到当前交战，保留有效的武器和目标，刷新 SP、HP、气力、命中、暴击、伤害及能力状态。
- 返回选目标或取消攻击不消耗攻击行动；已经施放的精神及其 SP 消耗保留。

## 图二：敌方攻击／我方反击

![反击实机界面](images/battle-ui-counterattack.png)

场景：左侧敌方攻击，右侧万丈应对。万丈已使用必闪，SP 剩余 3，对方命中为 0%；重新选定合法武器后恢复反击。HP 1575/3000、EN 75/150，已损失部分用红色表示。

**操作需求**

- 支持“反击”“回避”“防御”三种应对，明确当前选择；确认按钮或相邻状态应让玩家知道将执行哪一种。
- 可以更换反击武器，也可以在本页使用精神。选择回避／防御后使用精神，返回时保留应对选择；重新选择合法反击武器后切回反击。
- 回避／防御导致我方不攻击时，攻击数值显示为“—”并说明原因，卡片高度与信息位置保持稳定。
- 敌方攻击已成立时，不提供退出该次交战的普通取消入口；关闭精神菜单只返回应对页。

## 两种页面的共同需求

| 信息区域 | 必须显示及行为 |
| --- | --- |
| 机体与驾驶员 | 机体大图、机体名、驾驶员头像与姓名、等级、气力。两侧机体相向；驾驶员头像保持原图方向。 |
| 资源 | 双方当前／最大 HP、EN，驾驶员当前／最大 SP。HP／EN 当前部分绿色，全部已损失部分红色；左右填充方向镜像，数值与条长一致。 |
| 武器 | 当前武器名、EN／弹药消耗、武器命中与暴击补正；不可用选项说明限制。最终概率中已计入武器补正，不能再次叠加。 |
| 核心预览 | 双方命中率、暴击率、命中时伤害及暴击伤害。突出主要数值，次要解释放在相邻区域或详情中。 |
| 精神状态 | 双方已习得及当前生效的精神以状态格呈现。未生效灰色、生效高亮；即时恢复类不显示为持续 buff。显示名称，避免仅靠颜色表达状态。 |
| 精神选择 | 我方参战机体的各驾驶员分别显示已习得精神、当前 SP、消耗与可用状态；不能透支、重复错误扣费或消耗另一驾驶员的 SP。 |
| 特殊防御 | 双方均显示切落、盾防、分身的本次几率。说明装备、技能等级、气力、必中覆盖、武器是否可切落等限制；这些是各判定的条件概率，不能直接相加。 |
| 护罩 | 按本作实际护罩类型与武器属性判定，显示本次是否适用、无效化／减伤／贯穿、伤害变化与 EN 消耗。不能单凭武器名称是否含“光束”判断。 |
| 能力效果 | 底力、新人类／强化人间、圣战士、超能力，以及其他影响命中、回避、防御的能力，显示等级、本次是否生效、具体补正与未生效原因。底力随当前 HP 刷新，不沿用其他作品的装甲加成。 |

## 布局与交互验收

- 双方卡片等宽等高，HP／EN、身份、精神、武器、核心数值、特殊防御及能力区逐行对齐。不能因一侧内容更多而把整张卡片撑高。
- 命中、伤害和当前应对优先可见；详细补正允许独立滚动，但不能挤出主要操作区。长名称与精神状态格不能重叠或遮住主要数据。
- 精神菜单打开时，背景操作不可触发；方向键与 Tab 只在当前可用选项中循环。Esc 先关闭子菜单，确认键不能穿透到地图。
- 通过鼠标和键盘均能完成完整操作。更换武器、使用精神、切换应对后，所有关联数值同步刷新。
- 在中文 960×720、英文 800×600、日文 1100×760 的逻辑窗口下，主要按钮均可见且可操作，左右结构保持一致。
- 以新 native build → 主菜单 → 自制迷你关卡验证；使用现有调试接口、实际 SP／资源变化与 GPU 截图验收。

## 当前边界与下一轮视觉重点

- 需要在地图选择目标的精神，以及自爆、复活，目前在战前页禁用并提示地图入口；当前页面不包含地图目标选择流程。
- 两图是当前实现基线。反击图中“命中 0%”仍与条件伤害并列，后续应把“命中时伤害”的含义放到数值附近，避免被理解成必定受到该伤害。
- 当前反击确认按钮仍统一写“开始战斗”；后续可根据应对显示“开始反击／回避／防御”，强化当前操作状态。
- 信息较多的一侧目前需要滚动查看部分补正。后续调整应优先保持主数值和能力状态可见，再压缩重复解释，继续保留地图空间。
