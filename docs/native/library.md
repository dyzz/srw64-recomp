日期：2026-10-02。原版没有的资料页：标题画面右下角 MOD 左边的「Library」，也可从设置「通用」页的「Library · 图鉴」进入（给够不到标题按钮的手柄）。窗口沿用设置窗口的框体，左边列表、右边详情，分「机体」「人物」「动画」三页（动画见[下文](#动画)）。

## 作品分组

| 机体表 | `D_801CB964`，ROM `0x114EB4`，316 条 | `u16 机体, s16 作品, s16 型号` | `801C930C` 建表，`801C9578` 详情显示型号（文本 `110+型号`，−1 无）与作品名 |
| 作品名 | 文本 `60+作品`（带换行的版本 `85+作品`），25 部 | | 中英文译名在词条表 `series` 段 |
| 重复记录别名 | 人物 `D_800C6A08`（ROM `0x513F8`，33 对），机体 `D_800C6A8C`（ROM `0x5147C`，22 对） | `u16 重复编号, u16 主编号` | 原版「见过」判定 `80091574`／`80091670` 用它把重复记录归到主记录；同一编号多次出现时最后一对生效，照搬 |

原版没有介绍文字：两个详情画面只显示上面这些，ROM 文本里也没有成段的人物／机体介绍。原版的列表还按「见过」位图（`D_8010F4D0`／`D_8010F520`）决定显示哪些，图鉴不做解锁，全部显示。

归组顺序：在表里 → 按别名找到主记录 → 表里同名的记录 → `library.cpp` 的补充表（徒步的ドモン 等、ハイパー系オーラバトラー、盖塔战机、ビッグゴールド、ドラゴノザウルス，以及能从兵种名确定作品的杂兵）→ 都不行的归「其他」（AI、ゲリラ 等）。**真・ゲッター1/2/3 原版表归在オリジナル，图鉴改归ゲッターロボ**（用户决定）。组的顺序是作品在原版表里第一次出现的顺序（UC 高达各作 → G → W → 超级系 → 原创），组内按原版表顺序，表外的排在后面按 ROM 顺序；机体详情加型号，两页详情都显示作品名。

### MOD 加的机体与人物

已启用的包加的新机体、新人物（[新编号](../design/new-unit-ids.md)、[完整机体 MOD](../design/unit-mod-kit.md) §5）都在列表最后的「MOD」组（2026-11-18 用户定），不并进原作的组；详情行写「包名 · 原作」（原作取包里写的 `work`，否则取照抄对象的作品）。新人物的能力按它自己的记录行读，头像用包里的图。

## 页面

版式以 Steam Deck「特大」界面（1280×800 像素、1.48 像素／dp，约 865×540dp）为基准设计：面板几乎占满窗口（96%×94%，上限 1180×760dp），标题与页签同一行，列表固定 210dp；图框取详情区宽度的 30%（150–220dp，Deck 约 164），地形放在图下；金色标签（改造上限／二回行动）在名字右边，人物的阵营等短标签跟在全名后；机体数值每行 3 格，人物 7 项加一个「Lv1 → Lv99」图例格每行 4 格，恋爱补正单独一行；武器名后的标签放不下时换行，列表长名字自动缩字。改界面大小或窗口时整页重建。Mac「标准」大小下同一版式更宽松。

两页同一版式：左边方形大图（机体战斗立绘、人物头像），右边作品（机体加型号）、名字（人物加全名）、标签行、数值条、地形；下面是各自的小节。

- **机体**：金色标签是改造上限（+0x20，6–15 段，武器共用），其后移动类型、尺寸、特殊能力、盾、强化部件槽（+0x19）、修理费。六项数值条满格取全体前 10% 左右（HP 22000、EN 300、移动力 10、运动性 130、装甲 2300、限界 380）。武器表加「满改」（改到上限的攻击力）与「型」（改造类型 Ⅰ–Ⅳ，武器 +0xE；每段增量是常驻表 `D_800CA590` 的一行，费用是改造画面 overlay 的四张 u32 表），表下按本机出现的型列出改满共加多少攻击力、花多少资金。满改解锁的武器（`D_801DC87C` 18 条，已在机体武器表里，+0xF 带未解锁位 0x04）标「满改解锁」，+0xF 0x02 标「合体技」，其后列出搭档机体（按驾驶员判定的列全部驾驶员；本形态不能领队的列能领队的形态），见[合体技](../gameplay/combination-attacks.md)。
- **人物**：金色标签是二回行动等级，其后阵营（原版人物表第三字段，1＝以敌方登场）、副驾驶员／妖精（能力记录 +0 的 0x80／0x40；这两类六项能力与二回行动照原版能力页显示「–」，精神点数照常）。恋爱补正（表 ROM `0x1012B4`）每位搭档带小头像，标「双向」或「单向」：搭档也有一行指回本人才算双向，原版有 7 条单向（阿莲比→多蒙、利修→塞蕾茵、艾玛丽→布莱特、比查→艾露、艾露→捷度、波士→纯、波士→沙也加）。数值条白色到 1 级、青色延伸到 99 级。精神指令为卡片（习得等级、消耗），特殊技能画在 1–99 级的刻度轴上。
- 没展示的原版数据：换乘类别（机体 +0x12、驾驶员 +0xB）、出售基础价（只有 9 种量产机可卖，表 ROM `0x109030`），按用户决定不显示。

## 收录规则

- 按作品分组，见上。
- 名字为空、`???` 或纯数字的占位人物不收。
- 同名且记录完全相同的后续条目去掉（机体比较 36 字节记录和武器编号；人物比较能力、阈值、精神记录）；同名但数值不同的保留，同一作品内从第二个起加「(2)」「(3)」（不同作品的同名人物如两个「大作」不编号）。当前 ROM：机体 353 条、人物 293 条。
- 没有能力记录的人物（映射为 −1）只显示头像和名字，注明「不上场战斗的人物」。
- 数值是基础值：不含改造、强化部件、精神和气力效果。人物 284（我方クェス）的阈值按游戏的实际读法越界读进精神表，页面照游戏显示。

Library 与战斗鉴赏的底层不透明，标题在下面看不见；设置窗口框架上的任何页面（Library、MOD、设置）打开时，`battle_viewer::hold_title` 每帧把标题的两个待机计数（`D_801CC390` 到 180 帧开演示、`D_801CC3A4` 到 0x385 帧回开场剧情）清零，标题停在原处，不会在页面底下开演示或放开场剧情（2026-10-04 实测：修前 Library 开约 55 秒标题就进了开场剧情，修后 65 秒仍在主状态 2）。

两页各记住自己选到的位置；切语言、切 Original／HD 会重建页面。详情跟随选择用 `SetInnerRML` 局部更新，不重建整个窗口。调试接口：`ui.click --id library-open`、`lib-tab:0|1`、`lib-item:N`。

## 动画

第三页「动画」（2026-11-20）列出战术地图上播放的 12 段动画：コン・バトラーV 合体、オーラロード ×4（其一原版无调用者，标「未使用」）、ゲッター 变形 ×6、ゴッドマーズ 合体。表与触发来源见[战斗图形](../data/battle-graphics.md)；按所示机体的作品分组（盖塔 1/2/3 与 G 各归原表），作品顺序同机体页。

**怎么播的。** 原版播放器 `802176A8`（选曲、置状态）与每帧步进 `8021779C`（状态表 `D_8021E6D4`，各段子表 `D_8021E410` 等）在战术 overlay 里，只调常驻的精灵、擦除和声音函数，不读地图状态。`tools/recomp/toolchain/generate_cpu.py` 的 `write_movie_sandbox` 把 overlay 里 `80214030..80217888` 的 66 个函数从重编译输出里再抄一份（`funcs_movie.c`，函数名 `srw64_movie_*`），段内调用改成直接调用、`jalr` 查自己的表，段外只允许 10 个常驻函数并改名为宿主替身；出现别的调用就让生成失败。`src/host/map_movie.cpp` 开一块 8 MB 的私有 RDRAM，装入 ROM `0xAB160..0x107BF0`（overlay 的数据，含各段表；以 `D_8021E6D4` 首项 `802175FC` 核对），用和 3D67 一样的方式调用：`802176A8(编号)` 一次，之后每拍 `8021779C` 直到返回 1。游戏本身的内存一字不动。

宿主替身（行为按原函数静态阅读）：

| 原函数 | 替身做的事 |
| --- | --- |
| `80098158` → `80097C68`/`8008B4F4` | 槽头 +0 模式、+1 在用；子记录 +0 在用、+1 alpha 0xFF、+8 种类 1、+C/+E/+10 场景/图集/调色板、+18 首步帧数、+19 步 0、+1A 播放标志、+1C 镜像 0；子记录已在用时不建新节点（换场景、保留节点与 alpha） |
| `80098738`（每拍、每个在用的槽） | +18 减到 0 进下一步；走完时 +1A bit0 置位则停在末步并置 bit1，否则回 loop_step |
| `8008B888` / `8008B988` / `800988B8` | 释放槽与节点 / 节点隐藏位 4 / 读 +1A |
| `80099814` 6、7 与 `800998F4`、`800997D0` | 擦除：第 73–167 行之外的每行一条黑条，奇数行从右、偶数行从左，速度 20–69 像素/拍（原版用 `80082334(50)`，这里用自己的随机数）；≥ 0x90 行到位算完成 |
| `80099C88` | ゴッドマーズ 一段的调色板效果（资源 0x5F0），**不画**，帧保持原调色板 |
| `8007E810` / `8007E8A8` | 记下，游戏线程上用原版函数放 BGM / 音效 |

声音按 `D_8016131C`（原版每两个 VI 加一）对表 `D_8021E910[编号]`（(拍, 音效) 对）播放；沙盒每拍加一。BGM 按编号：0 → 0x14，1–4 → 6，5–10 → 0xE，11 → 0x17。一拍 = 1/30 秒，按墙钟计（游戏帧率不影响）。离线跑出的时长：0 号 482 拍（16.1 秒）、1/3/4 号 328/419/449 拍——与 2026-09-16 实测的 16.03/10.87/13.93/14.93 秒一致；5–10 号 205–244 拍，11 号 548 拍。

**怎么画的。** 节点链按优先级降序（`8008B614` 插在第一个更低的之前，同值新的在后），从头画到尾：背景 0x8D 在下、机体 0x88 在上，擦除 0x83 最上。模式 0xB 是屏幕坐标的逐零件 TEXRECT（`800975A4`：取整后的 x、y 加零件偏移，+1C 镜像），模式 0xE 是槽矩阵下的四边形；地图的镜头 `80081CB8` 固定为看向原点、眼在 (0, 0, 1000)，透视 50°、4:3，零件 y 向上。每个精灵画成「该帧零件外框」一张图：HD 图像模式下用美术包里同 (场景, 图集, 调色板, 帧) 的 HD 帧（`sprites::frame_file`，覆盖同一外框），否则用 ROM 现拼的原图。

所有动画都在画面中央 112×96 的窗口里（x 104–216、y 72–168；各段背景场景 128 宽、末 16 列透明，上下两条擦除黑条盖住窗口外的行），页面的舞台就是这个窗口，左右伸出窗口的零件（原版会画在地图上）被裁掉。背后的地图不画。舞台要设 `clip:always`：RmlUi 的 overflow:hidden 只在内容往右/往下溢出时才裁，盖塔 1 的鹰从上方进场、雷霆王的特写也越过上/左边，只靠 overflow 会画到舞台外（2026-11-23 修）。

**页面与操作。** 左侧列表，右侧是 7:6 舞台（HD 包有全部帧，所以尽量大：详情区宽的 68% 与面板高度二者取小，Deck 特大约 370×320dp）、其下播放/暂停、后退一帧、前进一帧、从头、循环、本页的「原版 / 高清」和进度（美术包里没有这段的 HD 帧时不出这两个按钮；默认跟随全局图像模式，只影响这一页）；右边作品、名字、金色类别标签、段数与时长、出现场合与相关机体。选中条目再按 A/Enter（或点舞台、点「播放」）开始/暂停；手柄/键盘在列表上按右进入舞台下的按钮行，左右在按钮间移动、A 按下，最左再按左、上下或 B 回列表（动画页的右不再跳作品；按「原版/高清」重建详情后焦点留在原按钮）；换条目、换页、关 Library 都会停下并把标题曲换回来。暂停时 BGM 停（原版音乐不能从中间续），一帧一帧走时静音；后退一帧是从头静默重跑到前一拍（确定性：擦除随机数按编号固定种子）。播放前舞台显示静默跑到时长 45% 处的一帧。详情是浮在列表文档上的非模态文档，body 的 pointer-events 为 none，动画区单独设成 auto 才能点；说明文字用 wrap_paragraphs 断行（RmlUi 不在中日文处断行）。

离线检查（不开游戏）：把 `funcs_movie.c` 和 `map_movie.cpp` 链进一个小程序，读 ROM 跑完 12 段，按窗口拼出每拍画面；2026-11-20 的结果：12 段都走到状态 0xE，没有越界调用，画面顺序与原版截图一致。实机（2026-11-20，Mac，HD、中文，tools/recomp/debug/check_library_movies.py）：12 条都在、按作品分组；コン・バトラーV、ゲッタードラゴン、ゴッドマーズ、オーラロード · ズワァース 播放时拍数按 30/秒走、画面为 HD 帧、BGM 依次 0x14/0xE/0x17/6、音效按表时刻放出（如 0 号 21 拍 106、70 拍 107…402 拍 90）、オーラロード 328 拍结束；暂停时拍数不动，前进一帧 +1、后退两帧 −2；关 Library 后标题曲换回。「原版 / 高清」按钮之后加入，用户在游戏里手动切换过，确认可用。
