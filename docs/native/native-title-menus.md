# 标题菜单画面：ロード、オプション、サウンドセレクト、カラオケモード 的原生接管

日期：2026-09-24。标题环形菜单四项之后的画面。ロード 复用[データセーブ 页面](native-save-screens.md)，改成读取的文案与流程；オプション 与两个曲目表是新页面（[`title_page.cpp`](../../src/host/title_page.cpp)）。页面只负责画，原版状态函数继续管解锁、滚动、放歌和切 overlay，页面的选择以按键形式交给它们。设置页「标题菜单画面」可以选回原版画面。环形菜单上的四个项名见[标题画面与剧情文字图](native-title-and-story-images.md)。

## 1. 原版画面（静态分析）

标题 overlay 是 `load_0010DA50`（RAM `801C4500`，ROM `0x10DA50`，BSS 从 `0x801CC150` 起，重新装入时不清零）。每帧任务 `801CA9CC` 先看淡入淡出状态 `80099B30()`：不为 0、2 时才按主状态 `D_801CC3A6` 查表 `D_801CB250` 调状态函数，子状态是 `D_801CC3A7`。坐标均为 320×240。

### 环形菜单与各项去向

| 项目 | 依据 |

## 2. 接管方式

源码：[`title_page.cpp`](../../src/host/title_page.cpp)（オプション 与曲目表的游戏线程适配器）、[`save_page.cpp`](../../src/host/save_page.cpp) 的 `title_*`（ロード）、[`frontend.cpp`](../../src/native/ui/frontend.cpp) 的 `title_sync`（オプション 与曲目表页面；ロード 仍由 `save_sync` 画）、[`game_hooks.cpp`](../../src/host/game_hooks.cpp) 的 `SRW64_TITLE_BUILD`／`SRW64_TITLE_STEP` 包装。16 个函数在 `generate_cpu.py` 的 `NATIVE_HOOKS` 里改名为 `srw64_original_title_*`，改动后要重跑 `generate_cpu`。

| 原函数 | 包装 |
| --- | --- |
| `801C697C` オプション 构建 | 不调原函数。只释放槽 2–6 和 9，然后打开页面 |
| `801C6B14` オプション 每帧 | 移动：由适配器写 `D_801CC397` 并播 0xB9。サウンド：适配器自己完成切换、`8009187C`、`80076D90`（原版这个分支会往可能已失效的标签槽画字）。其他项的 A 和 B：以按键调原函数，由它去调已经钩住的列表构建，或淡出回环 |
| `801C86A8`／`801C9888` 列表构建 | 不调原函数。做 `801C4850`、`8007E810(-1)`、`801C81C0(0／1)`，然后打开页面 |
| `801C8724`、`801C89E4`、`801C9904`、`801C9ADC` 列表每帧 | 每帧都调原函数（它要跟踪是否在放歌，B 的行为靠这个）。上下以按键写进连发字，A、B、Z、R 写进本帧按下字；点击某一行时由适配器改列表变量；调完后释放槽 0x2F 的箭头 |
| `801C83D0` 画列表 | 改成空操作并重发页面状态。它也会在 カラオケ 返回、淡入期间被调用，页面靠这里跟上光标 |
| `801C6F3C`、`801C709C`、`801C7328`、`801C783C`、`801C7A48`、`801C7C90`、`801C8074` ロード | 按 [データセーブ](native-save-screens.md) 的做法：构建函数不调原函数，存档头读取、介质切换、确认窗和 Pak 提示由适配器照原版状态机处理。B、确认窗的 はい 以及提示页的 A／B，写好变量后以按键调原函数，由原函数淡出或切模式 |
| `801CA9CC` 每帧任务 | 原函数跑完后检查主状态：不在对应主状态、或已到子状态 0xD 时关闭页面 |

**overlay 切换**：カラオケ 播放、ロード 确认、コンティニュー 都会让别的 overlay 装到 `801C4500`。`overlay_loaded` 只要看到新装入的区间与 `801C4500–801CC150` 重叠，就当帧关闭页面，之后不再读标题 overlay 的 BSS。

**原版／新版**：设置页「标题菜单画面」（`presentation.json` 的 `title_ui`，调试接口 `settings {"title_ui": "original"}`）。下一次打开画面时生效，覆盖 ロード、オプション、サウンドセレクト、カラオケモード。

**页面**：按原版位置画框、标题、EXIT、10 行曲名和上下箭头；正在放的歌在曲名前加 ▶，不在光标行时文字改成浅蓝。

**文字**：标题、项目、曲名都通过 `dialogue::ui_text` 从文本表取，跟随阅读语言；ロード 在标题环境下把两句换成 0x1E3、0x1E4。曲名（文本 0xE8–0x118）目前不在数据词条表里，所以中英文界面下仍显示日文原名。

**快照**：`status.title_page` 字段如下，事件写在 `title-page-events.jsonl`。

- 通用：`screen`（`options`／`sound`／`karaoke`）、`serial`、`title`。
- オプション：`items[]`（`label`，以及可选的 `value`）、`cursor`、`mono`。
- 曲目表：`songs[]`（`text`、`song`、`playing`）、`current`、`top`、`rows`、`exit`、`exit_focus`。
- ロード：沿用 `status.save_page`，另加 `context`（`title` 或 `intermission`）。

**调试**：稳定 ID 是 `tp-option:N`、`tp-song:N`、`tp-exit`；键盘 ↑↓、Q／E（上一首／下一首）、Enter／Z、Esc／X。

## 4. 未验证与限制

- コントローラパック 的读档与修复分支只有静态分析：宿主没有 Pak，Pak 路径稳定停在状态 7 的提示。
- 已通关存档（緑の大地の上で）和见过特定机体的解锁，没有专门的存档来验证；页面只显示 `801C81C0` 建好的列表。
- 曲名还没有中英文，要等数据词条表收录文本 0xE8–0x118。
- 原版确认窗的选项框：`native-save-screens.md` 写的是 (221,122)–(251,163)，布局表是主窗 (53,101)–(267,139) 再向下接 (221,139)–(251,163)。原生页面两处都按前者画，没有和原版截图对照过。
