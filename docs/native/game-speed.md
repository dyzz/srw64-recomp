# 游戏速度（2／3／4 倍速）

设置「通用」页的「游戏速度」：原速／2 倍速／3 倍速／4 倍速，默认原速，存进 presentation.json 的 `game_speed`（1–4；旧版的 1、2 照读）。一键切换的是改键表里的「切换游戏速度」：键盘默认 Tab，手柄默认 R4 背键（SDL 的第一个 paddle），安卓触屏在左上角「开始」右边有一个速度按钮，显示当前倍数（1×–4×），高于原速时显示琥珀色。每按一次依次切到下一档，4 倍速之后回到原速。切换后左上角出现一个小标签（「游戏速度：3 倍」）约 1.5 秒；安卓上不显示，按钮本身就是状态。

3、4 倍速要设备每秒画出 90、120 帧，达不到时实际速度会低一些（Seeker 上约 1.7 倍，见 [120hz-scheduler.md](../design/120hz-scheduler.md) §5.3），设置说明里有写。

代码：`src/host/game_speed.hpp`（判定与写入）、`src/host/sched_rate.hpp`（120 Hz 调度）、`src/host/host.cpp` 的 `frame_start`（每个 VI 调用）、`src/host/game_hooks.cpp`（战前画面的步进记号）、`src/native/ui/frontend.cpp` 的 `toggle_speed`。

## 原理

原版每隔 `D_8010F0C8` 个 VI 跑一帧逻辑。`8008163C` 在 `D_80172D0C`（距上一帧的 VI 数）小于它时直接返回；`8007FC48` 开机时写成 2，之后再没人写（[60fps.md §2.1](../design/60fps.md)）。游戏里所有等待、步进、滚动都按帧计数，所以改成 1 就是整体 2 倍速。VI 频率和音频线程不变：音乐速度不变，音效触发会密一倍。

但 60 Hz 下 2 倍速是结构上限：原版调度器每个 VI 最多放行一帧画面，游戏又要等画面交出去才跑下一步。所以 VI 默认跑 120 Hz（[120hz-scheduler.md](../design/120hz-scheduler.md)），间隔按档位写：

| 档位 | 加速时的间隔（120 Hz 的拍） | 逻辑步／秒 |
| --- | --- | --- |
| 原速（以及不加速的画面） | 4 | 30 |
| 2 倍速 | 2 | 60 |
| 3 倍速 | 1、1、2 轮流（平均 4/3） | 90 |
| 4 倍速 | 1 | 120 |

3 倍速的轮流靠数逻辑步：帧边界上 `D_80172D0C` 为 0 说明上一拍跑过一步。宿主每个 VI 按场景写间隔；值还不是 1、2、4 时不写，开机流程照原样走。音频隔拍、宿主 VI 计数保持 60 Hz 单位。

`SRW64_VI_RATE=60` 退回原版的 60 Hz 调度（对照、排查用），这时最高只有 2 倍速，切换在原速和 2 倍之间。

## 哪些场景加速

| 场景 | 判定 | 速度 |
| --- | --- | --- |
| 战斗演出 | 模式 2、0x1A、0x1C | 2 倍 |
| 世界地图（剧情） | 模式 12、13 | 2 倍 |
| 战术地图·事件脚本 | 模式 3／0xB／0x11／0x16／0x22，且 `engine+0x97C` 不是 0x80（同 `script_inject.hpp` 的 `idle_reason`） | 2 倍；当前指令是选择肢（3D44）或出击选择（3D3D）时原速 |
| 战术地图·敌方与第三方阶段 | `0x8010F5E8` 不是 1 | 2 倍 |
| 战术地图·我方阶段 | 主状态 `0x80172EB0` 是等玩家操作的状态：5、6、8、0xC、0xD、0x16、0x17、0x19、0x1B、0x22、0x3A、0x3C、0x2E–0x37 | 原速 |
| 战术地图·我方阶段的其他状态 | 单位移动、阶段切换（0x39）等 | 2 倍 |
| 战前确认、敌方攻击时的应对选择 | `801D5064`／`801D5294` 在最近 4 个 VI 内步进过（无论哪个阶段） | 原速 |
| 其他（标志、标题、场间、姓名页、读档、结局、出售等） | 其余模式 | 原速 |

菜单保持原速，是因为原版的按键连发（按住 12 帧后每 3 帧一次）也按帧计数，2 倍速下光标会快一倍。

## 热键与原生页面

Tab 在战前确认页、场间画面里原本就用来换选项，所以只在没有原生页面、设置窗口、图鉴、MOD 管理和战斗查看器时才切换速度；这些画面本来就是原速。

Steam Deck 在 Steam Input 模板下不一定把背键交给游戏。SDL 看不到 R4 时，可以在 Steam 的控制器设置里把一个背键映射成键盘 Tab。

## 调试与验证

- 调试状态 `game_speed`：`level` 是档位（1–4），`top` 是这次运行的最高档（120 Hz 为 4，60 Hz 为 2），`double` 表示高于原速，`running` 表示这一帧是否在加速；调试接口 `settings game_speed=1..4` 直接设档位。
- 虚拟手柄键名 `r4` 按的是速度开关（`srw64_pad`）。
- 单元测试 `tests/native_game_speed.cpp`（`make recomp-game-speed-test`）覆盖场景判定、写入时机，以及按 8008163C 的计数规则模拟一秒 120 拍：四档分别 30/60/90/120 步，3 倍速是 60 个隔 1 拍加 30 个隔 2 拍。
- Mac 实测（2026-10-24，标题演示战斗，`SRW64_FORCE_FAST=1`）：四档 29.9／59.9／90.0／116.8 帧/秒；R4 依次切到 2、3、4、原速；`SRW64_VI_RATE=60` 下最高 2 倍。

还没实机看过的点：每个 VI 一份显示列表时 RT64 的缓冲是否够用；背键在 Deck 的 Steam Input 下能否被 SDL 看到。
