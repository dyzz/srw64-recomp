# 移动选格：按住 R 跳到最远格

2026-09-25 用户要求加现代机战的操作：选移动目的地时按住 R1，高亮能到达的最远格；按住 R 时按方向，光标在这些格子之间快速跳，A 确认移过去。参考《超级机器人大战30》：移动范围显示时按 R1，光标跳到最大范围（[ナノゲームス TIPS](https://ds-can.com/srw30/system/s_tips.html)）。

实现在 [`move_jump.cpp`](../../src/host/move_jump.cpp)。下面的地址全部来自静态分析（战术 overlay `load_000AB160`，生成代码 `build/recomp/cpu-bound/generated/`）。

## 操作

- **按住 R**（键盘 E、手柄 RB）：最远格叠一层暖黄色，缓慢呼吸，范围不超出原版的格子。按 R 之前光标已经离开单位的，跳到这个方向上最远的格子；光标还在单位身上就不动。
- **按住 R 时按方向**（十字键或摇杆，斜向也可以）：
  - 光标在最远格上：跳到这个方向左右 45° 以内最近的最远格，按住方向就沿外圈一格一格走，拐角也不跳过；这个范围里没有，就取前方偏离最少的。
  - 光标不在最远格上：跳到从单位看这个方向最远的格子。
  - 按住方向时按游戏自己的连发节奏走：按下立即走一格，12 帧后每 3 帧一格。
- **A／B**：照常确认、取消，松不松 R 都一样。松开 R，高亮消失，光标留在原处，方向键恢复原版的逐格移动。

## 什么是「最远格」

单位可以停下的格子里，没有任何一条最短路径经过它再通到另一个可停格的那些格子。最短路径按网格里每格的进入代价算，与原版填表的 `801C3B0C` 一致。

- 平地上就是范围的外圈；死胡同的尽头也算。
- 范围碰到地图边时，贴边那一行只算两端。
- 只被湖、友军挡住一面的格子不算：绕过去还能走得更远。

## 原版怎么做（静态分析）

| 项 | 地址 | 说明 |
| --- | --- | --- |
| 每帧状态分发 | `801DFBD0` | 表 `0x80217E0C[状态]`，状态字节在 `0x80172EB0`。之后依次调用 `801C3020`（光标下的单位）、`80081BFC`（对象速度）、`801FFADC`（镜头跟随） |
| 状态 0xC | `801CD6E4` | 按子状态 `0x80172EB2` 查表 `0x80217B38`：0 选格 `801CBB04`，1 单位行走 `801CC290`，2 `801CC72C`，以后是 3–6 |
| 选格 | `801CBB04` | A 确认，B 取消（音 0xB8，光标回锚点，回状态 8），方向调用 `801C66E8`→`801C63D8`，按住 C 下／C 左时移动加速。**R、L、Z、START 在状态 0xC 和 6 都不读** |
| 输入字 | `D_80178A08` 本帧按下、`D_800F97D0` 按住、`D_801612E0` 连发 | 每口一个半字，摇杆并入十字键位。A 0x8000、B 0x4000、R 0x10、上 0x0800、下 0x0400、左 0x0200、右 0x0100 |
| 光标 | `0x80102308`／`0C` | f32 地图像素，等于格×16+32（对象 0x35）；目标 `0x80172EB4`／`EB8`，速度 `0x8010232C`／`30` |
| 镜头 | `0x8010F5D4`／`D8` | 整数，屏幕坐标 = 地图坐标 + 偏移。`801FFCB0(px,py)` 把点移到屏幕中央：x 偏移 = clamp(152−px, 320−地图宽, 0)，y 偏移 = clamp(112−py, 240−地图高, 0)；`801FFE34` 判断点是否在 [32,288]×[32,208] 内 |
| 地图尺寸 | `0x80172EC4`／`EC8` | 像素 |
| 移动范围 | `0x80227BD0` | 以单位为中心的 31×31 网格，按行存，单位在 (15,15)：2 可停，3 有友军只能穿过，中心为 0。进入代价在 `0x80227328` |
| 画范围 | `801E4760` | 节点 0x2E 的回调（`801CB9B0` 登记），a0 = `Gfx**`。设组合器为图元色、关纹理，图元色 (0,192,0,96)，每个值为 2 的格一个 16×16 G_FILLRECT；左上角 = 锚点 + 镜头偏移 + (格−15)×16 |
| 确认 | `801CBB04` 的 A 分支 | `801E0B94(2, 光标x, 光标y)` 查光标格是否为 2；不是就蜂鸣 0xBA，是就算路径、单位走过去 |

原版把光标放到某处（`801C8E20` 切换单位等）时都内联同一段：光标和目标一起写，点不在屏幕内就调用 `801FFCB0`，播光标音 0xB9。按住 R 的跳格也照这样做。

## 接管方式

- `NATIVE_HOOKS` 包装两个函数（[`game_hooks.cpp`](../../src/host/game_hooks.cpp)）：
  - `801CBB04` 改名为 `srw64_original_move_select`。
  - `801E4760` 改名为 `srw64_original_move_range_draw`。
  - 改了 `NATIVE_HOOKS` 要重新跑 `generate_cpu.py`。
- **选格**：R 按着，而且本帧没有按 A 或 B 时，由宿主处理这一帧，原函数不运行，方向也就不会让光标逐格移动（进不了状态 6）。其余情况都照原版运行。
- **跳格**：做法与原版放光标的那段一样，镜头移中的条件也相同。
- **高亮**：原版画完范围后，在同一张显示列表后面追加一个图元色（暖黄，alpha 72–128 按 VI 呼吸）和最远格的 G_FILLRECT，裁到屏幕内，混合模式沿用原版画范围时的设置。
- **重算时机**：锚点变了（换了单位）、R 松开再按下，都会重算最远格。
- **日志**：`move-jump-events.jsonl`，记录 on、off、jump 三种事件。

## 实机验证

测试关卡 [`move-jump.json`](../../config/recomp/mini-stages/move-jump.json)：地图 20，タケル 在 (8,8)，友军 ダンバイン 在 (10,8)，敌人在 (15,12)。检查脚本 [`check_move_jump.py`](../../tools/recomp/debug/check_move_jump.py) 通过调试键盘操作（E 是 R），检查以下 10 项：

1. 进入选格；
2. 按住 R 出现最远格，光标不动；
3. 高亮画出来了；
4. 按右跳到最右格；
5. 按两次下沿外圈走；
6. 按住左连发；
7. 松开 R 后高亮消失；
8. 方向键恢复逐格移动；
9. 再按住 R 沿射线跳出；
10. 按住 R 时按 A，单位走过去，出现移动后菜单。

结果（`build/recomp/debug/20260925T103341.713940Z/`）：

- 10 项全部通过。
- ガイヤー 的范围是半径 6 的菱形，最远格正好是外圈 24 格。
- 按住左时沿外圈一格一格走到最左格，底角也经过。第一次运行时直线优先，跳过了底角，已改成 45° 以内取最近。
- 高亮是半透明暖黄，叠在原版绿格上，不超出格子。

没有覆盖到的：

- 地形挡路（湖、山）时的最远格：这一关的范围是完整菱形。
- 跳到屏幕外时的镜头移中：这一关的范围整个都在屏幕里。
- 先按住方向（光标已经在移动中，状态 6）再按 R：这时不接管，要等方向键松开。
- 查看敌方范围（名册标志只读）时按住 R：同样可以跳格，但 A 照原版不起作用。
