# 剧情短跳过（R + START）

2026-09-29。现代机战的「短跳过」：在剧情对白中按 R + START（键盘 E + Enter，Steam Deck R1 + 菜单），剧情脚本直接执行到下一个停点，中间的对白不显示，等待和演出不播放。所有命令仍由原版处理函数执行，所以旗标、变量、资金、单位登场与移动、地图切换的结果和逐句读完相同。按 B 或打开回看会在当前位置停下。代码：[script_skip.hpp](../../src/host/script_skip.hpp)、[game_hooks.cpp](../../src/host/game_hooks.cpp) 的 `skip_begin`/`skip_polls`，开始与停止由[对白阅读器](native-dialogue-ui.md)负责（[native_dialogue.cpp](../../src/host/native_dialogue.cpp)）。

之前的跳过只是让阅读器每帧替玩家确认一页，脚本照原速执行，演出、镜头、等待一样不少，看起来像一路闪台词的快进（第一话世界地图段约 14 秒）。现在同一段在 2 VI 内完成。

## 脚本轮询的契约（静态分析）

事件引擎在 `8015F950`，上下文在 `+0x948`（下称 vm）。每帧 `8009E180` 在有事件运行时调用一次 `8009EFDC(engine, vm)`，把返回值写回 `engine+0x97C`。

- `8009EFDC`：命令状态 `vm+0x24` 为 0 时，遇 `FFFF` 结束事件（状态 0x80）；否则 `8009F0E8` 处理条件与路线标记，`8009EED0` 取指（PC 只前进 2 字节，处理函数写入 `vm+0x30`，状态置 1）。状态不为 0 就调用处理函数；调用后状态为 1 的改成 2。一次轮询至多取一条、调用一次处理函数。
- 处理函数自己完成：把状态清 0 并把 PC 推过参数。`+0x26`、`+0x28`、`+0x2A`、`+0x2E` 是它们的局部字段，取指时清零。

所以跳过只要在同一帧里接着轮询：命令一完成就取下一条。

## 做法

1. 阅读器检测到 R + START（`Reader::update`），且当前有脚本在读，就 `script_skip::start(vm)`。
2. 该脚本本帧第一次轮询之前（`skip_begin`）：若刚开始，先调用 `800A34D8` 关掉正在读的对白窗口（与 `3D48` 相同）。之后 `8008FED4` 在跳过中直接返回 3，也就是原版「这一页已读完」的答复，对白框不打开。
3. 每次轮询之后（`skip_polls`）：刚执行的命令是停点就停；命令还在等待，就按下表把它推到终点，再轮询。遇到还没有办法的命令就让出本帧，下一帧再接着做，它按原速走完这一段。
4. 跳过的每一页照样进回看（`Reader::skipped`）。`8008FED4` 被拦下时带着面板和文本编号（a0、a1）；宿主以此调用原版 `8008CE54` 读出记录头的说话人数字，名字取记录 `0x111E 加说话人数字`。这正是原版名字框显示的记录（`8008F648` 以面板 `+0x20C` 的原始数字加 0x111E 调用 `8008D0E8`），因此 25–32 号的主角与搭档也经 `record_text` 显示为玩家的名字。正文与名字按每种阅读语言各存一份，换语言后回看跟着换。跳过开始时正在读的那一页不会重复，只补成完整的已读条目。第一话实测：跳过的四页说话人（卡茨、卡茨、布拉德、卡茨）与逐句读时游戏自己显示的相同。
5. 跳过期间音效静音（`8007E8A8`，-1 停止放行），否则一帧里执行的命令会同时发声；BGM 照常切换。

| 命令 | 处理函数 | 当帧完成的办法 |
| --- | --- | --- |
| 对白 `3D3E`–`3D43` | `8009F654` 起每 0x1C | 首次调用照原版把镜头瞬移到说话人（`80209DAC` 第三参非 0 即瞬移）；下一次 `8008FED4` 返回 3 |
| 等待 `3D38` | `800A00F0` | 计数 `+0x2E` 置 0，下次调用即 < 0 完成 |
| 关窗等 32 帧 `3D47` | `800A013C` | `+0x2E` 置 0x1F，下次调用到 32 |
| 关窗让一帧 `3D4E` | `800A0468` | 再轮询一次即完成 |
| 淡入淡出 `3D3B` | `8009F948` | 渐变引擎记录 1（`800FF9E8`）：`+C` 当前透明度写成 `+5` 目标，`+4` 清 0。这正是 `8009AD64` 最后一步所做的；处理函数随后自己解开输入锁 `8010F6BA` |
| 画面震动 `3D36` | `8009F880` | 结束判断 `8020D4B0`（战术地图）/ `801C5138`（世界地图）每调用一次推进一步，同一帧连续轮询 |
| 登场 `3D45` | `8009FC04` | 仅战术地图：前后两段 10 帧计数推到 9；登场动画 `8020C524(0)` 每调用一次推进一步，连续轮询。机体与驾驶员由 `8020B154` 照常生成 |
| 单位移动 `3D3C` | `800A0360` | 仅战术地图：`8020A788` 每次只给单位精灵设速度（±8 像素），位置由逐帧的精灵运动 `80081BFC` 积分；连续轮询，每次之前先调用一次 `80081BFC`。到格后 `801CBEB8` 写回名册坐标 |

「连续轮询」每条命令每帧最多 600 次，超过就让出本帧。

`8020C524` 以参数 1 调用时会经 `8020BE34` 立即放好全部登场单位，但原版唯一的调用者 `3D45` 只传 0，这条路径从未被执行过，所以没有采用。

## 停点

跳过在下列位置结束，阅读器回到手动：

- 事件脚本结束（`FFFF`）；
- 选择肢 `3D44`（`8009FA94`，选择页照常出现）；
- 出击选择 `3D3D`、关卡胜利结算 `3D4A`、游戏结束 `3D4C`、结局 `3D71`；
- 从世界地图切往战场 `3D4D`（`800A031C`）：它只把 `engine+4` 设为 3，overlay 要过几帧才切换，脚本在这期间继续取下一条。原版靠 `3D45` 开头的 10 帧等待刚好拖到战术 overlay 装好；把它压缩掉就会在世界地图 overlay 里调用战术 overlay 的 `8020B0D4` 而崩溃（实测）。所以 `3D4D` 之后不再加速；
- overlay 切换、执行脚本换人、对白重置（阅读器原有的停点）。

## 验证

- 组件测试：`make recomp-script-skip-test`（[tests/native_script_skip.cpp](../../tests/native_script_skip.cpp)，并入 `recomp-native-check`），覆盖停点表、对白处理函数识别、各命令写入的字段、非战术地图不加速。
- 实机：[check_script_skip.py](../../tools/recomp/debug/check_script_skip.py) 新游戏（布拉德路线）第一段对白读两页后跳过，战场第一句再跳过一次。世界地图段 2 VI 停在 `3D4D`，战场开场段（部署、四次 `3D3C`、对白）2 VI 执行到脚本结束，两次都没有显示任何对白。`SRW64_SCRIPT_SKIP_TRACE=1` 逐条记录跳过执行的命令；按原速执行的命令总会记一行 `SRW64_SCRIPT_SKIP wait`。
- 状态对照：[check_script_skip_state.py](../../tools/recomp/debug/check_script_skip_state.py) 依次跑两局，一局逐句按 A 读完开场，一局两次跳过，都到战术地图我方回合空闲后，经调试接口 `memory.read` 读取名册、机体实例、驾驶员实例、剧情变量、关卡字段（阶段、回合、地图、场景、资金）、事件上下文、出击排除名单和母舰表：2026-09-29 八个区域逐字节相同（读完 VI 8222，跳过 VI 6496）。两局末帧光标下的单位一张有一张没有，连拍确认是原版的闪烁。

## 未做与已知差异

- 其他演出命令（`3D32`/`3D33` 世界地图定位与航迹、`3D35` 阻塞卷动、`3D37` 格子特效、`3D46`/`3D4F` 退场与击破、`3D49` 脚本战斗、`3D51` MAP 兵器、`3D55` 精神演出、`3D50`/`3D5C`/`3D63`/`3D67`/`3D6A`/`3D75` 等）仍按原速执行；执行正确，只是那一段不快。按出现次数依次补。
- 跳过少跑的帧会让两个随机播种时钟（`8015DC50`、`80172D0C`）与读完不同，之后战斗的台词、背景等随机选择可能不同。对白快进早已有同类差异，本作战斗结果在演出前已结算。
