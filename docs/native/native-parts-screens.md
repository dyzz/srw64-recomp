# 強化パーツ 画面：机体列表、槽位与库存、持有者的原生接管

日期：2026-09-23。场间菜单第 7 项。三个原版画面（画面号 7、18、19）由 RmlUi 页面接管，保持原构图；装备、卸下、从别的机体拿走部件都注入 A 边沿交给原版函数完成，机体记录与库存记录不由页面直接改写。原版画面可在设置页「场间画面」选回，见[场间主菜单](native-intermission-menu.md)。

## 2. 接管方式

源码：[`parts_page.cpp`](../../src/host/parts_page.cpp)（游戏线程适配器）、[`frontend.cpp`](../../src/native/ui/frontend.cpp) 的 `parts_sync`（页面）、[`game_hooks.cpp`](../../src/host/game_hooks.cpp) 的包装（`parts_build`／`parts_step`／`parts_frame`，六个钩子在 `generate_cpu.py` 的 `NATIVE_HOOKS`，改后要重新生成 CPU 代码）。设置页「场间画面」选原版时三个构建入口都交回原画面；`SRW64_NATIVE_PARTS=0` 或不加载 profile 时整次运行保留原画面。

| 原函数 | 包装 |
| --- | --- |
| `801D4A00` 列表初始化 | 不调原函数。保留背景调用（含随机数）、`801CB540`（排序、页数）、行副本、选中机体写入 `D_801DEC5C`；不建布局、文字、光标精灵。发布快照后淡入 |
| `801D4A98` 列表每帧 | 移动／翻页：适配器写页、行、副本与 `D_801DEC5C`，播放 0xB9（每页 8 行，末页压低光标与原版一致）。确认／返回：注入 A／B 边沿调原函数 |
| `801D4BEC` 槽位初始化 | 不调原函数。保留背景、库存页 1、`801CBA78`、模式 0、计数清零；`D_801DECCA` 初值写 0x12（原版写 0，会让未移动时的预览带上 0 号部件的加成——页面按光标下的 はずす 显示不变） |
| `801D4C94` 槽位每帧 | 模式 0：移动写 `D_801DEC58`；确认由适配器自己切到模式 1（原版的 A 分支只建光标精灵、清行与计数，这里不建精灵）；返回注入 B。模式 1：移动／翻页写 `D_801DD0A2`／`D_801DD63C` 并把光标下的部件写进 `D_801DECCA`；取消由适配器切回模式 0（原版 B 分支释放的精灵和文字这里从未建）；确认注入 A，由原版完成卸下或进入画面 19 |
| `801D5168` 持有者初始化 | 不调原函数。保留背景与 `801CC988` |
| `801D51EC` 持有者每帧 | 移动写 `D_801DEC58`；确认／返回注入 A／B |

**快照**：`status.parts_page`：`screen`（`list`／`slots`／`holders`）、`serial`、`labels`；列表有 `page`（0 起）、`pages`、`cursor`、`rows[]`（`slot`、`number`、`name`、`pilot`、`level`、`parts[]{part,name}`、`en`）；槽位画面有 `unit`（同上）、`cursor`（槽位）、`mode`（0 槽位／1 库存）、`stats[]{key,current,preview}`、`selected`（库存光标下的部件号，0x12＝はずす）、`description[]`、`inventory{page,pages,cursor,rows[]{part,name,remove,equipped,owned}}`；持有者画面有 `unit`、`part{part,name}`、`target_slot`、`cursor`、`rows[]{free,slot,name,pilot}`。事件日志 `parts-page-events.jsonl`。

**页面**：三块布局按上面的矩形；列表每行 16、槽位行 17、库存行 16、持有者行 17；预览列高于现值绿色、低于红色（原版用两种字色）。

**调试**：稳定 ID `parts:N`（当前列表的行：机体列表／库存／持有者；点光标行即确认，点其他行移动）、`parts-slot:N`（槽位行；库存打开时点击先回到槽位）；键盘 ↑↓、←→（翻页）、Enter／Z、Esc／X；等待条件 `parts_page`。

## 3. 实机验证（2026-09-23）

```sh
.venv/bin/python tools/recomp/debug/check_parts.py            # 构建并检查
.venv/bin/python tools/recomp/debug/check_parts.py --reuse-build
```

`intermission-cold-1` 第一话通关存档（没有任何部件）。运行 `build/recomp/debug/20260923T031518.017920Z/`：`parts-checks.json` 14 项通过，退出码 0。

| 检查 | 结果 |
| --- | --- |
| 列表 | ダイターン3（万丈 Lv5）、ドール（シモーヌ Lv3）、スイームルグ（マナミ Lv2），按驾驶员等级降序；1/1 页；↑↓ 首尾循环；标签 強化パーツ／装備中のパーツ／レベル 取自原文本 |
| 槽位画面 | ダイターン3 两个空槽；六项能力现值＝预览（HP 8000、EN 200、移動力 5、運動性 70、装甲 1800、限界 270）；库存首行 はずす、光标 0、第 1 页 |
| 槽位光标 | ↓ 到第二槽，↑ 回来 |
| 库存 | Z 打开（模式 1，`selected`＝0x12，无说明）；X 关闭回模式 0 |
| はずす 对空槽 | Z Z 后原版重进画面（serial 增加），槽位仍为空 |
| 返回 | X 回列表，光标仍在 ダイターン3；再 X 回主菜单，光标在 強化パーツ |

第一版键盘不响应而鼠标能点：`frontend.cpp` 的键盘分发有两处按「哪些页面开着」放行的守卫没算上新页面，已加。第一版库存光标读到 0xFFFF：原版只在进入模式 1 时清 `D_801DD0A2`，构建时页面自己写 0。

## 4. 未验证

- 装备、替换、从别的机体拿走：第一话通关存档没有任何部件，只能验到 はずす 对空槽位的重进画面；脚本 `check_parts.py` 在库存有部件时会继续验装备与持有者画面，需要一份带部件的存档。
- 多页列表（8 台以上机体、7 件以上部件）的翻页。
- 7 号部件的气力变化、9／10 号的标志类效果只由原版处理，页面不显示。
