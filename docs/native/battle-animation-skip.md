# 战斗演出中途退出（按 X）

2026-09-25。进战斗后随时按 **X**（键盘 X／手柄 B／Steam Deck R2）中止演出回到地图，并按照「关闭战斗动画」时的样子把结果展示出来。默认开启，没有设置项。

实现在 [`battle_animation_probe.hpp`](../../src/host/battle_animation_probe.hpp)，挂在 `load_00121560_func_801C9710`（演出主循环）和 `load_000AB160_func_801DFBD0`（地图每帧分发器）。地址来自静态分析加实机验证，运行记录在 `build/recomp/debug/`。

**2026-09-26：两部分都已做成并实机验证**——中止回到地图后，地图按「关动画」的原版流程自己算伤害、画数字与 HP 条、扣血、发奖励。做法见[交还给原版的关动画分支](#交还给原版的关动画分支)。

## 已经做成的：中止

演出状态机在 `D_80250000`，主循环 `801C9710`。按 X 时：

1. 状态字节写 21（收尾状态），帧计数 `D_8025020C` 清零
2. 直接替它发淡出请求 `80099814(5, 1, 2)`，并把 `D_80250205` 置 1，免得状态 21 再发一次
3. 状态 0..20 都受理，所以进战斗第一帧就能按；21 以上排除，收尾已经在淡出了

**不能走原版的 Z+START 中止**。那条路设 `D_80225810`，`801C97E4` 的分支会调 `800A5138` 再选游戏模式 7 或 0x11 —— 是标题／重置路线。实测把关卡直接丢回标题画面（`build/recomp/debug/20260925T023507.767082Z`）。它的语义是「退出这场战斗关卡」，不是「跳过这段动画」。

状态 21 本来要等 `801C9DD0` 报告镜头稳定、且帧计数过 10（`801C813C` 的 `slti 0xA`）才自己发淡出，实测端到端要 7.8–8.8 秒。既然玩家已经表示不想看，就直接发。

**为什么安全**：真正的重型清理（`8008B950` 释放全部 300 个精灵槽、`8008DB2C`、`8008AC78(4)`）在 `801C9710` 里淡出**之后**的共用收尾段跑，不在被跳过的状态里。

**没有「跳到反击」这个功能**。把状态机往前推（4 → 10）在状态轨迹上看着对，画面是坏的：状态 3..9 才是加载这一回合精灵、图集、驾驶员台词的地方，状态 9（`801C7960`）还要跑自己的清理，而状态 10（`801C7BC0`）只动镜头。跳过之后反击方不出现、对话框叠在一起。已放弃。

## 原版的两条路径

这一节修正了本文早先的说法（「伤害由 0x4B 链的子状态 2 计算」）。子状态 2 是「下一回合」的步骤，读上一回合的表当输入，不是入口；伤害其实在演出之前就结算好了。

**状态 24（`801D6534`）是整个攻击流程**，子状态表 `D_80217CC4`：

| 子状态 | 函数 | 作用 |
| --- | --- | --- |
| 0 | `801D4794` | 建参战表 `8018B6E8`（步长 `0x5C`：+0 句柄、+4 机体记录、+8 武器、+0x14 造成的伤害、+0x26 反应码） |
| 1 | `801D5064` | 我方攻击确认页（宿主的 `battle_confirm_step`） |
| 2 / 3 | `801D5294` / `801D5404` | **结算 `801F7D6C`**：命中／伤害都算好写进参战表；敌方攻击时 2 是防御方应对页 |
| 8 | `801D5898` | `801DF96C`：`D_801602FA = 4`，状态改成 `0x4F`（空转），下一帧分发器调 `801D4E6C` |
| 4 | `801D5498` | **开动画回来后的落点**：`801FCA78` 静默套用结果，再到 9 |
| 9 | `801D5E88` | `801FC160` 发经验、资金框 |

**分叉 `801D4E6C`** 先调 `801FC994`（只是问一句「守方会不会被击坠」，不改任何东西），再看开关 `8015DDA8 & 4`（置位＝关动画）：

```
动画开：80080188(2) 装战斗 overlay，80099814(5,1,2) 淡出。
        战斗 overlay 是纯演出，读 801F3578 填好的演出方块 800F97E0，从不写名册。
        回来时 801C7168（D_8022722C==1）把地图放回状态 24 子状态 4：
          801FCA78 → 801FB460：开关位清零 → 把 HP 直接写进名册、不排回合
                   → 801FC83C 扣 EN／弹药、气力 +5、清精神位
          然后子状态 9 发奖励。玩家看不到任何数字——动画已经演过了。
动画关：D_80228528 = 0；8009DB8C()；
        （D_8022796C==1 时：8008B888(0x9C) 释放，镜头对准守方格，801CBEB8）
        同一个 801FCA78 → 801FB460：开关位置位 → 不动名册，
                   把每一回合排进表：D_802277E8 回合数、D_802277E9[] 目标句柄、D_80227862[] 伤害
        回合数为 0 → 801C29DC(D_80172EE4) + 801C8AB4；否则 D_80172EB0 = 0x4B、D_80172EB2 = 3
        D_8022731C = 0、D_8021F464 = 0；最后给两个参战单位打「已行动」位 0x40
```

**状态 0x4B（`801D92B0`）只是演出**，子状态表 `D_80217D4C`：3 取本回合的目标与伤害、4 等 20 帧放命中特效 `801E3AE4`、5 逐帧从名册扣 HP 并用 `801FCC6C` 播种数字、6 数字浮起、7..10 下一回合或收尾——收尾就是回到**状态 24 子状态 9**，与开动画的路径在这里汇合。

所以两条路径的差别只在 `801FB460` 的一个分支：开关位决定是「立刻写名册」还是「排回合让 0x4B 链慢慢扣」。

## 交还给原版的关动画分支

按 X 中止后，地图回来仍会落在状态 24 子状态 4。宿主在分发器钩子里（`801DFBD0` 之前）看到 `D_80172EB0 == 24 && D_80172EB2 == 4` 且欠着一次结果展示，就**替代子状态 4 跑一遍分叉的关动画分支**（`801D4E6C` 从 `.L801D4EE0` 起那一段，`replay_animation_off`）：

1. `D_80228528 = 0`，`8009DB8C()`
2. 把分叉那一帧记下的 `D_8022796C`、`D_80227250/54` 写回去（它们在战斗 overlay 覆盖的区域里；分叉帧是分发器看到 `D_801602FA == 4` 且开关位清零的那一帧，钩子先于分发器运行，正好能读到）
3. 临时把 `8015DDA8` 的位 4 置上，调 `801FCA78`，再还原——只有 `801FB460` 读这个位，它决定排回合还是写名册
4. 回合数为 0 走 `801C29DC` + `801C8AB4`，否则状态 0x4B 子状态 3；清 `D_8022731C`、`D_8021F464`

不需要补任何输入：参战表、名册、`D_80172EE2` 都在 overlay 之下，战斗 overlay 只读参战表（`80221B5C` 一处）；名册 HP 仍是战前值，因为子状态 4 还没跑；`801FC994` 和已行动位分叉时已经做过，不重复。之后 0x4B 链自己算、自己演、自己扣，节奏、音效、击坠溢出处理全是原版的，收尾照常进子状态 9 发奖励。

**RNG**：`801FCA78` 本来就会在子状态 4 跑，回放没有多抽；其余是 0x4B 链的演出，与关动画一致。

**实机结果**（`build/recomp/debug/20260926T014604.081648Z`，敌方 ムゲ兵 3000 攻击 ミニフォー 2800，状态 3 按 X）：

```

chain-done            hp_after  [1971, 2800]
ui-text.jsonl         " -1029" 逐位浮现，map_state 75 sub 6
```

`anim-abort-t4.png` 是关动画的画面：受击单位旁 `-1029` 描边白字加蓝框 HP 条；`t5` 已是下一场的应对页。3000→1971 与完整演出的基线一致。

| --- | --- | --- | --- |

### 走过的弯路

- **宿主自己画数字**（`801FCC6C` + 每帧 `801FCF00`）能画出来，实测 `-200` 正常浮现。但那时没有可用的伤害值——名册还是战前 HP，「演出方块 − 名册」不是伤害；而且把参战表槽位当成了演出方块下标，实测出现 `hp=3000/2800`（超上限的超长血条）。
- **从子状态 0 进 0x4B 链**连崩三次：`D_802284DC` 空指针（`801FCA78` 经 `801FC110/801FC45C` 是唯一写入者）、`D_802277E9[0]` 被清成 0 而合法句柄从 `0x42` 起、`801FB8B4` 的指针参数是野值。根因是子状态 2 不是入口——它是「下一回合」，读上一回合的表。正确入口是分叉分支本身：`801FCA78` 之后直接进子状态 3。
- **手工填 `D_80228530` 六格**画不出任何东西：整个地图 overlay 里 `80209900` 只被引用一次，就是 `801FCC6C` 末尾把它注册给 `8008B4F4` 当精灵绘制回调。
- **`801FCF00` 的返回值是反的**：六格都到状态 3 才返回 1，非零＝**结束**。
- **格子坐标表步长是 `0xC4`**（按句柄索引），不是 `0x34`。
- **`8008B888(id)` 是释放不是装载**：`D_800FFA71[id]` 非零才释放三个槽并调 `8008198C`。分叉里那次 `8008B888(0x9C)` 是清掉瞄准阶段的精灵。

## 验证

[`check_battle_animation.py`](../../tools/recomp/debug/check_battle_animation.py)，迷你关 `config/recomp/mini-stages/battle-ui.json`：

```bash
SRW64_BATTLE_ANIMATION_PROBE=1 .venv/bin/python tools/recomp/debug/check_battle_animation.py --mode abort --at 3
```

- 默认从空格结束阶段，让敌方来攻、在应对页确认；`--player` 改为我方主动攻击（单位菜单 → 攻撃 → 首件武器 → 首个目标），覆盖分叉的另一个调用者
- `--mode baseline` 录不按键的状态序列；`--no-anim` 录关动画时地图的表现作对照
- `--pad` 用手柄 R2 代替键盘 X，`--audio` 开声音，`--binary PATH` 跑快照（别的会话在改 `src/host` 时用）
- 断言：`jumped-to-winddown`、`replayed-animation-off`（钩子接管了子状态 4 那一帧）、`rounds-queued`、`roster-untouched-by-animation`（分叉时与回放时名册 HP 相同）、`chain-done`、**`hp-settled-like-animation-off`**（每个参战单位的终值 = 战前 HP − 排进表的伤害，钳到 0）、`damage-redrawn`（`ui-text.jsonl` 里真的出现了数字）
- 脚本退出时一律 `Session.quit()`；按键条件是 `state >= --at` 而非相等，因为轮询 trace 文件会和状态机赛跑

## 不能提前按住 X

X 在战前确认页是「取消」（`battle_page.cpp` 把 back 映射到 `0x4000`），按住它确认会让战斗根本开不起来。这是语义冲突，不是 bug。
