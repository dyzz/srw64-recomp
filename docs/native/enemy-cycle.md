# 战术地图：L2 / R2 切换敌方机体

2026-09-25 用户要求：像现代机战那样，用 L2、R2 在战场上遍历敌方机体。原版的 L / R（以及 Z）已经在我方未行动机体之间切换，这里补上敌方。实现在 [`enemy_cycle.cpp`](../../src/host/enemy_cycle.cpp)，键位总表见 [Steam Deck 键位](../design/steam-deck-controls.md)。

## 操作

- 地图空闲时（没有打开单位菜单、没有选格）：**R2** 把光标放到下一个敌方机体，**L2** 放到上一个。按住会连发：24 VI 后每 8 VI 一个。
- 光标原本在某个敌方机体上，就从它往前或往后数；不在任何敌方机体上，R2 从第一个开始，L2 从最后一个开始，首尾循环。
- 顺序是名册顺序：先敌方（阵营 1）30 个槽，再第三方（阵营 2）30 个槽，只算在地图上的（状态字节为 1）。
- 放好光标之后的操作都是原版的：按 A 查看该机体（能力、移动范围等），和用方向键把光标移过去一样。
- 两个扳机同时按、设置窗口开着时不起作用。L2、R2 是宿主键，游戏本身看不到；对白里它们另有用途（L2 自动阅读、R2 快进）。

目前只有手柄能用，键盘没有对应键。

## 原版怎么做（静态分析）

生成代码 `build/recomp/cpu-bound/generated/funcs_32.c` 里的 `load_000AB160_func_801C8B04`，是战术地图空闲状态（主状态 5，状态表 `0x80217E0C`）每帧的函数：

| 步骤 | 说明 |
| --- | --- |
| 触发 | 读连发字 `D_801612E0 & 0x2030`（Z、L、R）；不为 0 就走切换，否则去处理方向（`801C66E8`）、A、B 等 |
| 列表 | 遍历我方名册 `0x8015E100 + 槽×0x14`（30 槽）：状态字节 `+0` = 1、驾驶员（`+0xC` 机体 → `+0x38`）`+0x35` 非 0、`+1 & 0x80` 为 0（未行动）；`801E514C(阵营, 槽)` 给出句柄 |
| 当前位置 | `801C2BFC()` 是光标下的句柄，在列表里找到它的下标，存在 `0x80172EDF`；Z 或 L 减一，R 加一，越界循环 |
| 放光标 | 句柄对应的对象坐标 `0x800FFA74 + 句柄×0xC4`（`+0`、`+4`，f32 地图像素）同时写进光标 `0x80102308/0C` 和目标 `0x80172EB4/B8`；`801FFE34(x, y)` 判断在不在屏幕内，不在就 `801FFCB0(x, y)` 把镜头移过去 |
| 音效 | 一开始就播 `8007E8A8(0xB9)` |

`801E514C` 只是把阵营、槽位换成句柄：阵营 0/1/2 分别是 `0x42`/`0x60`/`0x7E` 加槽号。名册每个阵营 `0x258` 字节。

## 接管方式

- `NATIVE_HOOKS` 把 `801C8B04` 改名为 `srw64_original_map_idle`，[`game_hooks.cpp`](../../src/host/game_hooks.cpp) 的包装先问 `map_idle` 钩子。改了 `NATIVE_HOOKS` 要重新跑 `make recomp-cpu`。
- 扳机刚按下（或按住到了连发时刻）的那一帧，宿主照原版的做法放光标：先播 0xB9，写光标和目标，镜头只在机体离开屏幕时才移，然后这一帧不运行原函数。其他帧原样运行，方向、A、B、L、R 都不受影响。
- 敌方与第三方都不看已行动位，也不看驾驶员 `+0x35`（这两项只对我方有意义）。
- 光标是否已在某个敌方机体上，按坐标判断（相差不到半格），不调用 `801C2BFC`。
- 日志：`enemy-cycle-events.jsonl`，每步一行（方向、阵营、槽、句柄、坐标、敌方数）。调试接口 `status` 里有 `enemy_cycle`（步数和最后一步）。

## 验证

尚未实机运行。准备的做法：

- 调试接口新增 `pad` 方法和 `srw64ctl pad`（按 Deck 键名，如 `srw64ctl pad r2 r2 l2`），在 Mac 上不用真手柄就能按 L2、R2。
- 在有多个敌人的迷你关卡里：R2 连按走遍全部敌方，最后回到第一个；L2 反向；敌人在屏幕外时镜头跟过去；光标在敌人上按 A 打开原版的敌方查看；按住 R2 连发。
- 需要确认的静态推断：第三方（阵营 2）句柄的对象坐标同样在对象表里；敌方的状态字节为 1 时一定在地图上、可以被光标指到。
