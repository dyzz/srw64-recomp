# 改造画面：机体列表、五项改造与武器改造的原生接管

日期：2026-09-22。状态：**ユニット改造（机体列表、五项改造）与 武器改造（机体列表、武器列表、改造确认）五个画面都已接管并实机验证；武器实际改造成功的一步（はい 后扣款、加值、満改追加武器提示）因存档資金不足未走到**。做法与[场间主菜单](native-intermission-menu.md)相同：原版初始化函数跳过绘制，原生页面按 ROM 里的布局矩形画同样的面板；选择只是写光标、给原版每帧函数注入一次 A／B 边沿。改造数值、价格、上限、传播、EW 换装都仍由原版函数和[15 段改造规则](../gameplay/upgrade-limits.md)的钩子决定。

## 2. 接管方式

源码：[`upgrade_page.cpp`](../../src/host/upgrade_page.cpp)（游戏线程适配器）、[`frontend.cpp`](../../src/native/ui/frontend.cpp) 的 `upgrade_sync`（页面）、[`game_hooks.cpp`](../../src/host/game_hooks.cpp) 的包装。`SRW64_NATIVE_UPGRADE=0` 或不加载 profile 时保留原画面。

| 原函数 | 包装 |
| --- | --- |
| `801CF388`／`801D03D0` 列表初始化 | 不调原函数。保留：背景调用（含随机数）、列表生成函数、按 `D_801DECD4` 恢复光标、选中机体的重算；不建布局、文字、光标精灵。发布快照后淡入。 |
| `801CF564`／`801D04A4` 列表每帧 | 输入被过滤成 0 时原函数零写入，照常调用。移动：适配器写页、行、`D_801DEC5C` 并重算该机体，播放 0xB9。确认／返回：注入 A／B 边沿调原函数，由它写下一画面并转场。 |
| `801CF680` 五项初始化 | 在既有 `decide` 作用域内：不调原函数，保留背景调用和状态清零；`D_801DEC50` 写成当前光标，这样原每帧函数不会自己重画費用。 |
| `801C80E0` 五行绘制 | 页面可见时整体跳过（它只画，但会先调 `800A5254`；适配器自己在发布快照前调 `800A5254`＋`801C4DE4`）。 |
| `801D0600` 武器列表初始化 | 不调原函数。保留背景、`801C7254`、按 `D_801DEBD2` 恢复光标；读 `D_801DD20A`／`D_801DEC5A` 决定是否显示満改追加武器提示后按原样清成 999。 |
| `801D087C` 武器列表每帧 | 与机体列表相同：移动自己写行、页；确认／返回注入 A／B。提示窗关闭只清状态，不调原函数（它只释放自己画的东西）。 |
| `801D0C7C` 确认初始化 | 在 `weapon` 作用域内：不调原函数。保留背景，自己按类型写 `D_801DEBCC`、`D_801DECD0`；段数≥有效上限时页面直接显示 これ以上。 |
| `801D1100` 确认每帧 | 在 `weapon` 作用域内。はい：資金不足时页面显示 資金が足りません（原函数不跑），否则注入 A；いいえ、消息关闭、返回：注入 B。 |
| `801CF988` 五项每帧 | 在 `decide` 作用域内。移动：写光标和 `D_801DEC50`。选择：适配器按「段数＜有效上限且資金≥价格」决定弹确认窗还是消息，都由原生页面显示，原版弹窗不建。确认：写 `D_801DEBCC=价格`、`D_801DECD8=1`、`D_801DD0A2=0`，注入 A，原函数完成扣款、加值、传播、EW 判定和重新进入。返回：注入 B。 |

**15 段规则的口径**：快照里每项带 `level`、`cap`（有效上限 `allowed_cap`：开突破为 15）、`original_cap`、`price`／`preview`（段数＜有效上限时才有，直接读内存里的表，规则文件补丁生效）和 `gauge`。刻度串与 `upgrade_rules.hpp` 的规则一致：原作上限以内 ▶／▷，超出部分 ●／☆；开突破画到有效上限，关掉只画到已有段数。「最大で N 段階まで」显示有效上限；当规则把上限抬高（`original_cap` < `cap`）时，五项画面的資金／費用框与武器确认画面各多一行 `upgrade_cap_original`（本来の上限 N段階 ▶▷ · 上限突破 ●☆），让玩家分清固有段数与突破段数。原版的两个作用域钩子没有改动，所以能否改、扣多少钱仍是原版在 `+0x51` 被作用域改写后的判断——适配器只是用同一个 `allowed_cap` 先行判断以决定弹哪个窗。

**快照**：`status.upgrade_page`：`screen`（`list`／`stats`／`weapons`／`weapon`）、`kind`（`stats`／`weapons`）、`serial`、`funds`、`cursor`；列表有 `page`（0 起）、`pages`、`rows[]`（`slot`、`number`、`name`、`hp`、`en`、`mobility`、`armor`、`limit`、`pilot`）；五项有 `unit`（`slot`、`number`、`name`、`art`）、`cap`、`rows[]`（上文）、`window`（空／`confirm`／`maxed`／`poor`）；武器列表有 `rows[]`（`index`、`number`、`name`、`power`、`range_min/max`、`hit`、`critical`、`en`、`morale`、`skill`、`ammo`、`ammo_max`、`terrain`、`level`、`type`、`cap`、`price`、`preview`、`gauge`）、`unit.en`／`unit.morale`、`window`（空／`bonus`）；确认画面有 `weapon`（同一行）、`cursor`（はい 0／いいえ 1）、`window`。事件日志 `upgrade-page-events.jsonl`。

**页面**：列表面板按布局 0x6B 的矩形，列位置照原版；五项画面照原版截图分成机体名、提问、資金／費用、机体图、五行五块（原布局只有一块外框，内部分隔是原版按精灵画的，这里按截图定）。机体图用本地 ROM 导入的战斗姿势（`battle_assets.units`）。确认窗与消息窗按布局 0x74／0x87 的矩形。

**资金**：三个画面的資金数字都可点击直接修改（见[场间主菜单](native-intermission-menu.md) 6a 节），改后立即影响费用判断与扣款。

**调试**：稳定 ID `upgrade:N`（行；点当前行即确认，点其他行移动光标）、`upgrade-confirm`、`upgrade-cancel`、`upgrade-dismiss`；键盘 ↑↓、←→（列表翻页）、Enter／Z、Esc／X。
