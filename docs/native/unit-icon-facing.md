# 地图机体图标按阵营朝向与阴影

战术地图上，我方机体的图标整体朝左，敌方朝右，第三方看它对我方是否敌对（2026-10-26 用户定）。原版图标照各自的画法有的朝左、有的朝右，HD-2D 版照原版朝向画（见 [机体标识 HD](../design/unit-icon-hd.md)），所以朝向不再照原图，而是由宿主在绘制时按阵营镜像。原版画面和 HD 画面同样生效，HD 包不用改。

## 规则

- 每张图标（资源 688–1009）有一个原图朝向：左、右或正面，表在 [`content/art/unit-icon-facing.json`](../../content/art/unit-icon-facing.json)。2026-10-26 定稿：朝左 225、正面 91、朝右 4（717、834、981、996）。表是在 HD-2D 母版上逐张判断的，用户在本地过目页上改过 51 张；偏一点的头也算朝左。
- 目标朝向：
  - 我方（阵营 0，含出击值 3 的中途加入单位）朝左；
  - 敌方（阵营 1）朝右；
  - 第三方（阵营 2）读名册 `+0xB` 的 0x20 位：置位的是友军 NPC（出击值 4），朝左；否则是敌对第三方（出击值 2），朝右。
- 原图朝向和目标不同就镜像；正面的哪一方都不翻。
- 这个位怎么来的：AI 选目标 `80202188` 用它决定第三方是否攻击我方；部署 `8020BA30..8020BA84`、`8020C250..8020C2A0` 在出击记录 `+0x14 == 4` 时 `ori 0x20`。同一关里两种第三方可能并存（第 15、38、84、100、105、107、138 话），所以只能按单位判断，不能按关。原版两种第三方都用黄色调色板 1012，画面上不区分。

## 实现

- 图标是模式 5 的精灵：绘制器 `801E2C5C` 对单位槽 0x42–0x9B 调 `801E2734`，输出一个 16×16 的 G_TEXRECT（E4＋E1＋F1）。精灵的镜像位（子记录 `+0x1C`、槽 `+0x50`）只有 `8009761C` 的顶点组读，对它无效。
- 所以翻转放在宿主的 `srw64_render_node`（`src/host/game_hooks.cpp`）里：`801E2C5C` 画完子 0 以后，[`unit_icon_facing.hpp`](../../src/host/unit_icon_facing.hpp) 在刚写出的这段显示列表里找到 texrect，把 S 起点移到远端（跨度减 1/32 texel），并把 DsDx 取负。
- HD 图标按哈希替换贴图，坐标沿用 texrect 的，所以跟着一起翻。阴影是子 1，不受影响。行动完换灰色调色板是在同一次绘制里换 TLUT，也不受影响。
- 阵营判断：
  - 单位槽按 `801E514C` 的区间分：0x42 起是我方，0x60 起是敌方，0x7E 起是第三方，第三方再读名册 `0x8015E100 + 2×0x258 + 号×0x14 + 0xB`；
  - 复制图标的槽 0x3D、0x9C 不属于这些区间，看子 0 的调色板：1010 朝左，其余朝右。
- 表在程序里是 [`unit_icon_facing_table.hpp`](../../src/host/unit_icon_facing_table.hpp)，由 [`tools/content/unit_icon_facing.py`](../../tools/content/unit_icon_facing.py) 生成；`tests/test_unit_icon_facing.py` 检查两者一致。改 JSON 后要重跑这个脚本。
- GL 宿主（Switch）走同一个 `srw64_render_node`，它的 texrect 解释器按有符号数读 DsDx。Switch 上还没实机看过。

## 验证（2026-10-26，Mac）

迷你关（每种情况一组）：
- 敌方ダンバイン（原图朝左）翻成朝右；
- 敌对第三方アルベルト翻成朝右，友军第三方保持朝左；
- 出击值 3 的我方 ヴァイローズ（原图朝右）翻成朝左，和镜像母版的像素误差 33，和原样母版是 49；
- 我方ガイヤー不动。

原版和 HD 画面都对。在 1 倍内部分辨率下，原版像素图标翻转后边缘没有错列，也没有绕回。

阵营色不受影响：原版图标的颜色是换调色板（1010–1013）实现的，翻转只改 texrect 的 S 和 DsDx 两个字，不碰装调色板的命令。另外给一台被翻转的 ヴァイローズ 直接置上名册 `+0xB` 的 0x80 位（行动完）：原版画面下它换成了灰色调色板，HD 画面下换成了灰版贴图，两种画面里都和旁边没行动的那台朝向一致。

## 阴影（2026-10-30）

用户参考 Z2：地面单位脚下也要有阴影，要贴着图片边缘；而且要在程序里做，不改贴图。地面阴影要淡一些，好和空中单位区分（地面 45%、空中 70%）。空中单位的头像和阴影离得太远。

- **原版怎么画**：每台机体都有阴影，就是精灵的子 1（资源 687，16×16 图里只有最下面 6 行是一个椭圆），由 `801E21F8` 画在地面那一格，alpha 0xB4（约 70%）。画图标时会减去单位高度（槽 `+0xC`），所以飞行单位的头像被抬高，阴影露在下面。地面单位的阴影节点在建图标时（`801C61D8`／`801E04DC` 的 `ori 4`）被藏起来（节点 `+1` 的 0x04）；就算放出来，也会被 16×16 的头像正好盖住。
- **地面单位：剪影阴影**（[`unit_shadow.hpp`](../../src/host/unit_shadow.hpp)）。`801E2734` 画完子 0 的图标以后，在它的 texrect 前面插 56 字节：
  - 一条 FA，prim alpha 乘 0x73/0xFF；
  - 一条 FC，把组合器两个周期的颜色输入 a 改成 0，于是颜色为黑、alpha 仍是 TEXEL0×PRIM；
  - 同一张贴图的 texrect，压扁成一半高（DtDy 加倍）、放在格子下半、再下移 1.25 像素；
  - 最后恢复原来的 FA、FC。

  插入后把显示列表游标往后推，做法和 `wide_map` 一样。阴影用的是同一张贴图，所以 HD 画面下 RT64 会按哈希换成同一张 HD 图，阴影的形状就精确沿着图标边缘。朝向翻转先做，所以阴影跟着一起翻；行动完变灰也照样，因为阴影是黑色。只处理组合器是 `FC119623 FF2FFFFF` 的常规显示列表，碰到别的就照原样画。
- **空中单位**：保留原版的椭圆和 70% 的深度，`after_draw()` 把它往上挪 2 个原像素，靠近头像。HD 画面下，[`native_icon.cpp`](../../src/host/native_icon.cpp) 的 `rewrite_shadow()` 用程序生成的柔边椭圆来画（HD 包里没有阴影贴图）。
- **图标 MOD**：MOD 图标由宿主自己画。`rewrite()` 把块里最后一个 texrect 当图标，前一个（插入的阴影）用 MOD 自己的图画成黑色剪影。`HdPortraitPS` 的 `fill.w` 原来只表示「画成剪影」，现在同时也是 alpha 倍数（头像剪影仍是 1）；GL 端用 `color[3]`。实测：一个 32 像素的三角形测试 MOD，阴影跟着三角形的形状。
- 用户从样张里选的是 C：剪影压扁一半、贴住底边。其他几种是：固定椭圆下移加宽、按轮廓定宽的椭圆、剪影下移 2 或 3 像素、加柔边。效果很克制：地面单位只在下沿露出一点点，主要用来和空中单位的深椭圆区分。
- 被光标选中的单位原版会闪烁，图标熄灭的那几帧阴影也跟着不画。

## 去掉阵营描边（2026-10-30）

有了朝向，敌我已经能分清，用户决定下一版不要红、黄描边。图标 MOD 生成的四份图（[`unit_icon_art.hpp`](../../src/host/unit_icon_art.hpp)）已经去掉描边，只保留行动完变灰。HD-2D 图标的描边也已去掉：`unit_icon_imagegen.py` 的 `faction_mark` 现在只处理灰色，图标重打为 `assets/hd-ai/worldmap-surfaces/pack-v13`（在 pack-v11 上），并绑定进美术清单。只有敌方和第三方那 628 张贴图变了，我方和已行动的逐字节相同。要等下一版 HD 包发布后，玩家才能看到。去掉以后，敌方和敌对第三方都朝右，只能靠调色板之外的信息区分；原版画面仍按颜色区分。
