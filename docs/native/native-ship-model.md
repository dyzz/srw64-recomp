# 世界地图过场模型 HD：舰船、地标与航迹

2026-09-24。剧情之间的世界地图上，部队航行时航迹前端画的舰船、按场景摆放的地标，以及蓝白航迹，全部换成宿主 GPU 绘制的高精度版本。15 个模型按官方设定重做（每个 0.8–2.1 万面，原版 4–330 面），航迹换成平滑光带，片假名名牌按阅读语言显示日／中／英文。游戏继续提供位置、朝向、镜头与演出时序，不改 ROM、不写 RDRAM；F6 切回原版画面，F7 切换名牌语言。

## 世界地图上画什么

世界地图 overlay `load_000A7EC0` 的模型对象表 `801C5670`（ROM `0xAAF30`）收齐了这里出现的全部立体资源：舰船、5600 标记、各区域地表。本次从代码读出三条使用路径，并用迷你关卡实机确认：

1. **航行舰船**：`3D33` 以 `engine+0x990`（`3D72 n` 写入 `n mod 15`）为下标取 `D_801C5644`，值是**模型表下标**，不是人物编号（布局锁此前的解释已原地更正）。`n = 0` 时取 ブライト（46）所乘机体，经机体→模型配对表 `801C560C` 换成下标；找不到用 24。
2. **按场景摆放的地标**：进入世界地图时 `801C310C` 按当前场景号查 `801C5728` 的 17 个场景，再从 `801C57B0` 取（资源, 地点）列表摆放。
3. **标记**：`801C2E30` 建立 5600 黄色标记（槽 `0x9C` 起）；正常流程只传 k = 0。

下标 13、14、17–20 是各区域地表（14 = 5599 宇宙；18/19 = 5604/5605 地球），属于贴图高清化，不在本页范围。原脚本实际用到的 `3D72` 参数只有 0、3、8、10、12、14；其余舰船只在 ブライト 恰好乘坐时出现或从未出现，但同样替换，行为一致。

## 设定与建模

每个模型一个 Blender 脚本 `tools/models/<key>_blender.py`，文档字符串写明官方数据（全长、全宽、武装、设计者）与参考来源（ガンダムチャンネル、各作品官网、ガンダムWiki、授权立体商品照片等）；参考图只在浏览器中查看，不进仓库。共用部件库 [`blender_kit.py`](../../tools/models/blender_kit.py) 提供放样、方块、圆柱、球、倒角与导出，并用同一组机位渲染原版资源（带原贴图）生成 `compare.png` 左右对照：

```sh
/Applications/Blender.app/Contents/MacOS/Blender -b --factory-startup \
  --python tools/models/ra_cailum_blender.py -- assets/models/ra-cailum --previews
```

- **坐标系**：沿用各原资源的局部坐标，+Y 向上，舰首方向与原版一致（本批都是 +Z），尺寸以原版包围盒为准、比例按官方设定。アウドムラ、ミデア 按官方长宽比，比原版短 16–21%；其余长轴差 ±4% 以内。
- **输出**：`assets/models/<key>/mesh.json`（位置、逐角法线、sRGB 顶点色，alpha < 128 为自发光喷口）、`model.glb`、预览与 `compare.png`。网格与其他 HD 资产一样只在本地 `assets/`，不随源码分发。
- **已知取舍**：ゴラオン 用官方暗灰绿，原版为蓝；アウドムラ 用 TV 版橙粉色；ピースミリオン 只有透视彩图，平面比例沿用原版；ネェル・アーガマ 按 UC 版比例；ガンドール 龙形态参考现代商品原型。各脚本文档字符串列出其余不足。

ラー・カイラム 的设定依据：《逆襲のシャア》ラー・カイラム級，全长 487 m、全宽 165 m，メカニックデザイン 増尾昭一；连装メガ粒子砲 4 基（前 3 后 1）、舰首导弹 6 门、对空机銃 22 基、左右舷弹射甲板与后部着舰甲板、双舰桥、带长放热板的引擎块（[ガンダムチャンネル](https://www.gundam-c.com/manual/mechanic/counter/ra-cailum.html)、[ガンダムWiki](https://gundam.wiki.cre.jp/wiki/%E3%83%A9%E3%83%BC%E3%83%BB%E3%82%AB%E3%82%A4%E3%83%A9%E3%83%A0%E7%B4%9A)），外形对照 [Cosmo Fleet Special](https://www.megahobby.jp/products/item/1437/)。

## 航迹

![航迹：左 HD，右原版](images/worldmap-trail.png)

原版航迹由 `801C4960` 每帧逐步发出：每一步一个 `G_QUAD`，顶点取自缓冲区 `801C97C0`（`801C3694` 每步平移模板追加），PRIM 色 `(c, c, 255)` 的 c 由 `801C3958` 按总步数从 0 渐变到 255。地球区域模板为 10×10 方块、每 8 单位一步；宇宙区域 6×6、每 4 单位、高度 −10。方块轴对齐，斜向航行时叠成台阶锯齿。世界地图只有这一种航迹，两种样式只差模板。

宿主在识别到这组命令（`FA`／`E7`／`G_VTX 8`／`G_QUAD` 的固定序列、顶点地址落在缓冲区内、且常驻的 `801C4960` 代码与 ROM 一致）时，在第一块上快照全部步的中心、宽度与颜色，其余方块抑制。中心点是整数坐标，先做保端点的滑动平均；然后画一条三角带：宽度等于原方块，外加 45% 的淡光晕，两端各延长半个方块，边缘按 `fwidth` 抗锯齿，颜色逐步插值原来的 `(c, c, 255)`。深度比较跟随原 draw，不写深度，混合绘制。

## 标记：金色信标

![5600 标记的虚线环：左 HD，右原版](images/worldmap-marker-ring.png)

5600 标记外的黄色虚线环是一块 28×28 的水平方片（y = 4），贴一张 64×64、1 位透明的贴图：12 段短划线，中心在 atan2(−z, x) = 20.2° + 30°k，各长约 10.5°，半径为半宽的 0.87–0.955；由偏移 `0x1A08`–`0x1A20` 的四条 TRI2 画出（正反两面）。宿主在识别 5600 时一并认出这四条：第一条换成同尺寸方片，在片元着色器里按上述角度与半径画圆角弧段（边缘按 `fwidth` 抗锯齿，外加一圈淡暗边，在浅色陆地上更清楚），其余抑制；颜色取原版的黄。与 5600 本体一样，只在 HD 画面、加载了 5600 资源包时生效。

在此基础上做成“金色信标”（用户从三个方向里选定）：宿主用自身时钟驱动动画，位置、镜头与出现时机仍由游戏决定。

![金色信标：出现、停留与到达（实机连续帧）](images/worldmap-beacon.png)

- **出现**：标记超过 0.25 秒没画过就视为刚出现；本体与圆环在 0.55 秒内带回弹放大（ease-out-back），同时从中心放出一圈较亮的波纹（0.8 秒内半径 4 → 16 单位）。开场淡入、每次 `3D33` 抵达后都会触发。
- **停留**：本体沿局部 Y 以 2.8 秒为周期上下浮动 ±1.2 单位（以局部变换乘在游戏的世界矩阵之前，不改游戏数据）；虚线环的 12 段每秒转 18°；中心下方一块淡暗底盘（半径约 8.5 单位，在虚线以内）增加在陆地上的对比；每 2.4 秒一圈淡出波纹从半径 5 扩到 15 单位，刚越过虚线（半径约 12.8）就消失。所有效果都收在原版虚线环（±14）附近，不比原版标记占地更大；圆环方片只加宽到 ±17 单位留给波纹淡出。
- **本体造型**不在这里：5600 资源包由另一路工作维护，当前为金色多面体；信标只加浮动与入场缩放。

## 名牌

![名牌：日文、中文、英文（实机）](images/worldmap-plates.png)

リーブラ、ラビアンローズ、バルジ、アクシズ、フィフス・ルナ 的名牌是 200×30 的绿框黑底牌子（绿框 2 单位宽，内侧两块各贴一张 64×64 的片假名贴图），画在舰体或地标同一原点上方。文字在贴图里，不经过文本系统，所以另行处理：

- **名字**：日文沿用原名牌文字；中文、英文取数据区词条表 `content/locales/terms/`，没有的再查台词专名表（フィフス・ルナ → 月神5号 / Fifth Luna，中文与数据区地形名「5thルナ」一致）。当前为 天秤座 / Libra、玫瑰人生号 / La Vie en Rose、巴鲁智要塞 / Barge、阿克西斯 / Axis、月神5号 / Fifth Luna。词条表改了之后重新打包即可。
- **贴图**：打包时按原牌子的样式重绘（每单位 8 像素，1600×240；HarmonyOS Sans 描边加粗、右倾 0.22，外加暗色阴影），每种语言一张；宿主载入后生成 mipmap。
- **绘制**：名牌那条显示列表（类型 5）同样按命令偏移识别，第一条换成一块 200×30 的贴图四边形，其余抑制。语言在分类时取当前目录（`localization::snapshot()`），编进绘制 id，同一帧两个渲染目标一致；F7 立即生效。
- **画面模式**：名牌是文字，所以原版画面下只有日文保留原贴图，中文、英文仍显示译名；HD 画面下三种语言都用重绘的牌子。
- **宇宙区域的名牌**：宇宙地表 5599 本身带 7 块同样的牌子（第 6–12 条类型 5 显示列表：サイド1／2／3／5／6／7、スウィートウォーター）。它们不换网格，资源包里是只有名牌的条目（清单 `plates`，打包脚本的 `BOARDS`），宿主照样按命令偏移识别、按语言绘制。中英文为 Side 1…Side 7（台词译文写法）与 甘泉／Sweetwater。见[剧情世界地图 HD](native-worldmap-regions-hd.md)。

实机：同一关卡分别以日、中、英启动，两处地标与三艘带名牌舰船的名牌都按语言显示，方向与原版一致（航行中的名牌随航向旋转、向左飞时倒置，这是原版行为）；运行中连按 F7，阿克西斯 名牌依次变为 日→中→英；原版画面下日文保持原贴图、中英文显示译名。

ラビアンローズ 的中文已按用户决定统一为“玫瑰人生号”（数据区词条表与台词专名表一致）。バルジ 的中文按用户决定为“巴鲁智要塞”（地形名与名牌用全名，台词里单独出现的改为“巴鲁智”）。英文统一为 Barge（台词「バルジ要塞」为 Barge Fortress）。

## 宿主接入

沿用 [5600 原生水滴](native-model-replacement.md) 的路子：

- [`native_model_hook_patches.py`](../../tools/recomp/toolchain/native_model_hook_patches.py) 让 RT64 的 `TRI2`（`G_QUAD` 也走这里）调用分类钩子；舰船 DL 主要是 `TRI2`。
- [`native_marker.cpp`](../../src/host/native_marker.cpp) 在段 4 基址逐字节核对完整原资源，命令偏移落在被替换显示列表的三角形命令表里才命中；第一条带原生绘制标记，其余抑制（id 段 `0x534D`），航迹 id 段 `0x5452`。变换取自该 draw 所在的不可变 workload，深度设置跟随原 draw；舰船着色为顶点色加主光、补光、高光与边缘光。
- [`build_native_models.py`](../../tools/models/build_native_models.py) 从 ROM 取出各资源（核对 SHA-256）、解析被替换显示列表的三角形命令（拒绝矩阵变更与子列表调用），连同网格写入 `build/recomp/native-models/assets/`；航行舰船打包时放大 1.3 倍（呈现选择，网格仍按设定比例），带名牌与地标不放大。清单记录航迹代码指纹，以及缺网格与不处理的资源。
- 抗锯齿（下图左为关闭、右为 4× MSAA，原始像素放大）：宿主默认让 RT64 以 4 倍 MSAA 绘制整个场景（`SRW64_MSAA`，见[开发指南](../guide/native-development.md)），这些原生管线都按场景目标的采样数建立，因此舰船与名牌边缘同样抗锯齿；5600 水滴管线也改为按目标格式缓存，避免原尺寸与放大目标交替时反复编译。实机对照了带对白的整段迷你关卡流程（世界地图、战术地图、场间与存档页）与 MSAA 关闭时逐帧对照，画面内容一致、没有缺失或错位（边缘像素本就不同）；转场里的横条两者相同，是游戏自带的扫描线效果。

  ![MSAA 前后](images/worldmap-msaa.png)
- 开关：`SRW64_NATIVE_MODELS=<资源包>` 或 `run_host_probe.py --native-models`；不设置时宿主行为不变。与画面模式联动，Original 保留全部原三角形与原航迹（名牌规则见上节）。

## 验证

两个迷你关卡：

- [`worldmap-models.json`](../../config/recomp/mini-stages/worldmap-models.json)：绑定场景 103，世界地图自动摆出 アクシズ 与 フィフス・ルナ；依次定位两处地标后，`3D72 1`–`14` 各在宇宙区域做一次短程 `3D33`。
- [`worldmap-libra.json`](../../config/recomp/mini-stages/worldmap-libra.json)：绑定场景 84，停在 リーブラ 地标。
- 单舰展示用的 [`ra-cailum.json`](../../config/recomp/mini-stages/ra-cailum.json)：地球与宇宙区域各两段航行。

```sh
.venv/bin/python tools/models/build_native_models.py
SRW64_NATIVE_MODELS=build/recomp/native-models/assets .venv/bin/python tools/recomp/debug/srw64ctl.py \
  launch --mini-stage config/recomp/mini-stages/worldmap-models.json --images hd --diagnostics light
```

2026-09-24 实机结果：

- `worldmap-models` 一次运行里 15 个模型都有原生绘制（航行舰船各约 260–300 次，两处地标各 5,704 次），按 F6 取原版的帧里各有原版绘制，`rdram_modified: false`；航迹 1,417 次快照、2,834 次原生绘制，无过期快照。
- 同一关卡分别以 HD 与 Original 各跑一遍，自进入起每 50 VI 定点截图；关卡时序确定，同帧号舰船位置一致，逐艘对照见上两图。所有舰首朝航行方向，名牌与舰体的遮挡关系与原版一致；`3D72 8`（下标 24）两边都只有航迹、不画舰，与原版一致。
- `worldmap-libra` 的 HD／原版定点截图：リーブラ 地标被替换，名牌与标记照常叠加。
- `tests/test_native_models.py`：从 ROM 读两张表确认 `3D72 14` 与机体 69 都指向 5591；5591 的命令与三角形数；资源包往返、篡改检测、坏网格拒绝；名牌取名、样式与带名牌资源的打包。

## 限制与后续

- 5597（デビルアクシズ）与 5601（红色标记）没有出场路径，暂不处理；地图地表属贴图高清化另行处理。
- 原剧情场景本身没有实机走到；验证走的是原版世界地图 overlay、原版 `3D72`／`3D33` 与场景地标初始化。
- 光照为固定视空间近似，没有阴影或环境反射；喷口自发光与航迹光晕是新增表现。
- 与 5600 相同，仅接入 macOS Metal 路径；网格资产与资源包在本地生成，发布时的分发与默认开关尚未决定。
