## 游戏怎么画

### 场景精灵

标题元素和剧情文字图都是**场景精灵**：一帧由场景资源列出的若干零件拼成，每块零件从图集里取一小块。`80097C68` 按模式选择绘制器（跳转表 `800D0530`，下标为模式 − 1）：

| 模式 | 绘制器 | 画法 |
| --- | --- | --- |
| 11、12 | `800975A4` → `80096CD8` | 每块零件一个 TEXRECT（屏幕坐标，不能缩放） |
| 13 | `8009751C` → `80096CD8` | 同上，y 减去深度 |
| 14、15、16 | `8009761C` | 每块零件四个顶点加一个 G_QUAD，受精灵矩阵变换（缩放、旋转、透视） |

显示列表里每块零件的命令：

- `80096CD8`：`FD48` 贴图、`F5`、`E6`、`F4` LoadTile、`E7`、`F5`、`F2` SETTILESIZE，然后 `E4`/`E1`/`F1` 三条组成的 TEXRECT。坐标为负时夹到 0，并调整 S。
- `8009761C`：`01004008` G_VTX（零件的 4 个顶点），贴图装载，两条 `F2`，然后 `07` G_QUAD。静态阅读时以为 G_VTX 紧挨四边形，实机转储才看清它在贴图装载之前。

两者都在开头装 16 色调色板（`FD10` + LoadTLUT）；精灵透明度不是 FF 时，另写一条 `FA` 原色（alpha 在低字节）。

**资源号可以直接读到。** 精灵子记录在 `800FFAAC + 槽 × 0xC4 + 子 × 0x30`：+0xA 场景、+0xC 图集、+0xE 调色板都是资源句柄，+0x11 是当前步。句柄表在 `80160340`，每项 20 字节：+0 在用、+2 **ROM 资源号**、+0x10 数据地址（`8008A11C` 取地址，`80089EB0` 按资源号查找或分配）。所以不必像头像那样按像素摘要识别。场景数据的第 0 字节是步数，从第 2 字节起每步是（帧号, 时长）。

### 标题画面

标题 overlay 在 ROM `0x10DA50`（RAM `801C4500`）。

| 元素 | 槽 | 模式 | 场景 / 图集 / 调色板 |
| --- | --- | --- | --- |
| 火焰 | 9 | 11 | 686 / 684 / 685，位置 (160, 120) |
| Logo | 2 | 14（进场）后 11 | 683 / 681 / 682 |
| PRESS START BUTTON | 3 | 11 | 651 / 623 / 625 |
| 环形菜单 | 3–6 | 14 | 652 スタート、653 ロード、654 コンティニュー、655 オプション；图集 623 |

环形菜单靠调色板区分状态：624 灰白、625 和 626 蓝色（正面项）、627 暗色。原生文字以白到浅灰的渐变绘制，再乘上当前调色板里最亮的颜色，所以原版的高亮和变暗照样生效。

火焰的每一帧其实是图集里一块 128×128 的图块，横向铺 2.5 次（x −160…160，y −8…120，列序 3、0–3、0–3、0）。有两处例外：

- 第 4、10 帧顶行各少画两块，图集里那两块是无关的亮黄像素，原作有意不画；
- 第 5 帧在图块上方多画两块 16×16 火苗（y −24）。

所以高清图按「实际画出的零件」重建图块，上方多留 16 px。

### 章节标题卡

地图 overlay（`load_000AB160`）的开场状态机 `D_80217AE8`：

1. `801C72C8` 建两个模式 14 精灵：槽 0x9C 是标题（卡片号 = `D_802195B1[场景 × 2]`，经 `8009C8EC` 查表 `0x84B20` 得到场景 / 图集 / 调色板），槽 0x9D 是「第 N 話」（场景 5106 + 话数计数，上限 98）。初值：缩放 20、深度 740、绕 Y 轴 180°；并调用 `800836CC(1)` 打开残影。
2. `801C7460`：每帧缩放减去 1/24，同时绕 Z 轴转 5°，直到缩放 ≤ 1。
3. `801C7514`：继续转到整圈。
4. `801C765C`：绕 Y 轴从 180° 每帧回转 5°（翻面）。
5. `801C77A0`：停 91 帧后释放两个精灵，`800836CC(2)` 关残影。

残影由 `80083744` 实现：`D_8010F5B6` 为 1–3 时，把上一帧画面当贴图、以递减的 alpha（从 200 起）叠回屏幕。RT64 以原机分辨率复制这张帧缓冲，所以旋转时的拖影是方块状的；这与本次替换无关，定格后的卡片本身是高清原生字。

## 宿主实现

- [`native_sprite.cpp`](../../src/host/native_sprite.cpp)（三种宿主共用）：`generate_cpu.py` 把 `80096CD8`、`8009761C` 改名为原函数，[`game_hooks.cpp`](../../src/host/game_hooks.cpp) 包一层，记下本次写入的显示列表范围。绘制后按子记录和句柄表得到（场景, 图集, 调色板, 帧），决定替换成什么：
  - 有原生文字：总是替换；
  - 美术包里有这一帧的高清图，且在 HD 模式：替换；
  - 否则保留原零件。

  替换时留最后一块零件作标记，其余置空：TEXRECT 改成覆盖整帧的矩形；四边形保留原来的 G_VTX 和 G_QUAD。标记前一条命令改成带编号的 G_NOOP 标签。RT64 构建时认出标签，在同一绘制位置调用宿主的 Metal 回调：TEXRECT 按屏幕坐标画矩形；四边形取这次绘制的世界矩阵和投影，在模型空间里画一个矩形，所以缩放、旋转、翻面和透视都与原版一致。
- 文字按原帧的中心放置（章节标题按顶边），大小由排版决定，比原图宽也可以。
- 高清图的解码和文字栅格化都在后台线程完成。没准备好时，高清帧这一次照画原图，文字则先不画（多为缩放刚开始的几帧）。纹理为预乘 Alpha，带 mipmap；常驻超过 48 张后，释放闲置 20 秒以上的。
- [`sprite_text.cpp`](../../src/host/sprite_text.cpp)（只在游戏宿主）判断每个精灵显示哪段文字，并排字、描边、加阴影：
  - 菜单与标题卡用 HarmonyOS Sans 2.040 可变字体的 **Bold** 实例（wght 706，`game_font_sources(locale, 700)`），没有单独的粗体文件；英文先用 Condensed，再用 SC，符号字体垫后；
  - 序章和结局页用 Regular，宽 256，放不下时逐步缩小字号；
  - 描边由距离变换得到，字面带竖向渐变。
- 日志：运行目录的 `scene-sprites.jsonl` 记录每种（场景, 图集, 调色板, 帧）第一次的处理方式和 VI；退出时写 `scene-sprite-summary.json`。

## 高清素材

[`title_hd.py`](../../tools/hd_ai/title_hd.py) 分四步：`prepare` 从 ROM 冻结请求，`run` 经 `run_benchmark.run_one` 发送，`compose` 配准、保色、抠图，`build` 写出运行时目录。

- 模型为 `qwen-image-3.0`，seed 640903（与头像相同），共 5 次请求，按公开价约 1 元：
  - Logo 一次：黑底留 16 px 边，放大 7 倍；
  - 火焰四次：每次 2×2 四帧，每帧左右各带 64 px 自身的循环内容，放大 4 倍。
- 配准：逐窗口测量位移，按两轴拟合缩放和偏移；重采样时单元格边缘向外复制，避免把黑色间隔吸进底边。
- 保色：高频细节取模型输出，低频颜色取原图（半径 2 个原像素）。Alpha 取原图 1 位遮罩，放大后平滑成约 1 个输出像素宽的边。
- 循环：图块左边 8 个原像素交叉淡入模型在右边之外画的延续内容，所以首尾无缝。
- 缩回原尺寸后与原图的平均差异：Logo 5.1，火焰 3.7–8.5。
- 输出在 `assets/hd-ai/title/whole-v1`（Logo 1792×448，火焰 16 张 512×576），由 [`stage1-hd.json`](../../content/art/stage1-hd.json) 的 `scene_images` 段引用，[`assets.py`](../../src/srw64_native/assets.py) 校验摘要后复制到美术包并写出 `srw64-scene-images.json`。

## 实机验证（2026-09-24）

- **标题**：中文和英文截图里，Logo 与火焰是整帧高清，接缝消失；菜单字按语言显示，正面项蓝色、其余灰色，与原版一致。F6 切到原版后，Logo 与火焰回到原图，菜单字仍是原生文字。用户在窗口里切换过语言，确认多语言正常。
- **开场序章**：新游戏的公共序章，中、英、日逐页原生显示，缩放进场与翻页由原版驱动。
- **结局**：`ending.json` 迷你关卡执行 3D71，结局 7 页全部原生绘制（中文）；之后的制作人员名单仍是原图。
- **章节标题卡**：三处都截到放大旋转进场：`act.json` 迷你关卡、第一话通关档经「前往下一关」进入的第二话、新游戏的第一话。`act.json` 那次按 VI 定点截图，拍到了翻面和最后的定格：「第2话」「「战斗吧！热血的斗士们」」，是原生中文（迷你关卡的话数计数使「第 N 话」多 1）。
- 退出统计（第二话那次）：2951 次绘制被改写，0 次保留原样，24 个素材全部解码成功。
- **制作人员名单与开机画面**（补充）：中文 `ending.json` 一路截到 2D 美术页，英文截到 SD 原画页（20 页中的 17 页），逐页原生文字，放大进场照旧；开机的 BANPRESTO 标志是高清整帧，版权页原生文字，「葦」等日文字形正常。
- **GAME OVER**（补充）：英文 `game-over.json`，定格后高清、切到原版后是原图（原图字底有零件接缝形成的细线），再切回高清。

## 命令

```sh
.venv/bin/python -m tools.hd_ai.title_hd prepare --output assets/hd-ai/title/v1
.venv/bin/python -m tools.hd_ai.title_hd run --output assets/hd-ai/title/v1 --env-file /path/to/.env
.venv/bin/python -m tools.hd_ai.title_hd compose --output assets/hd-ai/title/v1
.venv/bin/python -m tools.hd_ai.title_hd build --output assets/hd-ai/title/v1 --target assets/hd-ai/title/whole-v1
.venv/bin/python tools/content/text_images.py header --write   # 卡片 → 话名对照
.venv/bin/python tools/content/text_images.py render           # 结局页原图，供转写核对
.venv/bin/python -m tools.hd_ai.flat_scene_hd build --base assets/hd-ai/title/whole-v1 --target assets/hd-ai/title/whole-v2 --bind
```

改了 `generate_cpu.py` 的钩子后要先重跑它，再构建宿主。

## 遗留

- 标题集中线、演示战斗的作品名与机体名仍是原图。
- 制作人员名单的英文人名是按汉字推测的读法，原作没有注音；拿不准的列在 `content/dialogue/en/credits.txt` 开头，待核对。
- 标题卡旋转时的残影仍是原机分辨率（RT64 复制帧缓冲的方式）。
- 结局只在迷你关卡里验过；从通关存档走完整结局没有跑。
- 这条路径只在 Metal 下可用，与头像、5600 模型相同。
