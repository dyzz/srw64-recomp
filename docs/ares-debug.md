## ares configuration

1. Open **Settings > Debug**.
2. Leave port at `9123`.
3. Enable **GDB-Server > Enabled**.
4. Leave **Use IPv4** disabled. The server then listens only on IPv6 loopback
   at `[::1]:9123`.
5. Quit and reopen ares after enabling the server, then load the ROM exactly
   once. During the initial configuration session, repeated enable/load actions
   accumulated several v148 listeners on the same port; a restart reduced this
   to one stable listener.
6. Load **Nintendo > Nintendo 64** and select `rom.z64`.
7. If ares requests a Game Boy/Color cartridge for the configured Transfer
   Pak, cancel that secondary dialog. The N64 ROM remains loaded.

`Settings > Boot Options > Await GDB Client` is optional. The probe can attach
to an already-running ROM and halt it with the RSP Ctrl-C byte.

## Reproducible smoke test

With the ROM running in ares:

```sh
python3 /Users/nate/srw64/tools/ares_rsp_probe.py
```

The probe uses only the Python standard library. It verifies:

- RSP handshake and ares capability response;
- Ctrl-C halt and resume;
- all 71 64-bit N64 register values, including PC and SP;
- 64-byte reads through cached `0x80000000` and uncached `0xa0000000` aliases;
- stepping stop packets and PC sampling (the PC may repeat in a tight loop);
- a software breakpoint inserted, hit at the exact address, and removed;
- a real RDRAM read-watchpoint trigger and removal;
- final resume before disconnect.

Use `--skip-watchpoint` for a lighter probe.

## Observed v148 behavior

- The ROM booted to the `PRESS START BUTTON` title screen at 60 VPS.
- The server reported `PacketSize=4096`, software breakpoints, XML registers,
  and `qXfer:features:read` support.
- A register read returned 71 registers and a live PC in the `0x80000000`
  virtual region.
- Cached and uncached RDRAM reads returned identical bytes.
- Breakpoints hit at the requested address.
- A broad RDRAM read-watchpoint produced a real report such as
  `T05rwatch:800cd9a0;`.

Watchpoint stops are asynchronous. Under the N64 recompiler, several memory
accesses can be reported before the emulation thread fully halts. A client must
filter queued `S...`/`T...` stop packets instead of assuming every request has
exactly one immediately corresponding reply. `ares_rsp_probe.py` implements
that filtering.

Stepping under v148's recompiler can move between recompiler boundaries and a
PC may occasionally repeat. Treat it as execution-control evidence, not yet as
proof of exact one-MIPS-instruction stepping.
