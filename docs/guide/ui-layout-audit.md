# 界面排版离线审计

日期：2026-09-29。不启动游戏、不读 ROM 运行，也能检查共用界面（`src/native/ui/frontend.cpp` 画的场间画面、战前确认、标题菜单、设置窗口、联动页）在各语言、各窗口尺寸下有没有文字超出框、框线伸出边框。

```bash
.venv/bin/python tools/recomp/ui_audit/run_audit.py                 # 四种尺寸 × 三种语言，约 3 分钟
.venv/bin/python tools/recomp/ui_audit/run_audit.py --sizes deck --only 'zh-Hans$'
```

前提：已经有一次图形宿主构建（`build/recomp/gfx-build`，要用它的编译参数和 RmlUi、RT64、plume 静态库）和 `build/fonts` 里的字体，本地有 `rom.z64`（只读文字表）。运行时会开一个小窗口画页面，不碰存档，不会启动宿主，所以和别的会话的宿主不冲突。

## 做法

- [`layout_audit.cpp`](../../tools/recomp/ui_audit/layout_audit.cpp) 链接真实的 `frontend.cpp`、语言目录和 RmlUi 渲染器；游戏一侧的页面适配器（`battle_page::state()` 等）、设置和手柄状态换成替身，直接返回夹具里的页面状态。每个夹具排版几帧后截图，再遍历元素：
  - `text-past-box`／`text-past-item`：不换行的文字超出所在块或所在的行内块、弹性项。
  - `run-wider-than-block`：会换行的文字里，两个空格之间的一段比块还宽。RmlUi 只在空格处断行，中日文长句就是这种溢出（见 [RmlUi 中日文不断行](../native/settings-window.md)）。
  - `box-past-parent`：带边框的盒子伸出父元素的边框，例如分隔线比外框长。
  - `text-clipped`／`text-cut-below`：一行字超出裁剪它的面板右缘，或一半以上落到面板下缘以外（这一行等于丢了）。
  - `text-overlap`：同一面板里两个绝对定位的格子互相压住。原版 320×240 页面的格子宽度随文字，自己不会溢出，只会撞上邻格。横向压缩（`transform`）过的行、高清原版战前页按原版数字池逐格摆的数字不参与比较；盖在页面上、带底色的绝对定位框（战斗鉴赏的选择框 `#vw-pop`）里的字只和框里的字比较。
  - `nowrap` 文字按排版时的样子量：连续空格算一个（按键提示「选择   ·   …」原样量会多出 36 dp）。只在纵向滚动的列表（`overflow-y:auto`）也算裁剪面板，滚出一半的行不算压住列表外的字。
  - 小于 1.2 dp 的差值当作取整误差，不报；重叠 3 dp 以内是字形外沿相碰，也不报。
- [`run_audit.py`](../../tools/recomp/ui_audit/run_audit.py) 用主机构建里 `frontend.cpp` 那条编译命令的参数编译，源文件或头文件更新过才重编。夹具来自 [`states.json`](../../tools/recomp/ui_audit/states.json)：9-23 各场间页检查、9-24 标题菜单检查、9-28 战前确认检查录下的页面状态（图片路径已去掉，不影响文字排版）。每个字符串经 ROM 文字表对回记录号，再换成中、英、日三种文字；改造画面和曲目表没有录下的状态，照 `upgrade_page.cpp`、`title_page.cpp` 的字段拼出来。另加最坏情况：按实际字体量出来最宽的 7 个机体名、驾驶员名、武器列表名、关卡名，4 位和 5 位伤害、99999 HP。
- 战斗鉴赏：夹具带 `clicks`（按 id 点控件，和调试接口的 `srw64_click` 同一条路），从设置「一般」页点 `viewer-open` 打开整页，再分别点开机体、机师、武器、反击武器、双方结果、场景、BGM 各个框。图鉴数据（`library::contents()`）由 `run_audit.py` 按 `library.cpp` 的字段拼：机体 0（`battle_viewer_pilots.inc` 里可乘人数最多，13 人）对机体 28，名字、型号、作品名、技能、武器名都取最宽的；曲目取 ROM 记录 232–280。场景缩略图、头像不画（替身返回空）。
- 尺寸：`deck` 1280×800 点、界面大小「特大」（Steam Deck 默认，也是定字号的基准）；`deck-standard` 同窗口「标准」；`wide` 1920×1080；`smallest` 960×720。截图和 `audit.json` 在 `build/recomp/ui-audit/<尺寸>/`。
- 有问题时退出码为 1。
- 缩字报告：`fit` 类把放不下的文字缩小时会在元素上记下原字号（`data-fit-from`），审计把每个缩过的元素连同原字号、现字号、比例和文字写进 `audit.json` 的 `shrunk`，`run_audit.py` 按比例从小到大列出低于 `--shrunk`（默认 0.85）的那些。缩字不算失败——`fit` 就是用来缩的——但缩得最狠的几条说明哪里的字号定大了、哪个栏定窄了，改字号前先看它。`--shrunk 1` 列出全部，`--shrunk 0` 不列。

## 原版画面文字覆盖层

战术地图的机体能力、机师能力、武器一览、指令菜单等是原版画面，文字由 [`ui_text.cpp`](../../src/host/ui_text.cpp) 覆盖（[原版界面文字覆盖层](../native/native-ui-text.md)）。它的排宽规则是确定的，所以 [`overlay_fit.py`](../../tools/recomp/ui_audit/overlay_fit.py) 可以对全部数据文本（记录 0–5643）离线判断：

```bash
.venv/bin/python tools/recomp/ui_audit/overlay_fit.py                # 中英日；中文有「一定放不下」时退出码 1
```

- 原宽度按 ROM 字形格算：码 0 与 0x13B 以下窄 8，其余宽 14。译文可用原宽度，后面没有东西时最多用到 1.35 倍 + 4；先压窄（中日 70%、英 80%），再最多缩 1.5 号。
- `overflows`：后面空着也放不下；`depends`：只有后面不紧跟别的东西时才放得下。
- 含两个以上连续空格（给数字留位）的行，逐段放得下，或把数字移进整句后放得下，都算放得下，与 `ui_text` 的做法一致。
- 日文是对照组：原样显示的 ROM 文字按规则必然放得下，结果为 0 条。
- 只知道每条记录自己的宽度，不知道同一行后面紧跟什么；`depends` 的条目要看具体画面。

## 覆盖不到的

- 对白框与底栏（`dialogue_scene.cpp`）、HUD 徽章不走 RmlUi，这里查不到；它们用实机检查（`check_dialogue.py`、`check_ui_text.py`）。原版画面覆盖层只能按记录判断，见上一节。
- 姓名页走自己的探针（`srw64-ui-probe`）。
- 只查水平方向的溢出；行内框比行高高一点（16 单位的列表行）很常见而且看不出来，不报。
- 夹具是录下的状态加最坏情况，不是全部游戏状态；新页面或新字段要把状态加进 `states.json` 或在 `run_audit.py` 里拼出来。
