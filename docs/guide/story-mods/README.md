# 剧情 MOD：给原版关卡加事件

给 MOD 作者看，也可以把这个文件交给你的 AI 助手，让它照着写。设计与原版机制在 [MOD 包](../../design/mod-packages.md) §7，包的通用规则在同一文档 §2。官网版的说明是[剧情 MOD](../../../web/src/content/docs/zh/mod-story.md)（三语）。

**现状（2026-11-03，已合并进 main，随 0.5.3 发布，`game` 写 `">=0.5.3"`）**：能在原版任意一关加事件——什么时候触发、要满足什么、做什么、说哪些新台词。不占原版的事件位，原版事件一个不动。示例包 [`config/recomp/mods/master-asia`](../../../config/recomp/mods/master-asia/)（独立军线「死斗！大屿山大决战（下）」与 OZ 线「绝望与悲伤之拳（下）」说服东方不败，过关后加入）两条线都已在 Mac 实机走通。同一剧情放到另一关时要先看那关的原版事件：交谈变量、东方不败被击破后原版接着做什么、结束事件按哪些变量播哪些段，示例的 `persuade-oz` 就是照场景 137 改的。

## 1. 包的结构

```text
<包 id>/
  mod.json
  story/
    <任意名>.json     剧情脚本（schema srw64.story.v1），可以有几份
  data/
    pilots.json       需要时顺便改数值（见数值 MOD）
```

`tools/mods/pack.py <源目录> -o <输出目录>` 打包时把 `story/` 里的剧情脚本编译成游戏读的格式（也可以单独 `python tools/mods/story.py compile story/x.json -o out.json` 看编译结果和每个事件的指令清单）。写错了编译就会报哪个事件、哪一项。

## 2. 写法

```json
{
  "schema": "srw64.story.v1",
  "events": [
    {
      "id": "persuade",
      "scene": 129,
      "when": { "persuade": { "by": 4, "target": 18 } },
      "if": { "vars": { "131": 0 }, "kills": { "4": 50 } },
      "do": [
        { "say": 4, "text": { "ja": "「師匠！」", "zh-Hans": "“师父！”", "en": "“Master!”" } },
        { "say": 18, "mode": 2, "text": { "ja": "「……」", "zh-Hans": "“……”", "en": "“...”" } },
        { "leave": 18 },
        { "set": { "131": 3 } }
      ]
    },
    {
      "id": "joins",
      "scene": 129,
      "when": { "after": "end" },
      "if": { "fired": ["persuade"] },
      "do": [ { "join": { "pilot": 18, "unit": 27 } } ]
    }
  ]
}
```

- **`scene`**：场景号（0–255），即这关在 ROM 里的编号。全部关卡的场景号和三语标题见同一文件夹的 [`scenes.csv`](scenes.csv)（`tools/content/export_story_tables.py` 由 `content/stages/scene-*.json` 生成）。
- **`id`**：包里唯一；`if.fired` 用它引用别的事件。
- **默认每关只触发一次**，游戏自己记、跟着中断存档走，**不用像原版那样自己写变量防重放**。要跨关记事用标记（§2.2.1）。要能反复触发写 `"repeat": true`（开场／配置／结束之后的不行）。
- `note`：随便写说明，游戏不读。

### 2.1 `when`：什么时候

| 写法 | 意思 |
| --- | --- |
| `{"turn": {"turn": 3, "side": "player"}}` | 第 3 回合起、该阵营的回合开始（`player`／`enemy`／`third`） |
| `{"defeated": 18}` | 某人物的单位被击破（离场不算） |
| `{"hp_below": {"who": 18, "percent": 30}}` | 某人物 HP 降到 30% 以下 |
| `{"battle": {"between": [4, 18], "moment": "after"}}` | 两人交战后（`before` 是交战前；0 表示任何人） |
| `{"enemies_gone": true}` | 敌方全灭；可写 `{"by_turn": 5}` 限第 5 回合内 |
| `{"remaining": {"side": "enemy", "at_most": 3}}` | 敌方（或 `third` 第三方）只剩 3 台以下 |
| `{"persuade": {"by": 4, "target": 18}}` | 4 号站在 18 号旁边时，菜单出现「说服」，选了就触发 |
| `{"after": "opening"}`／`"setup"`／`"end"` | 接在这关原版的开场／初期配置／结束事件之后 |

原版事件优先：同一时刻原版也有事件要触发时先跑原版的，下一次轮询再看你的。

### 2.2 `if`：还要满足什么

- `"vars": {"131": 0}`：剧情变量（0–199，值 0–3）。原版用它们记剧情分支，例如场景 129 的 131 是「多蒙在战斗中和东方不败说过话」（说过是 0）。
- `"kills": {"4": 50}`：我方这个人物的击坠数至少这么多；`"kills_below": {"4": 50}`：不到这么多。人物不在我方名册里时两者都不成立。

**成功／失败两套台词**：同一个时机写两个事件，条件互斥，游戏选符合的那个。示例的说服：

```json
{ "id": "persuade", "when": { "persuade": { "by": 4, "target": 18 } },
  "if": { "vars": { "131": 0 }, "kills": { "4": 50 } }, "do": [ "……成功的台词与后续……" ] },
{ "id": "refused",  "when": { "persuade": { "by": 4, "target": 18 } },
  "if": { "vars": { "131": 0 }, "kills_below": { "4": 50 } }, "repeat": true, "do": [ "……被拒的台词……" ] }
```

交谈过之后「说服」一直都在；击坠数不够时选它播被拒的台词、多蒙这回合的行动用掉，东方不败留在场上，之后可以再试（`repeat`）；够了再说服就是成功的那个。
- `"fired": ["persuade"]`：本包的这些事件本关已经触发过。
- `"not_fired": [...]`：还没触发过。
- `"roster": {"pilots": [18], "units": [27]}`：这些人物、机体在我方名册里（不管出没出击）；`"not_roster"`：都不在。
- `"flags": ["persuaded"]`：本包的这些**标记**已经设过；`"not_flags"`：都没设过。

### 2.2.1 跨关：标记

`fired` 只管本关，下一关就清空。要让后面的关知道前面发生过什么，在事件上写 `"set_flags": ["标记名"]`（小写字母、数字、`_`、`-`，最多 32 个字），事件**跑完**时设上。标记只属于你的包，和原版剧情变量互不相干，跟着中断存档和场间存档走，只有开新游戏才清空。

示例在下一关开场后让东方不败说句话，只在他真的跟来了的时候：

```json
{ "id": "persuade", "scene": 129, "set_flags": ["persuaded"],
  "when": { "persuade": { "by": 4, "target": 18 } }, "...": "..." },
{ "id": "comes-along", "scene": 81, "when": { "after": "opening" },
  "if": { "roster": { "pilots": [18] }, "flags": ["persuaded"] },
  "do": [ { "say": 18, "text": { "ja": "「ドモン、遅れを取るでないぞ！」", "zh-Hans": "“多蒙，别落在后面！”" } } ] }
```

同时看名册是因为他之后可能又被原版剧情或别的事件（`remove`）从名册删掉；只看标记的话人不在也会说话。

### 2.3 `do`：做什么

| 动作 | 意思 |
| --- | --- |
| `{"say": 人物号, "text": {...}, "mode": 0–5}` | 一句台词。`text` 必须有 `ja`，其余语言没写的用 `ja`（繁体没写用简体）。一句最多 200 字，阅读器自己分页，不要写 `<STOP>`。引号要自己写，和原版台词一样：日文、繁体「」，简体、英文 “”。`mode` 是原版对白的显示方式（3D3E–3D43），地图上一般 0（我方）、2（敌方）；世界地图上 0／1 上下交替 |
| `{"join": {"pilot": 18, "unit": 27}}` | 人物和机体加入我方。等级照原版规则取这关的基准等级（我方前 15 人平均等算出）；`"level": {"offset": 3}` 在基准上加减，`"level": {"like": 4}` 和 4 号人物同级（加入那一刻算）。SP、能力、技能、精神按等级由原版算好，基础值用 `data/pilots.json` 改 |
| `{"remove": {"pilot": 18, "unit": 27}}` | 从名册删掉（单位要先离场） |
| `{"leave": 18}` | 人物的单位离场（不算击破） |
| `{"leave_group": 11}`／`{"deploy": 11}` | 原版这关的出击组离场／登场 |
| `{"set": {"131": 3}}` | 设剧情变量 |
| `{"if": {"var": 128, "is": 2}, "then": [...], "else": [...]}` | 按变量分支 |
| `{"focus": 18}` | 镜头切到人物 |
| `{"bgm": 11}`、`{"sound": 124}`、`{"fade": "out"}`、`{"wait": 30}` | 音乐、音效、淡出／淡入、等待（帧） |
| `{"close": "window"}` | 关掉对白窗口 |
| `{"op": "3D35", "args": [2335, 1]}` | 原版指令照写（指令表在原版数据目录 `script_opcodes`），可以直接引用原版台词号，例如 `{"op": "3D40", "args": [43215]}` |

人物号、机体号查 [数值 MOD 的表](../data-mods/)（`pilots.csv`、`units.csv`）。

## 3. 要注意的

- **原版事件只认原版变量**。想让原版的某段事件不播或换一段，就得改它判断的变量。示例里说服之后写 `131 = 3`，原版结束事件只在 131 为 1 或 2 时播东方不败的死别。
- **单位离场（`leave`）不会触发原版的「击破」事件**。原版击破后要做的事（示例里是王登场、打开过关条件），要在你的事件里自己做一遍。
- **加入的人物的数值**：敌方人物的 SP、精神常常是空的，用 `data/pilots.json` 补（示例补了 SP）。
- **标记存在游戏存档旁边**（存档目录的 `story-state/`），不在存档本身里。把存档拿到别的模拟器、或者删了这个目录，读回来就没有标记，跨关的事件不会触发；本关的说服之类不受影响。
- 自制追加剧本（`campaign/`）里不跑剧情 MOD。

## 4. 自己验证

开发环境里 `tools/recomp/debug/check_story_mod.py --route ia|oz` 是示例包的实机检查：装包、直接进入场景 129／137 的验证关卡（`config/recomp/mini-stages/story-master.json`、`story-master-oz.json`）、说服、过关、看名册。写自己的包时可以照它改一个。运行时宿主把触发、开始、结束记在运行目录的 `story-mod-events.jsonl`，读不了的包在日志里报 `SRW64_STORY_MOD_PROBLEM`。
