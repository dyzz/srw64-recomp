# 剧情 MOD：给原版关卡加事件

给 MOD 作者看，也可以把这个文件交给你的 AI 助手，让它照着写。设计与原版机制在 [MOD 包](../../design/mod-packages.md) §7，包的通用规则在同一文档 §2。官网版的说明是[剧情 MOD](../../../web/src/content/docs/zh/mod-story.md)（三语）。

**现状（2026-11-03，已合并进 main，随 0.5.3 发布，`game` 写 `">=0.5.3"`）**：能在原版任意一关加事件——什么时候触发、要满足什么、做什么、说哪些新台词。不占原版的事件位，原版事件一个不动。示例包 [`config/recomp/mods/master-asia`](../../../config/recomp/mods/master-asia/)（独立军线「死斗！大屿山大决战（下）」与 OZ 线「绝望与悲伤之拳（下）」说服东方不败，过关后加入）两条线都已在 Mac 实机走通。同一剧情放到另一关时要先看那关的原版事件：交谈变量、东方不败被击破后原版接着做什么、结束事件按哪些变量播哪些段，示例的 `persuade-oz` 就是照场景 137 改的。

## 1. 包的结构

```text
<包 id>/
  mod.json
  story/
    <任意名>.json     剧情脚本（schema srw64.story.v1），可以有几份
  data/
    pilots.json       需要时顺便改数值（见数值 MOD）
```

`tools/mods/pack.py <源目录> -o <输出目录>` 打包时把 `story/` 里的剧情脚本编译成游戏读的格式（编译器是官网关卡编辑器的那一份，要装 node 23 以上）（也可以单独 `python tools/mods/story.py compile story/x.json -o out.json` 看编译结果和每个事件的指令清单）。写错了编译就会报哪个事件、哪一项。

## 2. 写法

```json
{
  "schema": "srw64.story.v1",
  "events": [
    {
      "id": "persuade",
      "scene": 129,
      "when": { "persuade": { "by": 4, "target": 18 } },
      "if": { "vars": { "131": 0 }, "kills": { "4": 50 } },
      "do": [
        { "say": 4, "text": { "ja": "「師匠！」", "zh-Hans": "“师父！”", "en": "“Master!”" } },
        { "say": 18, "mode": 2, "text": { "ja": "「……」", "zh-Hans": "“……”", "en": "“...”" } },
        { "leave": 18 },
        { "set": { "131": 3 } }
      ]
    },
    {
      "id": "joins",
      "scene": 129,
      "when": { "after": "end" },
      "if": { "fired": ["persuade"] },
      "do": [ { "join": { "pilot": 18, "unit": 27 } } ]
    }
  ]
}
```

- **`scene`**：场景号（0–255），即这关在 ROM 里的编号。全部关卡的场景号和三语标题见同一文件夹的 [`scenes.csv`](scenes.csv)（`tools/content/export_story_tables.py` 由 `content/stages/scene-*.json` 生成）。
- **`id`**：包里唯一；`if.fired` 用它引用别的事件。
- **默认每关只触发一次**，游戏自己记、跟着中断存档走，**不用像原版那样自己写变量防重放**。要跨关记事用标记（§2.2.1）。要能反复触发写 `"repeat": true`（开场／配置／结束之后的不行）。
- `note`：随便写说明，游戏不读。

### 2.1 `when`：什么时候

| 写法 | 意思 |
| --- | --- |
| `{"turn": {"turn": 3, "side": "player"}}` | 第 3 回合起、该阵营的回合开始（`player`／`enemy`／`third`） |
| `{"defeated": 18}` | 某人物的单位被击破（离场不算） |
| `{"hp_below": {"who": 18, "percent": 30}}` | 某人物 HP 降到 30% 以下 |
| `{"battle": {"between": [4, 18], "moment": "after"}}` | 两人交战后（`before` 是交战前；0 表示任何人） |
| `{"enemies_gone": true}` | 敌方全灭；可写 `{"by_turn": 5}` 限第 5 回合内 |
| `{"remaining": {"side": "enemy", "at_most": 3}}` | 敌方（或 `third` 第三方）只剩 3 台以下 |
| `{"persuade": {"by": 4, "target": 18}}` | 4 号站在 18 号旁边时，菜单出现「说服」，选了就触发 |
| `{"defeated": {"who": 18, "by": 4}}` | 18 号被 4 号击破（交战的另一方是 4 号） |
| `{"downed": {"side": "player", "group": 2, "who": 18, "at_least": 2}}` | 本关到现在被击破的单位够数了（`side`、`group`、`who` 至少写一个，`at_least` 默认 1）。只算战斗里被打掉的，事件里离场不算 |
| `{"group_gone": 3}` | 原版这关的第 3 组都被击破了（至少打掉过一台、场上没有了） |
| `{"reach": {"who": 18, "area": [10, 4, 12, 6]}}` | 18 号进入这块区域（两个角的格，含边）；`"side": "player"` 换掉 `who` 表示该阵营任意一台。已经站在里面的也算 |
| `{"remaining": {"side": "player", "at_most": 2}}` | `side` 也可以是 `player`：我方只剩 2 台以下 |
| `{"after": "opening"}`／`"setup"`／`"end"` | 接在这关原版的开场／初期配置／结束事件之后 |

原版事件优先：同一时刻原版也有事件要触发时先跑原版的，下一次轮询再看你的。

### 2.2 `if`：还要满足什么

- `"vars": {"131": 0}`：剧情变量（0–199，值 0–3）。原版用它们记剧情分支，例如场景 129 的 131 是「多蒙在战斗中和东方不败说过话」（说过是 0）。
- `"kills": {"4": 50}`：我方这个人物的击坠数至少这么多；`"kills_below": {"4": 50}`：不到这么多。人物不在我方名册里时两者都不成立。

**成功／失败两套台词**：同一个时机写两个事件，条件互斥，游戏选符合的那个。示例的说服：

```json
{ "id": "persuade", "when": { "persuade": { "by": 4, "target": 18 } },
  "if": { "vars": { "131": 0 }, "kills": { "4": 50 }, "not_fired": ["refused"] }, "do": [ "……成功的台词与后续……" ] },
{ "id": "refused",  "when": { "persuade": { "by": 4, "target": 18 } },
  "if": { "vars": { "131": 0 }, "kills_below": { "4": 50 } }, "do": [ "……被拒的台词……" ] }
```

交谈过之后出现「说服」；击坠数不够时选它播被拒的台词、多蒙这回合的行动用掉，东方不败留在场上。被拒只有一次（没写 `repeat`），成功的那个又要求 `not_fired: refused`，所以被拒之后本关两个都不成立，菜单里不再有「说服」，剧情照原版走。想让玩家可以再试，就给被拒的写 `"repeat": true`、去掉成功那个的 `not_fired`。
- `"fired": ["persuade"]`：本包的这些事件本关已经触发过。
- `"not_fired": [...]`：还没触发过。
- `"roster": {"pilots": [18], "units": [27]}`：这些人物、机体在我方名册里（不管出没出击）；`"not_roster"`：都不在。
- `"flags": ["persuaded"]`：本包的这些**标记**已经设过；`"not_flags"`：都没设过。
- `"turn": {"from": 3, "to": 5}`：当前回合在这之间（可只写一个）。
- `"on_map": [18]`／`"defeated": [18]`／`"absent": [18]`：这些人在场上／本关被击破了（不在场上）／不在场上。
- `"hp": {"who": 18, "below": 50}`：在场且 HP 低于 50%。
- `"count": {"side": "enemy", "at_most": 3, "at_least": 1}`：该阵营场上的台数。
- `"in_area": {"who": 18, "area": [x0, y0, x1, y1]}`：此刻在区域里（`side` 同 `reach`）。
- `"downed": {…}`：同时机 `downed`。
- `"route": [0, 1]`：主角路线（0 布拉德、1 真奈美、2 阿克、3 赛莲）；`"choice": 2`：上一个选项选的是第 2 项；`"funds": {"at_least": 50000}`（或 `below`）：资金。
- `"any": [{…}, {…}]`：其中一个成立就行；`"all": [{…}, …]`：都成立；`"not": {…}`：不成立。里面写的仍是这些条件，可以嵌套。

### 2.2.1 跨关：标记

`fired` 只管本关，下一关就清空。要让后面的关知道前面发生过什么，在事件上写 `"set_flags": ["标记名"]`（小写字母、数字、`_`、`-`，最多 32 个字），事件**跑完**时设上。标记只属于你的包，和原版剧情变量互不相干，跟着中断存档和场间存档走，只有开新游戏才清空。

示例在下一关开场后让东方不败说句话，只在他真的跟来了的时候：

```json
{ "id": "persuade", "scene": 129, "set_flags": ["persuaded"],
  "when": { "persuade": { "by": 4, "target": 18 } }, "...": "..." },
{ "id": "comes-along", "scene": 81, "when": { "after": "opening" },
  "if": { "roster": { "pilots": [18] }, "flags": ["persuaded"] },
  "do": [ { "say": 18, "text": { "ja": "「ドモン、遅れを取るでないぞ！」", "zh-Hans": "“多蒙，别落在后面！”" } } ] }
```

同时看名册是因为他之后可能又被原版剧情或别的事件（`remove`）从名册删掉；只看标记的话人不在也会说话。

### 2.3 `do`：做什么

| 动作 | 意思 |
| --- | --- |
| `{"say": 人物号, "text": {...}, "mode": 0–5}` | 一句台词。说话人也可以是包里新人物的 `"@名字"`，名牌和头像是它自己的。`text` 必须有 `ja`，其余语言没写的用 `ja`（繁体没写用简体）。一句最多 200 字，阅读器自己分页，不要写 `<STOP>`。引号要自己写，和原版台词一样：日文、繁体「」，简体、英文 “”。`mode` 是原版对白的显示方式（3D3E–3D43），地图上一般 0（我方）、2（敌方）；世界地图上 0／1 上下交替 |
| `{"say": 36, "silhouette": true, "text": {...}}` | 以原版的剪影（名字「???」、黑色头像）说话；只有原版有剪影版的 33 个人物能用（万丈、大作、阿姆罗、钱博迪等，编译器会列出） |
| `{"join": {"pilot": 18, "unit": 27}}` | 人物和机体加入我方。等级照原版规则取这关的基准等级（我方前 15 人平均等算出）；`"level": {"offset": 3}` 在基准上加减，`"level": {"like": 4}` 和 4 号人物同级（加入那一刻算）。SP、能力、技能、精神按等级由原版算好，基础值用 `data/pilots.json` 改 |
| `{"remove": {"pilot": 18, "unit": 27}}` | 从名册删掉（单位要先离场） |
| `{"replace": {"pilot": 171, "unit": 224, "with": "@final"}}` | 换机：名册里的旧机体换成新机体，人物坐上去，改造段数按原版的继承表搬过去（原版 224 换 223 就是这条 `3D5A`）。新机体用 `@名字` 写（本包 `data/new_units.json` 里的，别的包写 `包id@名字`），号码由游戏在载入时填上；要继承改造，新机体包里写 `inherits_from`（数值 MOD 说明「新机体与新武器」）。`join`、`remove`、`remove_unit`、`crew` 的机体，`unlock` 的武器，`if.roster.units` 也都可以写 `@名字`；`join`、`remove`、`replace` 的 `pilot` 可以写包里新人物的 `@名字` |
| `{"remove_unit": {"pilot": 166, "unit": 228}}` | 只删机体，人物留在名册里（`3D5A …,3000`）。按人物找机体：人物要坐在这台上 |
| `{"unlock": 881}` | 解锁一件剧情解锁的武器（`3D6F`）。换机不会把原武器的解锁带过去，要对新武器再解锁 |
| `{"build": "@final"}` | 事件**开始**时由宿主给我方建一台这样的合体机（`data/new_units.json` 写了 `combine` 的新机体）：乘员是各部件的主驾驶，改造段数从 `inherits_from` 抄，不出击。同一事件里后面的 `unlock` 能解禁它的武器。已经有一台就不再建 |
| `{"crew": {"unit": "@final", "pilots": [171, 168, 170, 169, 166]}}` | 事件跑完时由宿主把这些人物挂成这台机体的乘员（最多 5 人，第一个是主驾驶，要已经坐在上面）；他们原来坐的机体会把他们去掉。原版的乘员表只在新建机体时用、也没有空位，所以由宿主写。包里的新机体更适合在 `data/new_units.json` 写 `crew`：换机时就挂上，不用这一步 |
| `{"leave": 18}` | 人物的单位离场（不算击破） |
| `{"leave_group": 11}`／`{"deploy": 11}` | 原版这关的出击组离场／登场 |
| `{"deploy": "rival"}`／`{"leave_group": "rival"}` | 包自己的增援组（`deployments`，见下）登场／离场 |
| `{"set": {"131": 3}}` | 设剧情变量 |
| `{"if": {"var": 128, "is": 2}, "then": [...], "else": [...]}` | 按变量分支 |
| `{"if": {…条件…}, "then": [...], "else": [...]}` | 按 2.2 里的任何条件分支（写法同事件的 `if`）。由游戏在执行到这一步之前判断：同一事件里紧挨着的前一步（如刚 `join`）可能还没算进去 |
| `{"choose": {"text": {"ja": ["はい", "いいえ"], "zh-Hans": ["是", "否"]}, "options": [[...], [...]]}}` | 让玩家选（2–3 项）。`text` 也可以写原版选项文本号；自己写时每项不超过 24 字，要有 `ja`。问题句用前一条 `say` |
| `{"focus": 18}` | 镜头切到人物 |
| `{"bgm": 11}`、`{"sound": 124}`、`{"fade": "out"}`、`{"wait": 30}` | 音乐、音效、淡出／淡入、等待（帧） |
| `{"close": "window"}` | 关掉对白窗口 |
| `{"op": "3D35", "args": [2335, 1]}` | 原版指令照写（指令表在原版数据目录 `script_opcodes`），可以直接引用原版台词号，例如 `{"op": "3D40", "args": [43215]}` |

人物号、机体号查 [数值 MOD 的表](../data-mods/)（`pilots.csv`、`units.csv`）。

### 包自己的增援（`deployments`）

剧情文件顶层可以写 `deployments`，定义只属于这个包的出击组，事件里用 `{"deploy": "组名"}` 让它登场、`{"leave_group": "组名"}` 让它离场：

```json
"deployments": [
  { "id": "rival", "scene": 78, "units": [
    { "x": 10, "y": 9, "pilot": "@rival", "unit": "@rz", "level": 1 },
    { "x": 12, "y": 10, "pilot": 289, "unit": 21, "side": "enemy" } ] }
]
```

```json
{ "id": "rival-comes", "scene": 78, "when": { "turn": { "turn": 2, "side": "player" } },
  "do": [ { "deploy": "rival" } ] }
```

- `id` 只用小写字母、数字和 `- _ .`；`scene` 是关卡号，用它的事件必须在同一关。一组 1–30 台。
- 每台写 `x`、`y`（0–63）、`pilot`（人物号或 `@新人物`）、`unit`（机体号或 `@新机体`）；可选 `side`（`enemy` 敌方，默认；`third` 第三方；`third_hostile` 也攻击我方的第三方；`player` 我方）、`level`（在这关基准等级上加 0–20）、`upgrade`（改造档 0–5，原版敌方常用 0–3）。
- 人物号 287 以上（以及包里的新人物）按「通用驾驶员」生成；小于 287 的人物如果已在我方名册上，会直接用名册里的那个人。
- 场景登记时，游戏把这些记录接在这一关原版出击记录的后面，组号从这一关没用到的 0–31 里挑（离场按地图上 5 位组号认，所以只能在 0–31）。一关同时装的几个包都加增援时依次分配；没有空号或放不下（一关的出击块 8 KB）时这一组不加，引用它的事件不会触发。原版有 13 关的出击块结尾不规整，这些关也不加。
- 增援用到的新机体、新人物和新武器在中断存档里会记下来，号码变了读档时照样改号（敌方、第三方都算）。

### 战斗台词（`battle_lines`）

和 `events` 并列，写战斗演出里的新台词：

```json
"battle_lines": [
  { "id": "see", "scene": 129, "who": 36, "against": 287, "when": ["attack", "evade"],
    "text": { "ja": "「見える！」", "zh-Hans": "“看见了！”" }, "once": true }
]
```

`when` 是出手 `attack`、被击坠 `defeated`、重伤 `heavy`、中伤 `damaged`、轻伤 `light`、回避 `evade`、攻击无效 `no_effect`、弹药／EN 不足 `no_ammo`、射程外 `out_of_range`；`against` 不写就是对谁都说；还可以写 `if`（同事件的条件）。到了这些时候，这句换掉原版本来要说的那句。只有原版本来就有战斗台词的人物会说；原版有合体技对话之类的专门台词时，可能仍是原版那句。

### 本关情报里的隐藏要素（`stage_info`）

剧情文件顶层可以写 `stage_info`，给关卡的「本关情报」页加几条隐藏要素，和原版的写在一起：

```json
"stage_info": [
  { "scene": 78,
    "title": { "ja": "ファイナルダンクーガ", "zh-Hans": "终极断空我", "en": "Final Dancouga" },
    "text":  { "ja": "クリア時にアランとブラックウイングがいれば入手", "zh-Hans": "通关时阿兰和黑翼在队即可获得", "en": "Clear with Alan and Black Wing on your side" },
    "done":  { "units": ["@final"] } }
]
```

- `title`、`text` 按语言写，必须有 `ja`，一条最多 200 字。
- `done` 可不写；写了就按名册判断完成：`units`（机体号或 `@名字`，机体池里有）、`pilots`（人物号，在名册里）都满足时标「已完成」，否则「未开始」。
- 一关有几张路线卡片时，每张都加。

### 周目继承（`id` 与 `inherit`）

给一条写上 `id`，它就和原版的隐藏要素一样进历代记录：任何一个周目里 `done` 成立过，这个包里的这一条就算「历代已完成」，本关情报页上带标记。再写 `inherit`，规则页难度调整「周目继承」开着时，下一周目会在指定的关之后补登记：

```json
{ "id": "final", "scene": 78,
  "title": { "ja": "ファイナルダンクーガ", "zh-Hans": "终极断空我" },
  "text":  { "ja": "クリア時にアランとブラックウイングがいれば入手", "zh-Hans": "通关时阿兰和黑翼在队即可获得" },
  "done":  { "units": ["@final"] },
  "inherit": { "after": [78], "do": [ { "build": "@final" } ] } }
```

- `id` 只用小写字母、数字和 `- _ .`，同一个包里不能重复。历代记录按「包 id＋这个 id」记，改了 id 就算另一条。
- `after`：刚打完这些关之一的那次场间补；`before`：下一关是这些关之一时补（给原入队在开场事件里的要素用）。两个至少写一个。
- `do` 只能用 `join`、`replace`、`unlock`、`crew`、`build`，写法和事件里一样，`join` 的 `level` 也能写 `{"like": 人物号}`。不能改剧情变量，也不能说话；补登记不改变量，后面看变量的剧情照「没入队」走，和原版要素一样。
- 补之前看 `done`：已经成立就不补，所以在那次场间存档再读档不会补两次。写 `inherit` 必须同时写 `id` 和 `done`。
- 执行顺序：先 `build`（合体机要用到的部件得已经在队），再按顺序执行 `join`／`replace`／`unlock`，最后 `crew`。
- 历代记录按包记：包删掉或停用后，这一条不补、不显示，但记录留着，以后装回来还算数。
- 补了会在场间顶上提示「周目继承：XX 加入」。本关情报栏标题的「历代达成 N/M」里，M 包括启用的包里写了 `inherit` 的条数。

### 台词写在纯文本文件里

对话多、要交给别人翻译时，台词可以不写在 JSON 里：`text`（以及 `stage_info` 的 `title`、`text`）写成 `"@名字"`，各语言的文字放在包里的 `story/<语言>/*.txt`：

```json
{ "say": "@kai", "text": "@kai-joins" }
```

```text
# story/ja/kai.txt
@kai-joins カイ
カイ、出撃する！

# story/zh-Hans/kai.txt
@kai-joins 凯
凯，出击！
```

- 写法和游戏附带的台词文件一样（[台词文本文件](../dialogue-text.md)）：`@名字 备注` 开始一条，下一行是这句台词；`#` 是注释，空行随便加；台词要以 `@`、`#`、`\` 开头时前面加 `\`。名字只能用小写字母、数字和 `- _ .`。
- 一条只写一行：阅读器自己分页、折行，不写 `---`。一句最多 200 字。
- `ja` 必须有这一条；别的语言缺的用 `ja`（繁体缺的用简体），和写在 JSON 里一样。同一语言里一个名字只能写一次（文件可以分好几个）。
- 语言目录是 `ja`、`zh-Hans`、`zh-Hant`、`en`、`ko`。打包（`tools/mods/pack.py`）时编进剧情文件，这些 `.txt` 不放进包里；玩家在游戏里改不到它们（这和游戏附带台词不同）。
- JSON 里直接写 `{"ja": …}` 的台词照旧可用，两种写法可以混用。

## 3. 要注意的

- **原版事件只认原版变量**。想让原版的某段事件不播或换一段，就得改它判断的变量。示例里说服之后写 `131 = 3`，原版结束事件只在 131 为 1 或 2 时播东方不败的死别。
- **单位离场（`leave`）不会触发原版的「击破」事件**。原版击破后要做的事（示例里是王登场、打开过关条件），要在你的事件里自己做一遍。
- **加入的人物的数值**：敌方人物的 SP、精神常常是空的，用 `data/pilots.json` 补（示例补了 SP）。
- **标记存在游戏存档旁边**（存档目录的 `story-state/`），不在存档本身里。把存档拿到别的模拟器、或者删了这个目录，读回来就没有标记，跨关的事件不会触发；本关的说服之类不受影响。
- 自制追加剧本（`campaign/`）里不跑剧情 MOD。

## 4. 自己验证

开发环境里 `tools/recomp/debug/check_story_mod.py --route ia|oz`（加 `--refuse` 看被拒与之后不能再说服）是示例包的实机检查：装包、直接进入场景 129／137 的验证关卡（`config/recomp/mini-stages/story-master.json`、`story-master-oz.json`）、说服、过关、看名册。写自己的包时可以照它改一个。运行时宿主把触发、开始、结束记在运行目录的 `story-mod-events.jsonl`，读不了的包在日志里报 `SRW64_STORY_MOD_PROBLEM`。
