# 原版图片提取与武器标记

更新：2026-09-11。

原始数据浏览器现在为人物、机体和地图显示原版图片。图片是从固定日版 ROM 解码得到的本地 PNG，与原始字节一起纳入输出清单。没有修改 ROM 或运行时渲染路径。

## 覆盖与入口

| 分类 | 关联范围 | 当前图片 |
| --- | --- | --- |
| 人物 | 361 个名称身份 | 96×96 或 97×97 头像；按各自调色板解码，身份可共用图片。 |
| 机体 | 363 个机体／形态 | 16×16 战术地图图标，统一用我方调色板 1010；不是战斗动画的大图。 |
| 地图 | 158 条地图资源记录 | 完整静态战场底图；保留图块翻转，不含机体、辅助叠加层、事件变化和运行时效果。 |
| 场景／脚本 | 144 个物理地图槽、142 个脚本槽 | 复用初始地图预览；不代表可玩关卡数量，也不预测脚本中后续换图。 |

列表显示缩略图，详情显示图片和来源资源链接，点击图片打开原始尺寸 PNG。“地图”已提升为主分类。815 份独立预览去重后写入 `images/portrait/`、`images/unit-icon/`、`images/map/`；地图另生成缩略图。

生成方式仍为：

```sh
.venv/bin/python -B tools/content/extract_original.py \
  --snapshot build/recomp/gfx-probes/female-map-audio-1/latest-gfx-rdram.bin
```

不需要历史观察记录时可以省略 `--snapshot`。图片提取不依赖快照。

## 人物与机体绑定依据

绑定和代码字节锁放在 `config/data/original-jp-v1.json` 的 `images`、`evidence` 中。

- 人物：resident `8009C768..8009C7DC` 从 ROM `0x84220 + actor_id × 4` 读两个大端 u16，分别为图像资源和调色板资源。不能简单将人物 ID 加常数作为图片 ID。例如人物 28 → `33/333`，162 → `166/466`，165 → `169/469`。361 个头像绑定独立于仅有 360 槽的数值／精神映射表。
- 机体：`load_000AB160:801C60A4..801C6180` 取运行时机体记录 `+2` 的机体 ID，查 VRAM `0x80218218`，对应 ROM `0x100D78` 的 u16 表。调色板参数为 `1010 + 阵营`。当前统一采用 1010，标注为我方配色。例如机体 0 → 688，36 → 718，216 → 898，362 → 1009。
- 头像资源类型为 15 或 6，8 字节头部后是 CI8 索引；机体图标类型为 14，后接 CI4 索引，高半字节在前。调色板类型为 3，第二个 u16 是调色板字节数，头部后是 RGBA5551 大端颜色。透明位保留；5 位色阶按项目现有图片解码约定映射到 8 位。

每个 `images[]` 项保留文件路径、尺寸、资源 ID、解压 SHA-256；人物与机体还保留绑定记录的 ROM 地址、原字节及全表 SHA-256。图像不是按文件相邻关系或名字相似度猜配。

## 地图布局格式

资源记录的前三个 u16 分别是布局、图集、调色板。`801C6EFC` 传入 mode 8，经 `80097C68` 选择绘制器 `800945D4`。

布局的 8 字节头部为 `(type=7, group_count, width, height)`。`width`、`height` 以 8 像素为单位；实际 16×16 图块网格为 `width/2 × height/2`。后接这张网格的四字节地形记录，本批保留其原字节，没有解释地形属性。

绘制组从 `8 + width × height` 开始，每组六字节：

```text
u16 tile      图集索引
u16 count     放置次数
u16 offset    放置列表相对布局资源起点的偏移
```

每项放置记录也是六字节：`u16 flags, u16 x, u16 y`。图集源坐标按原绘制器计算：

```text
sx = (tile & 0x000F) * 8 + ((tile & 0x0300) >> 1)
sy = ((tile & 0x00F0) >> 1) + ((tile & 0x0C00) >> 3)
```

从该位置取 16×16 像素，按放置记录绘制。`0x4000` 水平翻转，`0x8000` 垂直翻转；部分地图还含 `0x2000`，这一绘制路径未读取它，不赋予额外语义，完整 flags 留在预览元数据中。

全部 158 份布局共含 290,706 个放置项，均通过画布边界、图集边界、无重复位置、网格完整覆盖、放置列表连续性与资源尾边界检查。女性第一话的地图 20 使用 `6284/6228/6243`，输出 448×512、28×32 格底图；辅助资源 `6422/6429` 仍留在原记录，不纳入这张底图。

## 武器名称与属性

原来的整合页面在纯武器名下面重复显示整个菜单字符串，例如 `格アイアンネットP`。现在显示为：

| 武器名 | 属性 |
| --- | --- |
| アイアンネット | 格 · P |

`格` 为格斗，`射` 为射击，`P` 为可移动后使用，`B` 为光束，`MAP` 为地图武器。页面提供独立属性列、颜色、悬停说明和文字图例。原始名称、菜单文本及其 TextKey 保留在记录和来源详情中。

解析要求“前缀 + 原始名称 + 允许的属性后缀”与原菜单字符串完整相等；名称本身的 P、B 不会被截掉。少数纯名称已带 MAP，菜单在 MAP 前插入 B，这种情况只有两份字符串共同匹配时才将 MAP 从显示名称中拆出。当前 1,329 条武器记录全部匹配；未知格式会保留名称并显示“标记待解析”。

`weapon_traits.source` 明确为 `original-menu-text`。这些是原界面的属性标记展示，不是新增的 ROM 数值位解释，也不取代气力、弹药、形态、技能等完整可用性检查。
