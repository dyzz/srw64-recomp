# 战斗图像：机体战斗图、动画零件、特效与 cut-in

更新：2026-09-19。本文记录战斗与剧情演出用的 2D 图像：资源分布、绑定表、「精灵场景」格式和整理导出。武器动画怎样调用这些场景、能否加入自定义机体和武器，见[战斗动画与自定义机体](battle-animation.md)。全部为静态 ROM 解析，没有启动游戏。

## 一键导出

```sh
.venv/bin/python -B tools/content/export_graphics.py
```

约 15 秒，输出到忽略的 `assets/original-graphics/`（约 70 MB），重跑整体替换。`index.html` 是图库（需经本地 HTTP 打开，例如 `python3 -m http.server --directory assets/original-graphics`），缩略图为逐帧横排、点开为 APNG 动画；`manifest.json` 为每个文件记录类型、SHA-256、来源资源和绑定表索引。

| 目录／文件 | 内容 |
| --- | --- |
| `units/NNN-机体名/` | 363 台机体各一个文件夹：`battle.png` 战斗基本姿势、`battle-sheet.png` 该机战斗图集（带自身调色板）、`map-icon.png` 地图图标、`animations/` 该机图集上的全部动画零件、`unit.json`（数值；每件武器的数值、属性标记、战斗记录、动画记录与命中特效记录，actor 逐个指到导出的图片文件） |
| `cutins/NNNN-武器名/` | 战斗 cut-in：14 件武器（爆熱ゴッドフィンガー、シャイニングフィンガー、ファイナルゴッドマーズ、超電磁スピン、断空光牙剣、V-MAX 等）用到的特写大图，按武器分组，附所用图集 |
| `movies/NN-名称/` | 地图上的合体／变形动画 12 段（コン・バトラーV、ゴッドマーズ 合体，ゲッター 6 种变形，オーラロード 4 段），按播放顺序编号 |
| `battle-scenes/atlas-AAAA/` | 其余战斗场景：光束、爆炸、斩击等特效和盾，按图集分组，附整张图集 |
| `portraits/NNN-全名.png` | 361 个人物身份的头像（多个身份可共用同一张图） |
| `chapter-titles/`、`maps/` | 133 张章节标题卡；158 张静态战场底图 |
| `units.csv`、`weapons.csv` | 机体、武器数值总表（UTF-8 BOM，表格软件可直接打开） |
| `animations.json` | 全部武器动画、命中特效、防御反应记录的解析结果 |

原有的数据浏览器图片 `assets/original-data/images/` 仍按资源编号命名，供浏览器使用；本导出按机体、人物、武器名称重新组织同一批头像、地图图标和战场底图，并补上全部战斗图像。两者使用同一套绑定。

## 绑定表

(场景, 图集, 调色板) 三元组都是 6 字节 `u16 scene, u16 atlas, u16 palette`，表尾 2 字节补零。表字节的 SHA-256 固定在 `src/srw64_native/battle_graphics.py`。

| 表 | ROM | 条目 | 读取代码 | 索引 |
| --- | --- | ---: | --- | --- |
| 机体战斗基本姿势 | `0x84E40` | 365 槽（0–362 有效） | 常驻 `func_8009C864` | 机体 ID |
| 战斗场景总表 | `0x11E3D0` | 1,053 槽（1,051 有效） | 战斗 overlay `load_00121560` 的 `func_801C3170` | 武器动画 actor 的 registry 字段 |
| 地图动画 | `0x106F20–0x107200` | 12 段、95 项 | 战术地图 overlay `load_000AB160` 的播放器 `func_802176A8(id)` | 动画编号 0–11 |
| 章节标题 | `0x84B20` | 133 | 常驻 `func_8009C8EC`（战术地图 `func_801C72C8` 在开场调用） | 标题编号 |

- **机体表**按机体 ID 索引，逐台目视核对：0 ガンダムシュピーゲル、3 シャイニングガンダム、5 ドモン・カッシュ（生身，专用小图集 4930）、7 ノーベルガンダムB 等。调用者分布在战斗 `load_00121560`（`801C5328`、`801C5808`、`8021FB4C`）、战术地图 `load_000AB160` 与 `load_0008E580`、`load_0008F4B0`、`load_0010DA50`、`load_00217FD0`。330 张图集服务 363 台机体；形态差分常共用图集（如 11／12 ガンダムローズ）。
- **354–362**（イーグル号…シャトル号、ブラックジョーカー、シュバルツ）数值与武器相同（HP 4000、パンチ／キック／突進），全部借用 シャイニングガンダム 的战斗图，战斗单位表也只有 354 行——是占位记录，见[可行性](battle-animation.md#加入自定义机体与武器)。
- **战斗 cut-in** 就是战斗场景总表的 984–1038 项，由武器动画的普通 actor 引用；其中 9 项没有被任何武器记录直接引用。
- **地图动画**：播放器用 `80098158(slot, 0, 0xB, 0x8D, scene, atlas, palette, 1)` 逐段载入。ID 5–10 共享一段 30 项的数据，每 5 项一组。触发来源（代码确认）：脚本指令 `3D67`（ID 0–4）、`3D6A`（ゴッドマーズ 合体，ID 11）、ゲッター 系机体 171–176 首次变形（由 2 位脚本变量控制，只放一次；按住 START 可重看，按钮含义为推测）、コン・バトラーV（196）合体。ID 2 没有找到调用者。
- 常驻 `0x847D0` 另有一张 141 槽的同格式表，内容是 cut-in 与地图动画的汇总，但它的读取函数 `func_8009C7DC` 没有任何调用（也不在函数指针表里），部分条目与实际使用的两份拷贝不同；ROM `0x8AB58` 的 1,449 项表属于调试用的 ROBO VIEWER（`load_00089EA0`）。这两张表本导出都不使用。

## 精灵场景格式

场景资源把一张图集切成若干块（多为 32×32），拼成若干帧，再按步骤表播放。大端：

```text
u8  step_count, u8 vertex_mode
step_count × (u8 frame, u8 ticks)     frame = 0xFF：这几拍什么都不画
u8  0xFF, u8 loop_step                 结束标记；loop_step 为循环回到的步骤
u16 frame_offsets[n]                   n = (frame_offsets[0] − 表起点) / 2
frame：16 字节零件，直到 flags & 0x8000
    u16 flags   0x0010 = 水平翻转（其余位全 ROM 未出现）
    u16 s, t    图集内源坐标
    u8  w, h    零件尺寸
    s16 x, y    相对场景原点的屏幕坐标（y 向下）
    u32 vertex_offset
```

- **播放**（代码确认）：常驻 `func_80098880` 每个 overlay 帧对 300 个精灵槽各调用一次 `func_80098738`（槽记录 `0x800FFA70 + slot × 0xC4`）。它递减计数，到 0 时进入下一步；走完最后一步时，槽的播放标志 bit0 置位则停在最后一步（地图动画），否则跳回 `loop_step`（`80098838`）。所以一拍 = 一次精灵更新；它对应多少 VI 未核对，导出的 APNG 暂按每拍 33 ms 预览。
- **绘制**：矩形绘制器 `80096CD8`（模式 11，地图动画用）只读零件记录；顶点绘制器 `8009761C`（模式 14–16）读 `vertex_mode`：0 = 每零件 8 个顶点，前 4 个是按零件矩形的一组，后 4 个是 x 取反的镜像组（敌我朝向，绘制时 +0x40 选用）；1 = 每零件 4 个顶点；2 = 不画。两者都跳过 0xFF 步。
- 19,408 个模式 0 零件的顶点矩形与翻转位全部与零件记录一致，导出直接按零件记录绘制。模式 1 有 686 个零件的顶点不是简单矩形（缩放／旋转类演出），这些镜头导出为未变形的样子。
- 机体基本姿势都只有 1 帧；战斗场景 470 个、地图动画若干为多帧。
- 19 个场景有零件越出图集右／下边缘，越界处按透明处理（实机按纹理夹取／重复规则采样，差异只在边缘）。
- 部分调色板比图像能索引的多：CI4 特效常配 112 色（7 组×16），少数 CI8 配 592 色。导出用第 0 组；其余为调色板动画数据，选组方式未追踪。

## 验证

- `tests/test_battle_graphics.py`：步骤表／空白帧／循环、翻转、非法输入、超长调色板和动画记录的合成用例。有 ROM 时核对各表哈希与关键绑定，解析所有表引用的全部场景、解码全部图集并逐个比对模式 0 零件与顶点，确认 1,329＋159＋28 条动画记录都引用真实场景，cut-in 恰好由 14 件武器引用。
- `tests/test_original_images.py`：头像、地图图标、战场底图绑定（图像类型 7 加入可解码类型后不变）。
- 在浏览器中目视检查了全部 363 台机体基本姿势、cut-in、地图动画和部分武器零件；背景贴图组表 ROM `0x1161C0`（`(首资源, 数量)` 对，覆盖 6063–6214）留作 3D 背景的后续线索。
