# 战斗 cut-in 总表

2026-09-30 整理。战斗演出里的特写（cut-in）一共 55 个场景，全在战斗场景登记表（ROM `0x11E3D0`）的 984–1038 项。本文按招式列出每一项画的是什么、尺寸与帧数、哪件武器怎样引用。格式与解码见[战斗图像](battle-graphics.md)，渲染机制、遮框与 HD 路线见[战斗演出渲染机制](../design/battle-animation-rendering.md) §6.3／§7。

数据由 `battle_graphics.py` 的 `read_triplets`、`read_animation_bank`、`parse_scene` 直接从 ROM 读出；「内容」一列是看导出图（`assets/original-graphics/cutins/`）写的。演员字段的含义只有静态依据，标「推断」的没有实机核对。

## 1. 规模

| 项 | 数量 |
| --- | --- |
| 登记项 | 55（984–1038），其中 46 项被武器记录引用、9 项没有任何引用 |
| 图集 | 27 张（1337、1339–1364）：CI8 大图集 14 张（最大 512×512），CI4 背景图集 13 张 |
| 帧 | 308 帧，其中背景类 26 帧 |
| 不同零件切片 | 1736 个 |
| 用到的武器 | 14 个武器号，实际 10 招（24/29、874/881、1062/1075 是同一招的两份记录；18 与 1216 共用 ドモン 特写） |
| 涉及作品 | G ガンダム（7 个武器号）、ダンクーガ、レイズナー、ジャイアントロボ、ゴッドマーズ、コン・バトラーV |

`hit` 与 `reaction` 两个动画库都不引用 cut-in；所有 cut-in 都在攻击方的武器记录里。场景全部是 vertex_mode 1（没有镜像顶点组，敌我两边画出来一样），只有 1025/1026 是 mode 2。

## 2. 一段 cut-in 的构成

每段都是 2–3 个演员叠起来，按演员表顺序建、按节点优先级画：

1. **背景**：CI4 图集上的 128×96 纹理（速度线、云、光带），1–3 帧。常带 h4 高位标志 `0x8000` 或 `0x4000`。
2. **主图**：CI8 大图集上的人物／机体特写，画布多为 128×96，动效全在帧里（没有滑入代码）。
3. **叠加层**：纹章、放射线、剪影、闪电等，h5 多为 140–190（推断是半透明度，255 为不透明）。

演员字段：h4 低字节是触发相位（`0x44`/`0x50`–`0x57`），`0xFFFF` 和个位数是同段内的先后序号；行为 240 是标准 cut-in，350 是 シャイニング／ゴッド 系开场特写，351 是 シャッフル同盟拳 的横移长图，352 带 x/y 偏移的小件（纹章、标志），373 是 h6 = 2 的受控演员。显示时缩放 1.29、屏幕居中、y = 47，所以 128×96 的画布约占 165×124 屏幕像素；z == 1 的演员会挂上遮框 `800C6D00`（留 140×120 的窗）。

## 4. 没有引用的 9 项

1003、1006、1016、1025、1026、1029、1030、1032、1033。都在被引用场景的同一张图集上，是同一招的备用或弃用镜头：シャッフル同盟拳 少了「全身出掌」「纹章聚拢」「爆闪」三个镜头（1029–1033），石破ラブラブ天驚拳 留了两片 mode 2 残片。行为例程也可以用 `801C5700` 换场景，所以「武器记录不引用」不等于「运行时一定不出现」——要确认得在 `801C3170` 上按登记号加只读探针。
