# 原生试玩

双击仓库根目录的 `Play SRW64.command`，或在仓库目录运行：

```sh
.venv/bin/python tools/recomp/play_native.py
```

程序会检查 ROM 和生成代码身份并编译当前宿主，然后打开 macOS Metal 窗口。
点击游戏窗口后操作。标题菜单使用左右键旋转；第一次选择 **Load → ROM 卡带
→ 存档 1**，读取第一话通关存档：玛娜米等级 2、总回合 7、资金 14,500。
`Continue` 读取地图中断存档，与这个通关存档不是同一槽位。

| 键盘 | N64 输入 / 用途 |
| --- | --- |
| 方向键 | 十字键：光标、菜单；标题左右旋转 |
| Z | A：确认、推进对话 |
| X | B：取消、返回 |
| Enter | Start |
| E + Enter | R + START：跳过当前整段开场缩放文字 |
| Q / E | L / R；地图上可切换我方机体 |
| 空格 | Z 扳机 |
| I / K / J / L | C 上 / 下 / 左 / 右 |
| W / S / A / D | 模拟摇杆上 / 下 / 左 / 右 |
| Esc 或窗口关闭按钮 | 退出程序 |

字母键按物理键位映射。窗口失去焦点时释放全部键；带 Command、Option 或
Control 的系统快捷键不会送入游戏。键盘以外的手柄尚未接入。

游戏内保存后再退出。首轮从冻结的 32 KiB 通关备份复制 SRAM，以后按运行报告的
ROM 身份、正常退出和最终摘要筛选最近可核验副本；损坏会话会报告原因并回退。
可用 `--list-saves` 查看、`--restore-session SESSION_ID` 指定恢复、`--restore-session initial`
选择冻结备份。文件完整性与游戏内槽位有效性分别判断，详见[存档恢复](native-save-recovery.md)。
每次运行写入独立的 `build/recomp/play/sessions/` 目录。
冻结备份不被覆盖，旧试玩目录也会保留。窗口不设自动退出时限，不会自动操作游戏。
试玩模式只保留最近一张 GPU 截图和对应元数据，音频与控制诊断保存在该次目录。

当前音频修复已验证设备队列不会在已测战斗中持续累积，实际扬声器音画同步仍需
人工试听。新增键盘接入以编译和启动验证为基础，物理键盘操作由试玩验收。
2026-09-12 已从冻结通关档冷启动恢复到整备，核对总回合 7、资金 14,500 和
玛娜米等级 2 / SP 102/102；没有进入第二话。完整证据与边界见[存档恢复](native-save-recovery.md)。

历史交接时已实际运行交互入口至 1,584 VI，验证无限时模式、存档副本哈希、重复启动
拒绝及正常退出。证据在 `build/recomp/play/handoff-evidence.json`；这次只检查启动，
没有继续操作通关存档。
