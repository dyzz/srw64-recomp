この MOD は、**原作にない**ユニット・武器・キャラクターをゲームに加えます。どれも独自の番号を持ち、原作の全キャラクター・全ユニットと並んで加わるので、誰かを置き換えることはありません。原作のユニットかキャラクターを 1 つコピーして出発点にし、名前・数値・武器・グラフィック・台詞を変えていきます。

1 つのパッケージで加えられるもの：

- **変形するユニット**。形態ごとに武器とマップアイコンを持ちます。
- **マップ上で合体するユニット**。パッケージに書いた組み合わせで合体し、また分離でき、合体した状態で出撃することもできます。合体後に改造しても、各パーツ自身の改造は消えません。
- **新しい武器**。**合体攻撃**も作れます。相方・EN・気力は原作と同じ規則で判定され、武器画面・図鑑・バトルビューアに相方が表示されます。
- **新キャラクター**。独自の顔グラフィック、**戦闘台詞とボイス**（通常の戦闘場面のほか、特定の武器を使うときや特定の相手に向けた台詞）、独自の**戦闘曲**を持てます。
- **敵側の新ユニット・新キャラクター**。シナリオで登場させます。
- **独自の立ち絵・戦闘グラフィック・カットイン**。立ち姿と技の中の場面を、HD と原作の画面用に 1 枚ずつ。

新ユニットと新キャラクターは、図鑑とバトルビューアに自分のグラフィックと作品名で表示されます。

バージョン 0.5.4 以降が必要です。パッケージのインストールと管理は [MOD パッケージ：インストールと作り方](../mods/) を見てください。

## ユニット MOD メーカーで作る

公式サイトの[ユニット MOD メーカー](/ja/mods/units/)で、こうしたパッケージをブラウザーの中で作れます。**画像と録音はどこにもアップロードされません**。

1. 原作のキャラクター・ユニット・武器をコピーし、4 言語の名前、数値、武器、形態、搭乗者、合体攻撃を変えます。
2. 自分の画像から顔グラフィックを切り出します。ユニットに立ち絵、カットイン付きの戦闘グラフィック、マップアイコンを付けると、ブラウザーがゲームの色数に減色します。
3. 4 言語の戦闘台詞を書き、1 つずつボイスを付けて波形の上で切り出せます。戦闘曲も付けられます。
4. ゲーム自身のエフェクトを組み合わせて武器の演出を作ります。役者を一人ずつ、または発射位置ごと動かし、原作のどの武器からでも役者を借り、カットインを加え、原作のエフェクトの色を変えます。手元の ROM を選ぶと、ステージに原作のエフェクトが描かれます（ROM はブラウザーの中で読むだけで、アップロードしません）。
5. このユニットがいつ加入するか、パッケージ独自の増援を書きます。`.srw64mod` を書き出すほか、Thunderstore 用のパッケージとしても書き出せます。

メーカーにはそのまま始められるテンプレートがあります。ゲームの「情報」ページにあるスイッチ（標準はオフ）を入れると、メーカーから起動中のゲームにパッケージを直接送り、バトルビューアで試せます。ゲームは受け取る前に確認します。

メーカーで今コピーしたり、演出を借りたり、ユニットに加えたりできるのは、よくある汎用武器（ビームライフル、ビームサーベル、バルカン、マシンガン、ミサイル、バズーカ、ビームキャノン、キャノン、格闘、体当たり、斧、サーベル）と、ユニット自身のコピー元のユニットの武器だけです。ほかの武器は今後対応します。もっと複雑なパッケージは、下の書式で手作業で書くか、AI アシスタントに任せてください。

## パッケージの中身

```text
yourname.rival/
  mod.json
  data/new_units.json            新ユニット・新武器・新キャラクター・新しい戦闘グラフィック（必須）
  data/units.json、pilots.json、weapons.json
                                 任意：コピーしてきた後の数値を変える（数値 MOD の書き方）
  dialogue/names.json            名前（名前 MOD の書き方）
  dialogue/battle_quotes.json    任意：新キャラクター専用の戦闘台詞
  art/…                          立ち絵・戦闘グラフィック・顔グラフィック・マップアイコン
  audio/…                        任意：ボイス・戦闘曲
  story/…                        任意：いつ加入するか、敵の登場（シナリオ MOD）
```

## new_units.json

```json
{
  "schema": "srw64.new-units.v2",
  "scenes":  { "cannon-pose": [2560, 1716, 2118] },
  "weapons": { "cannon": { "copy": 875, "inherits_from": 875,
                           "animation": { "camera": 1, "hit": 59, "action": 84, "defender": 125, "sounds": [219],
                                          "actors": [ { "scene": "@cannon-pose", "h4": 1, "h5": 255, "behavior": 359 } ] } } },
  "units":   { "final": { "copy": 224, "pose": [2324, 1724, 2016], "icon": 978,
                          "weapons": [870, 871, "@cannon"], "inherits_from": 224,
                          "crew": [171, 168, 170, 169, 166] } }
}
```

新ユニット・新武器・新キャラクター・新しい戦闘場面は、どれも**名前で書き**、番号はゲームが割り当てます。ユニットは 400〜998、武器は 1400〜2399、キャラクターは 400〜511、場面は原作の後ろに続きます。原作の番号は 1 つも使いません。

- 名前に使えるのは英小文字・数字・`-` `_` `.` だけです。パッケージのほかのファイルでは、このパッケージの新しいものを `@名前` で指します。`data/units.json` なら `"@final": {"hp": 8000}`、`dialogue/names.json` の `units` なら `"@final"`、マップアイコンは `art/icons/@final.png`、シナリオ MOD では `"with": "@final"`、`"unlock": "@cannon"` です。ほかのパッケージのものは `パッケージid@名前` と書き、そのパッケージを `mod.json` の `requires` に書きます。
- 番号は「パッケージ id@名前」から計算されるので、同じパッケージならどのマシンで、どの順にインストールしても同じになります。2 つの名前が同じ番号になったときだけ、片方が 1 つ後ろにずれます。セーブの横には、各番号がどのパッケージのどの名前かが記録されます。あとから入れたパッケージで番号がずれたときは、ロード時に今の番号へ自動で直します。そのパッケージを無効にした場合、そうしたセーブをロードするとタイトルに戻り、必要なパッケージが表示されます。

### ユニット（units）

| 項目 | 説明 |
| --- | --- |
| `copy` | コピー元のユニット（独自の戦闘記録を持つ原作のユニット番号か、別の新ユニット）。数値・武器・グラフィックはまずここから来ます。コピーのとき変形・分離・合体は外れます |
| `pose` | 立ち絵：原作の `[場面, 図集, パレット]` の 3 つのリソース番号か、パッケージの `"@画像名"`（[独自の戦闘グラフィック](#独自の戦闘グラフィック)を参照） |
| `icon` | マップアイコン：原作のアイコン番号。パッケージに `art/icons/@名前.png` があればそちらを使います |
| `weapons` | 武器表：原作の武器番号と `@新武器` |
| `inherits_from` | シナリオでこのユニットに乗り換えたとき（シナリオ MOD の `replace`）、改造段数をこの古いユニットから移します |
| `crew` | 1〜5 人のキャラクター番号。先頭がメインパイロットです。このユニットがメインパイロットに登録されると、残りの人物がその搭乗者になります |
| `combine` | パーツから合体します（下を参照） |
| `forms` | 変形（下を参照） |
| `work` | 図鑑の詳細に表示する原作。原作の作品番号 0〜24 で、書かなければコピー元のユニットと同じです。図鑑の型式の行は `dialogue/names.json` の `models` に書きます（48 文字まで） |

パッケージが加えたユニットとキャラクターは、図鑑のいちばん後ろの「MOD」グループに並びます。新ユニットの数に上限はありません。

**合体**：`"combine": {"parts": [2〜5 機のパーツ], "over": [原作の合体ユニット]}`。パーツの順がそのまま搭乗者（各パーツのメインパイロット）の順になります。マップ上で原作の合体ユニット（`over`）の「合体」が成り立ち、残りのパーツ（たとえばブラックウイング）もそばにいて未行動のとき、合体してできるのがこの新ユニットです。「分離」で全パーツに戻ります。このユニットはシナリオ MOD の `build` で作ります（[シナリオ MOD](../mod-story/)）。ステージ開始時に自分から出撃することはありません。

**変形**：基本の形態に `"forms": ["@wr"]` と書き、ほかの形態（同じファイルの新ユニット）を 1〜2 個並べます。各形態はこれまでどおり自分の `weapons`・`pose`・`icon` を書きます。各形態の武器は 1 つの共通リストにまとめられ、それぞれの武器はその武器を並べた形態でだけ使えます。改造段数・武器の段数・搭乗者は系列全体で共有し、原作と同じです。マップのメニューに「変形」が出ます（形態が 3 つあるときは選択肢が開きます）。ステージ開始時に出撃するのは基本の形態です。1 つのユニットは 1 つの変形系列にしか入れず、原作のユニットは加えられません。

### 武器（weapons）

- `copy` で原作の武器を 1 つコピーします。`inherits_from` は、この新武器の改造段数を古いユニットのどの武器から移すかを指します（古いユニットがもともと持っている武器はそのまま移ります）。
- `animation` は戦闘演出です。カメラ、命中エフェクト、動作、防御側の反応、効果音、役者（役者の `scene` にはパッケージの `@場面` も書けます）。ここはユニット MOD メーカーで組み立てるのがいちばん楽です。
- コピーした武器の格闘／射撃・移動後・ビームを `data/weapons.json` で変えると、メニューの名前の前後の「格／射」「P」「B」も変わります。

**合体攻撃**：`"combination": {"units": ["@z", 228], "parts": [196, 899], "multiplier": 1.5}`。`units` は参加する 2〜5 機のユニット（原作の番号か `@名前`）、`parts` は同じ順に各ユニットの構成武器を書きます。攻撃力はそれらの今の攻撃力の平均に `multiplier` を掛けたものです。省略可で `pilots: [[人物, 人物], …]` を書くと、メインパイロットがどれか 1 組そろっている必要があります。武器表にこの武器を持つ参加ユニットなら誰でも先頭に立てます。参加者は全員マップにいて、ひとつながりに（8 方向で隣り合って）並び、それぞれ EN と気力が足りている必要があります。使うと全機がこの武器の EN を消費し、弾数は減りません。弾数を使う武器をコピーしたときは、`data/weapons.json` で `en` と `"ammo": -1` を設定してください。相方がいないときは、マップの武器画面で灰色の文字になり、誰が足りないかが表示されます。合体攻撃は原作と同じく改造できません。`dialogue/names.json` の `weapons` で名前を付けるのを忘れないでください。付けないとコピー元の武器の名前で表示されます。

### キャラクター（pilots）

```json
"pilots": { "kai": { "copy": 166, "voice": 166,
                     "portrait": { "image": "art/kai.png", "hd": "art/kai-hd.png" } } }
```

| 項目 | 説明 |
| --- | --- |
| `copy` | コピー元の原作キャラクター（能力記録を持つもの）。能力・技能・精神・顔グラフィック・戦闘曲はここから来ます |
| `voice` | 戦闘で誰の台詞を借りるか。書かなければ `copy` と同じです。パッケージで専用の戦闘台詞を書いた場合も、書いていない場面ではこの人物の台詞を話します |
| `portrait` | パッケージの顔グラフィック：`image` は 96×96、63 色までのドット絵、`hd` は一辺が 96 の整数倍の正方形の高解像度画像（省略可）。原作の 2 つのリソース番号 `[画像, パレット]` も書けます。書かなければコピー元の顔グラフィックです |
| `love` | 省略可。恋愛／友情補正：`[{"with": 166, "mutual": true}]`。2 マス以内で攻撃 +30%、受けるダメージ −30%。`mutual` で相手にも付きます |
| `combo_as` | 省略可。合体攻撃のパイロット条件で、どの原作キャラクターとして数えるか |

新キャラクターは全パッケージ合わせて 112 人までです。数値・技能・精神は `data/pilots.json` の `"@kai"` で、名前は `dialogue/names.json` の `pilots."@kai"` で変え、加入はシナリオ MOD の `{"join": {"pilot": "@kai", "unit": 9}}` で行います。

`image` はリポジトリのツールで大きな画像から縮小して作れます：

```bash
python3 tools/mods/sprite_pixels.py 元画像.png kai.png --size 96 96 --colors 63
```

## 新キャラクター専用の戦闘台詞

```json
{
  "schema": "srw64.battle-quotes.v1",
  "pilots": {
    "@kai": {
      "attack":  [{"ja": "「カイ、行くぞ!」", "zh-Hans": "“凯，上了！”", "en": "\"Kai, here I come!\"", "voice": "kai-attack.ogg"},
                  {"ja": "「これでも食らえ!」", "zh-Hans": "“吃我这招！”"}],
      "evade":   [{"ja": "「見切った!」", "zh-Hans": "“看穿了！”"}],
      "special": [
        {"weapon": 49, "lines": [{"ja": "「全力の一撃だ!」", "zh-Hans": "“全力一击！”"}]},
        {"opponent": 298, "situation": "evade", "lines": [{"ja": "「そんな攻撃が当たるか!」", "zh-Hans": "“这种攻击打不中我！”"}]}
      ]
    }
  }
}
```

`dialogue/battle_quotes.json` に置きます。書けるのはパッケージの新キャラクター（`@名前`、またはほかのパッケージの `パッケージid@名前`）だけで、原作のキャラクターの台詞は変えられません。

- 場面は 9 種類で、原作と同じく毎回その組からランダムに 1 つを話します：`attack` 攻撃、`shot_down` 撃墜された、`heavy` 大ダメージ（残り HP 30% 未満）、`medium` 中ダメージ（30〜90%）、`light` 小ダメージ（90% 以上）、`evade` 回避、`no_damage` 攻撃が効かない（バリア、装甲）、`no_ammo` 弾切れか EN 不足で反撃できない、`out_of_range` 射程外で反撃できない。**書かなかった場面では `voice` の人物の台詞を話し**、台詞の枠にもその人物の名前と顔グラフィックが出ます。
- 台詞は 1 つずつオブジェクトで書きます。各言語の台詞（`ja` は必須で 42 文字まで、ちょうど 1 ページ 3 行分です。ほかの言語は 200 文字までで、リーダーが台詞の枠の幅に合わせて組みます）。省略可の `voice` は `audio/voice/battle/` にある `.ogg` のファイル名で、その台詞が表示されるときに流れます（Ogg Vorbis だけです。[音楽 MOD](../mod-music/#戦闘ボイス)を参照）。
- `special` は条件付きの台詞で、条件が成り立てば必ずそれを話します：
  - `"weapon": 武器`：この武器で攻撃するとき（原作の武器番号か `@新武器`）。同じ名前の武器は同じものとして扱い、新武器はコピー元の武器として扱います。`"sometimes": true` を付けると、原作の一部の武器台詞と同じく、よく通常の攻撃台詞に取って代わられます。
  - `"opponent": 原作の人物`：相手がこの人物のとき。`situation` に 9 種類の場面のどれかを書きます（既定は `attack`）。
  - 条件付きの台詞は 1 人あたり合計 119 個までです。同時に成り立つものが複数あればランダムに 1 つを選びます。
- 台詞の番号はゲームが割り当て（全パッケージ合わせて 2048 個まで）、セーブには記録しません。パッケージを無効にすると、借りていた台詞にそのまま戻ります。

新キャラクターの戦闘曲はパッケージの `audio/music.json` に `"battle": {"pilot": {"@kai": "@kai-theme"}}` と書き、曲は `audio/music/kai-theme.ogg` に置きます。[音楽 MOD](../mod-music/) を参照してください。

## 独自の戦闘グラフィック

新ユニットの立ち絵、技の中の場面、カットインには、パッケージの PNG を使えます。`new_units.json` に `sprites` を書きます：

```json
"sprites": {
  "stand":  { "image": "art/battle/stand.png", "origin": [59, 90], "hd": "art/battle/stand-hd.png" },
  "cutin":  { "image": "art/battle/cutin.png", "origin": [56, 48], "mirror": false, "ticks": [22], "hd": "art/battle/cutin-hd.png" }
},
"scenes": { "cutin": "@cutin" },
"units":  { "final": { "pose": "@stand" } }
```

- `image` はゲーム内の実際の大きさのドット絵（立ち絵でおよそ 128×96）で、127 色まで。半透明より薄い部分は透明として扱います。`python3 tools/mods/sprite_pixels.py 元画像.png 縮小.png --size 128 96` で大きな画像から縮小・減色して作れます。
- `hd` は 1 コマ 1 枚の高解像度画像です。HD の画面ではこれを、原作の画面では `image` を描きます。改造・能力などの画面と図鑑もこの 2 枚を使います。
- `origin` は、場面の原点に当たる画像内のピクセルです。立ち絵では足元の中央を書きます。
- `mirror` の既定は `true` で、ユニットや技の中のものは敵味方に合わせて反転します。カットインのように反転させないものは `false` にします。
- 複数コマは `"frames": [...]` で書き、`"ticks"`（各コマの長さ）と `"loop"`（最後まで流したあと戻るコマ）を添えます。
- `"around": [前, 後]`：武器エフェクトの中には「次の場面」に切り替わるものがあります（たとえばビームはビームの胴、ビームの尾と順に切り替わります）。そうした役者に自分の画像を使うときはこれを書きます。ユニット MOD メーカーの画像の差し替えでは自動で書かれます。一部の武器（約 95 件。何人かで連携する大技など）は、演出が場面番号どうしで計算し合うため、その役者の画像は差し替えられません（カットインは加えられます）。メーカーでは差し替えが固定され、ゲームもそうしたパッケージを読み込みません。
- 立ち絵の `pose` と場面の一覧 `scenes` には `@画像名` を書けます。これまでどおり原作の 3 つのリソース番号でもかまいません。
- 色替え：`scenes` に `{"recolor": 56, "colors": {"2": "#20e060"}}` と書くと、原作の戦闘場面 56（ビーム）の絵と動きのまま、パレットの指定したマスだけを新しい色にします（マス番号 0〜255。透明のマスは透明のまま）。原作画面でも HD 画面でも反映されます。**0.5.4.1 以降のゲームが必要**で、`mod.json` の `game` は `">=0.5.4.1"` にします。ユニット制作ツールでは「戦闘演出 → 色」でクリックして変えられ、書き出し時に自動で記入されます。

原作の画像を借り、HD パックで画像を差し替えるパッケージは、`mod.json` に `"requires": {"srw64.hd": ">=1.3"}` と書きます。HD パックがないときや画像を原作にしているときは、パッケージ全体が読み込まれず、MOD ページに「HD 画面が必要」と表示されます。ゲーム内で画像を切り替えたときは、再起動すると反映されます。

## 加入させる、敵に使わせる

新ユニットと新キャラクターは、インストールしただけでは出てきません。いつ加入するかをシナリオで書きます（[シナリオ MOD](../mod-story/)）：

- `{"join": {"pilot": "@kai", "unit": "@rz"}}`：人物とユニットが味方に加入します。
- `{"replace": {"pilot": 171, "unit": 224, "with": "@final"}}`：名簿の古いユニットを新しいユニットに替え、改造段数は `inherits_from` に従って移します。
- `{"build": "@final"}`：味方に合体ユニット（`combine` を書いた新ユニット）を 1 機作ります。
- `{"unlock": "@cannon"}`：イベントで解禁される新武器を解禁します。
- ストーリーファイルの `deployments`：敵や第三勢力にもパッケージの新ユニット・新キャラクターを使わせられます。

[追加シナリオ](../mod-campaign/)の出撃レコードにも `@名前` を書けます。

## サンプル

- 「ファイナルダンクーガ」：[`config/recomp/mods/final-dancouga`](https://github.com/dyzz/srw64-recomp/tree/main/config/recomp/mods/final-dancouga)。新ユニットは原作のファイナルダンクーガをコピーしたもので、搭乗者は 5 人、独自の立ち絵・カットイン・マップアイコンを持ちます。マップ上でダンクーガとブラックウイングが合体し、分離と再合体も、合体した状態での出撃もできます。[MOD ダウンロード](/ja/mods/#srw64.final-dancouga)ページから入手できます。
- 「カーツとスーパーアースゲイン」：[`config/recomp/mods/super-earthgain`](https://github.com/dyzz/srw64-recomp/tree/main/config/recomp/mods/super-earthgain)。ブラッド編「決着の時」をクリアするとカーツが仲間になり、アースゲインとヴァイローズがスーパーアースゲインに合体します（ブラッドがメイン、カーツがサブパイロット）。改造はアースゲインから引き継ぎます。出撃は合体した状態で、マップ上で分離すると 2 機で合体攻撃「招雷 天竜魔滅陣」が使え、隣り合えば再び合体できます。[MOD ダウンロード](/ja/mods/#srw64.super-earthgain)ページから入手できます。

### AI に書かせる

リポジトリの [`docs/guide/data-mods/`](https://github.com/dyzz/srw64-recomp/tree/main/docs/guide/data-mods) フォルダーに、完全な書式の説明（「新机体与新武器」の節）と CSV のユニット表・キャラクター表・武器表があります。各項目がどの表に入り、ゲームがどう読むかは [`docs/design/new-unit-ids.md`](https://github.com/dyzz/srw64-recomp/blob/main/docs/design/new-unit-ids.md) にあります（どちらも中国語です）。サンプルパッケージと一緒に AI アシスタントに渡せば、考えたとおりに書いてもらえます。書き終えたら `python3 tools/mods/validate.py パッケージ.srw64mod` で確認します。
