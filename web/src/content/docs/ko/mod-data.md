수치 MOD는 기체, 파일럿, 무기 자체의 수치를 바꿉니다. 그 수치를 읽는 모든 곳, 즉 전투 결과, 상태 화면, 도감이 이를 따릅니다.

JSON을 직접 쓰지 않으려면 [수치 MOD 제작 도구](/ko/mods/data/)를 사용하세요. 페이지에서 기체, 파일럿, 무기를 골라 수치를 바꾸고 .srw64mod로 내보낼 수 있습니다. 번호는 [기체](/ko/mods/ids/units/), [파일럿](/ko/mods/ids/pilots/), [무기](/ko/mods/ids/weapons/) ID 표에 있습니다.

패키지 설치와 관리: [MOD 패키지](../mods/). 지형 적응은 0.5.1부터, 그 밖의 필드는 0.5.2 이상에서 동작합니다.

## 패키지에 들어가는 것

```text
yourname.balance/
  mod.json
  data/
    units.json      기체, 기체 번호별
    pilots.json     파일럿, 파일럿 번호별
    weapons.json    무기, 무기 번호별
```

세 파일 중 어느 것이든 하나만 있어도 됩니다. `mod.json`은 다른 패키지와 똑같이 씁니다.

## 작성 방법

```json
{
  "184": { "hp": 5200, "armor": 1300, "terrain": { "sea": "A" } },
  "262": { "terrain": { "space": "A" }, "abilities": ["i_field"] }
}
```

- 최상위 키는 **번호**이며, 앞에 0을 붙이지 않은 일반 10진수입니다. `units.json`에는 기체 번호, `pilots.json`에는 파일럿 번호, `weapons.json`에는 무기 번호를 씁니다. 번호와 원작 수치는 [ID 표](/ko/mods/ids/)에서 찾을 수 있습니다.
- 각 번호 아래에는 바꾸는 필드만 씁니다. 나머지는 그대로 유지됩니다.
- 여러 패키지가 같은 대상을 바꾸면 MOD 목록에서 위에 있는 패키지가 우선합니다.

규칙은 엄격합니다. 모르는 필드, 범위를 벗어난 값이나 번호는 오류이며, **오류가 하나라도 있으면 파일 전체가 제외됩니다**. 이때 게임 로그에는 패키지, 파일, 이유를 적은 `SRW64_MOD_DATA_PROBLEM` 줄이 남습니다.

### 기체(units.json)

| 필드 | 의미 | 범위 |
| --- | --- | --- |
| `hp`, `en` | 최대 HP, EN | HP 1–65535, EN 0–65535 |
| `move` | 이동력 | 1–30 |
| `mobility`, `armor`, `limit` | 운동성, 장갑, 한계 | 0–65535 |
| `repair_cost` | 수리 비용 | 0–65535 |
| `upgrade_cap` | 개조 상한 | 0–15 |
| `terrain` | 지형 적응, 아래 참고 | |
| `size` | 사이즈 | `SS`, `S`, `M`, `L`, `LL` |
| `shield`, `sword` | 실드, 검 보유 여부(실드 방어와 베어내기에 사용) | `true` 또는 `false` |
| `parts_slots` | 강화파츠 슬롯 | 0–4 |
| `abilities` | 특수능력. **목록 전체**를 씁니다. 목록에 없는 것은 제거됩니다 | 아래 참고 |

특수능력 키:

| 키 | 특수능력 | 키 | 특수능력 |
| --- | --- | --- | --- |
| `beam_coat` | 빔 코트 | `mach_special` | 마하 스페셜 |
| `i_field` | I필드 | `true_mach_special` | 진 마하 스페셜 |
| `planet_defensor` | 플라네이트 디펜서 | `god_shadow` | 갓 섀도 |
| `aura_barrier` | 오라 배리어 | `getter_vision` | 겟타 비전 |
| `afterimage` | 분신 | `shungensoku` | 순환족 |
| `hyper_jammer` | 하이퍼 재머 | `hp_regen_10`, `hp_regen_20` | HP 회복 10%, 20% |

변형, 합체, 분리는 그 뒤에 있는 형태가 필요하므로 MOD로 추가하거나 제거할 수 없습니다. 원래 가진 기체는 그대로 유지합니다.

### 파일럿(pilots.json)

| 필드 | 의미 | 범위 |
| --- | --- | --- |
| `melee`, `ranged`, `evade`, `hit`, `reaction`, `skill` | 레벨 1의 여섯 능력치(격투, 사격, 회피, 명중, 반응, 기량) | 0–255 |
| `sp` | 레벨 1의 최대 SP | 0–255 |
| `double_move` | 한 턴에 두 번 행동하기 시작하는 레벨 | 0–99 |
| `terrain` | 지형 적응, 아래 참고 | |
| `skills` | 특수기능, 아래 참고 | |
| `spirits` | 정신기, 아래 참고 | |

능력치는 레벨 1의 값입니다. 레벨이 오를 때마다 원작과 같은 만큼 더해집니다(격투, 사격, 반응, 기량 +1, 회피, 명중 +2, SP +2).

**특수기능**은 특수기능 키와 습득 레벨로 씁니다. N번째 숫자가 L N이 되는 레벨이며, 최대 9개, 오름차순입니다. `null`은 그 특수기능을 제거합니다.

```json
{ "133": { "skills": { "newtype": [1, 4, 8, 12, 18, 24, 30, 38, 45], "parry": null } } }
```

| 키 | 특수기능 | 키 | 특수기능 |
| --- | --- | --- | --- |
| `newtype` | 뉴타입 | `esp` | 초능력 |
| `enhanced` | 강화인간 | `potential` | 저력 |
| `holy_warrior` | 성전사 | `parry` | 베어내기 |
|  |  | `shield_defense` | 실드 방어 |

뉴타입, 강화인간, 성전사, 초능력, 저력은 원작에서 레벨 한 줄을 함께 쓰므로 파일럿은 이 중 최대 하나만 가질 수 있습니다. 하나를 쓰면 다른 것을 대체합니다. 쓰지 않은 특수기능은 그대로 유지됩니다.

**정신기**는 목록 전체를 씁니다. 최대 6개 항목이며, 각각 `[정신기 키, 습득 레벨]`이고 레벨은 오름차순입니다.

```json
{ "133": { "spirits": [["focus", 1], ["guts", 5], ["valor", 12], ["soul", 40]] } }
```

정신기 키: `self_destruct` 자폭, `scout` 정찰, `accel` 가속, `mercy` 힘조절, `focus` 집중, `alert` 번뜩임, `guts` 근성, `strike` 필중, `trust` 신뢰, `wall` 벽, `cover` 대신 맞기, `valor` 열혈, `spirit` 기합, `great_guts` 초근성, `luck` 행운, `drain` 탈력, `effort` 노력, `soul` 혼, `stealth` 은신, `awaken` 각성, `refuel` 보급, `provoke` 도발, `encourage` 격려, `disrupt` 교란, `friendship` 우정, `love` 사랑, `reactivate` 재동, `miracle` 기적, `prayer` 기도, `revive` 부활.

### 무기(weapons.json)

| 필드 | 의미 | 범위 |
| --- | --- | --- |
| `power` | 개조 전 공격력 | 0–25500, 100의 배수 |
| `range_min`, `range_max` | 최소 사거리와 최대 사거리 | 최소 0–30, 최대 1–30(맵 병기는 15까지), 최소는 최대 이하 |
| `hit` | 명중 보정 | -128–127 |
| `critical` | 크리티컬 보정 | -128–127 |
| `ammo` | 탄수, 없으면 `-1` | -1–99 |
| `en` | EN 소모 | 0–255 |
| `morale` | 필요 기력 | 0–255 |
| `terrain` | 무기 자체의 지형 적응 | |
| `attack` | 격투 또는 사격: 파일럿의 어느 능력치를 쓰는지, 그리고 이름 앞의 格／射 | `melee` 또는 `ranged` |
| `post_move` | 이동 후 사용 가능 여부(이름 뒤의 P) | `true` 또는 `false` |
| `beam` | 빔 무기 여부(이름 뒤의 B. I필드, 빔 코트, 플라네이트 디펜서는 빔만 막습니다) | `true` 또는 `false` |
| `parryable` | 베어내기로 막을 수 있는지 여부 | `true` 또는 `false` |
| `terrain_at` | 무기 자체의 지형 적응을 누구의 칸을 기준으로 판정하는지 | `attacker` 또는 `target` |
| `requires` | 상태 화면에 必要技能으로 표시되는 사용 조건, 아래 참고 | 키 또는 `null` |
| `upgrade_type` | 개조 유형: 0은 개조 불가, 1–4는 공격력 증가 줄(2와 3은 같은 줄을 쓰고 가격만 다릅니다) | 0–4 |
| `locked` | 스토리에서 해금될 때까지 목록에서 숨김(원작의 석파천경권, 단공광아검 등. 스토리 MOD의 `unlock`이나 원작의 풀개조 표가 해금합니다) | `true` 또는 `false` |

`attack`, `post_move`, `beam`, `parryable`, `terrain_at`, `requires`, `upgrade_type`, `locked`는 0.5.3 이상이 필요합니다. MAP 무기는 새로 만들거나 일반 무기로 바꿀 수 없습니다. 그 형태가 무기 51개분밖에 없는 표에 들어 있기 때문입니다. 합체 공격도 마찬가지입니다.

무기를 이동 후에 쓸 수 있게 하려면 `post_move: true`를 씁니다. 예를 들어 뉴 건담(50)의 핀 판넬(209)은 원작에서는 이동하지 않았을 때만 쓸 수 있지만, 이렇게 하면 이동한 뒤에도 쓸 수 있고 무기 목록의 이름 뒤에 P가 붙습니다. `false`는 그 반대로 P를 없앱니다. 이름 앞뒤의 格／射, P, B는 이 필드들을 따르므로 이름을 고칠 필요는 없습니다.

```json
{ "209": { "post_move": true },
  "731": { "attack": "melee", "beam": true, "requires": "newtype" } }
```

`requires` 키와 원작 상태 화면에 표시되는 내용:

| 키 | 조건 | 표시 | 키 | 조건 | 표시 |
| --- | --- | --- | --- | --- | --- |
| `null` | 없음 | | `newtype` | 뉴타입 또는 강화인간 L1 이상 | NT1 |
| `ally` | 아군 전용 | | `newtype_4` | 뉴타입 또는 강화인간 L4 이상 | NT4 |
| `hyper_mode` | 파일럿이 하이퍼 모드 / 슈퍼 모드 상태 | 明鏡 | `holy_warrior` | 성전사 L1 이상 | 聖戦1 |
| `super_mode` | 위와 같으며 표시만 다름 | Sモード | `holy_warrior_3` | 성전사 L3 이상 | 聖戦3 |
| `level_10` … `level_45` | 파일럿 레벨 10 / 15 / 20 / 25 / 30 / 35 / 45 이상 | LV10 … LV45 | `v_max`, `v_max_red` | V-MAX / V-MAX 레드 파워 발동 중 | V-MAX |

개조하면 원작과 같이 공격력이 오릅니다. **여러 기체가 가진 무기는 모든 기체에서 함께 바뀝니다.** ID 표의 “장착 기체” 열에 그 기체들이 나와 있습니다.

### 지형 적응(terrain)

바꾸는 지형만 씁니다: `air`, `land`, `sea`, `space`에 `A`, `B`, `C`, `D`, `-` 중 하나. 나머지는 그대로 유지됩니다. 기체, 파일럿, 무기 모두 이 방식을 씁니다.

## 전투에서 지형 적응을 합산하는 방법

전투에서 기체의 적응은 **기체의 적응과 파일럿의 적응을 더한 값**을 구간으로 나누어 정합니다.

| 적응 | A | B | C | D | - |
| --- | --- | --- | --- | --- | --- |
| 점수 | 4 | 3 | 2 | 1 | 0 |

| 합계 | 8 이상 | 6–7 | 4–5 | 1–3 | 0 |
| --- | --- | --- | --- | --- | --- |
| 판정 | A (120%) | B (100%) | C (80%) | D (60%) | - (0%) |

공격 측의 공격력과 방어 측의 장갑에 각각의 배율을 곱합니다. 그래서 **기체가 이미 A라면, 전투에서 A가 되게 하는 것은 파일럿뿐입니다**. 고쇼군(184)은 우주 A, 신고(133)는 B여서 합계 7이며, 원작에서는 B로 판정됩니다. 신고의 우주를 A로 올리면 A가 됩니다.

무기 자체의 지형 적응은 무기에만 달려 있으며, 한 번 더 곱해집니다.

## 변경이 적용되는 시점

패키지를 설치하거나 켜고 끈 뒤에 다시 시작할 필요는 없습니다. 게임은 이 수치를 메모리에 계속 들고 있지 않고 필요할 때마다 다시 읽으므로 다음과 같습니다.

- **세이브를 불러올 때**(인터미션 세이브든 스테이지 중의 중단 세이브든) 모든 기체, 무기, 파일럿을 지금 켜져 있는 패키지로 다시 만듭니다. 패키지를 켜고 불러오면 새 수치가 되고, 끄고 다시 불러오면 원작 수치로 돌아갑니다. 세이브 자체는 절대 바뀌지 않습니다.
- 기체의 수치와 무기의 공격력, 최대 사거리, 공중 적응은 맵이나 인터미션에 들어갈 때 갱신됩니다.
- 무기의 나머지 필드와 파일럿의 모든 수치는 불러오기(또는 새 게임)가 필요합니다. 파일럿은 레벨업할 때도 갱신됩니다. 스테이지 도중에 패키지를 바꿨다면 저장하고 불러오세요.
- 도감에도 바뀐 수치가 표시됩니다.

## 공유 레코드

일부 파일럿은 능력 레코드(능력치, 지형 적응, 특수기능) 하나를 함께 씁니다. 대부분 같은 캐릭터의 다른 번호입니다(예: 도몬의 4, 273, 274). 하나를 바꾸면 모두 바뀌며, ID 표의 “능력 기록 공유” 열에 그 대상이 나와 있습니다. 정신기는 별도의 레코드를 쓰며, 이것도 공유될 수 있습니다.

이름이 같은 항목도 번호가 다르면 다른 대상입니다. 변형한 형태, 적 쪽의 복사본, 스토리 전용 등이 있습니다. 바꾸기 전에 원작 수치를 확인하세요.

## 예시

예시 패키지 “주력 우주 적응 A”(Main Cast: Space A)는 [MOD 페이지](/ko/mods/#srw64.space-a)에서 받을 수 있고, 소스는 [`config/recomp/mods/space-a`](https://github.com/dyzz/srw64-recomp/tree/main/config/recomp/mods/space-a)입니다. 주력 아군 중 우주 적응이 A 미만인 파일럿 20명과 기체 21기의 우주 적응을 A로 올립니다. 마징가 팀, 컴배틀러 V, 겟타 3, 고쇼군, 자이언트 로보, 단바인 진영, 건캐논, 건탱크 등이 해당합니다.

무기 속성의 예시는 패키지 “판넬 이동 후 사용 가능”입니다. 같은 [MOD 페이지](/ko/mods/#srw64.funnels-p)에 있고 소스는 [`config/recomp/mods/funnels-p`](https://github.com/dyzz/srw64-recomp/tree/main/config/recomp/mods/funnels-p)입니다. 판넬과 비트 계열 무기 9개에 각각 `post_move: true` 한 줄씩이며, 0.5.3 이상이 필요합니다.

이름과 초상화: [이름·초상화 MOD](../mod-names/).

### AI에게 맡기기

저장소의 [`docs/guide/data-mods/`](https://github.com/dyzz/srw64-recomp/tree/main/docs/guide/data-mods) 폴더에는 형식 설명과 기체, 파일럿, 무기 표가 CSV로 들어 있습니다. 폴더 전체를 AI 어시스턴트에게 건네고 원하는 `units.json`, `pilots.json`, `weapons.json`을 만들어 달라고 하세요.
