剧情 MOD 给原版的关卡加事件：第几回合、谁被击破、谁和谁交战、选了「说服」……的时候，播你写的台词，让人物加入、离场，或者改剧情变量让后面的原版剧情换一条路走。触发判断由游戏来做，你只写条件和要做的事，不用懂原版的事件表。原版的事件一个都不会被改动或挤掉。

包的安装和管理见 [MOD 包：安装与制作](../mods/)。需要 0.5.3 或更新的版本；下面标了「0.5.4」的条件和动作需要 0.5.4 或更新的版本。

完整的示例是「东方不败存活」，源文件在 [`config/recomp/mods/master-asia`](https://github.com/dyzz/srw64-recomp/tree/main/config/recomp/mods/master-asia)：独立军线「死斗！大屿山大决战（下）」和 OZ 线「绝望与悲伤之拳（下）」里，多蒙在战斗中和东方不败交谈过之后可以说服他，击坠数 50 以上时东方不败撤退，过关后加入。

## 包的结构

```text
yourname.story/
  mod.json
  story/
    <任意名>.json     剧情脚本，可以有几份
  data/
    pilots.json       需要时顺便改数值（见数值 MOD）
```

打包时（`tools/mods/pack.py`）`story/` 里的剧情脚本会被编译成游戏读的格式，写错了会报出是哪个事件的哪一项。

## 写法

```json
{
  "schema": "srw64.story.v1",
  "events": [
    {
      "id": "persuade",
      "scene": 129,
      "when": { "persuade": { "by": 4, "target": 18 } },
      "if": { "vars": { "131": 0 }, "kills": { "4": 50 } },
      "do": [
        { "say": 4, "text": { "ja": "「師匠！」", "zh-Hans": "“师父！”", "en": "“Master!”" } },
        { "say": 18, "mode": 2, "text": { "ja": "「……」", "zh-Hans": "“……”", "en": "“...”" } },
        { "leave": 18 },
        { "set": { "131": 3 } }
      ]
    },
    {
      "id": "joins",
      "scene": 129,
      "when": { "after": "end" },
      "if": { "fired": ["persuade"] },
      "do": [ { "join": { "pilot": 18, "unit": 27 } } ]
    }
  ]
}
```

每个事件：

| 字段 | 说明 |
| --- | --- |
| `id` | 事件名，包里唯一，别的事件用它引用 |
| `scene` | 哪一关，写场景号（0–255）。各关的场景号见[场景号对照表](https://github.com/dyzz/srw64-recomp/blob/main/docs/guide/story-mods/scenes.csv) |
| `when` | 什么时候触发，见下 |
| `if` | 可选，还要满足什么 |
| `do` | 做什么，按顺序执行 |
| `repeat` | 可选，写 `true` 可以反复触发 |
| `set_flags` | 可选，事件跑完时设上的标记，给后面的关用 |
| `note` | 可选，随便写说明，游戏不读 |

**每个事件每关默认只触发一次**，游戏自己记，跟着中断存档走，不用像原版那样自己写变量防止重复播放。

人物号、机体号见[数值 MOD 的人物表和机体表](../mod-data/)。

## when：什么时候

| 写法 | 意思 |
| --- | --- |
| `{"turn": {"turn": 3, "side": "player"}}` | 第 3 回合起、该阵营的回合开始（`player`、`enemy`、`third`） |
| `{"defeated": 18}` | 某人物的单位被击破（离场不算） |
| `{"hp_below": {"who": 18, "percent": 30}}` | 某人物的 HP 降到 30% 以下 |
| `{"battle": {"between": [4, 18], "moment": "after"}}` | 两人交战之后（`before` 是交战之前；人物号写 0 表示任何人） |
| `{"enemies_gone": true}` | 敌方全灭；写 `{"by_turn": 5}` 限第 5 回合以内 |
| `{"remaining": {"side": "enemy", "at_most": 3}}` | 敌方（或 `third` 第三方）只剩 3 台以下 |
| `{"persuade": {"by": 4, "target": 18}}` | 4 号站在 18 号旁边时，指令菜单出现「说服」，选了就触发 |
| `{"defeated": {"who": 18, "by": 4}}` | 18 号被 4 号击破（交战的另一方是 4 号）。0.5.4 |
| `{"downed": {"side": "player", "group": 2, "who": 18, "at_least": 2}}` | 本关到现在被击破的单位够数了（`side`、`group`、`who` 至少写一个，`at_least` 默认 1）。只算战斗里被打掉的，离场不算。0.5.4 |
| `{"group_gone": 3}` | 原版这关的第 3 组都被击破了（至少打掉过一台、场上已经没有）。0.5.4 |
| `{"reach": {"who": 18, "area": [10, 4, 12, 6]}}` | 18 号进入这块区域（两个角的格，含边）；把 `who` 换成 `"side": "player"` 表示该阵营的任意一台。已经站在里面的也算。0.5.4 |
| `{"remaining": {"side": "player", "at_most": 2}}` | `side` 也可以写 `player`：我方只剩 2 台以下。0.5.4 |
| `{"after": "opening"}`、`"setup"`、`"end"` | 接在这关原版的开场、初期配置、结束事件之后 |

同一时刻原版也有事件要触发时，先跑原版的，你的事件在下一次检查时再看。开场、配置、结束之后的事件不能写 `repeat`。

## if：还要满足什么

| 写法 | 意思 |
| --- | --- |
| `"vars": {"131": 0}` | 剧情变量（0–199）等于这个值（0–3）。原版用剧情变量记分支，例如场景 129 的 131 号是「多蒙在战斗中和东方不败说过话」（说过是 0） |
| `"kills": {"4": 50}` | 我方这个人物的击坠数至少这么多 |
| `"kills_below": {"4": 50}` | 击坠数不到这么多 |
| `"fired": ["persuade"]` | 本包的这些事件本关已经触发过 |
| `"not_fired": [...]` | 本关还没触发过 |
| `"roster": {"pilots": [18], "units": [27]}` | 这些人物、机体在我方名册里（不管出没出击） |
| `"not_roster": {...}` | 都不在名册里 |
| `"flags": ["persuaded"]` | 本包的这些标记已经设过 |
| `"not_flags": [...]` | 都没设过 |
| `"turn": {"from": 3, "to": 5}` | 当前回合在这之间（可以只写一个）。0.5.4 |
| `"on_map": [18]`、`"defeated": [18]`、`"absent": [18]` | 这些人在场上／本关被击破了／不在场上。0.5.4 |
| `"hp": {"who": 18, "below": 50}` | 在场而且 HP 低于 50%。0.5.4 |
| `"count": {"side": "enemy", "at_most": 3, "at_least": 1}` | 这个阵营在场上的台数。0.5.4 |
| `"in_area": {"who": 18, "area": [x0, y0, x1, y1]}` | 此刻在这块区域里（也可以写 `side`，同 `reach`）。0.5.4 |
| `"downed": {…}` | 同时机里的 `downed`。0.5.4 |
| `"route": [0, 1]` | 主角路线（0 布拉德、1 玛娜米、2 阿克、3 塞蕾茵）。0.5.4 |
| `"choice": 2` | 上一个选项选的是第 2 项。0.5.4 |
| `"funds": {"at_least": 50000}` | 资金（也可以写 `below`）。0.5.4 |
| `"any": [{…}, {…}]`、`"all": [...]`、`"not": {…}` | 其中一个成立／都成立／不成立。里面写的还是这些条件，可以嵌套。0.5.4 |

人物不在我方名册里时，`kills` 和 `kills_below` 都不成立。

**成功和失败两套台词**：同一个时机写两个事件，让条件互斥，游戏会选符合的那个。示例里击坠数够就成功，不够就播被拒的台词：

```json
{ "id": "persuade", "when": { "persuade": { "by": 4, "target": 18 } },
  "if": { "vars": { "131": 0 }, "kills": { "4": 50 }, "not_fired": ["refused"] }, "do": [] },
{ "id": "refused", "when": { "persuade": { "by": 4, "target": 18 } },
  "if": { "vars": { "131": 0 }, "kills_below": { "4": 50 } }, "do": [] }
```

被拒的事件只触发一次，成功的又要求 `not_fired: refused`，所以被拒之后本关两个都不成立，菜单里不再出现「说服」，剧情照原版走。想让玩家能再试，就给被拒的写 `"repeat": true`，并去掉成功那个的 `not_fired`。

## 跨关：标记

`fired` 只管本关，到下一关就清空。要让后面的关知道前面发生过什么，在事件上写 `"set_flags": ["标记名"]`（小写字母、数字、`_`、`-`，最多 32 个字），事件跑完时设上。标记只属于你的包，和原版剧情变量无关，跟着中断存档和场间存档走，开新游戏才清空。

```json
{ "id": "persuade", "scene": 129, "set_flags": ["persuaded"], "when": { "persuade": { "by": 4, "target": 18 } }, "do": [] },
{ "id": "comes-along", "scene": 81, "when": { "after": "opening" },
  "if": { "roster": { "pilots": [18] }, "flags": ["persuaded"] },
  "do": [ { "say": 18, "text": { "ja": "「ドモン、遅れを取るでないぞ！」", "zh-Hans": "“多蒙，别落在后面！”" } } ] }
```

这里同时看名册，是因为他之后可能又被原版剧情或别的事件从名册删掉；只看标记的话，人不在也会说话。

## do：做什么

| 动作 | 意思 |
| --- | --- |
| `{"say": 18, "text": {...}, "mode": 0}` | 一句台词，见下。说话人也可以是包里新人物的 `"@名字"`，名牌和头像是它自己的（0.5.4） |
| `{"say": 36, "silhouette": true, "text": {...}}` | 用原版的剪影说话（名字「???」、黑色头像）。只有原版有剪影版的 33 个人物能用（万丈、大作、阿姆罗、奇波迪等），写了别人编译会报错。0.5.4 |
| `{"join": {"pilot": 18, "unit": 27}}` | 人物和机体加入我方 |
| `{"remove": {"pilot": 18, "unit": 27}}` | 从名册删掉（单位要先离场） |
| `{"remove_unit": {"pilot": 166, "unit": 228}}` | 只删机体，人物留在名册里；人物要正坐在这台上。0.5.4 |
| `{"replace": {"pilot": 171, "unit": 224, "with": "@final"}}` | 换机：名册里的旧机体换成新机体，人物坐上去，改造段数照原版的继承表搬过去。新机体写 `@名字`（见[新机体、新人物与新武器 MOD](../mod-units/)），要继承改造就在新机体上写 `inherits_from`。0.5.4 |
| `{"unlock": 881}` | 解锁一件剧情解锁的武器（也可以写 `@新武器`）。换机不会把原武器的解锁带过去，要对新武器再解锁。0.5.4 |
| `{"build": "@final"}` | 事件开始时给我方建一台合体机（写了 `combine` 的新机体）：乘员是各部件的主驾驶，改造段数照 `inherits_from`，不出击。同一事件里后面的 `unlock` 能解锁它的武器；已经有一台就不再建。0.5.4 |
| `{"crew": {"unit": "@final", "pilots": [171, 168, 170, 169, 166]}}` | 事件跑完时把这些人物挂成这台机体的乘员（最多 5 人，第一个是主驾驶，要已经坐在上面）。包里的新机体更适合在 `new_units.json` 写 `crew`，换机时就挂上。0.5.4 |
| `{"leave": 18}` | 人物的单位离场（不算击破） |
| `{"leave_group": 11}`、`{"deploy": 11}` | 原版这关的出击组离场、登场 |
| `{"deploy": "rival"}`、`{"leave_group": "rival"}` | 包自己的增援组（`deployments`，见下）登场、离场 |
| `{"set": {"131": 3}}` | 设剧情变量 |
| `{"if": {"var": 128, "is": 2}, "then": [...], "else": [...]}` | 按剧情变量分支 |
| `{"if": {…条件…}, "then": [...], "else": [...]}` | 按「if：还要满足什么」里的任何条件分支，写法同事件的 `if`。在执行到这一步之前判断，所以紧挨着的前一步（比如刚 `join`）可能还没算进去。0.5.4 |
| `{"choose": {"text": {"ja": ["はい", "いいえ"], "zh-Hans": ["是", "否"]}, "options": [[...], [...]]}}` | 让玩家选（2–3 项），`options` 按顺序写选了每一项之后做什么。`text` 也可以写原版的选项文本号；自己写时每项不超过 24 字，要有 `ja`。问题句用前面的 `say`。0.5.4 |
| `{"focus": 18}` | 镜头移到这个人物 |
| `{"bgm": 11}`、`{"sound": 124}` | 换音乐、放音效 |
| `{"fade": "out"}`、`{"fade": "in"}`、`{"wait": 30}` | 淡出、淡入、等待（帧） |
| `{"close": "window"}` | 关掉对白窗口 |
| `{"op": "3D35", "args": [2335, 1]}` | 原版脚本指令照写，见[关卡脚本指令参考](../script-commands/)。可以直接用原版的台词，例如 `{"op": "3D40", "args": [43215]}` |

**台词**：`text` 必须有 `ja`，其他语言没写的显示日文（繁体没写时用简体）。一句最多 200 字，阅读器会自己分页，不要写 `<STOP>`。引号要自己写，和原版台词一样：日文、繁体用「」，简体、英文用 “”。`mode` 是原版对白的显示方式，地图上一般我方写 0、敌方写 2；世界地图上 0 和 1 上下交替。

**加入的等级**：照原版规则取这关的基准等级（由我方前 15 人的平均等级算出）。`"level": {"offset": 3}` 在基准上加减，`"level": {"like": 4}` 和 4 号人物同级（按加入那一刻算）。SP、能力、技能、精神由原版按等级算好；基础值要改就用 `data/pilots.json`（敌方人物的 SP、精神常常是空的，示例就补了 SP）。

## 包自己的增援

剧情文件顶层可以写 `deployments`，定义只属于这个包的出击组（敌人也可以用包里的新机体、新人物），事件里用 `{"deploy": "组名"}` 登场、`{"leave_group": "组名"}` 离场：

```json
"deployments": [
  { "id": "rival", "scene": 78, "units": [
    { "x": 10, "y": 9, "pilot": "@rival", "unit": "@rz", "level": 1 },
    { "x": 12, "y": 10, "pilot": 289, "unit": 21, "side": "enemy" } ] }
]
```

```json
{ "id": "rival-comes", "scene": 78, "when": { "turn": { "turn": 2, "side": "player" } },
  "do": [ { "deploy": "rival" } ] }
```

- `id` 只用小写字母、数字和 `- _ .`；用它的事件必须在同一关（`scene`）。一组 1–30 台。
- 每台写 `x`、`y`、`pilot`（人物号或 `@新人物`）、`unit`（机体号或 `@新机体`）；可选 `side`（`enemy` 默认、`third` 第三方、`third_hostile` 也攻击我方的第三方、`player` 我方）、`level`（在这关基准等级上加 0–20）、`upgrade`（改造档 0–5）。
- 人物号 287 以上（以及包里的新人物）按「通用驾驶员」生成；小于 287 的人物如果已经在我方名册里，会直接用名册里的那个人。
- 组号由游戏从这一关没用到的号里分配，你不用管；放不下时这一组不加，引用它的事件不会触发。

## 战斗台词

和 `events` 并列写 `battle_lines`，给战斗演出加新台词（0.5.4）：

```json
"battle_lines": [
  { "id": "see", "scene": 129, "who": 36, "against": 287, "when": ["attack", "evade"],
    "text": { "ja": "「見える！」", "zh-Hans": "“看见了！”" }, "once": true }
]
```

- `when` 是出手 `attack`、被击坠 `defeated`、重伤 `heavy`、中伤 `damaged`、轻伤 `light`、回避 `evade`、攻击无效 `no_effect`、弹药或 EN 不足 `no_ammo`、射程外 `out_of_range`，可以写一个或一组。
- `against` 是对手，不写就是对谁都说；还可以写 `if`（同事件的条件），`once` 让它本关只说一次。一句最多 60 字。
- 到了这些时候，这句换掉原版本来要说的那句。只有原版本来就有战斗台词的人物会说；原版选中合体技对话之类的专门台词时，可能仍是原版那句。包里新人物自己的战斗台词另有写法，见[新机体、新人物与新武器 MOD](../mod-units/#新人物自己的战斗台词)。

## 本关情报里的隐藏要素

剧情文件顶层可以写 `stage_info`，给关卡的「本关情报」页加几条隐藏要素，和原版的写在一起：

```json
"stage_info": [
  { "id": "final", "scene": 78,
    "title": { "ja": "ファイナルダンクーガ", "zh-Hans": "终极断空我", "en": "Final Dancouga" },
    "text":  { "ja": "クリア時にアランとブラックウイングがいれば入手", "zh-Hans": "通关时阿兰和黑翼在队即可获得", "en": "Clear with Alan and Black Wing on your side" },
    "done":  { "units": ["@final"] },
    "inherit": { "after": [78], "do": [ { "build": "@final" } ] } }
]
```

- `scene` 是关卡号；`title`、`text` 按语言写，必须有 `ja`，一条最多 200 字。一关有几张路线卡片时，每张都加。
- `done` 可不写；写了就按名册判断：`units`（机体号或 `@名字`）、`pilots`（人物号）都在队时标「已完成」，否则「未开始」。
- `id`（小写字母、数字和 `- _ .`，包内不重复）可不写；写了，这一条就和原版的隐藏要素一样进历代记录：任何一个周目里 `done` 成立过，本关情报页上就标「历代已完成」。
- `inherit` 是周目继承：规则页难度调整「周目继承」开着、这一条在历代记录里、而且 `done` 还不成立时，在 `after` 里的关打完后的场间（或 `before` 里的关开打前的场间）执行 `do`。`do` 只能用 `join`、`replace`、`unlock`、`crew`、`build`，不改剧情变量。写 `inherit` 要同时写 `id` 和 `done`。包删掉或停用后这一条不补、不显示，但历代记录留着，装回来还算数。

## 台词写在纯文本文件里

对话多、要交给别人翻译时，`text`（以及本关情报的 `title`、`text`）可以写成 `"@名字"`，各语言的文字放在包里的 `story/<语言>/*.txt`：

```json
{ "say": "@kai", "text": "@kai-joins" }
```

```text
# story/ja/kai.txt
@kai-joins カイ
カイ、出撃する！

# story/zh-Hans/kai.txt
@kai-joins 凯
凯，出击！
```

- 写法和游戏附带的台词文件一样：`@名字 备注` 开始一条，下一行是这句台词；`#` 是注释，空行随便加；台词要以 `@`、`#`、`\` 开头时前面加 `\`。名字只能用小写字母、数字和 `- _ .`。
- 一条只写一行，阅读器自己分页、折行；一句最多 200 字。
- `ja` 必须有这一条，别的语言缺的用 `ja`（繁体缺的用简体）。同一语言里一个名字只能写一次，文件可以分好几个。
- 打包时这些文字编进剧情文件，`.txt` 不放进包里。JSON 里直接写 `{"ja": …}` 的台词照旧可用，两种可以混用。

## 要注意的

- **原版事件只看原版变量**。想让原版的某段事件不播或者换一段，就要改它判断的变量。示例里说服之后写 `131 = 3`，原版结束事件只在 131 为 1 或 2 时播东方不败的死别。
- **单位离场（`leave`）不会触发原版的击破事件**。原版击破后要做的事（示例里是王登场、打开过关条件），要在你的事件里自己做一遍。
- 同一段剧情搬到另一关前，先看那关的原版事件：交谈用哪个变量、某人被击破后原版接着做什么、结束事件按哪些变量播哪些段。示例的 OZ 线事件就是照场景 137 的原版事件改的。
- **标记存在存档旁边**（存档文件夹 `saves/` 里的 `story-state/`），不在存档文件本身里。把存档拿到别的模拟器，或者删掉这个文件夹，读回来就没有标记，跨关的事件不会触发；本关之内的事件不受影响。
- 追加剧本（`campaign/`）里的关卡不跑剧情 MOD。

## 检查和打包

编译器和官网的关卡编辑器是同一份（TypeScript），命令行要装 [Node.js](https://nodejs.org/) 23 或更新的版本，`python3` 会自动调用它。

```bash
python3 tools/mods/story.py compile story/master.json -o out.json
```

```bash
python3 tools/mods/pack.py yourname.story -o build/mods
```

第一条只编译一份剧情脚本，看每个事件编译出的指令。第二条打包并用和游戏相同的规则检查。游戏读不了的包会在日志里报 `SRW64_STORY_MOD_PROBLEM`。

仓库的 [`docs/guide/story-mods/`](https://github.com/dyzz/srw64-recomp/tree/main/docs/guide/story-mods) 文件夹里有完整的格式说明和场景号对照表，可以整个交给 AI 助手，让它照你的想法写剧情脚本。
