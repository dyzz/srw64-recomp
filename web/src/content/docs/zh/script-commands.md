关卡里的每个事件是一串 16 位字：指令码 `3D31`–`3D79` 后面跟它的操作数，条件指令 `3E00`–`3E1D` 组成判断块，上下文标记 `3DD0`–`3DDB` 按当前主角路线或选择肢挑出要执行的段落，`FFFF` 结束事件。写[迷你关卡](../mini-stage/)时，指令写成 `{"op": "3D45", "args": [1]}`，条件指令和标记也用同样的写法。

本页由 [`config/data/original-jp-v1.json`](https://github.com/dyzz/srw64-recomp/blob/main/config/data/original-jp-v1.json) 的 `stage_scripts` 表生成。「代码确认」表示含义已从游戏的处理函数确认；「结构确认」表示读写位置已确认，作用还没完全弄清。「依据」是对应的游戏代码（地址为日版 Rev 0 的内存地址），「实测」是在游戏里运行得到的结果。

### 3D31 · 世界地图定位（地点，与 3D32 同处理函数）

操作数（1 个字） · 代码确认 · 处理函数 `0x800A0E64`

1. 地点 — `world_location`

**依据**：一字索引 D_801C5310 的三个半字调用 801C4BCC，等待 801C4FBC 返回 1；load_000A7EC0 世界地图 overlay；PC+2。

**实测**（2026-09-16）：原脚本无实例。迷你关卡中 3D31 4 与基准 3D32 4 指向同一表项，画面同为不列颠／北海居中且带标记，用时同为 106 VI；与 3D32 共用 800A0E64，行为一致。

### 3D33 · 世界地图移动（目的地点）

操作数（1 个字） · 代码确认 · 处理函数 `0x800A0EFC`

### 3D34 · 切换地图并卷动至位置（地图编号, x, y, 种类）

操作数（4 个字） · 代码确认 · 处理函数 `0x8009F6FC`

1. 地图编号 — `map`：地图编号（base:map_assets；写入 8010F5EE）
2. x — `x`：格 x
3. y — `y`：格 y
4. 种类 — `raw`：未解释

**依据**：第 3 字为 0 → 状态 1：8020A9F4 把第 0 字低字节存入 802279EC 并调用 80099814(5,1,-1)，8020AAC8 按 8021E240 状态表推进到状态 2；否则状态 2：80212464 → 8020A874 直接把该字节写入当前地图索引 8010F5EE 并重载地图资源（8008B888(0x3B)、80098158、8009CB04/8009CA28、801C6394），8021261C 等待完成。之后 80209DAC(x, y, 1) 卷动视点；第 1/2 字为 0x4000 时改用 3D54 记住的位置；完成后 PC+8。非战术地图模式直接 PC+8。

**实测**（2026-09-16）：注入 3D34 0,10,10,0 与 3D34 0,24,24,1：当前地图索引 8010F5EE 由 20 变为 0，随机数表 2081 字节重建，整幅画面重绘为地图 0（14254/19200 采样像素变化），分别 64／42 VI 完成。

### 3D35 · 镜头卷动至位置（位置, 等待标志）

操作数（2 个字） · 代码确认 · 处理函数 `0x800A03E8`

1. 位置 — `position`：高字节 x／低字节 y，0x40–0x44 相对 3D54 位置
2. 等待标志 — `raw`：未解释

**依据**：第 0 字经 800A38DC 解码（高字节 x／低字节 y；0x40–0x44 为相对 3D54 记住位置：同位、上、右、下、左），第 1 字为 80209DAC 第三参数；完成后 PC+4。

**实测**（2026-09-17）：两个参数都已测清。第 1 字不是速度，而是等待标志：原脚本只出现 0（86 次）与 1（1076 次）；同一段距离分别执行，3D35 2068,0 与 5642,0 各阻塞 80／68 VI 直到卷动完成，3D35 2068,1 与 5642,1 都在 0 VI 立即返回、画面在其后帧里继续卷动。第 0 字：高字节 0x40–0x44 为相对 3D54 记住的位置（同位／上／右／下／左），低字节为格数；其余为绝对坐标（高字节 x、低字节 y）。把记住的位置设在地图中央后，以逐帧位移检测（160×120 采样，1 格 = 8 像素，残差 0.0）测得：相对上 3、下 3、左 3 各使画面内容精确位移 24 像素即 3 格，方向正确；相对右 3 只位移 4 像素，方向正确但被地图右边界截住（早先 inject-2 中右 3 同样贴边）。原脚本分布：绝对坐标 643 次、相对同位 490 次、右 15、上 8、下 5、左 1。相对移动每 3 格约 10 VI。此前 inject-2 已确认绝对卷动与 0x4000 回到记住位置。

### 3D36 · 画面震动（强度编号）

操作数（1 个字） · 代码确认 · 处理函数 `0x8009F880`

1. 强度编号 — `raw`：未解释

**依据**：战术地图模式：8020D3C8(低字节) 后等待 8020D4B0 状态机；其他模式 801C5000／801C5138；PC+2。

**实测**（2026-09-16）：逐帧采样定案。命令期间 frame-trace 的 mean_delta 由 0 跳到 23.65 并**保持恒定**，同时 mean_rgb 在 56.53 与 50.37 两个值之间**逐帧交替**（静止时为 54.23，即在静止位两侧摆动）；恒定的帧间差配合两值交替，正是画面在两个位置间逐帧往复。采样帧显示此时视口偏移、边缘露出黑边，与摆动一致。原脚本用法完全吻合：196 处调用几乎全部是「3D39 音效 → 3D36 n → 角色惊讶台词」（如 40 号音效后接「まさか……敵の攻撃だってのか!?」「え……何!?」），是配合音效表现冲击。参数决定时长：5 → 18 VI（9 帧摆动）、6 → 22 VI（11 帧），二者占 196 次中的 161 次；其余值 8/4/2/12/16/3 未逐一测量。不写任何状态，采集窗口内确证无声（声音由相邻的 3D39 提供）。

### 3D37 · 地图特效叠加（特效编号, 位置）

操作数（2 个字） · 代码确认 · 处理函数 `0x8009FF2C`

1. 特效编号 — `raw`：未解释
2. 位置 — `position`：高字节 x／低字节 y，0x40–0x44 相对 3D54 位置

**依据**：第 0 字索引 D_800C99D4 → D_8021DDE0 三半字资源参数，经 80098158 载入窗口 0x122；位置经 800A38DC 解码为格坐标；D_800C99D6[索引] 交给 8007E8A8 播放音效；卷动后等待窗口标志再关闭；PC+4。

**实测**（2026-09-17）：在同一单位格（位置 0x4000 = 3D54 记住的位置）上依次放三个原脚本用到的编号，逐帧测量该格亮度（基线 88.6）并截取峰值帧（build/recomp/mini-stage/hit-1/3D37-overlays.png）：编号 0 峰值 176.6、历时 28 VI，是覆盖整格的大型黄白爆炸；编号 1 峰值 130.3、历时 12 VI，是一道橙黄色的被弹火花；编号 11 峰值 106.0、历时 20 VI，是环绕单位的蓝色光环（护盾类）。三者全帧帧差都很小（0.7–1.5），是限于该格的局部效果，且不写任何状态。与静态描述一致：编号经 D_800C99D4 取资源参数载入窗口 0x122，并把 D_800C99D6[编号] 交给音效函数（编号 0 → 资源 3、音效 167；编号 1 → 资源 4、音效 166）。原脚本分布：1 为 370 次（常放在正被攻击的单位上）、0 为 192 次、11 为 11 次。

### 3D3C · 单位移动至位置（驾驶员, 位置）

2. 位置 — `position`：高字节 x／低字节 y，0x40–0x44 相对 3D54 位置

### 3D3D · 出击（–, –, –, 台数：0 = 选母舰 200 = 全部自动 其余 = 出击选择上限, 基准组）

操作数（5 个字） · 代码确认 · 处理函数 `0x800A09D0`

1. 保留（原脚本抄基准坐标 x） — `raw`：未解释
2. 保留（原脚本抄基准坐标 y） — `raw`：未解释
3. 参数（原脚本恒为 0） — `raw`：未解释
4. 台数（0 母舰／200 自动／其余为上限） — `raw`：未解释
5. 基准组 — `group`：配套记录组号

五轮实验汇总：孤立执行、与 3D46 配对、机体移到母舰旁、机体移到母舰同格、原脚本上下文——表现完全一致。原脚本 7 处实例全部紧跟同一角色的 3D46（退场）并由 3D3B 2/3 淡出淡入包住，位置上确属退场那一下的演出；命中 7 项舰长表（46 ブライト／180 シーラ／179 エレ／253 葉月博士／37 エマリー／49 ヘンケン／250 ハワード，999 先改写为 46）后还要求名册之后的两个战舰全局 8015E85C/60 非空且其 +0x38 驾驶员匹配。该条件在上述任何一轮都未成立，而它不由部署战舰满足，因此效果始终未显形。保持 unknown。

第七轮（scene78t-3，2026-09-17）补上引擎块探针后重测，排除了「只写引擎字段所以前六轮看不见」的可能。3D75 跨度（VI 6830–7018）内引擎块仅 +0x96D 由 0x02 变 0x00；但全程 90 个命令转换中该字节变化了 67 次（74%），与 +0x967（100%）、+0x97A/+0x97B（51%）等同属脚本虚拟机自身的工作状态，是每条命令都会动的簿记，不是本指令的写入。作为对照，同一轮里 +0x997（3D66 的位 7）只变了 5 次，恰是场景 78 里那几处 3D66——稀有且专一，说明按变化频率区分簿记与指令效果是可靠的。结论不变：在名册、驾驶员、机体、部件、剧情变量与引擎块全部覆盖的情况下，3D75 仍无任何专属写入。
