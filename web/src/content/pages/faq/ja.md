## なぜ ROM を自分で用意する必要があるのですか？

ゲームの内容は、起動時にお手持ちの ROM から読み込みます。このプロジェクトでは ROM を配布せず、リコンパイル用のツールとランタイム、翻訳テキスト、インターフェースを提供しています。原作のプログラム・テキスト・画像・音楽は、それぞれの権利者に帰属します。

対応する ROM は『スーパーロボット大戦64』日本版 Rev 0 のみです。`.z64`・`.v64`・`.n64` のどのバイトオーダーでも、ゲームが自動で判別して変換します。`.z64` 形式での SHA-256 は
`ee5f4a21d8e5f7827d21199e27800edf250df9a8e4d10befb1a6992df597b13e`。ほかのリビジョンには対応していません。

<span id="rom-location"></span>

## ROM はどこに置けばよいですか？

- **Windows**：ROM の名前を `rom.z64` に変更し、展開した `Marchwind64-windows-x64` フォルダーに置いて、`Marchwind64.cmd` をダブルクリックします（`Marchwind64.exe` ではありません）。`%LOCALAPPDATA%\SRW64Recomp\rom.z64` に置くこともできます。Windows は既定で拡張子を隠すため、`rom.z64.z64` になりがちです。エクスプローラーの「表示」で「ファイル名拡張子」をオンにしてから変更してください。
- **Linux／Steam Deck**：`rom.z64` に名前を変更して `marchwind64.sh` と同じ場所、または `~/.local/share/srw64-recomp/rom.z64` に置きます。
- **macOS・Android**：名前の変更は不要です。初回起動時に表示される画面で ROM を選択します。

ROM が圧縮ファイルなら先に展開してください。`.n64`・`.v64` 形式は `rom.n64`・`rom.v64` でもかまいません。詳しくは[インストール](/ja/install/)をご覧ください。

## エミュレーターですか？

静的リコンパイルによるネイティブ移植です。N64 の MIPS プログラムを C に変換し、Windows・macOS・Linux・Android のネイティブアプリとしてビルドしています。描画には [RT64](https://github.com/rt64/rt64) を使用します。BIOS やプラグイン、エミュレーターの設定は不要で、原作をもとに画面の変更や機能の追加も行えます。

## 対応プラットフォームとコントローラーは？

| プラットフォーム | 動作環境 |
| --- | --- |
| Windows（試験的） | 64 ビット版 Windows |
| macOS | Apple シリコン、macOS 14 以降 |
| Linux | x86-64、glibc 2.35 以降、Vulkan ドライバー |
| Steam Deck（試験的） | Linux 版と同じパッケージ。Deck を自動認識 |
| Android（試験的） | arm64、Android 9 以降、Vulkan 1.1 |

キーボードと一般的なコントローラーに対応し、画面のボタン表示は最後に使った機器に合わせて切り替わります。Android でコントローラーを接続していない場合は、タッチ操作が使えます。画面に触れると、その画面で使うボタンが「決定」「早送り」「次の味方」などの機能名とともに表示されます。キーやボタンの割り当ては、設定ウィンドウの「操作」ページで変更できます。

## セーブデータはどこにありますか？エミュレーターと共有できますか？

セーブデータはユーザーディレクトリの `saves` フォルダーにあります。

- **Windows**：`%LOCALAPPDATA%\SRW64Recomp\saves`。エクスプローラーのアドレスバーに入力して Enter で開けます。
- **macOS**：`~/Library/Application Support/SRW64Recomp/saves`。Finder で ⇧⌘G を押してパスを入力します。
- **Linux／Steam Deck**：`~/.local/share/srw64-recomp/saves`。
- **Android**：システムの「ファイル」アプリで「Marchwind64」を開き、その中の `saves` です。

`cartridge.sram` がカートリッジのセーブ（セーブ 1・2）、`slots/` がセーブ 3 以降、`auto/` がオートセーブです。バックアップは `saves` フォルダーごとコピーし、戻すときはゲームを終了してから元の場所に置きます。別のパソコンやプラットフォームへの移行も同じ方法です。

カートリッジのセーブ `saves/cartridge.sram` は ares の `.ram` と同じバイト列なので、そのまま相互にコピーできます。ほかのエミュレーターとのやり取りには、設定ウィンドウの「セーブ」ページを使います。「エミュレーター用に書き出す」でセーブ 1・2 を ares・Project64・mupen64plus・RetroArch の形式に変換します。「エミュレーターから取り込む」では、`import` フォルダーに置いたセーブを新しいセーブ枠に読み込み、既存のセーブを残します。

## いつでもステートセーブできますか？

できません。ゲームはエミュレーター上で動いていないため、エミュレーターのように好きな瞬間に保存・読み込みするステートセーブはありません。セーブは原作と同じ方法で行い、そのうえでオートセーブを追加しています。

- 初期設定でオンになっており、マップクリア後・出撃前・毎ターン開始時に保存します。
- 初期設定ではインターミッションのセーブを 3 つ、ターン開始のセーブを 5 つ残し、それを超えると古いものから消えます。残す数の変更やオートセーブのオフは、設定ウィンドウの「セーブ」ページでできます。
- オートセーブはタイトル画面のロード画面から読み込みます。ターン開始のセーブを読み込むと、そのターンの最初からやり直します。

## HD パックとは？

ゲームの画像を差し替える、別途ダウンロードできる任意のパックです。未導入ならオリジナルの画面で遊べます。導入後はゲーム中いつでもオリジナルと HD を切り替えられます。Android では、アプリアイコンを長押しして「HD パックを導入」を選ぶか、ダウンロードした zip を SRW64 で開いて導入します。

画像は主に次の 2 つの方法で制作しており、パック内の説明とリリースノートにも出典を記載しています。

- **AI 生成**：顔グラフィック・インターミッション背景・宇宙のオブジェクト・タイトル画像は、Alibaba Cloud の Qwen 画像モデルで、オリジナルの画面を参考に生成しています。シナリオのワールドマップと戦術マップの下絵は、同じくオリジナルの画面を参考に、OpenAI の画像モデルで描いたものです。
- **オリジナルからの拡大**：ユニットグラフィックとマップ上のユニットアイコンは、ローカルの拡大モデルでオリジナルのドット絵から描き直しています。戦術マップのパレット番号マップは、オリジナルのマップ画像を拡大したものです。

枠はプログラムで描画しています。BANPRESTO ロゴ・GAME OVER・ウィンドウ枠は、実行時にお手持ちの ROM から生成するため、パックには含まれません。

## 言語の切り替え方は？

設定ウィンドウの「言語」で中国語・英語・日本語を選べます。ゲーム中に切り替えるショートカットもあり、ボタンはプラットフォームごとに異なります（設定の「操作」ページに表示）。会話・メニュー・データのテキストがまとめて切り替わり、選んだ言語は次回の起動時にも引き継がれます。

## 原作との違いは？

シナリオは原作を引き継ぎ、数値・敵の行動・戦闘の計算も原作をもとにしています。設定ウィンドウの「ルール」ページには個別にオフにできる修正項目があり、有効にすると該当する計算やルールが変わります。

主な追加機能は、画面表示・会話・操作に関するものです。ネイティブ描画の設定画面とインターミッション画面、会話の履歴とオート、早送りとスキップ、ワイド画面、追加のセーブ枠、自動セーブ、キー割り当ての変更などを用意しています。

原作にはソフトリセットがあり、戦闘中に N64 コントローラーの Z と START を同時に押すと（お使いのキーボードやコントローラーでの割り当ては設定の「操作」ページを参照）タイトル画面に戻ります。セーブしていない進行は失われます。

## ゲームがある画面で止まる、ウィンドウが「応答なし」になる

多くの場合、グラフィックスドライバーが古いことが原因です。たとえば 2021 年の NVIDIA ドライバー（472.12）を使っていた Windows のプレイヤーでは、オープニングの炎の画面で止まり、ログにはグラフィックスデバイスの消失（`VK_ERROR_DEVICE_LOST`）が記録されていました。まずグラフィックスドライバーを最新版に更新してください。

- **NVIDIA**：NVIDIA App（または GeForce Experience）で更新するか、NVIDIA の公式サイトからダウンロードします。
- **AMD**：AMD の公式サイトから Adrenalin ドライバーをダウンロードします。
- **Intel**：インテル ドライバー & サポート・アシスタントで更新するか、Intel の公式サイトからダウンロードします。
- 専用 GPU と内蔵 GPU の両方を持つノートパソコンでは、両方のドライバーを更新してください。Windows Update が入れるドライバーは古いことが多いため、GPU メーカーの公式サイトから入手するのがおすすめです。
- **Linux**：システムのグラフィックスドライバー（Mesa または NVIDIA ドライバー）を更新してください。**Steam Deck** は SteamOS を最新にしておけば十分です。

更新しても止まる場合は、ゲームを閉じてもう一度開き、「オプション → 報告」で不具合レポートを書き出して（前回の実行ログも含まれます）、グラフィックスカードの型番とあわせて [GitHub の Issue](https://github.com/dyzz/srw64-recomp/issues) に添付してください。

## 不具合はどこに報告すればよいですか？

[GitHub の Issues](https://github.com/dyzz/srw64-recomp/issues) のフォームで報告してください。バージョン・プラットフォーム・問題が起きるまでの操作があると、再現しやすくなります。ゲーム内の「オプション → 報告」で環境情報のコピーと不具合レポート（バージョン、システム、グラフィックス、設定、直近の実行ログ。セーブデータと ROM は含みません）の書き出しができるので、あわせて添付してください。スクリーンショットもあれば助かります。ストーリーのセリフや図鑑の訳名へのご意見は、サイトの[ストーリー](/ja/story/)と[図鑑](/ja/library/)のページから該当箇所に直接送れます。
