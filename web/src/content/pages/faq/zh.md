## 为什么要自备 ROM？

游戏的程序、文字、图像和音乐都属于原作的版权方，我们不能发布。本项目只发布我们自己写的部分：把 N64 程序转成本机代码的工具与运行时、翻译文本和界面。游戏本身在你启动时从你自己的 ROM 读出。

支持的 ROM 只有一种：《超级机器人大战64》日版 Rev 0，`.z64` 字节序，SHA-256 为
`ee5f4a21d8e5f7827d21199e27800edf250df9a8e4d10befb1a6992df597b13e`。其他版本不受支持；`.n64`、`.v64` 字节序的文件要先用常见的 N64 ROM 工具转换成 `.z64`。

## 这是模拟器吗？

不是。我们用静态重编译把 N64 的 MIPS 程序翻译成 C，再编译成 Windows、macOS、Linux、Android 的本机程序；图形由 [RT64](https://github.com/rt64/rt64) 渲染。所以不需要 BIOS、插件或模拟器设置，也能在原版之外改界面、加功能。

## 支持哪些平台和手柄？

| 平台 | 要求 |
| --- | --- |
| Windows（实验性） | 64 位 Windows |
| macOS | Apple 芯片，macOS 14 起 |
| Linux | x86-64，glibc 2.35 起，需要 Vulkan 驱动 |
| Steam Deck（实验性） | 与 Linux 同一个包，自动识别 Deck |
| Android（实验性） | arm64，Android 9 起，需要 Vulkan 1.1 |

键盘和常见手柄都能用，按键提示会随你最后用的设备显示手柄或键盘的按键。Android 上没有手柄时用触屏：手指碰到屏幕就出现按键，按当前画面只显示用得上的几个，并写着「确定」「快进」「下个单位」这样的功能名。设置窗口的「操作」页可以改键。

## 存档在哪里？能和模拟器互通吗？

存档放在用户目录的 `saves` 文件夹里：

- macOS：`~/Library/Application Support/SRW64Recomp/`
- Linux／Steam Deck：`~/.local/share/srw64-recomp/`
- Windows：`%LOCALAPPDATA%\SRW64Recomp\`

卡带存档 `saves/cartridge.sram` 与 ares 的 `.ram` 是同一份字节，可以直接互拷。其他模拟器走设置窗口的「存档」页：「导出给模拟器」把存档栏 1、2 写成 ares、Project64、mupen64plus、RetroArch 的格式；「从模拟器导入」读取放进 `import` 文件夹的存档，导入为新的存档栏，原有存档不会被覆盖。

## HD 包是什么？

一个单独下载、可选安装的图片包，不改游戏内容，只替换画面。不装就是原版画面；装了以后按 <kbd>F6</kbd> 随时切换。

包里的图有两类来源，都在包内说明和发布说明里写明：

- **AI 生成**：头像、场间背景、宇宙物件和标题图由阿里云百炼的通义千问图像模型以原版画面为参考生成；剧情世界地图和战术地图的底图由 OpenAI 的图像模型以原版画面为参考绘制。
- **由原版放大**：机体立绘和地图上的机体图标用本地放大模型从原版像素图放大重绘；战术地图的色号图由原版地图像素放大而来。

边框由代码绘制；BANPRESTO 标志、GAME OVER 和窗口边框由游戏运行时从你的 ROM 算出，不在包里。

## 怎么换语言？

按 <kbd>F7</kbd>（Steam Deck 按下左摇杆）在中文、英文、日文之间切换，或在设置窗口的「语言」里选。对白、菜单和数据文本一起切换，下次启动会记住。

## 和原版有哪些不同？

剧情、数值、敌人行动和战斗结算都照原版运行。不同之处在于界面、阅读和便利功能：原生绘制的设置与场间画面、对白回看与自动阅读、快进与跳过、宽屏、多存档栏与自动存档、改键等。少量规则修正放在设置窗口的「规则」页，可以关掉。

战斗中按 Z+START 是原版自带的软复位，会回到标题画面，未存档的进度会丢失。

## 遇到问题怎么反馈？

到 [GitHub Issues](https://github.com/dyzz/srw64-recomp/issues) 提交，写明版本、平台和出问题前做了什么；有截图更好。游戏内的一键反馈还在开发中。
